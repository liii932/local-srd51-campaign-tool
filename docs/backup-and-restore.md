# 备份与恢复

应用 JSON 存档与数据库级备份解决不同问题。不要把其中一种描述成另一种的等价替代。

## 应用存档

主机页面可以导出 UTF-8 JSON，并在写入前执行严格上传、预览和确认。存档使用稳定业务键，排除数据库内部 ID、行版本、凭据、私钥和完整内部审计历史。

确认导入会按存档表达的当前权威状态新建或替换整场战役。预览摘要必须与确认请求绑定，确认事务会重新解析和复核；冲突、未知字段、非法关系、冻结模组不一致或任一写入失败都必须整体回滚。成功导入后旧 Session/CSRF 写入能力失效。

当前存档 `formatVersion=1` 只表达冻结简化 v1 的角色、字段、职业等级、熟练、简单物品、
节点地图、最小遭遇和受限近期事件。完整 SRD 5.1 版必须使用新的存档格式版本表达角色构筑
选择、法术、装备、资源、先攻、回合、状态、持续效果和完整当前遭遇状态；不得向版本 1
静默增加字段或改变既有字段含义。

新格式必须继续使用稳定业务键和精确白名单，严格读取器应先按 `formatVersion` 分派。旧版本
要么按原语义完整导入，要么返回稳定的版本/规则不兼容错误；任何战役规则升级都必须单独
预览和确认，不能在普通导入或应用启动时隐式发生。

## 数据库级备份

需要精确恢复包括内部历史在内的数据库状态时，使用 [tools/backup-database.ps1](../tools/backup-database.ps1)。脚本要求：

- Tomcat 已停止；
- 输出目录在仓库外；
- MySQL 口令交互输入，不进入命令行或文件；
- 单事务导出结构、数据和触发器；
- 先写临时文件，再校验关键表、`schema_meta` 和触发器定义；
- 成功后报告大小与 SHA-256，失败时不留下可误认的正式备份。

所有机器相关路径都必须显式提供，例如：

```powershell
.\tools\backup-database.ps1 `
  -DatabaseUser '<备份账号>' `
  -BackupDirectory '<仓库外备份目录>' `
  -MySqlDumpPath '<mysqldump.exe 的绝对路径>'
```

脚本不会自动恢复。恢复是破坏性外部操作，必须使用单独授权的 migrator 流程，并在恢复前再次备份当前状态、确认 Tomcat 停止、核对目标数据库和备份哈希。

## 存放与验证

备份、存档、日志、回滚树和 client option file 不得进入 Git 或 WAR。验证时优先核对元数据、计数和摘要，避免在日志或问题报告中复制私人战役内容。
