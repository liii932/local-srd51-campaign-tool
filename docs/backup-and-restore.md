# 备份与恢复

应用 JSON 存档与数据库级备份解决不同问题。不要把其中一种描述成另一种的等价替代。

## 应用存档

SQLite 当前应用模式的保存、结束、下载、上传导入与同版重开按[运行合同](storage-vitality-loop.md)
执行。选择 runtime 后，便携文件保留准确类型化规则/字段链、初始计划与初始状态、当前角色、
全部角色/战斗/根历史、原骰/资源消耗、场景/物品、效果及 pending。文件不是旧 MySQL format 1；
两种格式的读取入口与资格独立，不能互相改名导入。下面的 format 1/导入替换说明仅用于旧 MySQL。

主机页面可以导出 UTF-8 JSON，并在写入前执行严格上传、预览和确认。存档使用稳定业务键，排除数据库内部 ID、行版本、凭据、私钥和完整内部审计历史。

确认导入会按存档表达的当前权威状态新建或替换整场战役。预览摘要必须与确认请求绑定，确认事务会重新解析和复核；冲突、未知字段、非法关系、冻结模组不一致或任一写入失败都必须整体回滚。成功导入后旧 Session/CSRF 写入能力失效。

当前存档 `formatVersion=1` 只表达冻结简化 v1 的角色、字段、职业等级、熟练、简单物品、
节点地图、最小遭遇和受限近期事件。完整 SRD 5.1 版必须使用新的存档格式版本表达角色构筑
选择、法术、装备、资源、先攻、回合、状态、持续效果和完整当前遭遇状态；不得向版本 1
静默增加字段或改变既有字段含义。

项目处于原型阶段，存档只需支持当前应用版本声明的格式与规则。读取器先检查支持资格，
不支持的旧格式返回明确的版本/规则不兼容错误，无需保留旧读取器、转换链或跨版本战役连续性。
当前支持格式仍使用稳定业务键、精确白名单及原子导入，不得将旧数据静默解释为新模型。
只有用户另行要求保留特定数据时，才设计转换流程；该要求不由文件存在或历史发布状态推定。

## v2 目标与当前程序的区别

[完整文件与生命周期](design/v2/save-and-recovery.md)选择携带完整冻结规则材料/字段链的
独立 JSON 战役文件、随应用保管的四个准确规则 ZIP，以及每次打开的私有 SQLite 工作库。工作库保存尚未导出的最新提交及 pending；同版重启先
查证/完整校验，再显式继续、救援保存或精确放弃，不用旧 AUTO 覆盖新状态。文件发布、
工作库保存接受和运行目录清理各有成功点，不由浏览器下载证明。

新建/从完整 JSON 打开由[应用 JSON 结构计划](design/v2/storage-schema-and-planning.md)
建立新空间和当前表结构，再直接写入完整事实；同版残留则保留原库、身份及收据，核验
已存模型/闭包/计划与真实结构，不补表、不重 seed。正式文件不携带物理 DDL 或结构计划，
也不允许改选规则来恢复旧历史。删除文件、清理运行和维护来源包是不同操作，按
[文件删除边界](design/v2/save-and-recovery.md)分别识别目标和保管依赖。

当前有限 SQLite 模型已接合上述工作库与完整文件路径。业务、根历史和接受收据在独占门
及一个 `BEGIN IMMEDIATE` 中共同提交，不另设持久 C0 接纳/裁定。commit/rollback 未知
阻断新写，显式 recover 完整核验真实库、历史和收据后建立新 epoch，不自动重播未持久请求。
每命令 SQLite 耐久与 INITIAL/MANUAL/FINAL 是当前责任；周期 AUTO/轮换仍需容量测量及
独立实现。逐域覆盖与剩余差异见[领域接合表](design/v2/domain-integration.md)。上传先严格核验
完整字节，再保留文件原 fileKey 登记受管文件；同 fileKey 已存在即拒绝，不换身份、不覆盖、
不激活运行；用户另行打开才能开始新运行。
删除只针对受管 fileKey，并先排除活动/残留/收据依赖；不能通过删除保存点来丢弃工作库。
显式放弃只隔离并清理准确的非活动 run，不删除保存文件；未识别文件或锁冲突失败关闭。

下述 MySQL 程序只用于其外部运维，不能拿它证明 SQLite 恢复完成。
SQLite 物理备份须受控关闭或使用引擎一致备份；不能只复制活动 db 文件并漏掉热
journal。便携恢复共同保管 JSON、准确规则制品和支持它们的应用；当前四包不要求来源
MySQL 在线。现有来源库若有真实安装/接受账本，仍单独备份保管。

## 数据库级备份

需要精确恢复包括内部历史在内的数据库状态时，使用 [tools/backup-database.ps1](../tools/backup-database.ps1)。脚本要求：

- Tomcat 已停止；
- 输出目录在仓库外；
- MySQL 口令交互输入，不进入命令行或文件；
- 单事务导出结构、数据和触发器；
- 先写临时文件，再校验关键表、`schema_meta` 和触发器定义；
- 成功后报告大小与 SHA-256，失败时不留下可误认的正式备份。

所有机器相关路径都必须显式提供，例如：

```powershell
.\tools\backup-database.ps1 `
  -DatabaseUser '<备份账号>' `
  -BackupDirectory '<仓库外备份目录>' `
  -MySqlDumpPath '<mysqldump.exe 的绝对路径>'
```

脚本不会自动恢复。恢复是破坏性外部操作，必须使用单独授权的 migrator 流程，并在恢复前再次备份当前状态、确认 Tomcat 停止、核对目标数据库和备份哈希。

## 存放与验证

备份、存档、日志、回滚树和 client option file 不得进入 Git 或 WAR。验证时优先核对元数据、计数和摘要，避免在日志或问题报告中复制私人战役内容。
