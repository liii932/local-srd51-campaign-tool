# 备份与恢复

SQLite 完整 JSON、私有运行根与 MySQL 数据库备份解决不同问题；按实际启动模式选择恢复入口。

## 应用存档

### SQLite 完整文件与同版恢复

当前 SQLite 模式的保存、结束、下载、上传导入与同版重开按[运行合同](storage-vitality-loop.md)
执行。选择 runtime 后，便携文件保留准确类型化规则/字段链、初始计划与初始状态、当前角色、
全部角色/战斗/根历史、原骰/资源消耗、场景/物品、效果及 pending，以及成员、控制、共享和
明确裁定的领域事实。完整文件携带准确冻结规则材料/字段链，当前四个原包随应用保管。
文件不是 MySQL format 1；两种格式的读取入口与资格独立，不能互相改名导入。

每次新建或打开完整文件都会建立新的私有 SQLite 工作库和执行身份，保存完整初始事实及
此后提交的最新事实。完整文件不携带物理 DDL、结构计划、本地 run/epoch、请求收据、
玩家设备恢复凭据或会话；打开它不恢复原设备的连接和写权限。
上传先严格核验完整字节，再按原 `fileKey` 登记受管文件；同 `fileKey` 已存在即拒绝，
不换身份、不覆盖、不激活运行，需另行打开。

同版进程重启后，Host 状态查询先列出残留；对准确 run 显式执行 recover 时，才完整核验
原工作库、历史和收据，并在可继续运行时建立新 epoch。保存或精确放弃分别按当前状态
允许的入口执行，不以旧保存点覆盖尚未导出的新状态。commit/rollback 结果未知时阻断新写，
不自动重播未持久请求。
玩家需由 Host 重新开放，原设备才能换取新会话、只读查证原请求；恢复身份不自动接管写连接。

每条命令提交 SQLite，INITIAL/MANUAL/FINAL 分别形成独立受管完整文件；当前没有周期
AUTO/轮换。文件发布、工作库保存接受及运行目录清理各有成功点，浏览器下载不证明 END
完成。删除只针对准确受管 `fileKey`，须排除活动/残留/收据依赖；显式放弃只清理准确 run，
不删除保存文件。未知材料或锁冲突失败关闭，不能通过删保存点丢弃工作库。

物理备份先受控停止应用并整体保管私有根，包含全部 run、数据库/journal、准备/清理材料和
saves；不能只复制活动 db 或 JSON。恢复到新位置或更换运行账号时，先核对
[私有权限与文件系统边界](configuration.md#sqlite-当前应用存储配置)，不能删锁或改用空根
掩盖残留。便携恢复共同保管 JSON、准确规则制品和支持它们的应用；当前四包不要求来源
MySQL 在线。来源库若有真实安装/接受账本，仍单独备份保管。

### MySQL format 1 存档

MySQL 主机页面可以导出 UTF-8 JSON，并在写入前执行严格上传、预览和确认。存档使用
稳定业务键，排除数据库内部 ID、行版本、凭据、私钥和完整内部审计历史。

确认导入会按存档表达的当前权威状态新建或替换整场战役。预览摘要必须与确认请求绑定，
确认事务会重新解析和复核；冲突、未知字段、非法关系、冻结模组不一致或任一写入失败都
必须整体回滚。成功导入后旧 Session/CSRF 写入能力失效。

当前 `formatVersion=1` 只表达冻结简化 v1 的角色、字段、职业等级、熟练、简单物品、
节点地图、最小遭遇和受限近期事件。不能向该格式静默增加字段或改变既有含义。

项目处于原型阶段，存档只支持当前应用版本声明的格式与规则。不支持的格式明确拒绝，
不把旧数据静默解释为新模型；当前格式仍须满足精确白名单和原子导入。

## MySQL 数据库级备份

需要精确恢复包括内部历史在内的数据库状态时，使用 [tools/backup-database.ps1](../tools/backup-database.ps1)。脚本要求：

- Tomcat 已停止；
- 输出目录在仓库外；
- MySQL 口令交互输入，不进入命令行或文件；
- 单事务导出结构、数据和触发器；
- 先写临时文件，再校验关键表、`schema_meta` 和触发器定义；
- 成功后报告大小与 SHA-256，失败时不留下可误认的正式备份。

所有机器相关路径都必须显式提供，例如：

```powershell
.\tools\backup-database.ps1 `
  -DatabaseUser '<备份账号>' `
  -BackupDirectory '<仓库外备份目录>' `
  -MySqlDumpPath '<mysqldump.exe 的绝对路径>'
```

脚本不会自动恢复。恢复是破坏性外部操作，必须使用单独授权的 migrator 流程，并在恢复前再次备份当前状态、确认 Tomcat 停止、核对目标数据库和备份哈希。

## 存放与验证

备份、存档、日志、回滚树和 client option file 不得进入 Git 或 WAR。验证时优先核对元数据、计数和摘要，避免在日志或问题报告中复制私人战役内容。
