# 产品说明

Local 5E Campaign Tool 是面向单一 DM 的本机战役工具。内置规则范围以 D&D 5e 2014 / SRD 5.1
为边界，目标覆盖角色、冒险、装备、战斗、状态、法术、怪物及魔法物品。规则原文查阅从
[本地主题索引](references/srd-5.1/README.md)定位相关分页与 PDF。

本文区分当前可用行为与 v2 目标。目标设计进入项目文档，不表示功能已实现、规则已发布或
数据库已迁移；详细采用边界见 [v2 设计入口](design/v2/README.md)。

## 当前可用范围

正式业务使用冻结简化规则 `dnd5e2014_srd51_se_v1` release `"1"`，支持战役管理、PC/NPC、
基础角色卡、简单物品、d20 检定、类型化效果、节点地图、最小遭遇与格式 1 战役存档。
战役权威状态保存在运行数据库，重启后按现行 v1 合同读取。

完整规则族 `dnd5e2014_srd51_se` release `"1"` 仍为 DRAFT。已有角色规则内部切片以及语言/工具熟练目录的
作者源、安装、来源读取和运行快照分区；它们不构成完整 v2 游戏入口。当前实现依据见
[架构](architecture.md)、[数据库](database.md)和[完整规则覆盖目标](rules/srd-5.1-complete.md)。
schema 2 的[初始授予计划](rules/schema-2-proficiency-grants.md)可从固定快照验证真实角色来源、
语言／工具选择及抑制事实；它仍是内部接入，不开放角色创建或完整战役初始化。
[角色成长与资源切片](rules/schema-2-character-statistics.md)可在准确准备身份上保存真实状态，
执行有界职业成长、子职业／ASI／专长和多职业选择、资源消费，以及[标准休息](rules/schema-2-character-rest.md)，
并保留完整局部历史和直接恢复材料。内部起点使用标准数组；种族能力修正、所有特性效果、
完整战役及 Host 创建／执行入口仍未开放。每个内部 run 仍限定单角色，时间推进的持续效果
集合必须由封闭历史证明为空。跨独立 prepared 角色的有界战斗见下文，不构成完整多角色战役系统。

[检定、装备与健康作者来源](rules/schema-2-foundation-authoring.md)已支持四类严格定义、
纯组合及与原包等价的类型化来源。运行 V028—V031 的
[镜像与事实存储](rules/schema-2-character-fact-storage.md)保存准确规则、完整链、检定/装备/健康输入结果与
前后状态，并提供叶仓储追加和直接恢复。
[检定、装备与健康基础](rules/schema-2-character-foundations.md)复用这一角色状态：
类型化模组声明驱动属性/技能/工具检定、普通装备准备、护甲限制、单目标环境伤害/恢复、
临时 HP、死亡豁免与稳定恢复；原始骰、派生结果及后果随局部历史直接恢复。
这些基础入口不执行完整战斗、施法、怪物动作或全部特性效果；适用而未接入的影响明确拒绝。

[战斗作者来源](rules/schema-2-combat-authoring.md)和[内部战斗消费者](rules/schema-2-combat.md)
复用真实角色的装备、HP、熟练与时间。参与者属于同一战役，各自保留独立准备的 run/snapshot，
冻结规则绑定必须相同且开始时分钟/秒一致。内部服务提供先攻、回合、普通近战攻击、移动和
离开触及前的机会攻击暂停/继续；完整状态、原骰、窗口、伤害、倒地和掉落随历史直接恢复。
完整 round 只推进一次六秒，稳定恢复和长休间隔按准确秒处理。地面物品拾取、完整装备动作、
怪物动作、完整基础包、Host 与 archive format 2 仍未开放。

[有限施法](rules/schema-2-spells.md)沿同一内部动作链接纳生命领域一级的 Bless／Cure Wounds，
以及单职业法师 1—5 级的 Shield／Counterspell。资格来自准确职业、实际特性获得、真实法术书与
准备事实、装备和组件；法术位复用角色原资源及标准长休，不产生第二份 HP 或位数。
法师初始学习六个、每级新增两个，准备受 INT 与等级上限约束；元数据法术可进入书和准备清单，
未接入的施放机制仍明确拒绝。Shield 在命中后伤害前触发，Counterspell 在施放完成前触发；
嵌套反应、Ready 攻击／移动／一动作法术和唯一父继续都保留已支付成本与原骰。

Bless 贡献接入攻击、CON 专注豁免及死亡豁免，记录专注结束、秒时钟到期和同强落选来源恢复。
固定十尺的 DM 抗魔区域由环境事实创建，各区域保留独立压制原因；这是明确的场景家规，
不代表 Antimagic Field 法术已实现。结束战斗转入有限探索时保留仍存续效果、区域和唯一角色时钟；
探索可施放所支持法术、推进有界秒数、处理健康及移动，再重新进入真实先攻。缺少持续效果 owner、
未决动作流或无法安全推进时间的状态明确拒绝。其他法术、高环施放、多职业、完整 Host/base 与
archive format 2 仍按各自消费者和跨域发布门采用。

## v2 产品目标

### 规则与战役

- 一次选择一个完整基础模组及零到多个扩展/兼容模组的准确版本，显式确定加载顺序，
  并运行一个战役工作集；公共合同见[模组接口基线](design/v2/module-interface-baseline.md)。
- 先准备经过验证的规则，再接纳完整初始化材料或恢复战役文件。
- 规则匹配使用完整稳定身份、有序准确版本及各自摘要；显示名称与可编辑组合预设不参与身份判断。
- 只接受显式声明的准确依赖版本与联合兼容搭配，不自动推断兼容、升级存档或人工放行坏规则。
- 健康且真正空闲时可重新选择组合，无需重启；活动运行固定组合，恢复沿用存档原准确组合。
- 普通业务及规则与覆盖来源的只读查询使用本次运行的完整不可变快照和覆盖链；来源库在准备边界读取。

### 角色与进度

- 角色身份、加入战役时的不可变初始卡、当前状态和业务历史都属于战役。
- 不建立孤立角色库、跨战役活动锁、修订排名或历史合并。
- 保存保留当前资源消耗、临时效果、战斗过程及全部已记录业务历史，不自动休息或治疗。
- 非战斗按玩家整步、战斗按 PC 完整回合计步，由 DM 显式确认完成；累计 50 步触发自动保存。
- 每个战役最多保留三份正式自动档，最终档独立保留。保存失败时暂停新的游戏写入。

### 保存、结束与恢复

正常结束先可靠保存最新完整战役文件，再独立验证已保存字节并清理本次工作集和规则快照。
服务端保存、清理与浏览器下载分别反馈；关闭浏览器或服务不会自动完成这一流程。

重启后发现的 v2 残留不自动恢复游戏执行资格，只能在核验后救援保存并结束，再通过独立
初始化恢复所选文件。该目标不改变 v1 的重启行为。具体协议见[保存与恢复](design/v2/save-and-recovery.md)。

## 暂缓的产品设计

首次新建 v2 战役、外部角色作者文件的准确输入合同和角色编辑器仍需专项细化；不能以
手造空战役或部分文件开放入口。进行中追加/替换角色、旧战役规则升级及导入人工裁定暂缓。

可选便携角色导出仅生成只读投影，不改变源战役、不建立独立检查点。只有已定义的转换规则
才能移除临时状态；转换受阻不影响完整战役保存。其逐领域转换仍需设计和验证。

模组组合、扩展和兼容修改的公共合同已确定，通用作者/安装/组合/运行链路仍待采用。
使用应用已有机制的自定义内容，目标上允许离线校验并由 DM 接受准确内容后独立发布；
这不表示当前已开放自定义模组。场景、遭遇和奖励的冒险战役包及应用尚不支持的新机制
仍需专项设计，不为其预建占位表或脚本入口。

## 持续适用的边界

产品保持 loopback-only、单 DM；游戏参与者概念不等于玩家账号或远程权限。不提供 LAN/
公网访问、公开 API、玩家页面、任意脚本或动态 DDL。服务器拥有随机结果、派生值、版本与
审计，业务状态仍以运行数据库为权威。

完整 SRD 的各领域须共同通过发布门后，才能发布完整规则、激活 archive format 2 或切换
新战役默认。旧 v1 战役继续按原合同使用；战役升级是独立设计，不自动发生。
