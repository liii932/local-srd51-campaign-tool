# 产品说明

Local 5E Campaign Tool 是面向单一 DM 的本机战役工具。内置规则范围以 D&D 5e 2014 / SRD 5.1
为边界，目标覆盖角色、冒险、装备、战斗、状态、法术、怪物及魔法物品。规则原文查阅从
[本地主题索引](references/srd-5.1/README.md)定位相关分页与 PDF。

本文区分当前可用行为与 v2 目标。目标设计进入项目文档，不表示功能已实现、规则已发布或
数据库已迁移；详细采用边界见 [v2 设计入口](design/v2/README.md)。

## 原型阶段的版本范围

项目处于原型阶段，只保证当前应用版本的功能与保存/恢复；不承诺读取、转换或升级旧应用
版本生成的存档，也不要求旧运行工作集跨版本延续。模型、API、物理存储和文件协议可随
当前需求与证据协调替换；既往设计、批准或完成记录不自动成为后续任务的采用依据。

同一受支持版本内，运行及恢复仍须保持准确规则绑定、完整状态与历史、事务原子性和幂等。
不支持的输入应在写入前拒绝。已应用迁移与真实数据的保护、处置授权仍按[数据库](database.md)
管理；下文记载当前实现保留的能力，不表示仅通过修订政策就已经完成代码替换。

## 当前可用范围

`DND_STORAGE_ROOT` 显式启用 [SQLite 当前应用运行路线](storage-vitality-loop.md)，默认不开启。
选择 `srd51-runtime@1` 时依赖生命值基础和治疗模块，使用不可变的有限 schema-2 规则组合，
不连接 MySQL。战役包含角色初始计划、初始/当前状态、全部角色及战斗历史、准确规则及完整
字段链、场景/位置/物品、根因果事件和未决动作。SQLite 工作库是活动权威；文件是完整保存点。

当前有限角色使用服务端标准数组分配，提供 fighter、Life-domain cleric、Wizard PC/NPC，
并支持名称/类型/活动状态、角色卡和已实现领域的命令。Fighter 成长到职业 6 级、cleric 到 1 级、
Wizard 到 5 级；成长、子职业身份、ASI、多职业前提/熟练、HP/生命骰、有限资源和真实休息
复用既有纯规则。种族属性提升、完整背景技能和未实现职业特性不由这些模板补造。
Fighter 相关特性与 Evocation Savant/Sculpt Spells 是可查的 `OPTION` 元数据，不自动获得；
Wizard Spellcasting、Arcane Recovery 与一级 Life profile 则由真实消费者拥有。

普通检定、装备实例/护甲限制、伤害/治疗、临时 HP、死亡豁免、先攻/回合、近战攻击、移动、
机会攻击和反应/继续保存实际骰点及完整状态。生命领域支持 Bless/Cure Wounds；单职业 Wizard
支持 Shield/Counterspell/Burning Hands、真实法术书、学习/准备和短休奥术回想。其余目录法术
只提供学习/准备元数据，不能施放。多施法职业的共享位数不在现有 casting 消费者支持范围。
有限怪物支持 Hell Hound 吐息、充能及所列防御；其他动作保留阻断元数据。抗魔区域是明确
DM 家规，不能称作已实现 Antimagic Field。规则来源及详细限制见
[有限包指南](../rule-packages/srd51-runtime/package-guide.md)。

角色、简单物品、节点连接/位置和消息与领域历史共享同一个战役根。发生游戏命令时，先完整
验证规则、对象集合、版本、容量及继续义务，再消费真实随机性；所有对象后果、原骰、历史、
版本与请求结果同一事务提交。未决反应或效果不得通过独立角色操作跳过。
严格类型化文档聚合和关系投影由同一快照校验，不允许自由 JSON 属性袋或恢复时补造索引。

新建接受首份完整检查点后才开放写入；手动保存不改变活动状态，结束先接受最新 FINAL 再
封存清理。下载、上传导入、同版文件重开、残留恢复及精确放弃分别操作准确身份。
重开直接恢复全部原骰、消耗和 pending，不重新创建角色、执行命令或施法。
检定的成功/失败分支由 `CampaignCheckEffects` 提供有序、类型化的健康规则、简单物品
delta、节点位置及消息效果，两条分支全部验证后才掷骰；验收入口见[测试指南](testing.md)。
自由字段卡、职业等级/熟练、MANUAL/SAVING_THROW、有序检定效果和简易遭遇名单/阵营使用
独立 DM-managed 领域；其初始/当前卡、效果、场景与完整文件共同保存，不能绕过 schema-2
角色验证或自动转换角色。具体操作和限制见[运行合同](storage-vitality-loop.md)。
当前业务选择独占门加一个 `BEGIN IMMEDIATE` 共同提交，没有独立 C0 接纳/裁定事务。
每命令 SQLite 耐久与 INITIAL/MANUAL/FINAL 已承担当前保存责任；周期 AUTO 与轮换属于
容量测量后的后续能力，不能成为略过当前领域生命周期的理由。

未配置 SQLite 时，MySQL 模式仍使用冻结简化规则 `dnd5e2014_srd51_se_v1` release `"1"`，
保留原战役管理、PC/NPC、基础字段、简单物品、d20/类型化事件、节点地图、最小遭遇及格式 1
存档入口。SQLite 模式关闭旧路由，两个运行模式不共享写权限、不双写、不自动转换真实数据。
旧模式及来源/运行 MySQL 的迁移、独立账号和真实数据保管仍按[数据库](database.md)执行。
完整规则族 `dnd5e2014_srd51_se` 的 DRAFT、通用来源安装/接受以及 archive format 2 资格
继续由各自合同限定，不因 SQLite 有限运行入口开放而转为完整发布。

### 局域网玩家参与

SQLite 模式有默认关闭的独立 HTTPS 玩家原型，支持邀请审批、PC 控制分配、明确共享、
有限服务端候选动作、DM 裁定与收据查证。玩家只接收本人角色卡和明确共享的场景、角色概况
及记录；Host 接口、完整历史图、规则材料和完整文件不传到玩家设备。DM 保留裁定、代操作和
保存管理；DM-managed 自由卡可分配并查看，当前玩家候选动作由有限规则角色消费者提供。

监听需要显式配置，应用不创建 Connector，也不改变 DM 的 `http://127.0.0.1:8080` 边界。
同版残留恢复保留业务参与事实，私有设备绑定仅留在本机；服务重启后须由 DM 重新开放，
恢复身份不自动取得写连接，文件重开须重新批准设备。运行与安全边界见
[运行合同](storage-vitality-loop.md)和[安全说明](security.md)，隔离验证见
[测试指南](testing.md#玩家参与原型验证)；这些机制不表示真实 LAN 部署、设备信任或外部设备验收已完成。
完整玩家参与设计单独维护在[设计文档](design/v2/player-participation.md)。

## v2 产品目标

以下是当前选择的目标流程；需求或验证依据变化时，按[v2 设计入口](design/v2/README.md)
修订相关方案与采用条件，并同步实现和验证。

### 规则与战役

- 一次选择一个完整基础模组及零到多个扩展/兼容模组的准确版本，显式确定加载顺序，
  并在私有 SQLite 运行空间运行一个战役；当前有限运行模型已采用该存储路径，
  完整 SRD 与通用外部组合仍待各自验收。公共合同见[模组接口基线](design/v2/module-interface-baseline.md)。
- 先准备经过验证的规则，再接纳完整初始化材料或恢复战役文件。
- 应用以当前版本 JSON 声明关系表结构，按准确规则、机制全部写入需求、历史和未决状态
  计算存储闭包。新建/文件打开一次建立私有库；同版残留恢复只核验原库，不能补表或重做初始化。
- 规则匹配使用完整稳定身份、有序准确版本及各自摘要；显示名称与可编辑组合预设不参与身份判断。
- 只接受显式声明的准确依赖版本与联合兼容搭配，不自动推断兼容、升级存档或人工放行坏规则。
- 健康且真正空闲时可重新选择组合，无需重启；活动运行固定组合，恢复沿用存档原准确组合。
  改变准确成员、版本、顺序或影响规则的组合配置须结束原运行并新建战役，旧历史不换规则解释。
- 普通业务及规则与覆盖来源的只读查询使用本次运行的完整不可变快照和覆盖链。当前四包
  由应用交付，文件携完整冻结材料，不依赖外部来源 MySQL；未来自定义包的安装/接受另设边界。

### 角色与进度

- 角色身份、加入战役时的不可变初始卡、当前状态和业务历史都属于战役。
- 不建立孤立角色库、跨战役活动锁、修订排名或历史合并。
- 保存保留当前资源消耗、临时效果、战斗过程及全部已记录业务历史，不自动休息或治疗。
- 每个游戏命令持久提交至工作库；手动保存可覆盖任何已提交中途状态。新建/文件恢复的首个
  完整检查点成功后才开放写入；提交或回滚未知先阻断新写，经真实库、全部历史及收据查证后显式恢复。
- 非战斗玩家整步、战斗 PC 完整回合和 DM 确认完成是后续玩家步骤目标，业务计步与耐久
  水位分离；当前不依靠步骤按钮或周期 AUTO 才保存游戏命令。
- 自动便携检查点的 revision/增长阈值、失败阻断、保留预算与安全轮换须先测量容量，再按
  [玩家步骤与自动保存](design/v2/player-steps-and-auto-save.md)同步实现和验收；当前未启用。

### 保存、结束与恢复

正常结束先发布最新完整文件、独立读验并在工作库登记封存，再关闭连接、隔离并清理
整个运行目录。文件发布、数据库接受、清理与下载分别反馈，不能假定跨资源原子提交。
未完成保存按原意图查证/恢复；当前没有独立取消或 REPAIR 入口。封存后只能清理，
从文件重新打开才能继续游戏。

重启先识别残留，不自动推进。当前版本内，完整核验和提交查证后可显式继续原运行，
保留所有骰子、消耗与未决选择并更新安全代次；也可救援保存或确认精确目标后放弃。
不支持的模型保留并拒绝，不跨版本转换。此为当前 SQLite 模式合同；默认 MySQL 模式
仍由其数据库保留状态，二者不自动互相接管。
完整文件、故障窗口和保管责任见[保存与恢复](design/v2/save-and-recovery.md)。

## 暂缓的产品设计

首次新建的[公共初始化闭包](design/v2/character-state-and-history.md#新建与文件恢复的公共初始化输入)
已确定；当前有限 profile 支持完整的空队伍起点，并在时间零点建立初始角色。
任意加入等级、完整角色构筑编辑器与通用外部创建适配器仍待实现；空集合不能掩盖所选
profile 必需的领域、历史或恢复材料。进行中追加/替换角色、活动战役更换规则组合及
导入人工裁定暂缓。

可选便携角色导出仅生成只读投影，不改变源战役、不建立独立检查点。只有已定义的转换规则
才能移除临时状态；转换受阻不影响完整战役保存。其逐领域转换仍需设计和验证。

模组组合、扩展和兼容修改已有[公共接口设计](design/v2/module-interface-baseline.md)，
通用作者/安装/组合/运行链路仍待采用。
使用应用已有机制的自定义内容，目标上允许离线校验并由 DM 接受准确内容后独立发布；
这不表示当前已开放自定义模组。场景、遭遇和奖励的冒险战役包及应用尚不支持的新机制
仍需专项设计，不为其预建占位表或脚本入口。

## 持续适用的边界

DM 保持 loopback-only、单 DM；可选玩家原型不自动开放监听或改变现有服务。玩家身份只
属于所加入战役，不建立全局账号；公网、匿名展示、公开 API、多 DM 和任意脚本执行仍
在范围之外。MySQL 模式使用预先迁移的业务表；SQLite
路线由应用自有 JSON 声明结构并编译建表，承接当前有限运行聚合。规则作者包只提供
内容与准确依赖。结构、种子、规则和业务
事实分工见[结构合同](design/v2/storage-schema-and-planning.md)，现有数据覆盖与替换验收见
[实施路线](design/v2/storage-data-map-and-rollout.md)。服务器拥有随机结果、派生值、版本
与审计，打开期间业务以本次工作库为权威。

完整 SRD 的各领域须共同通过发布门后，才能发布完整规则、激活 archive format 2 或切换
新战役默认。已有发布身份和持久化事实的解释不得通过原地改写改变；跨版本支持范围按本文
原型政策执行。
