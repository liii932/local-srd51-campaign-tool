# 安全模型

本项目的安全边界建立在“只有运行 Tomcat 的本机 DM 能访问”这一前提上，不应被解释为可直接暴露到局域网或互联网。

## 网络与请求边界

- Connector 只监听 `127.0.0.1:8080`。
- 主机路由要求 TCP 对端、本地端口、scheme 和精确 `Host: 127.0.0.1:8080` 全部匹配。
- `localhost`、`::1`、局域网地址、错误端口/scheme/Host 与伪造转发头不得放宽边界。
- 主机写请求还要验证 Session、CSRF、Origin/Referer、Fetch Metadata、`host_state_epoch`、对象版本、幂等键和请求摘要。
- 响应设置 `Cache-Control: no-store`、CSP、`nosniff`、`frame-ancestors 'none'` 与 `Referrer-Policy: no-referrer`。

## 权威输入

浏览器输入不可信。骰点、候选选择、派生修正、最终结果、效果算法、规范身份、行版本推进和审计结果均由服务端决定。未知、重复、未发布、摘要不一致、格式错误或尚未支持的冻结规则必须失败关闭。

随着完整 SRD 5.1 领域加入，服务器权威范围同时覆盖角色构筑候选、先攻和回合顺序、合法
动作与反应窗口、移动和目标合法性、攻击/伤害骰及调整顺序、法术位和其他资源消耗、状态
持续时间、专注、恢复时机和裁定类型。客户端可以从服务端给出的有界候选中选择，但不能
扩大候选集合、跳过前置条件或直接提交结算后的权威状态。

权威状态、根事件、检定快照、候选骰、效果、字段变化、对象版本和幂等结果必须在同一事务提交或整体回滚。战斗、法术、装备、资源和状态写入也必须复用该原子边界，不得建立可部分提交的旁路。

## 数据库权限

数据库职责分离：migrator 负责 DDL 和前向迁移；应用账号只获得所需 DML 与不可变目录读取；验收账号只读。不要通过授予广泛 schema 权限解决缺表或权限错误。授权脚本见 [database/grants](../database/grants/)。

## 秘密与私人数据

禁止提交数据库口令、client option file、私钥、证书私钥、Tomcat 外部配置、日志、数据库备份或真实战役存档。导出的存档可能包含私人游戏内容，应保存在仓库外并按敏感数据处理。

安全问题的报告方式见根目录 [SECURITY.md](../SECURITY.md)。
