# 安全模型

DM 管理面保持本机边界；SQLite 的[玩家参与原型](design/v2/player-participation.md#当前原型与剩余采用)
使用独立、默认关闭的 HTTPS 入口。不得把现有主机服务暴露到局域网或互联网。

## 网络与请求边界

- Host HTTP Connector 只监听 `127.0.0.1:8080`；可选玩家 Connector 使用下节的独立边界。
- 主机路由要求 TCP 对端、本地端口、scheme 和精确 `Host: 127.0.0.1:8080` 全部匹配。
- `localhost`、`::1`、局域网地址、错误端口/scheme/Host 与伪造转发头不得放宽边界。
- 主机写请求还要验证 Session、CSRF、Origin/Referer、Fetch Metadata、对象版本、幂等键和请求摘要；MySQL 使用 `host_state_epoch`，SQLite 使用自身运行 epoch。
- 响应设置 `Cache-Control: no-store`、CSP、`nosniff`、`frame-ancestors 'none'` 与 `Referrer-Policy: no-referrer`。

## 可选玩家原型的安全边界

`PlayerBoundaryFilter` 是全局首个过滤器，非 Host Connector 只能命中明确配置的玩家
HTTPS 地址和固定路径。玩家服务还要求 SQLite 模式已启用；默认 MySQL 不获得玩家权限。
Host Filter、Cookie 和 8080 端口保持上节合同。应用不会自行创建 Connector 或改动网络配置。

- 玩家使用独立 HTTPS 8443 入口，配置必须是同一个规范 IPv4 地址与 `https://IP:8443`。
  仅接受 loopback、私有或链路本地 IPv4，不接受 DNS、IPv6 或通配绑定；证书须匹配地址并获设备信任。
  玩家监听只开放加入和玩家白名单路由，拒绝 Host 页面/API、完整存档、路径及诊断；不转发主机 Session。
- 邀请只能申请加入；DM 核对批准后才绑定战役玩家与设备，昵称、PC 键或文件中的玩家键不提供授权。
  申请、凭据兑换、查证及普通读取均有界限流，错误不枚举其他成员或隐藏对象。
- 玩家 Cookie 与 DM 分离，采用 Secure、HttpOnly、SameSite=Strict、Path=/ 和有限有效期；写入核对 CSRF、
  精确来源、当前成员/控制资格、运行代次、对象版本与准确幂等身份。设备接管/撤权须即时使旧写资格失效。
- 玩家 DTO 在服务端按当前受众白名单生成，错误、日志、轮询与请求收据使用相同裁剪。不得下发完整
  Host JSON 再隐藏字段，也不泄露 DM 根序号、未公开对象、隐藏骰点或完整文件。响应 no-store，客户端
  不用持久缓存存放私密视图；撤权/重连清理旧视图，已经被人读取的信息不能承诺远程收回。
- 读取授权与返回投影、写入授权与业务提交都必须有明确并发顺序；撤权后的请求不能凭旧角色控制、
  旧动作候选或旧收据继续读取/执行。重新连接只同步与查证，不自动重发未知结果的游戏命令。
- 凭据、邀请、TLS 私钥和网络配置不进完整战役文件、Git、WAR 或日志。完整文件重开须重新批准设备，
  不因保存了玩家控制映射就恢复原设备访问。公网、匿名展示、多 DM 和通用脚本仍不开放。

现有测试入口见[测试指南](testing.md)。隔离 loopback HTTPS 测试不替代真实移动/桌面设备的
证书信任和局域网验收；证书、系统信任、防火墙与部署按明确目标操作，应用不自动更改这些设置。

`PlayerGatewayService` 管理临时 Session、邀请码和单一写连接；设备恢复凭据在
`core_player_control` 中只保留随机凭据摘要，并绑定 run 与成员授权版本。撤销后再启用成员
不能复活旧设备。该表严格核验 schema/run/字段/容量，保存暂停、设备绑定和精确已发送
请求关联材料，不形成游戏重放队列或独立接纳台账。

同一残留 run 的私有控制随工作库保留。恢复推进运行 epoch，失效旧 Session、CSRF、
写连接、邀请码和临时提议；DM 重新开放后，原有效设备可恢复身份并只读查证原请求，
恢复身份不授予写连接。完整文件重开建立新 run，不携带上述私有控制，须重新批准设备。
成员、控制、共享、探索许可及已执行裁定属于业务聚合和根历史，随完整文件保存。

会话 30 分钟、设备绑定 7 天、邀请码 10 分钟；读/写/加入/恢复/收据分别有令牌桶限制，
超限返回 `429`。原型最多 256 个临时会话、128 个设备绑定、512 个已发送请求关联、
100 条网关内临时沟通提议。容量用尽拒绝新增，不为接纳新请求自动淘汰查证材料或截断
业务历史；这些上限不表示无限期运行能力。

## 权威输入

浏览器输入不可信。骰点、候选选择、派生修正、最终结果、效果算法、规范身份、行版本推进和审计结果均由服务端决定。未知、重复、未发布、摘要不一致、格式错误或尚未支持的冻结规则必须失败关闭。

SQLite 已接合的角色、战斗、法术、装备、资源和持续状态仍由服务器验证，实际覆盖见
[当前运行合同](storage-vitality-loop.md)。玩家只能选择服务器当前提供的有限候选，不能
扩大集合、跳过前置条件或直接提交结算后的权威状态。候选读取不消耗游戏随机性；
候选随视图 revision 失效，执行前再次验证授权、控制、对象版本及规则前提。
当前 DM 裁定执行仅支持有限规则 PC 的有理由属性检定；文字提议、拒绝与叙事回复本身
不是已执行的业务命令，不承诺随完整文件或进程恢复保留。

权威状态、根事件、检定快照、候选骰、效果、字段变化、对象版本和幂等结果必须在同一事务提交或整体回滚。战斗、法术、装备、资源和状态写入也必须复用该原子边界，不得建立可部分提交的旁路。

## 数据库权限

MySQL 模式的数据库职责分离：migrator 负责 DDL 和前向迁移；应用账号只获得所需 DML 与不可变目录读取；验收账号只读。不要通过授予广泛 schema 权限解决缺表或权限错误。授权脚本见 [database/grants](../database/grants/)。

## 秘密与私人数据

禁止提交数据库口令、client option file、私钥、证书私钥、Tomcat 外部配置、日志、数据库备份或真实战役存档。导出的存档可能包含私人游戏内容，应保存在仓库外并按敏感数据处理。

安全问题的报告方式见根目录 [SECURITY.md](../SECURITY.md)。
