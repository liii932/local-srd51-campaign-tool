# v2 机制完整接入责任清单

状态：统一设计与验收清单；逐机制的合同、实现及采用证据须分别记录。
本清单适用于新增机制，以及使用应用已有机制的新增内容；不据此授予运行或发布资格。
公共身份、作者修改、组合与摘要遵循[模组接口基线](module-interface-baseline.md)，
采用状态遵循[采用边界](adoption-boundaries.md)。本清单不定义通用机制注册框架、DSL 或新 API。

## 使用方法与责任边界

每个机制使用文末记录格式，给下面各项指定可追责的负责者；同一人可承担多个角色。
内容作者负责准确声明已有机制支持的内容；应用维护者负责新增机制的语义、校验和实际执行。
安装者及 DM 的内容接受不能补足应用能力。内容只改变已有机制允许的有限参数时，无需
为每个条目新增算法；新的 mode、参数含义或执行效果则须先由应用建立相应支持合同。
已有机制的新内容可准确引用既有合同及有效证据，补齐本次内容差量，不必重复建立机制。

每项的“遗漏阻断”限制其涉及的采用层级和真实依赖能力，不能用空数组、默认值或 TODO
冒充完成。N/A 必须说明理由并证明该项没有真实状态、引用或待履行义务。纯计算或被动
修正可复用父命令的状态、事件、存档和事务，不必新建表或独立入口；必须指向真实父消费者
及证据，不能仅因无自有表或 UI 把责任标为 N/A。

## 当前有限消费者的责任落点

[有限施法合同](../../rules/schema-2-spells.md)及[作者来源](../../rules/schema-2-spell-authoring.md)
记录生命领域 Bless/Cure Wounds、法师学习/准备与 Shield/Counterspell、Ready、固定 DM 抗魔区域和
有限探索交接的 INTERNAL 范围。来源与规则镜像由 Spell/Wizard SourceRows、SnapshotRows 保存，
角色法术书与资源由 `Schema2WizardSpellbookRules` 及角色历史拥有；唯一动作流由
`Schema2ActionFlowRules` 保存 checkpoint/反应/继续，持续效果与探索分别由
`Schema2OngoingEffectRules`、`Schema2ExplorationRules` 接合。实际状态、根事件、原骰、成本和
幂等结果仍由 `Schema2CombatRuntimeService` 在共同事务内接受，真实数据库验收和完整
Host/base/archive 2 资格保持独立。这些具体落点可用于本清单的责任引用，不能推导未登记机制支持。

## 逐项责任与交付

1. **原文与适用范围** — 责任：领域设计者、内容作者。
   - 合同与证据：列明规则来源、小节、适用主体、前置条件和范围；SRD 原文优先引用[本地主题索引与分页文本](../../references/srd-5.1/README.md)，歧义按索引核对本地 PDF。执行方式沿用[完整 SRD 合同](../../rules/srd-5.1-complete.md#3-自动化边界)的自动结算、验证后 DM 有限选择、类型化 DM 裁定三种，另列尚不支持的阻断分支及依据。
   - 遗漏阻断：来源不明或开放式语义未界定时，不得宣称该分支支持；收录文本不证明可执行。

2. **机制身份与应用支持映射** — 责任：领域设计者、应用维护者。
   - 合同与证据：记录正式领域合同中的准确机制标识、支持的 mode、类型化参数及范围，并指向应用实际校验和消费者；明确已有机制的新内容与应用新增能力的分界。未知、重复、畸形及不支持组合均须有稳定拒绝结果。
   - 遗漏阻断：仅有名称、handler、安装成功或 DM 接受不能证明支持；未建立的标识和语义先进入领域合同，不能临时从请求解释。

3. **类型化作者字段与修改** — 责任：领域设计者、作者格式及组合实现者。
   - 合同与证据：定义完整字段、值域、必填/可空、复合原子边界、稳定条目身份、允许修改及禁用后的授予/引用语义；提供作者位置到字段覆盖链的映射与正负材料，遵循基线的设置、清空和启用协议。
   - 遗漏阻断：任意属性袋、半套复合修改、禁用后仍可新选/执行，或缺少准确来源链时，阻断相关安装或组合。

4. **离线安装与类型化来源** — 责任：离线工具、领域模型及来源持久化实现者。
   - 合同与证据：连接严格作者读取、离线投影、原包/接受账本和类型化来源 reader；逐字段列出引用与实际读回独立期望。目标来源镜像可重建，不要求每个新领域复制作者表；当前已实现来源约束仍按现行合同核验。使用已有分区基础时，说明尚未覆盖的领域和安装/接受权限边界。
   - 遗漏阻断：只有内存对象、写入成功或头摘要匹配，不能证明来源完整；缺失字段、引用或读回阻断其进入初始化材料。

5. **组合、完整快照与执行身份** — 责任：组合实现者、运行初始化及领域快照实现者。
   - 合同与证据：记录机制字段及引用如何进入完整最终规则和完整覆盖链，分别覆盖原始 ZIP、模组逻辑、组合配置、最终规则、完整覆盖链五类摘要；给出规范字节的独立期望及实际读回核验。业务消费绑定同一准确组合和 run/snapshot/campaign。
   - 遗漏阻断：部分镜像、旧摘要、跨运行引用或提交前发布执行视图均不合格；开始和恢复仍须重新核验准确来源及本地接受资格。

6. **有限输入、目标与选择** — 责任：命令 Service、纯规则组件；有入口时包括 HTTP 适配者。
   - 合同与证据：列明完整输入、合法目标集合、候选生成、数量/顺序、重复及互斥约束；服务端从固定规则与权威状态重算候选、派生修正和结果，客户端仅提交合同允许的有界输入与有限选择。
   - 遗漏阻断：可扩张候选、指定骰点/算法/版本推进，或只校验部分目标时，不得执行该命令；客户端可按合同提交待校验的预期版本。

7. **时机、资源与跨命令进度** — 责任：机制领域设计者、受影响业务消费者。
   - 合同与证据：逐分支说明触发/结束时机、动作与其他资源、随机性的消费点、持续或重复结算，以及跨命令未完成状态由谁产生、保存、继续和关闭；列出依赖的战斗、反应、效果或休息接合点及尚未接入部分。
   - 攻击、移动、施法、反应及其必需选择按[动作继续协议](action-continuation-protocol.md)接合：明确类型化阶段、触发事实、暂停所有者和继续后的重验/终止结果，复用唯一动作流。持续效果按[持续效果协议](ongoing-effect-protocol.md)区分存续、有效贡献、压制和结束；具体机制补齐比较/聚合、计时、恢复贡献及结束回调，不把免疫施加失败当可恢复实例。
   - 遗漏阻断：不能用立即结算、默认跳过或无效果占位替代缺失消费者；存在待处理义务却无状态和后续入口时，相关分支保持关闭。公共继续协议不替代具体触发、选择与效果的真实实现。

8. **纯计划与真实消费者** — 责任：纯规则作者、命令协调者。
   - 合同与证据：纯计算/计划明确只读输入、确定性输出及无随机/写入边界；标出真实 producer → plan → consumer，说明贡献如何归并、冲突如何拒绝、最终由谁一次应用，并以真实调用证明计划被消费。
   - 遗漏阻断：孤立算法、仅测试中的调用、计算后丢弃或多个消费者重复应用，不构成端到端接入。

9. **接纳、校验顺序与事务** — 责任：命令协调 Service、相关 Repository。
   - 合同与证据：按[运行与事务](runtime-and-transactions.md)明确共同守卫、锁序和调用方事务；完整目标、冻结规则、预算、乐观版本、幂等及领域条件全部校验后，才消费 RNG 或写入。给出顺序证据；涉及多目标时，补充失败无部分写入的证据。
   - 遗漏阻断：边校验边掷骰/写入、Repository 自行提交或持锁等待用户时，阻断命令采用。

10. **幂等与提交结果** — 责任：命令协调者、结果持久化及故障处理实现者。
    - 合同与证据：定义准确操作身份、意图比较、原结果重放及状态/结果原子提交；覆盖相同键不同意图、已提交但响应失败、回滚成功和提交未知。未知按同一操作在共同守卫下只读查证，执行资格保持受控。
    - 遗漏阻断：重放重新掷骰/消耗、把未知当回滚或换标识重试，均阻断该写路径。

11. **状态、历史、来源与版本所有者** — 责任：领域状态及历史设计者、事务消费者。
    - 合同与证据：按[角色状态与历史](character-state-and-history.md)逐项指定唯一权威 owner，列明初始/当前状态、类型化来源、根事件/正文、引用闭包和版本推进；给出同一事务写入、失败不推进及非活动对象保留引用的证明。
    - 遗漏阻断：双份权威状态、来源仅查外键存在、历史主体悬空或版本分散推进均不合格；纯计算沿用已有结果根须明确映射。

12. **完整保存与直接恢复** — 责任：状态 owner、文件 codec 与恢复协调者。
    - 合同与证据：按[保存与恢复](save-and-recovery.md)列出每个真实字段的源、文件落点/排除理由、独立期望及直接恢复映射；包括未完成选择、准备材料和持续/重复过程，核对全体已记录历史及准确规则绑定。
    - 遗漏阻断：只做 writer/reader 自洽往返、从初始卡推算当前值、重放事件或恢复时自动结算，不能证明完整恢复；缺分区不能用空数组代替。

13. **技术 END 与清理闭包** — 责任：领域 owner、保存结束及清理实现者。
    - 合同与证据：列出该机制的持久化进度、入向引用和清理顺序；END 如实保存中途业务状态，不自动完成 pending。按保存 P0—P3 发布/读验并封存，再关闭和隔离整个私有运行目录、可重入清理；完整引用图用于文件覆盖，不再要求逐领域 SQL 删除事务。部分清理失败保墓碑，正式档案独立保留。
    - 遗漏阻断：未盘点状态/引用/待办、保存失败仍删除，或清理顺带结算业务，均阻断清理及依赖该闭包的采用。

14. **容量、预留与增长** — 责任：领域状态 owner、预算及保存实现者。
    - 合同与证据：说明单次与长期状态/历史增长、输出结构和字节界、运行期必存事实计费，记录对完整保存/修复和目录清理峰值的影响与实测证据；在写前证明变化后仍可完整保存，容量取值沿用保存合同并补机制相关实证，不要求每个机制重建全局预算。
    - 遗漏阻断：先写后发现不可导出、漏计历史/待办、截断或自动删除用户档案腾空间，均阻断写入采用。

15. **独立验证与失败闭包** — 责任：各实现作者、主审者。
    - 合同与证据：提供独立推导的正负字段/规范字节期望和业务例证，覆盖适用的边界、坏冻结数据、禁用/未知内容、stale version、幂等、多目标与事务故障。
    - 随机性与故障证据：接纳或前置校验拒绝时须为零 RNG、零业务写入；合法请求消费随机性后发生数据库故障，按提交证据核验权威状态、历史、资源、版本及结果的整体回滚、已提交事实或未决查证，不要求倒退随机源。提交未知仍按第 10 项保持阻断并查证。
    - 遗漏阻断：共用同一投影/编码实现生成期望，或仅凭自洽往返不能代替独立证据；真实 SQL、权限、锁和连接语义未验收时保留相应边界。

16. **真实 Host 入口与可读结果** — 责任：有真实产品入口的 Service、Host 页面/API 实现者。
    - 合同与证据：保持既有本机安全边界；入口展示服务端有限候选、结果、资源变化和来源，诊断给稳定错误码、阶段及可取得的准确位置。被动能力可复用父命令的入口和结果；内部组件注明真实消费者和可见限制。
    - 遗漏阻断：页面成功而命令未落到真实消费者、任意 DM 输入代替类型化边界，或把内部测试入口宣称为产品支持，均不合格。

17. **合同同步与采用声明** — 责任：领域维护者、集成者及主审者。
    - 合同与证据：同步受影响的正式领域合同、设计入口和采用边界；逐项关联实际差量、测试及未接入依赖。验证按[测试指南](../../testing.md)选择相关行为和共享合同，不要求每次全量；适用的制品与发布检查点另行完成。
    - 遗漏阻断：文档把目标写成当前行为、以历史报告或 TODO 声称完成，或未保留真实依赖阻断时，不得提升采用层级。

## 四层采用门

| 层级 | 所需结论与证据 |
|---|---|
| 设计责任完整 | 全部适用项有 owner、正式合同、独立期望/验证方法及明确依赖；未实现部分如实标记。可作为实施输入，不授予执行资格。 |
| 内部可测 | 声明范围内的模型、计算或存储组件已有实际实现和定向证据；标清缺少的真实消费者和外层链路。 |
| 端到端接入 | 声明范围的作者/来源、快照、真实命令、原子状态/历史、保存恢复、END/清理与入口责任全部闭合；适用项有真实路径和证据，无未履行的跨域义务。 |
| 正式发布 | 适用的应用/规则发布门及获准采用检查点已完成；完整 SRD 须通过[跨领域发布门](../../rules/srd-5.1-complete.md#6-完成判定)。仅用已有受支持机制的自定义内容按公共基线独立接受与发布；单个 handler 或内容接受不替代缺失的应用能力。 |

四层不得互相代称；N/A 和较低层通过均不能解除已有运行阻断。legacy v1 保持 RELEASED
和默认，完整 SRD 保持 DRAFT，archive format 2 不因本清单激活。安装、接受、迁移、发布、
部署和默认切换仍是独立检查点；内容接受只能使用应用已经支持的机制。

## 可复用机制记录

每个机制在其正式领域合同中保留下列记录；表可按实际负责者细分，无需复制公共正文。

```text
机制身份：准确标识 / mode / 类型化参数；正式领域合同链接
内容身份：规则/条目完整身份、准确提供者版本；应用支持范围
来源与边界：原文小节；三种执行方式的适用分支；另列阻断分支
采用层级：设计责任完整 / 内部可测 / 端到端接入 / 正式发布
责任项 1—17（逐项记录）：
  负责者：
  合同：准确章节及本机制承诺
  实现：真实入口、状态 owner、文件/符号；未实现则明确写未实现
  证据：独立期望的来源、实际验证及结果；自洽往返另列
  N/A：理由及无真实状态、引用、义务的依据（适用时）
真实链路：producer → 纯计划 → consumer → 原子结果；无计划时说明
未接入依赖：具体 owner、缺口、受阻分支和采用层级；不得写成已支持
保存/恢复/END：状态与引用映射、直接恢复及清理闭包链接
剩余检查点：与本机制有关的内部验证、跨域门及独立外部操作
```
