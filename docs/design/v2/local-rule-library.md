# v2 本机规则库

规则库服务于战役准备，活动工作库负责战役事实。显式 SQLite 路线使用
`DND_STORAGE_ROOT/rule-library` 下的 `ledger.db` 及 `originals/`。每份原包以原始 ZIP 摘要定位，
导入绑定、独立 DM 接受及操作结果由 SQLite 账本保管，职责遵循[四层设计](module-layering.md)。

旧 MySQL 来源继续遵循独立的[离线安装与接受合同](../../rules/schema-2-installation-and-acceptance.md)。

## 持久材料与权限

| 材料 | 唯一权威及用途 |
|---|---|
| 原始 ZIP | 本机规则库保管通过有界、严格读取的完整原包，按真实字节摘要定位。导出保留原始字节。 |
| 导入记录 | 本机 SQLite 中的不可变绑定，登记准确模组键和版本、角色、作者协议、原包与逻辑摘要及原操作。一个准确身份只绑定一个原包。 |
| 本机接受 | 同一账本中的独立不可变记录，绑定准确导入材料、审阅使用的协议、接受者及原操作。 |
| 浏览与选择 | 当前清单读取账本，DM 选择有序准确成员。可重建搜索索引和组合预设是可选扩展，组合资格来自实际成员与接受。 |
| 战役冻结材料 | 每个活动工作库拥有该战役使用的准确组合、最终规则和完整来源链。多个战役可使用相同不可变内容，各自绑定和保存。 |

规则库的写入口分开处理导入和明确接受，普通战役准备只读。原包、账本及暂存位置由应用在受控
本机根中定位。备份与恢复同时保管原包和账本。普通游戏操作、保存和技术结束使用战役冻结材料。
Host 的规则库页面提供原包导入、审阅、下载、接受、组合预览和未知操作查询与恢复。

## 导入准确制品

1. 有界读取完整 ZIP，从实际字节计算原包 SHA-256。严格检查容器、路径、条目、清单及展开预算，
   拒绝重复、未登记文件、路径逃逸和外部访问。按[作者接口](module-interface-baseline.md#作者入口与字段修改)
   验证声明、类型、值域及依赖自洽，计算逻辑摘要。外部引用和依赖资格留待准确组合校验。
2. 在受控位置完整写入并读验原包，按原包摘要持久发布不可变文件。已有位置只核验并复用准确字节，
   遇到不符即阻断。确认发布结果后，在一次 SQLite 事务中写导入绑定和原操作结果。
   由文件和记录共同证明导入，数据库提交负责账本原子性。
3. 相同模组键和准确版本仅在角色、协议和双摘要全部相同且实际原包可核验时复用既有记录。
   同版本不同原包或逻辑一律拒绝，即使变化只来自重新压缩。修订内容使用新版本。

导入过程中断时，先区分完整可核验原包、可见导入记录及二者的准确绑定。已发布但未登记的字节不可选、
不可接受，可在证明同一导入意图后重用。账本有记录而原包缺失或损坏时，受影响版本阻断。
索引、文件名、缓存和同逻辑重打包均不能代替原字节。诊断标明准确版本、发现阶段及可取得的来源位置。

## DM 审阅和独立接受

导入成功只使原包可审阅。DM 在专门入口查看准确身份、角色、双摘要、依赖声明和可读规则差量，
明确接受所展示的准确材料。写入前重新读验原包，核验该次接受意图与导入记录；接受事实和其幂等结果
在一次账本事务中提交。相同操作同一意图只返回原结果，不同意图冲突。组合预览、新建、打开文件和
作者自报均不能登记接受。Host 可将随应用交付的包逐个导入；这些包与外部作者内容经过同一
严格读取、明确接受、组合及机制资格校验。

接受说明该准确内容已在本机获准进入组合候选。实际组合还要满足依赖、顺序、最终引用、应用支持
和玩法范围闭包。新版本、不同原始 ZIP 或新环境的内容不继承接受；战役文件、摘要以及来源说明
也不产生接受记录。

规则库以进程守卫和独占文件锁串行处理操作。提交结果未知时，用原操作 ID 查询并显式恢复；
恢复持有写守卫，用健康连接的 `BEGIN IMMEDIATE` 隔离旧写入者，再核验原包、绑定和收据，
返回已提交结果或允许原意图重试。待确认操作阻断库写入和新的绑定，缺损或不一致材料保持阻断。
已开始的健康战役继续使用冻结材料。

## 从规则库准备准确组合

新建前读取用户明确选定的 1–8 个有序准确成员和本机接受记录。文件打开从文件取得原有序绑定。
两者都核验每个原包的实际字节、逻辑和身份。完整文件可先导入受管保存区，再补齐原包及接受并打开。
按[公共组合合同](module-interface-baseline.md)检查依赖、覆盖、最终引用和受支持的机制范围，生成
有序成员、完整最终规则和完整字段链。打开时还须将结果逐项对照文件的冻结材料和指纹。
先完成全部验证并关闭规则库读取，再在私有工作库初始化事务中写入材料。开始时复核，
不能仅信旧预览、缓存或预设名。

缺少原包或接受、版本不符、未知机制、依赖不全、错误顺序或能力闭包不足时，拒绝创建运行。
移机前需取得准确原包，新机器完成本机导入和明确接受后才能打开文件。缺少所需材料时保留原文件，
提示准确缺项。活动命令、保存和同版工作库残留恢复不回读本机库，
由[规则存储](rule-storage-and-versioning.md)规定冻结材料的完整性、解释和恢复边界。

## 采用验收

- 用准确 `base` 和扩展原包验证导入、接受、组合、领域命令及保存后直接恢复。对照独立规则值、
  来源链、原骰和历史，并证明规则库变化不影响已绑定战役。
- 验证坏 ZIP、缺原包、同版本不同字节、未接受、未知机制、依赖和加载顺序错误均在建立活动运行前拒绝。
  用真实 SQLite 与文件系统覆盖原包发布后账本未提交、接受响应未知、原操作重试及并发冲突。
- 用一份完整文件验证新环境缺少原包、仅导入而未接受、已接受且准确一致三种结果。前两种阻断打开，
  第三种可恢复。另证同版健康工作库在规则库不可用时仍可继续、保存或显式恢复。
- 将原包保管、DM 接受、准确组合执行和发布各自记录在[采用边界](adoption-boundaries.md)。
  完成某个检查点只授予该阶段资格。

定向入口包括 `LocalRuleLibraryTest`、`CampaignRuleSupportTest` 和 `CampaignRuleBindingIntegrationTest`。
