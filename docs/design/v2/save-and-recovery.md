# v2 完整战役文件、保存与恢复

本文规定当前有限 SQLite 模型的完整文件和 P0—P3。它与
[规则存储](rule-storage-and-versioning.md)、[运行事务](runtime-and-transactions.md)共同维护，
具体用户入口见[运行合同](../../storage-vitality-loop.md)。当前文件覆盖所选应用模型的全部
初始与当前事实、历史和 pending。文件打开使用本机规则库的准确原包及独立接受。
完整 SRD、通用 MySQL archive、玩家步骤和新机制分别按各自采用门管理。

## 文件职责与权威边界

| 材料 | 内容与边界 |
|---|---|
| 完整 JSON | 稳定 campaignKey、独立 fileKey、准确规则 material/完整链、全业务状态/历史/未决图；保存点不可变 |
| 本机规则库 | 保管准确原始 ZIP、导入与接受账本及操作结果，供新建和文件打开复核 |
| 私有 SQLite | 活动权威、尚未保存最新提交、聚合与关系投影、业务接受/保存收据、epoch 与结构计划 |
| rollback journal | 引擎恢复材料，不是存档；不得手删以制造无事务或空闲 |
| 分配/清理标记 | 仅覆盖完整库尚不存在或封存/放弃清理窗口，绑定准确 run/计划/输入或最终产物，不独立编辑业务状态 |
| 临时保存文件 | 绑定原 P0 和唯一 fileKey，目标目录同卷；未接受时不作可打开保存点 |
| 日志/Session/下载副本 | 诊断、安全或用户保管材料，不能补状态、接受结果或证明源可删除 |

工作库是最新状态，旧 JSON 不能覆盖残留。完整 JSON 携冻结材料和全部业务事实。
文件完整性与本机接受分别核验。运行资格需要本机准确接受、原包复核、完整组合与应用对
所用机制的支持。[本机规则库](local-rule-library.md)

## 完整文件外壳与分区

当前 `CampaignCodec` 使用 `fileKind=RULE_BOUND_CAMPAIGN`、整数 `formatVersion=3` 和
`applicationModel=campaign-spaces-3`。根恰含 `applicationModel`、`campaign`、`domains`、
`fileKey`、`fileKind`、`formatVersion`、`integrity`。模型、字段、类型或完整性不符时拒绝整份文件。

`domains.material` 保存机制解释协议、准确绑定、完整规则、条目和 `FieldChain`。
`Material.restore` 从冻结行重建投影，核对 composition、final-rules、chain 指纹及应用支持范围。
完整身份、禁用项、被覆盖值、准确提供者和作者位置均保留。新打开另外用本机接受的准确原包重组合，
逐项核对这些材料。

| 逻辑领域 | 当前完整落点及唯一事实 owner |
|---|---|
| 角色身份/初始与当前 | `domains.characters` 的名称/PC-NPC/活动状态、InitialPlan、History/current 与初始事件；prepared 业务标识保留 |
| 成长/熟练/健康/资源/休息 | 所属角色 typed 状态和全部事件，含标准数组初始、职业、子职业、ASI、授予、HP、临时 HP、死亡、生命骰、资源、时钟和原骰。关系投影逐行核验 |
| 装备/法术书 | 所属角色 current/历史中的实例/位置/穿戴与已学/准备/恢复事实；不从目录重发物品或补书 |
| 场景/战斗 | `domains.combats` 全部 History/current，含部署/先攻原骰、轮回合、预算、场景模式和全部前后/因果依赖 |
| 动作/反应/施法/效果/怪物 | 所属场景聚合中的完整 flow/父子帧/返回点、窗口/候选/决定、原骰/成本、Ready/施法、专注/期限/全部压制原因、怪物HP/动作/充能/休息及共享伤害批次 |
| 空间/简单物品 | `domains.nodes/positions/space/items` 和根历史，保存路线、唯一安置、场景、焦点、各空间钟和稳定怪物事实，简单物品各有归属与数量 |
| 统一根历史/消息/检定后果 | `domains.roots` 保存原请求、原骰、各空间前后事实和全部子事件映射，`campaign.eventTail` 核对完整根数量 |
| DM-managed 自由卡等旧能力 | 采用独立 typed 领域，不写入或转换 schema-2 权威角色；其实际字段/历史/文件接合及证据由[接合表](domain-integration.md)核对 |

已结束、被压制、无有效贡献、已消费但仍被历史引用的实例也须保留。初始卡不等于打开
文件时的当前卡；保留所有已记录 before/after、选择、骰点、消耗和继续义务，不按近期列表截断。
玩家步骤和任意加入等级属于后续完整产品输入，当前文件不虚构这些尚无消费者的字段。

[玩家参与原型](player-participation.md)的 `domains.participation`、根 `actor` 和裁定事实
与角色和 pending 一起完整保存、严格读取；缺失的新字段拒绝，不补造归因。邀请、设备凭据、
Session、连接状态与网络配置不进文件；打开文件仅恢复业务关系，DM 须重新核对加入者并
批准设备绑定。残留恢复同样不复用旧连接写资格；原请求查证与新命令分开，不能从新运行
没有旧 HTTP 收据推断原行动未执行。私有安全控制只留在原 run，不随文件传递。

目标文件保存世界图与全部局部场景、主体的空间归属和实际位置、当前焦点及其代次、全部
世界节点和局部场景的时间域与逻辑秒，以及各空间的业务状态、历史和未决事项。是否冻结
由当前焦点推导。恢复核对安置、焦点、时间域、期限与未决事项的一致性，切回空间沿已保存
的时间和进度继续，冻结期间不补算。界面视口与显示尺度独立于业务文件。空间与时钟见
[空间合同](world-and-scene-spaces.md)。

### 必存、可推导与禁止项

- 必存：完整 material/链、稳定业务键、初始/当前值、用户选择、原骰、消耗、时间、pending
  及全部根/子历史。schema-2 prepared Identity、事件 operation/version 若参与业务引用，保留原值。
- 可推导：显示修正、AC、有效贡献、索引/计数和关系查询投影；只能从准确事实无副作用验证。
  若既有历史已经记录该值，不因可重算而删掉审计事实。
- 禁止：物理 `core_control.run_id`、本地 Host revision/epoch、HTTP Session/CSRF/请求执行收据、
  保存收据/路径、storageModel/plan digest/物理模块表清单、DDL/SQL、连接配置、日志及缓存。
  不能仅按字段名 run/snapshot/operation 一律排除真实业务标识。

## 编码、摘要与拒绝

文件为非压缩 UTF-8 JSON。外层 parser 拒绝 BOM、重复键、未知/缺失字段、尾随内容、坏
Unicode 和类型；typed 域拒绝未登记 discriminator、非 record/enum 类型、非规范整数/映射
及超界集合。writer 输出确定性键序/数组业务序。业务 int/long 用规范十进制字符串，协议
版本用有界 JSON 整数；数值不经 JavaScript Number 或浮点截断。

当前 integrity 为 SHA-256/canonical 1，使用 `DND-CAMPAIGN-FILE` 域、零字节、版本 `1`、
零字节和排除 integrity 后的完整 canonical 根。源指纹使用 `DND-CAMPAIGN-SOURCE`，
不含 fileKey/integrity 或本地执行控制。原包/规则/源/文件 raw 摘要各有职责，均非历史签名。

先有界读取，再核完整性、规则支持、身份/图、所有根/子历史、状态邻接、原骰/算术、资源、
一致时钟和动作/效果义务。恢复只验算并写已有事实，不调用 RNG、正常业务命令或效果回调。
同版残留还核对本地计划与实际结构；不得从库自报结构生成相同计划来掩盖篡改。

## 导入、再次打开与本地恢复

上传先严格核完整文件，再保留文件原 fileKey 登记为受管文件；原 fileKey 已存在即拒绝，
保留原文件。上传与打开是两个操作。首次或再次打开均建立新物理运行、epoch 和本地收据空间，
保留稳定业务标识、角色和场景历史版本以及全部因果。

新建和文件打开须核验本机准确原包和 DM 接受。打开用文件的原有序成员重新组合出校验候选，
逐项核对文件中的准确规则、完整来源链、绑定指纹和机制解释协议，再直接装载已有业务事实。
换到新机器时，先导入并明确接受所需的准确原包，再打开文件。上传和文件自报均不登记接受。缺包、未接受或规则
不符时拒绝打开并保留原文件，细节见[规则存储](rule-storage-and-versioning.md#完整文件打开前的规则核验)。

有未封存残留时阻止任何新建/文件打开。显式恢复原目录取得独占权，让引擎恢复并核验
完整库/全部收据，再提交新 epoch；不补表/seed，不重播未持久请求或原业务命令。确定
未提交但无持久接受事实的旧意图不作为自动重试任务。新 epoch 后只有明确用户命令可执行。
活动运行、保存和同版残留恢复只使用工作库已绑定的冻结材料。
下载只传递已接受准确文件；下载失败重传原字节，不重做游戏或产生第二收据。

## 保存 P0—P3：两个提交点

INITIAL、MANUAL、FINAL 使用同一协议。保存持服务接纳门并排空业务，固定完整源；
文件 I/O 不持数据库事务。不要求周期 AUTO 才能保存中途动作或开放当前应用运行。

| 阶段 | 当前成功点与失败处理 |
|---|---|
| P0 登记 | 短事务复核完整源/revision/容量，登记唯一请求意图、fileKey、准确 raw 摘要/长度与目的；已存在不同意图冲突 |
| P1 写临时并读验 | 同目录临时字节写出、force/关闭、严格读取；字节和完整投影须等于原固定源，不以编码/解码自洽替代独立字段覆盖 |
| P2 发布 | 同目录无覆盖硬链接发布唯一正式文件；POSIX force 目录，原生 Windows 按下述进程中断边界；硬链接/所选平台必需能力失败时不降级覆盖复制；既有目标只允许同一意图准确字节 |
| P3 接受 | 从正式路径重读并核原源/revision；短事务接受保存收据，FINAL 同时 seal；COMMIT 明确才报保存完成 |

P2 与 P3 不原子。P2 成、P3 未成/不明时保留文件和源，只完成原保存意图；不能另发文件、
开放新写或删源。未接受文件不列为可打开保存点。HTTP 200、内存编码或下载开始不能代替
发布/接受点。当前失败恢复按原意图重试或显式 recover；没有生产实现的取消/REPAIR
分支不由设计文字取得资格。

原生 Windows 采用本地 NTFS、当前运行账号私有 ACL、文件 force 和 SQLite DELETE/EXTRA。
Java NIO 无法对 Windows 目录执行同等 force，本版保留文件与数据库落盘，但不承诺物理
断电后新建、硬链接、改名或删除目录项必然持久。进程强制退出与物理断电分开验收；不能
把目录 force 静默失败当作 POSIX 耐久合同已满足。平台约束见[配置](../../configuration.md)。

每次保存新 fileKey，不原地更新正式字节。当前不自动轮换/删除保存点，AUTO 只有经过
容量/保留测量并完成新合同/实现/验证后才启用；详细后续要求见[自动保存](player-steps-and-auto-save.md)。
已接受结果与文件此刻是否仍可读分别核验；列表/latest/文件时间不能证明字节存在。

## 结束、放弃与运行空间释放

技术 END 如实保存当前完整状态，包括 OPEN/CLOSED 等待继续、已付未结成本、效果与
怪物休息过程。它不 PASS、不掷骰、不退出战斗、不结算剧情或结束专注。
关闭浏览器、Session 到期、GET/下载与正常停机均不等于 END。

P3 FINAL/seal 接受后重新核验最终文件与完整库源等价，再持久清理材料并按受控白名单
完成封存目录释放/墓碑清理；失败保留标记和准确对象，封存/清理中永不激活。当前清理
顺序以 `CampaignStorageService` 为准，不能把未实现的改名/取消/REPAIR 变体写成已交付。
未知文件、坏标记、锁/句柄冲突或路径越界阻止清理，不能递归扫删。文件系统删除不承诺
整体回滚，也不通过跨域 SQL DELETE 图重建第二条释放生命周期。

| 删除对象 | 限定责任 |
|---|---|
| 受管保存 JSON | 准确 fileKey，先排除活动/残留/保存/清理收据依赖；不结束运行、不删规则、不证明另有副本 |
| 非活动残留 run | 用户明确选择可能丢失的准确 run，持锁核分配/放弃/隔离材料后白名单清理，保存文件保留 |
| 已封存/隔离目录 | 仅按原持久清理标记继续准确对象，未知内容保留阻断 |
| 原规则包与接受账本 | 独立维护和保管，规则库变化不重解释现有冻结规则；END、档案删除和运行放弃只操作对应运行或档案 |
| 用户下载副本 | 用户保管，应用不因本地删除或 END 推定有权删除外部副本 |

## 关键故障窗口

| 中断 | 恢复要求 |
|---|---|
| 准备目录/锁/原输入/分配写入中断 | 原子目录名绑定准确 run/input/plan；完整输入可继续原准备，不完整输入只精确放弃；未知内容或完整身份不符保留 |
| 初始化 DDL/seed/装载/控制未提交 | 无执行资格；独占查证完整回滚与原分配材料，不补部分结构 |
| 初始化已提交、读回/INITIAL 未完成 | 保留完整源，只继续读验/原首份保存，不重新初始化 |
| 游戏 commit/rollback/close 不明 | 禁止新写；恢复真实库/全部根子历史与接受收据，已接受只返回事实，未持久意图不重播 |
| P0/P1 未完成 | 保留源与原意图，按准确临时/正式路径核验，不能换 request/fileKey 绕过 |
| P2 成、P3 未成 | 保留字节与源并完成原接受；不二次 END 或先删工作库 |
| P3 成、响应/下载丢失 | 原收据/原字节返回，不重掷、扣费或发效果 |
| 封存/放弃清理中断 | 只继续准确清理，墓碑/部分删除不恢复游戏 |
| 模型/规则/计划/投影坏 | 保留并拒绝，不重新编码一份默认状态掩盖损坏 |
| 本机规则库不可用 | 新建和文件打开保持阻断。活动运行、保存和同版残留恢复使用已绑定工作库 |

## 容量、验证与灾备

每个命令先预检域集合/事件计数预算及必需后缀，产生纯结果后在领域 SQL 写入前核验
完整候选不超过 16 MiB。计数预留不等于后续完整文件字节预留；现行有限上限不证明未来
完整 SRD、无限历史或最坏体积已完成测量。跨领域字段、独立字节期望、复杂 pending 与全部
