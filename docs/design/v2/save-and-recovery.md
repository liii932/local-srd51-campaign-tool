# v2 完整战役文件、保存与恢复

状态：本文确定当前选择的完整文件与发布合同，配合[规则存储](rule-storage-and-versioning.md)
和[运行生命周期](runtime-and-transactions.md)。它尚未实现，不激活 archive format 2。
现行 format 1 的 16 MiB、近期历史和内部 format 2 角色片段仍按各自实现解释。
原型只支持当前应用声明的模型与协议；这里的选择可修订，不建立跨版本读取或转换链。

## 文件职责与权威边界

打开期间，私有 SQLite 运行库是最新业务状态的唯一权威。战役文件是某个已提交保存点的
完整可移植投影，保存后不会跟随运行变化。关闭后用户保管文件及其准确规则制品；旧文件
不得覆盖尚未保存的残留。本设计不再把正式文件字节复制到共享数据库档案区。

| 材料 | 所有者、身份与版本 | 内容与引用 | 存在、重建与删除 |
|---|---|---|---|
| 完整战役 JSON | DM 保管，应用写出；稳定 campaignKey、每次产物独立 fileKey；准确应用模型、文件及分区协议 | 全部业务闭包和准确规则绑定，不含规则正文 | 必需交付物；手动、AUTO、首次检查点、FINAL 共用格式；不可从规则包重建丢失进度 |
| 规则原始 ZIP | 作者提供、独立维护入口安装/接受；准确模组键/版本、raw 与逻辑摘要、协议 | 全部原包字节；本地接受事实在来源账本，不由包自报 | 独立文件恢复的必需依赖；相同逻辑但不同原包不能替代；组合包只是可选分发容器，无需再建一份权威 |
| 私有运行目录及 SQLite 库 | 应用拥有；服务器分配目录、run_id、snapshot_id、存储协议、应用模型 | 完整固定规则/链、初始/当前状态、全部历史、幂等结果、保存意图和生命周期控制 | 活动及崩溃恢复必需；旧文件不能重建未保存的最新提交；封存或精确放弃后清理 |
| SQLite rollback journal | SQLite 引擎拥有，依附准确库 | 恢复未完成的 DB 事务，不是战役格式 | 热 journal 不是垃圾，由引擎独占恢复；不能单独删掉后宣称库完整。选定模式不依赖 WAL |
| 保存临时文件 | 保存协调器拥有；operation、fileKey、目标 revision 绑定 | 目标档案目录同卷的完整候选字节，无发布资格 | 必要但不另创格式；确定未发布才可删除/按同一意图重写，未知先查证 |
| 分配/清理标记 | 生命周期协调器拥有，版本化最小本地材料 | 分配 operation/身份、输入指纹/规则绑定或封存/放弃证明及准确目录；主体控制事实在库内 | 只在尚无完整库或关闭/删除库窗口需要；不携带第二份业务状态，不授予恢复资格；清理后删除 |
| 缓存、下载副本、日志 | 缓存可重建，下载副本由 DM 保管 | UI/索引不存独有事实，日志不是恢复源 | 不另建角色档、事件日志文件或全局永久收据库；外部复制不作已保存/可清理的自动证明 |

分配标记先于首次初始化事务持久化，绑定原 operation、新 run/snapshot、准确模型、创建
输入或导入文件 raw 指纹及规则绑定。创建输入的完整无副作用材料可在该私有准备目录暂存，
严格验证且不另赋业务权威；未提交初始化时重试必须匹配原输入，拿不到就保持准备或精确
取消。完整初始化提交后，库内初始化收据接管控制事实，分配标记不再独立决定是否执行。

运行与档案目录物理分开，均在应用管理根内且不在 WAR/Git。路径不是身份；上传文件不能
指定目录、库名或 SQL。禁止路径穿越、符号链接/重解析点逃逸和覆盖未知同名文件；只清理
准确登记且仍在受控根内的对象。物理运行副本仅供同版灾备，不作为外来便携输入直接打开。
数据库凭据、Session、CSRF、私钥和连接串均不属于战役文件。

## 完整文件外壳与分区

根对象的精确字段为 `fileKind`、`formatVersion`、`applicationModel`、`fileKey`、`campaign`、
`rules`、`partitions`、`integrity`。`fileKind=CAMPAIGN`，目标 `formatVersion=2`；
`applicationModel` 是应用明确支持的准确模型标识，不按版本大小比较。同为数字 2 的旧
内部角色片段也不能匹配本合同。fileKey 为服务器生成的规范 UUIDv4，不赋予幂等执行权。
`campaign` 恰含稳定 `campaignKey`、`name` 和 `eventTail`；name 为 NFC、1—80 个 Unicode
码点且非空白，eventTail 为非负规范十进制 long 字符串。

`rules` 使用[模组公共绑定](module-interface-baseline.md)：有序准确成员、各成员原包/逻辑
双摘要、必要协议/组合算法及组合配置、最终规则、完整覆盖链摘要。规则值作为已发生
检定/成本的审计事实可以保存，整份规则正文与含规则值的完整覆盖链不进入文件。

`partitions` 是以下封闭分区名到对象的映射，每个对象恰含准确 `version` 与类型化 `content`。应用根据受支持规则与
存储闭包确定必需集合，输入不能自称“不适用”。可选域的省略必须由应用证明无规则、
状态、历史或 pending 引用；核心 campaignState、characters、history 总是存在。合法无
对象可以是空集合，缺实现不能用空集合代替。分区内列级白名单、writer、reader、独立
向量必须随该域接入一起交付；缺少工件的组合没有完整文件资格，不能在导入时猜字段。

| 分区与唯一源 owner | 必须保存的内容 | 直接恢复与闭包要求 |
|---|---|---|
| campaignState / 战役与时间协调器 | 初始配置、玩家稳定名单/顺序及 PC 映射、唯一探索/战斗模式、业务时钟/单位、轮次/当前及挂起步骤、完成边界 | 初始与当前分开；现实时间不推进游戏；PC/玩家/步骤引用闭合 |
| characters / 角色与成长 | 身份、PC/NPC、ACTIVE/ARCHIVED；加入初始卡、完整当前卡及受规则约束的类型化字段，属性/职业等级/子职业/ASI/专长、HP/生命骰、熟练/授予来源与选择 | 初始卡不是导入时当前卡；保存既有分支/骰点；不从模板或等级补当前值；离场身份仍供历史引用 |
| equipment / 装备 | 实例、准确模板或受支持自定义内容、数量/消耗、持有者/地面位置、穿戴/持握/同调及阶段、取得/消耗事实 | 掉落共用真实健康因果；被历史引用的耗尽实例保留，不按模板合并实例 |
| resources / 资源与休息 | 最大/当前/已用资源、法术位/特殊恢复、活动休息、生命骰已花集合、收益资格、每日/长休时刻与日界依据 | 统一时钟；不自动休息、充能或补收益；最大值可重算验证，消耗必须保存 |
| spellcasting / 施法与学习 | 已知/法术书/准备及来源选择、施法 attempt、成本/组件/release、持续施法/Ready 与触发寿命 | 规则目录不是人物事实；资源、物品、flow、效果和历史以业务键交叉核验 |
| scenes / 场景 | 地图/节点或有单位的坐标几何、区域/环境、完整部署 roster、位置/阵营、怪物健康/动作/充能/休息 | 业务空间数据必须在文件中；准确引用规则模板；外部图片只能是可缺失装饰，不能承载唯一碰撞/范围数据 |
| combat / 战斗 | 遭遇及终结状态、先攻原骰/排序、轮/回合/边界、动作/附赠/反应/移动剩余、攻击序列、模式交接 | 角色 HP/资源引用唯一 owner，怪物归场景；不另存可写角色当前副本 |
| actions / 唯一动作流及结果 | flow、全部父子帧/返回点、窗口/机会/候选顺序/决定、choice、阶段、移动前缀/游标、攻击/检定/多目标批次、全部候选骰与选择、已应用结果/未结义务 | 冻结目标证明、共享骰/各目标 packet、成本与因果事件全引用；只存 top 或 pending 标志不完整 |
| effects / 持续效果与专注 | 来源/目标应用、ACTIVE/ENDED、期限/周期游标、全部压制原因、比较依据、holder、订阅、已发生转换及待回调义务 | 无贡献及被引用的已结束实例也保存；不补 tick、生效/结束回调或复活专注 |
| history / 战役根历史协调器 | 单一根序号、类型/主体/因果、全部已记录 typed 正文/前后状态、消息、原骰/成本/效果/决定及领域子事件 | 保存全部已有历史；跨角色/场景回到同一根；不并用 recentEvents/stateEvents；验算事实不执行事件 |

共用覆盖流程是：完整源 → 每个持久字段的保存/推导/排除清单 → 编码 → 严格读取 → 无副作用
恢复计划 → 全域验证 → 一个新运行事务写入 → 数据库实际全量回读。各阶段以同一字段清单
及独立期望比较，不能用“领域自行处理”省去跨域字段、因果和继续图的闭包。

### 必存、可推导与禁止项

- 必存：不能从准确规则和已存事实唯一重建的初始/当前值、用户决定、随机结果、消耗、
  时钟、未决后缀及全部已有历史。历史已记录的前后值不能因“可重算”删掉。
- 可推导：当前显示修正、AC/负重等查询投影、有效贡献、索引/计数/排序缓存。只能由准确
  规则与完整事实无副作用重算；保存作审计结果时校验相等，不以它覆盖事实 owner。
- 禁止：本地行 ID、run/snapshot、CAS、Host epoch、HTTP 令牌/幂等收据、保存路径/本地
  序号/清理代次、自动保存技术水位、SQL/表定义、连接配置、日志和缓存。业务 action/
  choice/event 身份须保留；现实现若复用 operation UUID 作业务因果键，采用器须明确
  映射业务键，不能因排除请求收据删掉真实因果。

## 编码、摘要与拒绝

选择单个非压缩 UTF-8 JSON，不以 ZIP、SQLite 页镜像或 JSON 行增量替代。
规范编码 `campaign-json-1` 按以下规则配独立字节向量后采用：

1. 无 BOM、尾随数据、注释、重复键、非有限数或孤立 surrogate；未知/缺失字段、类型与
   分区版本拒绝。reader 接受 JSON 格式空白；writer 无多余空白及结尾换行。
2. 文本按码点校验 NFC 和领域长度，拒绝 C0/C1 和 DEL，读取不静默正规化。标识按 ASCII
   合同，UUIDv4 为小写标准形状。对象键按 UTF-8 字节升序；字符串仅引号/反斜线转义，
   其余合法码点直接 UTF-8。
3. 业务整数（事件序号、秒、数量、骰点等）用规范十进制字符串，无前导零/加号/指数/负零，
   按字段验证 long 或更窄界。协议版本用有界 JSON 整数。坐标/精确量用声明单位的整数或
   比例，不经浮点或 JavaScript Number。布尔用 boolean；null 仅在准确字段合同允许处出现。
4. 有序数组保留确定顺序（加载、骰子、机会、历史）；声明 ordinal 的集合要求连续且不重复。
   历史事件序号按角色/历史合同保留原序号及已有间隙，不能重编号。无序集合按完整稳定
   身份的规范字节排序并拒绝重复，不能通过排序掩盖重复或重排有业务意义的数组。
5. integrity 恰含 `algorithm=SHA-256`、`canonicalVersion=1`、小写十六进制 digest。
   摘要输入为 ASCII `DND-CAMPAIGN-FILE`、零字节、ASCII `1`、零字节，接去掉根 integrity
   字段后的完整规范 JSON 字节。raw SHA-256/长度记入本地保存意图/收据，不嵌入自己的 raw 摘要。

保存和命令查证共用的完整源指纹另用 ASCII `DND-CAMPAIGN-SOURCE`、零字节、ASCII `1`、
零字节作前缀，接恰含 applicationModel、campaign、rules、partitions 的规范对象字节；
不含产物 fileKey、integrity 和本地控制。完整读取后的指纹只作快速比较，独立字段覆盖与
实际恢复等价仍必须验证。原包、规则逻辑/组合、文件 raw、文件逻辑和源指纹不可互换。

摘要证明完整性，不证明规则接受资格或历史真实签名。先有界读取，再核摘要、准确规则、
全部身份/引用、历史类型/序号/尾、初始/当前邻接、骰点算术、资源、唯一时钟和动作/效果图。
错模型/协议、缺依赖、悬空/跨战役引用、未知 pending 或缺分区使整份输入拒绝，不部分导入、
补默认值或猜旧语义。相同 formatVersion 不证明相同模型；不保留跨版本转换链。

缺规则原包、摘要不符、未本地接受或机制不支持时，只能展示通过结构检查的摘要和缺项，
不能激活。补齐依赖后重新完整验证，不选同名/高版本代替。同版本地残留可使用校验后的
完整规则镜像、链与原接受绑定，不要求来源在线；外来 JSON 不能自带“已接受”绕过来源门。

## 保存 P0—P3：两个提交点

所有保存目的共用此协议。全工具至多一个保存协调操作；排空在途事务并短暂阻止新游戏
写入，查询/原收据查阅可用，不跨文件 I/O 持有 DB 事务。意图固定 operation、purpose、run、
源 commitRevision、完整源指纹、fileKey、受控目标路径和预期字节。源指纹包含分区、所有
业务值及历史，不仅是事件尾或行数。确定性流式计数编码可取得预期 raw 摘要/长度，无需
整份驻留内存；临时和正式字节都须与它相等。

| 阶段 | 资源与事务 | 成功点及可重入 | 失败、取消与后续 |
|---|---|---|---|
| P0 捕获登记 | 运行短事务复核规则/全域源/容量，登记意图和写屏障，保留源与旧档 | commit 明确成功；同 operation 返回原意图，冲突拒绝 | 明确回滚即未开始；未知先查证，不产生第二意图 |
| P1 临时落盘及独立校验 | 目标目录同卷独占临时文件，流式写、flush/force、关闭后重读；无 DB 写事务 | reader、摘要/长度、恢复投影与完整源逐字段等价通过；不以往返自证 | 确定未发布才可清临时/重试或取消；坏源保持阻断，旧档不代替最新源 |
| P2 发布不可变产物 | 同卷原子改名到 fileKey 唯一正式路径，不覆盖，再持久化目录项 | 文件系统耐久发布点；既存目标仅可匹配同一意图准确字节 | 不支持原子/目录耐久语义不得报可靠保存；响应未知检查准确临时/正式路径，不推断失败重写 |
| P3 接受登记 | 从正式路径重新读验并核源 revision/指纹；运行短事务写 receipt、水位；END 同时封存 | DB commit 明确成功才报保存完成；相同意图只返回原接受结果 | P2 成而 P3 未成时保留文件与源，阻断并查证/继续同意图；未知不得删文件或开放新写 |

取消是独立受保护控制转换：先停止该保存执行者，查清 P2/P3、确认没有已接受收据/seal，
再在短事务中把原意图记为 CANCELLED 并撤销该操作的写屏障；同意图重复取消返回原事实。
P3 与取消在同一接纳门竞争，取消提交后 P3 必须拒绝，不能晚到封存。取消事务未知保持
阻断。P2 已发布的字节保留为可检查产物，但取消不推进检查点水位、不冒称保存已接受；
原 AUTO 原因仍未解决。已经接受的普通保存只能返回成功，END 已封存不能取消。

P2 与 P3 不是一个原子事务。任何后台写也受屏障约束。保存成功只证明受控本地文件和接受
事实；HTTP 200、内存编码、下载开始或浏览器确认不替代 P2/P3。下载失败只重传相同字节。
手动保存明确失败且没有未知结果可取消屏障回原业务状态；AUTO 阈值失败保留屏障，见
[自动保存](player-steps-and-auto-save.md)。END 在封存前可显式取消，须先查清 P2/P3；已发布
文件不会暗中删除。END 的 P3 封存一旦提交，只能清理，继续游戏须从完整文件新开运行。

### 替换、修复与保留

正式文件不原地改写，每次保存新代。列表由已验证产物/收据构成，latest 若存在只是可重建
索引，不作恢复/删除凭据。复制到用户同名目标是独立导出：在该卷临时写/读验，只有用户
指明的准确旧目标才可原子替换；失败不影响本地保存。

新 AUTO 的 P3 成功且正式字节可读后，才清除策略允许的旧 AUTO；至少保留最近成功 AUTO，
手动和 FINAL 不参与自动淘汰。数量/总字节策略须实测，不照搬三份；不能为新保存先删唯一
好档。轮换失败仅留下额外文件并计占用。

END 后文件复核损坏，只要原运行完整且源指纹相等，可受保护 REPAIR 以新 fileKey 执行
P0—P3 并替换封存引用；旧收据不改，不恢复游戏、不先删源。源也损坏则保留并报告无法
完整恢复。技术收据在运行存续期完整保留，目录清理后旧 run 请求永久失效，不建全局
无限收据库，也不让旧请求重新取得写入权。

## 结束、放弃与运行空间释放

技术 END 保存任何已提交阶段，包括 OPEN/CLOSING、待选、已支付未结算、效果已结束而
回调未完；不掷骰、替用户 PASS、退出战斗、治疗或结算剧情。[动作](action-continuation-protocol.md)
和[效果](ongoing-effect-protocol.md)的必需后缀原样保留，技术清理不调用业务结束消费者。

释放顺序：P3 END 封存 → 再核验最终文件与封存源等价 → 停止/关闭全部连接 → 持久化最小
清理标记 → 准确运行目录原子改名到私有待删除区 → 持久化父目录 → 按登记内容可重入删除
→ 最后删除标记/空目录。持有应用独占锁直到释放或残留识别结束。标记仅含运行身份、
准确原/目标目录、应用模型、END 或放弃依据及可核验产物引用；路径由受控根导出。
目录改名失败保留封存库；部分删除失败保留墓碑，禁止激活。文件系统删除不能承诺整体
回滚，不再要求逐领域 SQL DELETE B。坏标记、未知附加文件、路径不合或句柄未释放时
保留并阻断相应清理，不能递归扫删。规则库、档案和其他运行不在删除范围。

正常 END 可协调一次保存和一次清理，无需第二次确认；失败后精确继续。启动不自动删
可恢复运行。显式放弃须先展示战役/准确运行、最新提交与保存点和可能丢失内容，确认后
记录放弃事实再封闭清理。坏库无法读取时只能在精确识别目录并确认可能失去全部未保存
状态后隔离/放弃，不伪造保存收据。自动任务不替用户决定。清理失败若配额不足或隔离
不明则阻止新运行；墓碑隔离完整且容量足够可回空闲，但显示占用及准确重试入口。

## 关键故障窗口

| 中断位置 | 恢复行为 |
|---|---|
| 分配/建表未完 | 完整初始化未提交就无执行资格；只识别自身分配材料，再准备或精确放弃，空库不是新战役 |
| 游戏 commit 响应未知 | 隔离旧执行者，独占恢复 SQLite，核原请求/结果/状态历史闭包；已提交返回原事实，确定未提交才允许原意图重试，否则阻断 |
| P0 已登记、P1 未完 | 源完整，临时无发布资格；继续原意图或确定未发布后取消 |
| P1 后、P2 改名前后 | 查准确临时/正式路径及预期 raw 字节，分未发布/已发布/冲突；不按时间戳选最新 |
| P2 成、P3 未成/未知 | 文件和源保留；完成原 P3 或查明已成；不重复 END、不先删源 |
| P3 成、响应/下载丢失 | 返回原收据/重传同文件，不重掷、扣费或补发效果 |
| END 后、关闭/改名/删除中 | 仅继续准确封闭目录清理；部分删除不恢复游戏，不影响规则库/其他档案 |
| 来源离线 | 合格本地运行/残留据固定快照核验；文件导入缺准确接受材料则不初始化 |
| 重启活动残留 | 不自动执行；查证和全域验证后可显式继续原 run（新安全代次）、救援保存或放弃，原 pending/骰子保持 |
| 应用不支持模型 | 保留并拒绝，不转换、不换旧 reader 猜读、不自动删除 |

## 容量与增长

| 依据类别 | 约束 |
|---|---|
| 当前代码事实 | v1/内部 codec 的 16 MiB、近期 50 条及 INTERNAL 自身数组/历史上限只描述现实现，不能推导完整容量 |
| 本次结构选择 | 一个活动运行、一次保存、单 JSON、全历史、规则另存；发布前保留源与旧好档；长度/计数运算检查溢出 |
| 必须实测确定 | 文件最大字节 B，深度/数组/总节点/字段界，库/journal/规则链峰值，解析/恢复内存，保存时延，AUTO revision/增长阈值和保留预算 |
| 不沿用的数字 | 旧设计 64 MiB、1 GiB、128 MiB、固定元数据单位、50 步/三档无全域测量依据，不作为新发布指标 |

应用发布能力清单必须提供经实测的有限界，文件/模组不能扩大它。验收覆盖最坏规则闭包、
全部历史、最长合法 pending 和终结后缀，不能只测静态卡。每个命令在随机性/写入前证明
新状态可完整编码，并为已接受 pending 的必需后缀保留逻辑额度；不因保存不下截断历史。
超界拒绝新增增长，保留查询、保存、结束和已预留后缀能力。物理磁盘仍可能耗尽，失败
须保留上个提交与旧好档。

预算至少包括：当前库 + journal + 旧正式档 + 完整临时档 + 关闭前新正式档 + 未清墓碑；
初始化还含组合材料和新运行库。改名不复制候选字节，但解析内存/数据库增长/目录持久化
仍需测量。到界要求释放明确对象或增加受支持预算，不自动截断，也不承诺无限增长。

## 验收条件

1. 独立字段矩阵覆盖当前所有 owner：初始/当前、装备、场景/怪物、资源/休息/时钟、
   多层 pending、原骰、压制/终结效果和全历史；删除任一必存字段应失败。
2. 初始与当前不同、跨角色因果、历史引用已耗对象、复杂 pending 的独立期望文件，经
   新运行恢复和 DB 全量读回逐字段等价；恢复调用随机/扣费/效果消费者的次数为零。
3. 错版本、缺/未知/重复分区、摘要/原包/组合错误、悬空、缺接受、超界/精度丢失在激活前
   拒绝，不留下可执行半初始化或覆盖现有文件。
4. 对游戏 commit、P0—P3、关闭/改名/删除每窗口注入进程终止、I/O 错误/响应丢失；证明
   只执行一次、旧好档不丢、未知先查证、清理只影响准确封闭目录。
5. 真实 SQLite JDBC 与目标操作系统/文件系统验证耐久、锁/句柄、热 journal、原子改名、
   目录持久化/低磁盘；代理连接和 MySQL 测试不能替代。
6. 用实测填入有限发布参数，验证增长拒绝/后缀预留/完整结束，接合 Host 反馈和支持资格
   后才开放；依赖顺序见[采用边界](adoption-boundaries.md)。

灾备共同保管准确规则、JSON 和实际支持它的应用；持有旧 WAR 不代表新应用支持旧模型。
来源备份另含安装/接受账本；物理工作库副本须受控关闭或采用引擎一致备份，不能只复制
打开中的 db 文件。现行 MySQL 程序见[备份恢复](../../backup-and-restore.md)。
