# v2 规则存储与版本

状态：目标已确定；语言与工具熟练目录分区已有独立实现，全规则装配与业务采用未完成。
本文件服从 [v2 设计基线](README.md)的现状/目标区分和发布边界。

## 数据归属

```text
正式分域 JSON 作者源
  → 离线严格校验、领域投影和受控安装
  → dnd_tool_rules：已安装规则来源、安装事实和独立迁移账本
  → 启动准备；每次首次初始化前重新核验完整来源
  → dnd_tool_se：本次运行的完整不可变规则快照 + 可变业务工作集
  → 从实际读回快照构建不可变执行视图，确认提交后发布

业务工作集 → 完整战役文件 → 独立档案区/用户下载
```

JSON 是可审查的作者源；来源库是其受控安装结果；运行快照是不可独立编辑的派生副本。
不得三处分别维护规则，也不能用作者文件、旧快照或旧缓存补齐坏目录。产品存档不携带规则
内容快照，恢复仍需精确匹配、完整且受支持的规则。

## 物理存储选择

规则库采用**领域关系表和类型化列**。职业成长、种族选择、资源恢复、法术列表、装备属性
各有明确落点；公共发布身份和来源元数据可共享。目标不采用任意属性袋，也不为被替代的
DRAFT 三表模型建立双读、双写或兼容视图。后续领域的准确列宽、精确小数和引用仍须逐项设计。

运行库保存所选规则的**完整逻辑内容快照**，不是成员键清单或仅 JVM 缓存。战役绑定本地
`snapshot_id`；业务行用同一个快照 ID 同时约束父归属和规则成员，复合外键防止跨运行串用。
运行命令不得查询来源库或持有其连接，不使用跨 schema 外键或分布式事务。

双 schema 目标位于同一 MySQL 实例：运行池保留 `jdbc/DndToolSE`，来源只读池采用
`jdbc/DndToolRules`。运行与规则迁移独立编号、独立批准、独立核验，不能把旧运行迁移复制
为规则库历史。迁移、安装、只读加载、业务写入和发布账号职责分离。

来源数据库 ID、安装代次与运行身份不是同一件事。运行的 `run_id`、`snapshot_id` 由服务端
分别生成 UUIDv4，保存网络序 16 字节且永久登记已使用身份；成功使用后不回收。独立恢复
生成新身份对，同一已接受请求重放只返回原事实，不重新分配或复制。

## 版本与摘要

| 标识 | 负责什么 |
|---|---|
| `module_key` + `release_version` | 精确规则发布身份；发布版本是字符串，不取最大值或做模糊比较 |
| `content_sha256` | 完整规则逻辑投影的规范摘要，必须与独立批准值一致 |
| `canonical_format_version` | 规则规范字节编码；不等于物理表结构 |
| `archive_format_version` | 产品存档协议 |
| 作者 schema / 安装清单版本 | 作者输入及制品清单的协议 |
| 两侧 `schema_version` | 各自数据库迁移链 |
| `installation_revision` | 某来源发布根的安装代次，不能代替规则发布版本 |
| `row_version` / Host epoch | 业务并发与请求安全代次，不进入规则内容身份 |

规则键和版本按精确 ASCII 比较；`"1"`、`"01"`、`"1.0"` 不同。显示名与包目录名不授信。
文件 raw SHA-256、安装清单摘要、WAR 摘要、请求指纹和业务源状态指纹各有职责，不能代替
完整规则 canonical 摘要。清单自洽或安装成功均不能产生应用的发布批准。

## 安装、分区与发布

来源安装器只安装经过完整输入校验的 DRAFT 材料，先锁永久安装控制行，再锁发布根。
领域写入、头代次/观测摘要、安装事实、分区集合和计数同事务提交；永久操作身份支持对
原意图的查证，不通过换请求键绕过提交未知。已实现协议见[离线安装](../../rules/offline-language-installation.md)。

`PARTITION` 只证明已知分区，不能冒充全规则摘要、运行资格或 `COMPLETE`。`COMPLETE`
也不等于 `RELEASED`；仍需独立批准、全量重算及跨领域发布门。当前运行语言 Repository
仅接受 DRAFT PARTITION；未来完整快照使用新的身份对一次建立，不能原地把语言快照升级。

正式执行集合只包含受支持且验证通过的 RELEASED。身份注册表可以记载 DRAFT 以准确拒绝
请求，生产目录加载器不据此加载或执行 DRAFT。隔离测试可以验证 DRAFT，不增加 Host
绕过发布门的开关。未引用的 DRAFT 内容错误不应要求加载它；共享 schema 故障仍须拒绝。

RELEASED 内容不可原地改写。DRAFT 开发安装在隔离开发目标前向演进，观察摘要单独记录，
不建立旧草稿兼容版本群。正式作者包、离线安装类和来源 SQL 不进入 WAR，WAR 只携带其
必要读取/验证代码及独立批准元数据。
