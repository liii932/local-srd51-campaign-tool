# v2 规则存储与版本

状态：目标已确定；语言与工具熟练目录分区已有独立实现，全规则装配与业务采用未完成。
本文件按 [v2 设计导航](README.md)区分设计选择、实现与发布；模组组合、身份与摘要的
公共合同统一见[模组接口基线](module-interface-baseline.md)。
作者 schema 2 的具体输入、组合步骤、最终字段与来源链核对见
[最小组合链路验证](schema-2-composition-validation.md)；生产原包与摘要采用[制品合同](../../rules/schema-2-rule-artifacts.md)，
维护操作采用[安装与接受](../../rules/schema-2-installation-and-acceptance.md)。有限投影和维护事实
不代替完整基础验证、机制接入或运行快照的实际读回验收。

## 数据归属

```text
正式分域 JSON 作者源
  → 离线严格校验、领域投影和受控安装
  → dnd_tool_rules：各模组准确来源、原始制品、安装/接受事实和独立迁移账本
  → 选择准确有序组合；每次初始化前重新核验来源、组合与接受资格
  → dnd_tool_se：完整最终规则快照 + 完整覆盖链 + 可变业务工作集
  → 实际读回并核验快照、覆盖链及状态，确认提交后发布执行视图

业务工作集 → 完整战役文件 → 独立档案区/用户下载
```

JSON 是可审查的作者源；来源库是其受控安装结果；运行快照是不可独立编辑的派生副本。
不得三处分别维护规则，也不能用作者文件、旧快照或旧缓存补齐坏目录。产品存档不携带规则
内容快照，恢复仍需原准确有序组合的完整制品及受支持的协议与机制。组合恰有一个完整
`base`，可带零到多个 `extension` / `compatibility`；依赖、联合兼容和顺序按公共基线核验。

## 物理存储选择

规则库采用**领域关系表和类型化列**。职业成长、种族选择、资源恢复、法术列表、装备属性
各有明确落点；公共发布身份和来源元数据可共享。目标不采用任意属性袋，也不为被替代的
DRAFT 三表模型建立双读、双写或兼容视图。后续领域的准确列宽、精确小数和引用仍须逐项设计。

运行库保存本次组合的**完整最终规则快照和完整字段覆盖链**，不是成员键清单或仅 JVM
缓存。组合绑定、快照、覆盖链与业务状态在同一初始化事务中建立，实际读回核验；仅明确
提交成功后发布。战役绑定本地 `snapshot_id`；业务行用同一个快照 ID 同时约束父归属和
稳定规则身份，复合外键防止跨运行串用。
运行命令不得查询来源库或持有其连接，不使用跨 schema 外键或分布式事务。

双 schema 目标位于同一 MySQL 实例：运行池保留 `jdbc/DndToolSE`，来源只读池采用
`jdbc/DndToolRules`。运行与规则迁移独立编号、独立批准、独立核验，不能把旧运行迁移复制
为规则库历史。迁移、安装、只读加载、业务写入和发布账号职责分离。

来源数据库 ID、安装代次与运行身份不是同一件事。运行的 `run_id`、`snapshot_id` 由服务端
分别生成 UUIDv4，保存网络序 16 字节且永久登记已使用身份；成功使用后不回收。独立恢复
生成新身份对，同一已接受请求重放只返回原事实，不重新分配或复制。

## 版本与摘要

| 标识 | 负责什么 |
|---|---|
| `module_key` + `release_version` | 单个模组的准确发布身份；版本是字符串，不取最大值或做模糊比较 |
| 现行 `content_sha256` | 现行单发布规则逻辑投影的规范摘要，按既有合同与独立批准值一致 |
| `canonical_format_version` | 规则规范字节编码；不等于物理表结构 |
| `archive_format_version` | 产品存档协议 |
| 作者 schema / 安装清单版本 | 作者输入及制品清单的协议 |
| 两侧 `schema_version` | 各自数据库迁移链 |
| `installation_revision` | 某来源发布根的安装代次，不能代替规则发布版本 |
| `row_version` / Host epoch | 业务并发与请求安全代次，不进入规则内容身份 |

原型的支持范围是当前应用版本，见[产品说明](../../product.md#原型阶段的版本范围)。记录准确
规则版本、组合和文件协议用于当前版本内的正确解释，不承诺保留旧存档读取器、旧组合算法
或旧工作集结构；当前实现保留的历史格式路径与未来支持政策分别判断。

规则键和版本按精确 ASCII 比较；`"1"`、`"01"`、`"1.0"` 不同。显示名与包目录名不授信。
文件 raw SHA-256、安装清单摘要、WAR 摘要、请求指纹和业务源状态指纹各有职责，不能代替
完整规则 canonical 摘要。清单自洽或安装成功均不能产生应用的发布批准。

新组合的原始 ZIP、模组逻辑、组合配置、最终规则和完整覆盖链五类摘要职责见公共基线。
它们分别核验制品、输入、准确有序组合、最终内容与解释过程；不复用现行持久化摘要域。
`content_sha256` 或相同最终规则内容都不能代替完整战役规则组合绑定；当前 canonical 2
及格式 2 内部单模组字段尚未采用这一合同。

## 安装、分区与发布

既有 schema 1 来源安装器只安装固定 `dnd5e2014_srd51_se` release `"1"` 的语言与工具
熟练 DRAFT 材料，先锁永久安装控制行，再锁发布根。
领域写入、头代次/观测摘要、安装事实、分区集合和计数同事务提交；永久操作身份支持对
原意图的查证，不通过换请求键绕过提交未知。已实现协议见[离线安装](../../rules/offline-language-installation.md)。

schema 2 使用独立原包和接受账本，与 schema 1 共用永久安装锁；来源 V003 及准确字段见
[来源账本](../../rules/schema-2-source-ledger.md)。原始 ZIP 是保管与复核制品，不把任意 JSON
属性袋用作业务规则表；逐领域类型化来源与运行快照仍按上面的物理存储目标接入。
安装不自动接受，接受须绑定实际审阅的准确原包、逻辑摘要和协议；同一准确版本不替换原包。
当前完整基础和有领域声明/修改的包仍被机制资格门拒绝，不能从有限制品解析推导运行支持。

`PARTITION` 只证明已知分区，不能冒充全规则摘要、运行资格或 `COMPLETE`。`COMPLETE`
也不等于 `RELEASED`；仍需独立批准、全量重算及跨领域发布门。当前运行语言 Repository
仅接受 DRAFT PARTITION；未来完整快照使用新的身份对一次建立，不能原地把语言快照升级。

正式执行仍须满足受支持的机制、协议及发布资格。现行 built-in 独立批准路径不等于未来
自定义模组的离线校验、安装与 DM 对准确内容的接受路径；schema 2 的维护入口按公共基线
分离这些职责，安装成功或接受单个模组均不代替实际组合校验。身份注册表可以记载 DRAFT
以准确拒绝请求，生产加载器不据此执行 DRAFT。隔离测试不增加 Host 绕过发布门的开关；
完整 SRD release 1 仍为 DRAFT，canonical/archive 目标为 2/2，archive format 2 未正式激活；
legacy v1 保持默认 RELEASED。
未引用的 DRAFT 内容错误不应要求加载它；共享 schema 故障仍须拒绝。

当前仍支持的 RELEASED 身份须与其已接纳内容及安装事实一致；保留的真实事实不可重新
解释。这不承诺后续应用继续读取旧存档或旧规则制品。DRAFT 开发安装按
[迁移合同](../../database.md#迁移合同)选择保留数据库并前向演进，或采用新的初始化结构
并在明确授权后重建；观察摘要单独记录，不建立旧草稿兼容版本群。正式作者包、离线安装类
和来源 SQL 不进入 WAR，WAR 只携带当前所需的读取/验证代码及独立批准元数据。

- [作者入口](../../rules/language-author-package.md)：正式作者源含语言及工具熟练目录两分区。
- [来源 schema](../../rule-source-schema.md)与[来源读取](../../rules/source-language-reading.md)：
  独立规则迁移、安装证据和严格来源读取。
- [运行语言快照](../../rules/runtime-language-snapshot.md)：V019 登记、头和语言镜像。
- [工具熟练目录](../../rules/tool-catalog-partition.md)：来源 V002、运行 V020、双领域安装/读取及独立字段/字节核验。
- [链路等价核验](../../rules/language-partition-equivalence.md)：各层字段/字节比较的方法。
- [schema 2 生产制品](../../rules/schema-2-rule-artifacts.md)、[安装与接受](../../rules/schema-2-installation-and-acceptance.md)：独立生产编码、原包保管和来源维护协议。
- [schema 2 来源到运行快照](../../rules/schema-2-runtime-snapshot.md)：接受事实复核、有限 INTERNAL 类型化快照/完整链、原子收据和准确绑定；来源仍从保管原包重读，逐领域来源物理表另行采用。

这些固定身份、schema 1 和 PARTITION 锚点不构成通用组合平台，也不表示全域加载、
第二 JNDI、完整战役组合绑定或新规则默认已经接入。INTERNAL 有限字段的完整链不代表全领域覆盖。
