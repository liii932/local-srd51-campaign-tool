# 时间、日历与可携带的恢复资格

本文是第四阶段的目标时间合同。各空间有独立日历，随自己的逻辑秒推进；后台不产生日界
或黎明事件，切回不补算。跨空间被动后果不推进任何后台时钟或个人经历时间，接纳边界见
[世界与场景](world-and-scene-spaces.md#causal-scope)。这项调度选择不把现实墙钟当游戏时间。

长休间隔和奥术回想按个人经历时间计算，独立于目的空间的自然日。
空间钟、自然日活动账本与黎明消费者分别按[采用边界](adoption-boundaries.md)验收。
规则依据及其中标注的项目解释见[探索语义](../../semantics/srd-5.1/exploration.md)。

## 时钟事实及唯一所有者

| 事实/类型 | 必需字段、来源与 owner |
|---|---|
| `ClockDomain` | 空间稳定 ID、已提交非负整数秒、版本；统一时间服务唯一写入 |
| `CalendarDefinition` | 稳定定义 ID/版本、日长 86400 秒、日历零点、整数日编号、DAWN/DUSK 的日内秒；DM 在建立空间时明确选择。边界为封闭配置，不接脚本或墙钟时区 |
| `CalendarBinding` | 空间到日历定义、calendarEpisode、逻辑零秒对应日历秒；episode 来自该空间建立事实，在空间存续期固定。定义/绑定作为同版业务事实不可改写，显示纪年格式不改变边界 |
| `PersonalTime` | 主体 ID、累计实际经历秒、版本；由所在空间的实际时间增量唯一累加，形态替换/转移/后台被动伤害不增加 |
| `TimeAdvanceIntent` | 准确焦点/代次、time owner 操作身份、增量、参与/受影响主体、活动类型与证据、全部版本；客户端不能提交最终日号、到期集合或跳过清单 |
| `TimeAdvancePlan` | 来源、开始秒、目标秒、已耗前缀、按顺序的边界及依赖闭包、待执行余量、flow 返回点、容量；无 RNG/写入 |
| `TimeAdvanceResult` | 实际前缀、ClockDomain/PersonalTime 变化、已检查/消费的边界、领域后果引用、准确 pending 或完成；结果由共同根提交 |

每次推进至多 86400 秒，长期活动可显式继续多个受验证的段；单段最多 4096 个边界、
4096 个受影响主体和 8192 个后继义务。申请时证明完整日历/活动/效果/休息集合，超限应缩短
尚未接受的时间段或拒绝，不截断已经到达的必要边界。时间只能因真实命令的计划增长，
不能以保存、查询、网络超时或选择等待推进。未知提交沿共同事务查证，不再跑原段。

<a id="calendar-events"></a>
## 自然日、黎明与稳定发生身份

空间日历秒为 `calendarOffset + domainSecond`。日号和日内秒用数学向下取整的除法定义，
可显示不同纪年，消费者只使用规范整数值。每种日历事件的稳定身份为：

`CalendarOccurrence(domainId, calendarEpisode, kind, ordinal)`，其中 kind 恰为
`DAY_END/DAWN/DUSK`，ordinal 为相关日号。`DAY_END(n)` 关闭日 n 的活动；新日 n+1 在同一
边界完成后开始。黎明不默认等于午夜，必须使用定义中的 DAWN 日内秒。

只处理真实推进区间 `(oldSecond,newSecond]` 内到达的边界；起点上已处理的边界不再产生。
每个发生保存计划、原时间证据、完整适用消费者、`PENDING/CONSUMED/SKIPPED` 及原因。
SKIPPED 只适用于具体机制明确许可的不适用结果，不能用它掩盖未知机制或后台补算。
查询消费者使用的边界水位，任何重复请求、文件打开或物件转交均不重置发生身份。

后台日历不发生变化，没有一批等待切回补发的“漏掉的黎明”。同一节点中的两个场景可有
不同当前日历时刻；世界锚点不强迫它们同钟。界面显示时间域，不能把各场景秒相加当世界时刻。

初始/转入消费者只订阅**目的域严格未来**的边界。若转移恰在目的域已提交的黎明秒，须等
下一次黎明，不消费该起点事件。保留历史中的已消费发生 ID 和当前订阅 episode，不用资源
余额推断“是否恢复过”。本合同不提供活动空间的日历改制或更换 episode 命令：不能倒拨
日期、移动黎明时刻或重建绑定制造第二次恢复机会。要建立不同日历须创建有真实新身份的
空间，随后仍按正常转移合同进入；既有物件的消费账本保留，不能补发该空间过去的事件。

<a id="portable-time"></a>
## 各种期限与转移

期限必须选择下列一个基底，不能将同一余量复制为两个可写倒计时。

| `DeadlineBasis` | 唯一计算与转移规则 |
|---|---|
| `DOMAIN_ELAPSED(domain,deadline)` | 固定空间源在该域推进时到期。只有机制允许迁移时，使用 `PortableDeadline` 将源域剩余秒绑定到目的域当前秒 |
| `PERSONAL_ELAPSED(subject,deadline)` | 随主体的累计经历秒到期，转移保留 deadline/累计值。供长休间隔、Divine Intervention、感染进度及本轮可携带效果使用 |
| `TURN_BOUNDARY(context,turn,phase)` | 精确的真实 START/END，不乘六推算；跨模式/空间必须保留同一个 turn 责任或先结清，不凭目标域创建替代 turn |
| `CALENDAR_BOUNDARY(domain,episode,kind,ordinal)` | 消费真实自然日/黎明等发生，移入只订阅未来；过去未消费事件不补发 |
| `UNTIL_FACT` | 如 Glyph 触发/解除，只等真实事实，不分配永久占用 flow 的 timer |

`PortableDeadline` 保存原基底、源域/源时点/剩余秒、迁移操作、目的域/目的时点/新截止、
准确机制政策和原发生游标。交接前已到期的义务在源域处理；交接不重抽潜伏/恢复骰，不
重建效果来源，不清空已消费发生。状态、时间映射、安置、历史和焦点变化同事务提交。

本轮来源的目标选择为：Bardic Inspiration 的十分钟属于受领者 PersonalTime；Bless、
Polymorph、Spirit Guardians、Antimagic Field、Conjure Animals、Warding Bond 的最长
duration 属于施法者 PersonalTime；Glyph 无普通秒期限。专注、死亡、距离或移除仍可按
具体规则提前结束。施法者在后台时这些时长暂停，前台的合法跨空间后果仍可以发生，二者
不互相代替。这是多空间冻结政策的明确含义；不能宣称经过别的空间一小时就使该源到期。

个人期限的休眠/暂停（例如石化暂存疾病进展）记录真实原因集合和剩余进展，仅最后一个
暂停原因消失才在同一个人时间上重绑，不能因普通法术压制推断所有进展都暂停。
活动休息和长施法的已赚信用仍归其领域；时钟交接不自动认定休息完成或补一次工作动作。

<a id="personal-eligibility"></a>
## 个人恢复资格保持既定规则

长休的再次获益门比较同一主体实际经历时间与上次合法完成后的 86400 秒资格。
奥术回想仍以 `floor(experiencedSeconds/86400)` 的个人日及原使用事实判断。
角色移入较早或较晚的空间都不重置这两种资格。它们与自然日活动和物件黎明是不同机制，
不能共享一个 `dailyReset` 布尔值。

疾病潜伏“一天”和 Divine Intervention “等待七天”是经过的时长，分别使用 86400 和
604800 秒，不由午夜提前完成。个人时钟原值、恢复/使用实例、原骰、完成休息事实及
对应期限随完整文件保留。合法施法/特性可以恢复资源时，必须走相应消费者，不改个人钟。

<a id="daily-activity"></a>
## 旅行与食水的自然日账本

`DailyActivityAccount` 归主体活动领域：主体 ID、稳定 accountEpisode、当前归属空间和
日历 episode、将关闭它的 DAY_END、最初日号/全部迁移引用、旅行累计秒、额外小时已结游标、
当日摄入食物/水、热环境事实、食物欠量、食水恢复限制、历史及版本。它不是资源 owner 的
个人日资格，也不能从“推进过时间”反推主体一直在旅行。

`TravelActivity` 输入为明确参加者、路线/段、实际持续秒、DM 计时裁定或已登记旅行机制、
活动/休息分段和环境事实。目标路线可使用 DM 裁定的耗时。地形和遭遇算法分别验收。旅行在源空间结算已耗时间，每个主体只计真实参加的旅行段。

主体跨空间时保持开放账本的**所有累计值和游标**，不结日、不重置、不立即恢复；将其
关闭事件重新绑定到目的空间严格未来的 DAY_END，保留源日号和交接链。这意味着在异步
空间之间旅行的一个开放活动日可能不是 24 个个人经历小时；它在真正遇到下一日界时结束。
这是对独立空间日历的明确接合选择，不暗中把自然日变成个人日或滚动 24 小时。
同行者可以因不同经历拥有不同累计量，不能用队伍的一个小时数替代个人记录。

自然日内累计旅行到 9、10、11……小时的每个额外完整小时末产生一次强行军义务：
`MarchOccurrence(subject,accountEpisode,extraHourOrdinal)`，DC 为 `10+extraHourOrdinal`。
先提交当前时间/活动前缀并使用该时点的完整能力/力竭，再经 CheckStage 作 CON 豁免；
失败添加有该发生来源的一实际力竭等级。不同小时按顺序结算，前一次到达力竭 3 会影响
下一次豁免；不以出发时的状态批量算所有骰。未满额外一整小时不补一个检定。

同一时点恰为额外小时末及 DAY_END 时，先结该小时，再关闭旧日。下一日新账本旅行量为
0，原欠粮/力竭实例不因此消失。迁移不重置额外小时游标；重新经过原节点也不重掷已结小时。

食物单位为 1/1000 磅，水为 1/1000 加仑，均用非负整数；欠粮用千分之一日的精确整数
累计。摄入由真实库存消费/已登记获得事实或类型化 DM 摄入裁定产生，不能让客户端直接
写“已满足恢复”。正常食物需求 1000 单位，水 1000；本日有已证明热环境段时水需求为
2000。热环境混合日取较高需求是本合同的明确项目解释，不由保存时天气反算旧日。

在 DAY_END，按以下固定顺序提交有界营养计划，使用该时点真实 CON 与力竭：

1. 食物达到 1000 清零欠粮；否则增加 `1000-min(food,1000)`。欠粮超过
   `1000*max(1,3+CON modifier)` 时产生一级食物来源力竭，无骰；等于阈值不加。
2. 水达到需求不加；至少一半但不足全部，以 CON DC 15 检定；低于一半不掷骰直接适用。
   需要加级时，当前无力竭加 1，已有任意力竭加 2。食物先于水的同日顺序是项目解释。
3. 保存逐来源的实际加级及欠量，再结束旧账本并建立下一日空摄入/旅行账本。

原语义对非整份食物的比例解释和至少半份水的解释保持不变。食水来源力竭在足量吃喝前
禁止减除；足量摄入只解除该恢复限制，本身不自动减级。允许减除的机制仍由效果/休息
owner 按[疾病与力竭合同](ongoing-effect-protocol.md)执行，保留具体来源归属。
完成休息读取本次实际摄入证明，不因 DAY_END 清空视图而丢掉资格证据。

<a id="item-boundaries"></a>
## 物件黎明与关系计时

黎明恢复属于**物件实例**及其实际安置时间域，与持有人个人日、施法者的日历或显示场景
无关。装在容器/被持有时从唯一安置父链派生时间域，未安置物件不得开始需要日历的活动。
转交或迁移保存余额、同调、毁坏和全部已消费发生；未来 DAWN 到来时仅对仍存在且拥有
该机制的物件执行一次有上限的恢复。不能把转交做成新建同名满充能实例。

`CalendarOccurrence` 是恢复 producer，物件 owner 使用
`(objectId,mechanismId,occurrenceId)` 唯一消费身份。掷骰、恢复前后余额、上限截断、原骰及
对象版本共同提交；损毁者合法不适用并留原因，不重新生成物件。多个持有人收到同一
黎明通知也只存在一个消费者。

同调离身的 24 小时是关系持续时长，不是黎明：`SeparationTimer` 由同调 owner 管理，
固定以同调主体 PersonalTime 计时。空间证明相距超过 100 尺时记录该主体当前累计值；
持续超距至 +86400 时结束同调，回到不超过 100 尺立即清除这次连续计时。
后台主体不增加该计时，即使物件所在前台经过一天。任何一端移动都重新证明关系，
UNKNOWN 不能自动当 FAR 或 NEAR；会使已存在关系无法判定的空间变更在接纳时拒绝。

<a id="boundary-order"></a>
## 同时边界、暂停继续与共同保存

时间服务只负责已证明的边界调度和单调前缀，语义由具体 owner 解释。一次推进采用：

1. 无骰预检完整可能后果、目标、库存/资源、版本及余量，建立按业务截止秒排序的边界集。
2. 到下一边界时，所到秒、PersonalTime 前缀、该时刻完整 occurrence 及待履行义务集须同
   事务保存；不能只提交时钟，恢复后再靠 `(old,new]` 猜应发生的事件。在同一因果阶段先处理真实到期、原因变化和
   症状 onset，再处理活动段末（含强行军/合法休息）、DAY_END，最后同刻 DAWN/DUSK。
   同类独立发生按稳定 owner/来源 ID 排序；有明确规则依赖的按依赖图先后，而非请求到达顺序。
3. 每项领域计划按真实阶段共同提交。需要 d20 掷后选择、生命骰逐颗选择、DM 裁定或反应时
   保存已消费前缀、原骰、当前边界和未决余集，停止推进后续秒，不持锁等用户。
4. 当前必需义务全部终结后才继续时间后缀。日历边界即使已被调度也不能只标 CONSUMED 而
   丢失尚未完成的物件恢复/营养结果。相同 occurrence 的父请求重复不创建第二个子计划。

合法休息与疾病的局部顺序由休息/疾病合同规定：本次治疗资格快照、疾病豁免及独立恢复
不是时间服务另算的一套 HP。没有经过合法休息活动，任意八小时推进不能制造休息完成。
Spirit Guardians 等在探索中的真实 turn 责任由效果合同的 `TemporalTurnContext` 提供；
时间服务推进其准确六秒段/边界，不能独立伪造 START 或给参与者刷新动作。

文件与历史一同保存：日历定义/episode、全部空间秒、PersonalTime、开放自然日账本、
摄入/活动证据、期限唯一基底/转移链、日界/黎明发生、逐机制消费账本、时间前缀/余量和
当前 scope/flow 叶子。直接恢复验证边界顺序和实际消费，不跑边界、不重新抽潜伏/充能骰。
错误的日号、遗漏消费者、重复消费、来源不匹配或历史前后断裂均拒绝整份状态。

预检失败零 RNG/写入，已经接受的过去段不因新后缀非法而倒退。任一阶段落库失败回滚
该阶段全部时钟/状态/历史/收据；已提交响应失败按原收据返回。过期焦点或版本不消费新
边界；保存和重新打开不会把一次未决 DAWN 当成一次新的黎明。

## 复验向量

| 场景 | 必须得到的纸面结果 |
|---|---|
| V11 旅行 9/10 小时 | 第九小时 DC 11，A 从力竭 2 失败至 3；第十小时 DC 12 使用当前劣势，失败至 4；B 分别 11/12 成功 |
| 欠粮和缺水 | CON +0，六个半份日欠粮恰为 3 日不加级，第七日超过；热日喝 1 加仑走 DC 15，少于 1 加仑无骰，已有力竭则加 2 |
| 转移日历 | A 处于旧日旅行 8 小时、摄入半份，转入较晚域后值不变；只在目标的下一真实 DAY_END 关闭该账本，不补过去的日界 |
| V13 黎明 | 原物件余额 4，d6=5 只恢复到 7；转交、重复请求、恢复后仍是同一个已消费发生；已毁物件不复活 |
| 背景及跨空间被动伤害 | 背景日号、秒和 PersonalTime 不变，即使 HP/专注在获准因果 scope 中变化；切回不产生补偿时长或黎明 |
| V12/V15 | 潜伏两天仍为 172800 实际秒，七天等待仍为 604800；迁移或跨午夜不提前完成 |
| 故障与未决恢复 | 充能/强行军选择中保存原骰及边界，直接恢复零新增 RNG；当前阶段后端任意写失败不留下单独时钟或资源变化 |

完整旧/新结论及程序证据见[行为复验](rule-behavior-interface-validation.md)。本表不是已运行测试。
