# v2 采用边界

本文连接当前实现与 [v2 设计基线](README.md)。它记录稳定的差异、前置条件和暂缓范围，
不记录某次测试计数、数据库迁移成功或部署状态，不替代 GitHub 的实施任务。
模组组合、接受资格、摘要、初始化与存档绑定的**公共合同已确定**，统一见
[模组接口基线](module-interface-baseline.md)；下表区分当前实现与尚待逐领域规格或实施的采用条件。

## 当前实现与目标的区别

| 主题 | 当前仓库依据 | v2 目标与采用条件 |
|---|---|---|

| 发布资格 | built-in 注册表与独立批准值保持；[schema 2 离线流程](../../rules/schema-2-installation-and-acceptance.md)分别保存安装和显式接受事实，绑定准确审阅材料并支持原操作查证 | 接受不补足机制支持、基础完整性或运行装配；真实 MySQL 权限、事务与隔离验收及对应来源的本地接受仍是独立检查点 |

表中的“已有”指仓库交付边界，不证明测试本次运行、迁移实际执行或功能已部署。

成长、资源与标准休息具有内部作者、来源、运行镜像、真实状态/历史和直接恢复链路。
这一内部能力及有界战斗与语言/工具 PARTITION 都不能代替全域必需目录、交叉引用、COMPLETE
校验或完整生命周期。未具备相应消费者的效果、健康转换和环境义务仍拒绝；不能据此开放
完整新运行、Host 入口或完整战役文件。

## 采用顺序

1. 以公共模组接口基线统一目标入口，明确已定合同、v1、内部 DRAFT 与尚待实施的新模型边界。
2. 复用语言作者、安装和两侧存储链路，逐领域补足作者 schema、领域表、快照及独立投影。
   同步采用组合、接受记录及完整覆盖链合同；纯模型已归入 `module` 并由真实消费者共用，
   不复制兼容模型。
3. 完成外层装配、诊断和准备/执行能力分离；新旧写入口先共享接纳、版本和故障边界。
   在完整初始化材料未具备前，可以验证内部组件，但新运行入口保持关闭。
4. 按机制接入责任清单迁移角色/成长/资源及其余领域，为每个机制给出责任落点、真实消费者
   和验证证据；不能只替换 Servlet 的 loader 而遗漏 JDBC 内的规则 JOIN。
5. 汇总完整文件、直接恢复、结束保存/清理/修复、权限、容量和故障恢复验收。
6. 跨领域候选通过后，分别执行规则发布、数据库迁移/授权、应用部署和默认采用检查点。

这是依赖顺序，不要求每层所有未来能力先做完，也不授权创建空表/空接口。任务拆分应使每个
采用结果可以独立验证；新旧混合阶段要明确仍依赖旧库的路径，不能宣称整个应用已完成拆分。

## 未完成与暂缓边界

以下边界仍阻止相应能力，不因记录设计而关闭：

- schema 2 的有限作者读取、纯组合、生产制品和安装/接受链路分别有明确合同；局部投影通过
  仍须拒绝作为不完整 `base` 接纳。有限 INTERNAL 快照已接通来源重读、类型化存储与完整链；
  初始语言／工具授予已接入真实角色来源、稳定槽以及同事务保存和读回的准备计划。其余领域作者类型、完整基础及机制接入、
  其余来源表、业务快照、完整组合规则包及业务存档
  仍须实施。局部链路证据不代替真实 MySQL、内容接受
  或运行验收，不能沿用 schema 1 的 PARTITION 事实宣称组合通过。
- 完整初始/当前角色、装备/冒险、战斗/效果、法术、怪物/魔法物品及各历史类型的准确字段、
  引用、执行/恢复和独立覆盖尚须完成；语言或 NOTE 分区不能构成可运行的完整文件。
- 共同守卫已接入当前写入口；真实 MySQL 锁/触发器、授权与连接池隔离验收、完整删除图和运行清理仍须完成。
- 动作暂停与继续的公共协议已确定；具体反应与选择仍须证明完整候选、真实触发、父阶段
  重验、一次消费及恢复闭包。协议本身不扩大上表已接入的有限机会攻击、Ready、Shield、Counterspell 范围；其他
  效果仍须独立接合，持续效果生命周期按其正式协议采用，多目标豁免伤害按其具体合同采用。
- 持续效果的公共生命周期已确定；各机制的同组比较、目标级结束、压制计时、贡献转换与
  一次性后果仍需准确登记和实际验收。法术全文、条件枚举或一个持续效果头不能替代这些
  责任；上表固定 DM 区域的内部采用不开放 Antimagic Field、驱散、毒病或所有持续法术。
- 多目标豁免伤害已以地狱猎犬吐息完成公共接口的具体设计推演；区域完整性证明、真实
  CheckPlan/DamagePacket 消费者、动作与充能、反应及专注闭包、存储/恢复和故障验收仍须
  实施。其他伤害机制须另行登记，不因共享核存在就自动获得支持。
- 候选、最终档、长期技术事实、规则加载及解析/编码的物理容量和长期增长须有实际证据；
  设计预算和历史测试记录不能代替验收。
- 首次新建 v2 战役、角色作者输入白名单、编辑器及动态角色接纳暂缓；不以空战役绕过。
- 冒险内容包/业务包的领域协议、未知机制/效果的支持、旧战役升级及多实例接管另行设计；
  已确定的扩展与兼容模组公共合同按基线采用，不因此重新列为未决方向。
- 存档/规则/应用的独立制品保管、数据库回退后的身份连续性和实际恢复工具仍须落实。

## 验证与发布

每个实现切片使用相关定向测试，覆盖正常、边界、坏规则、跨运行串用、过期版本、幂等、
事务失败和禁止部分写入。来源、运行镜像与文件必须有独立字段/字节期望；仅自洽往返不足。
真实约束、权限、锁与连接语义需要隔离 MySQL 验收。全量测试、打包/WAR 审计及发布检查点
按[测试指南](../../testing.md)与[完整规则门](../../rules/srd-5.1-complete.md)执行。

保护 legacy v1 的行为、身份、摘要、算法与格式 1；已应用迁移只能追加。发现确需保留的
真实 DRAFT 数据时先明确迁移要求，不默认丢弃或引入全面兼容。旧类名、旧 DRAFT profile
和旧 codec 形状本身不构成永久承诺。
