# v2 采用边界

本文把当前源码和领域合同连接到[完整战役文件](save-and-recovery.md)、
[私有运行库](rule-storage-and-versioning.md)及[运行生命周期](runtime-and-transactions.md)。
选定目标是每次打开战役建立私有 SQLite 运行空间，以单个完整 JSON 交付可移植保存点；
它替换共享 MySQL 业务工作集和数据库档案字节区的目标方案。当前代码仍使用 MySQL，
未实现 SQLite、完整战役初始化、完整文件或该生命周期，不因本文修订取得执行资格。

这些选择可按需求与证据修订。原型只支持当前应用声明的模型与协议，不承诺跨版本读取；
仍受支持的当前路径须维持事实解释、准确规则绑定、原子提交和恢复一致性。
表中“替换／删除”指采用时协调修改合同、代码及测试，不授权清除真实数据或改写迁移历史。

## 依赖顺序与验收门

1. **先固定字段和支持闭包。** 按当前生产 owner 盘点 v1 与 INTERNAL 的全部持久字段、
   根/子历史、业务因果和 pending，映射到完整文件分区及封闭存储模块；同步公共创建输入。
   **门：** 每个字段有保存、无副作用推导或明确排除依据，跨域引用无缺口；业务键不会随
   请求收据排除而丢失；空分区不能掩盖未实现消费者。此门不扩大机制或发布资格。
2. **实现私有 SQLite 存储与所有权。** 交付驱动、固定 SQL 模块、初始化/存储协议、受控
   目录及排他锁，按规则、历史和待办依赖闭包装配。来源原包/接受账本保持独立，索引职责
   与来源 reader 协调改变。**门：** 真 SQLite JDBC 验证事务、外键、数值/Unicode、单写入者、
   锁/超时、热 journal 及所选耐久配置；持久 C0、业务提交和未提交控制裁定可分别查证，
   不得宣称现有 MySQL 迁移或代理连接已覆盖这些语义。
3. **统一战役初始化及状态根。** 替换多个单角色 run，建立同一 run/snapshot 的初始/当前
   角色、准确规则/链、统一时钟、事件根和全部必需域；新建与文件恢复共享完整计划验证。
   **门：** 全闭包一个事务建立并实际全量读回；失败无可执行半初始化，仍待首份可靠完整
   检查点前不开放游戏写入。编辑器、创建适配器和 Host 不能用授予计划替代此门。
4. **逐机制接合真实消费者。** 保持现有有限支持范围，把成长/资源/装备/健康、场景/战斗、
   施法/怪物、动作流/效果接到统一根和事务，不只替换 Servlet loader 而遗漏 JDBC 规则 JOIN。
   **门：** 依责任清单验证原输入、成本、随机、状态/历史、因果和终结后缀；未知机制、缺
   owner、坏冻结材料或不完整 pending 先拒绝。局部采用不授予完整 base/文件资格。
5. **实现完整文件、直接恢复及可靠保存。** 使用同一字段清单完成 writer/reader、规范编码、
   严格无副作用恢复计划与新运行读回，接入 P0—P3 和首份检查点、手动/AUTO/FINAL。
   **门：** 独立字段/字节期望覆盖初始/当前差异、全历史及复杂 pending；恢复不掷骰/扣费/
   发效果；P2/P3 分离故障可查证，已发布文件不因 DB 结果未知被删除，旧好档不丢。
6. **完成同版重启、结束与空间释放。** 识别残留并由引擎恢复，查证原意图后完整校验；
   明确接合继续原 run 的新安全代次、救援保存、精确放弃及封存目录清理。
   **门：** 对每个提交和文件窗口注入进程终止、响应丢失、I/O/关闭/改名/部分删除失败；
   不重做已接受动作，不自动接管执行，不跨目录删除，封存或墓碑绝不恢复游戏。
7. **完成容量与开放检查点。** 用最坏规则闭包、全部历史、最长合法继续/结束后缀测得有限
   发布参数，证明来源断开时可继续/保存，接合 UI/Host 的拒绝、保存屏障和恢复反馈。
   **门：** 真实 SQLite 与目标操作系统/文件系统证据、全域字段恢复及完整规则门均具备后，
   才可开放相应能力；规则发布、MySQL 迁移/授权、应用部署和默认切换仍各自独立授权。

每一步可拆成可独立验证的切片，但不能靠预建空表/空接口通过验收。新旧混合期明确每个
入口仍依赖的 MySQL/内部模型；完成某层不表示整个应用已替换，也不要求先实现所有未来
法术才能验证已选机制。未落地结构不预留迁移编号。

## 未完成与暂缓范围

上述完整文件、新建公共输入、私有运行库及恢复生命周期已选择合同，具体实现和全域
字段适配仍待交付；不能继续把这些公共责任列成无合同的远期方向。新建编辑器、动态
角色接纳、通用冒险/内容包协议和未登记机制仍按产品范围分别接入。多实例接管、玩家
账号、LAN/公开入口及跨应用版本存档延续不由本次设计取得资格。

原始规则 ZIP、JSON、准确应用及来源安装/接受账本的独立保管和实际恢复工具仍需落实；
不能从旧文件重建未保存提交，也不能从规则包重建业务进度。容量参数及保留策略须有
实际测量，不能以旧设计预算、历史测试计数或“往返相等”作为完整恢复证据。

## 验证与外部检查点

实现切片使用相关定向测试，覆盖正常、边界、坏规则、跨运行引用、过期版本、幂等、事务
故障及禁止部分写入；来源/镜像/文件必须有独立字段与字节期望。现有
`Schema2SnapshotTransferServiceTest`、`Schema2InitializationPreparationServiceTest`、
`Schema2CharacterRuntimeServiceTest`、`Schema2CombatRuntimeServiceTest` 及各机制测试提供
当前有限边界的定位；`CampaignArchiveExportServiceTest` 与 `CampaignArchiveCapabilityBoundaryTest`
用于定位现行投影/入口限制，不证明新完整文件、SQLite 或生命周期已实现。

纯文档变更不运行 Maven。实现验证、全量测试及需要时的打包/WAR 审计按
[测试指南](../../testing.md)选择；完整规则开放另按[完整规则门](../../rules/srd-5.1-complete.md)。
现有 MySQL 的真实约束、权限、锁与连接池隔离仍须其自身验收；未来 SQLite JDBC、目标
文件系统的耐久/改名/句柄与低磁盘测试是新增验收，不能互相代替。

保留现有数据库时遵守[迁移合同](../../database.md#迁移合同)并使用前向迁移；选择新初始化
结构也须在明确授权后处理真实数据，不改既有 checksum、不因私有运行目标自动删除旧库。
设计修订、规则安装/接受、迁移/授权、备份/恢复、应用部署及默认发布切换分别判断；
普通启动不执行这些外部写操作。单个 WAR 或文档变更不构成任何外部检查点的完成证据。
