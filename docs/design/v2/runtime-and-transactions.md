# v2 运行、事务与执行资格

状态：组件及跨领域协议已确定；共同写入守卫已采用，初始计划持久化、完整业务装配和执行资格尚待采用。
本文件描述新 v2，不能直接套用到现行 v1 重启或事务实现。
准确有序组合、接受资格与固定规则材料按[模组接口基线](module-interface-baseline.md)。
现有[内部快照链路](../../rules/schema-2-runtime-snapshot.md)已采用来源关闭后转存、完整规则/链
读回、原子收据及有限查证；材料守卫位于全部业务写入口共用的
[业务事务边界](../../rules/business-write-transactions.md)之内。初始授予计划仍为只读材料，
计划持久化与完整业务/历史初始化尚待采用；现有链路不发布游戏执行视图。

## 组件责任

保持单 Maven WAR 和现有职责根包。规则纯模型、验证及 canonical 属于 `module`；纯业务
计算与协调 Service 分开；JDBC 负责准确存储；`web` 负责装配和 HTTP 适配。包内划分随真实
消费者逐步形成，不先建立空框架，也不复制第二份同形目录模型。

Service 拥有运行事务，Repository 接受调用方连接，不自行提交、回滚、关闭或另开写连接。
文件 codec 只解析、编码和产生无副作用恢复计划；保存协调、档案存储和规则读取能力分离。
Servlet 不自行构造目录仓储；普通运行消费者不能取得来源连接或上下文发布能力。

## 准备、初始化与执行

1. **准备与组合检查**：核验应用支持边界和两侧 schema；工具健康且真正空闲时，可选择
   一个完整基础模组及零到多个扩展/兼容模组的准确版本和加载顺序。按该组合核验来源、
   接受资格及全部必需目录，在同连接、只读 `REPEATABLE_READ` 事务中完整读取来源。
   成功后的不可变准备材料和检查结果不创建工作集或运行快照，不授予执行资格。
2. **首次初始化复核**：严格验证开始或恢复输入，再全量读取并核对来源、安装/接受事实
   和准确组合。正常结束来源事务并关闭连接，形成仅供本次使用的固定输入；随后重建并
   验证最终规则与完整覆盖链、完成业务计划，再进入运行事务。不能只比较头摘要、代次
   或沿用旧检查报告。
3. **运行原子写入**：重新核对空闲、幂等、安全代次和容量，在一个运行事务保存新身份、
   准确组合绑定、完整最终规则、完整覆盖链、业务/历史、控制、预算和接受结果。它们绑定
   同一 `snapshot_id`；实际读回核验完整内容、链的最终值及其来源身份和加载顺序。
4. **提交后发布**：仅明确提交成功后发布本进程本次运行的执行视图。事务内候选不公开，
   不能只给启动目录贴上新 run ID 代替运行镜像读回。

准备视图没有活动战役，执行视图绑定 run/snapshot/campaign、准确组合和本进程初始化事实。
目录可保持不可变，但执行资格仍随守卫变化；一次只读就绪结果不能成为永久执行令牌。
可变业务状态和版本始终从运行数据库读取。

## 共同接纳与事务

目标使用进程内有界生命周期读写门和永久数据库单例守卫。先取得进程门，再借运行连接并
锁数据库守卫；禁止持数据库锁等待进程门或浏览器。来源复核完成并关闭连接后才进入运行
写事务，不做跨库提交。

新模型写入与提交查证采用 `READ_COMMITTED`，第一个业务 SQL 排他锁定永久守卫。后续
按固定层次取得容量、请求结果、运行身份/预留、档案组、结束记录、候选/文件、工作集/快照/
事件尾、角色及领域叶子锁。层内按准确主键顺序锁定，不把 SQL `ORDER BY` 当作锁顺序证明。
插入按父先子后，删除按完整引用图子先父后；缺领域锁或清理清单时拒绝相应能力。

完整目标、规则、乐观版本、幂等、容量与领域条件在随机性和写入前验证。一个游戏命令一个
短事务；玩家步骤或回合包含多个命令，不持锁等待整步完成。相同请求只返回原接受事实，
相同键不同意图冲突，不重新掷骰或授予当前步骤写入资格。

新旧写路径必须先共享接纳边界，才能开放新初始化；旧活动战役阻止新运行，不用新结束
协议清理旧 v1。双进程接管或租约不在范围，不能把“单 DM”当作缺失并发防线的理由。

## 动作暂停与继续

攻击、移动、施法、反应及其必需选择共用[动作继续协议](action-continuation-protocol.md)。
动作流负责唯一执行位置与父子关系，各领域继续拥有资源、位置、骰子和效果事实；不得
另建可独立推进的施法栈、移动栈或选择栈。暂停是完整提交的业务状态，不是悬挂事务。

每次继续仍走共同守卫，仅当前合法阶段允许的命令可写；窗口关闭但尚未恢复父阶段时，
不能开放普通游戏写入。已接受事实重放与当前可操作视图分开，重放不推进动作流。
反应引起的权威状态变化在继续点按登记合同重验，保留已发生的消耗、骰子和移动前缀。
生命周期限制优先于动作流：自动保存暂停、提交未决或重启残留不能凭 pending 获得执行资格。
重启后沿既定救援 END 与独立恢复流程保留中途状态，不直接重启动作执行器。

持续效果的状态变化遵循[持续效果协议](ongoing-effect-protocol.md)：在同一共同守卫下
先验证完整来源、目标、压制原因、贡献依赖和后继消费者，再原子保存本次状态、派生变化、
历史、版本与待结义务。需要反应或选择时，使用同一动作流的 `ONGOING_EFFECT_TRANSITION`
帧及准确父继续点；稳定存续的效果不长期占用动作流。查询不能顺带到期、解除压制或补回调，
缺失消费者不能以“无贡献”掩盖。

## 提交结果与未知查证

| 证据 | 结果与动作 |
|---|---|
| 未调用 commit，完整 rollback 明确成功 | 本次回滚，不留部分结果 |
| commit 明确成功，随后归还连接或发送响应失败 | 保留已提交事实，不能报告回滚或重执行 |
| commit 响应不明，或 rollback 失败 | 保持未决并使相应执行资格失效，禁止新写 |

故障连接须经验证的池失效能力隔离；未知时不能 `setAutoCommit(true)` 或当健康连接归还。
`close()`、网络超时、普通空查询或事后 rollback 都不能单独证明原事务未提交。

查证先隔离原执行者，另借健康连接开启新事务，锁同一个永久守卫，核对精确操作身份、
结果、工作集、字节/代次和计费闭包。查证只读，不补结果、不重试命令、不自动清理。
无法形成完整已决证据就保持阻断。曾因未决失效的执行视图不自动恢复游戏资格。

## 生命周期与故障

| 状态 | 允许的目标行为 |
|---|---|
| 健康且真正空闲 | 可重新选择并检查准确组合，无需仅因更换组合重启；准备合格后可开始完整初始化 |
| 本进程活动运行 | 使用可信执行视图和本地状态执行命令 |
| 自动保存暂停 | 查阅、获准保存重试或显式结束，拒绝全部新游戏写入 |
| 重启/资格失效残留 | 核验并救援保存结束，不自动继续游戏 |
| 最终保存已接受、清理未完成 | 核验、准确继续清理或修复，拒绝游戏写入 |
| 提交未决 | 查证；不猜测成功、回滚或空闲 |

生命周期由守卫、收据、工作集和结束事实推导，不另存可相互矛盾的 READY/UNCERTAIN 状态。
未决提交、运行残留或结束清理未完成均不属于可重选组合的空闲；活动运行及存档恢复固定
其原准确组合，不能借组合选择更换版本、顺序或原包。
启动只识别残留，不激活旧执行视图；GET、诊断、下载及停机不会初始化、自动保存或结束。

没有可信准备材料、完整性失效或无法安全归因的基础设施故障时，WebApp 可以启动，但
Host 页面/API 在既有安全边界之后稳定返回 503。`/health` 不是规则就绪证明。
尚未导入属于正常空闲，不因缺活动快照封锁加载入口；坏输入只拒绝该输入。

本进程已经合格的活动运行若仅来源库不可达，而本地快照、执行视图、应用和运行库健康，
可继续/保存/结束本次运行，但关闭新的初始化。完整性故障、自动保存暂停或未决守卫仍优先。
故障修复后仍通过受控重启重新准备，不由 GET 或重试恢复执行资格。正常结束且清理完成、
达到健康空闲后，可以重新选择组合并以新身份初始化；这不开放尚未完成的新战役入口。
