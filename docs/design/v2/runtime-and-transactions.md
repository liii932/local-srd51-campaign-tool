# v2 运行、事务与执行资格

本文规定当前有限 SQLite 战役的生命周期与共同事务选择。实际范围以
[领域接合表](domain-integration.md)及[运行合同](../../storage-vitality-loop.md)为准；
源码、测试方法、实际测试结果、真实部署和完整 SRD 发布各是不同证据。
当前不采用独立 C0 接纳事务或周期 AUTO 作为运行前提；相关取舍在本文及
[步骤与自动保存](player-steps-and-auto-save.md)完整说明。

## 单一运行权威与组件责任

新建/文件打开建立新私有目录和 SQLite 库；同版显式恢复才复用原库。准确 material/完整
字段链、初始/当前角色、全部根/子历史、场景/动作/效果/怪物与 pending，以及本地请求/
保存控制在同库。来源 MySQL、浏览器、旧文件和 JVM 缓存不能并行修改或补造事实。
当前规则由四个内置生产包提供，打开和恢复无需来源 MySQL 在线。

`CampaignDomainEngine` 不借连接，复用现有纯规则做预检、执行与完整历史验证。
`CampaignDomainData` 和严格 typed codec 保存领域聚合；`CampaignDomainRepository`
在调用方连接中写聚合和关系投影，不能提交、回滚或另开写连接。资源/装备等投影必须与
所属角色/场景聚合逐行相等，不能独立成为第二写 owner。Servlet 不处理 SQL 或路径。

物理本地 run、epoch、Host revision 和请求收据不进文件。schema-2 prepared Identity、
事件 operation 和版本若参与已记录业务/因果关系，则保持原值随初始/当前/历史保存。
它们不成为恢复后的 HTTP 权限；不得把字段名含 run/snapshot 的业务引用误删或重新分配。
身份和具体 owner 见[角色与历史](character-state-and-history.md)。

[局域网玩家原型](player-participation.md)复用一个运行权威和串行写门。读取先检查
当前成员与共享权限；游戏写在同一接纳/事务范围复核玩家身份、PC 控制和版本，撤权或
控制转移与并发命令形成确定顺序。加入申请和待 DM 裁定的提案不代表业务命令已接受，
也不成为断线重放队列。`PlayerGatewayService` 在存储 monitor 中处理授权与投影，
actor-aware `domainCommand` 在同一业务事务、收据查询及 RNG 之前再次调用授权守卫。
运行私有已发送关联只服务于精确只读查证，不授予接纳资格或在恢复时执行命令。

## 准备、初始化与执行

1. 健康空闲时验证准确应用规则选择及新建/文件输入。当前有限新建允许完整受支持 profile
   的空队伍起点，随后在时间零点创建初始角色；不能用空集合掩盖该 profile 必需实现。
   未来任意加入等级、玩家名单/步骤及自定义包另按各自合同采用。
2. 生产 reader/compose 验证本版四包并建立固定投影。文件读取将完整 members/rules/
   entries/chains 逐项精确比对此投影，复用其已验证的 composition/final/chain 指纹；
   不逐次重新组合，不换规则解释旧历史，也不执行来源安装或接受事务。
3. `StoragePlan` 按应用声明和所选 profile 求全部未来写入/历史/pending 闭包，无目录、
   数据库或 RNG 副作用。完整预检后取得实例及新目录独占权，以原子创建的准备目录名绑定
   runId、原输入摘要/长度及计划摘要；先发布完整原输入/分配材料，再转入正式运行目录。
   `.part` 是准备阶段的有界未完成槽，未知文件与身份不符不能作为可丢弃前缀。
4. 一个初始化事务建立 DDL/索引、静态 seed、完整固定规则、业务/历史与本地控制。
   文件打开直接装载已验证事实，不执行 INITIALIZED、掷骰、授予、休息或重放旧命令。
5. commit 后从新健康连接核实际结构、seed、固定规则、全部事实/投影/历史及控制；
   缺表、坏投影或规则/计划不符保留阻断，不用补表/重新 seed/补数据修好。
6. 首份完整文件按 P0—P3 发布并接受后才开放当前 epoch 的游戏写入。输入文件已经存在
   不代替该新运行的首份检查点，提交前内存候选或摘要相同也不代替完整读回。

初始化随机创建仅在未来对应创建消费者明确支持时采用，不能放入 seed/DDL 默认值；
当前标准数组初始化无 RNG。初始化结果未知不换身份、目录、规则或请求重新生成。

## 共同接纳与业务事务

一个服务实例持受控根操作系统锁，并以串行接纳门管理唯一活动运行/保存过程。原目录
所有权先于连接取得；`BEGIN IMMEDIATE` 的有界写争用发生在真实 RNG/写入前。不移植
MySQL `FOR UPDATE`、行锁层级或隔离级别，不跨浏览器等待或文件 I/O 持业务事务。

每个连接配置并读回 DELETE journal、EXTRA、外键 ON、UTF-8 与有界 busy timeout。
引擎负责热 journal 恢复，应用不得删 journal 制造空闲。平台锁、刷盘和断电耐久仍需
真实驱动/文件系统验证；这些设置不是平台测试结果。

业务事务中的顺序为：

```text
读取并验证完整源/规则/全部历史及关系投影
  → 当前 epoch、准确请求意图、幂等、revision/目标版本与领域计数容量
  → 全部目标/候选/两分支后果/继续义务预检
  → 服务端 RNG 和纯领域后果
  → 完整候选验证与文件字节上限核验（超界不写领域事实）
  → 全部领域聚合/投影、根子历史、版本、接受结果共同写入
  → 独立读回一致 → COMMIT → 发布已提交结果
```

一次成功新业务提交推进本地 revision，失败、GET、精确重放和保存控制不推进。
相同键同意图返回原接受事实，不重掷、不扣费、不执行父继续；相同键不同意图冲突。
旧 epoch 先拒绝，即使请求键曾被使用也不恢复当前写资格。调用方叶仓储无独立事务。

检定的成功/失败分支效果都须在真实骰前完整预检。已接入的 check-effects 入口把健康规则、
物品变化、节点位置、消息和检定子历史归同一根/事务；实现与验收入口见
`CampaignDomainCommands`、`CampaignCheckEffectsTest` 及共享 SQLite 域测试。测试类存在
不代表本次通过。DM-managed 自由卡/MANUAL 等旧能力的独立 typed 接合状态以接合表为准，
不得用自由字段修改 schema-2 规则角色的权威状态。

## 提交结果与持久查证

当前采用**独占实例/目录 + 单个业务/根/接受事务**。不在业务前另提交 C0，不在明确回滚后
另写 NOT_COMMITTED 控制裁定，也不持久化另一份尚未接受的游戏意图作为重放队列。

| 观察 | 处理 |
|---|---|
| RNG/写入前校验拒绝 | 无业务/根/接受写入，不推进版本 |
| 业务失败且 ROLLBACK 明确成功 | 完整事务未接受；保留原已提交源，不自动重试命令或倒退随机源 |
| COMMIT 明确成功，响应丢失 | 原根/子历史、状态和接受收据一起保留；只返回原事实，不重做 |
| COMMIT 响应未知、ROLLBACK 失败或可疑连接关闭失败 | 撤销当前写资格，保持 UNKNOWN；不能当作已回滚或用新请求绕过 |

显式 recover 首先隔离旧执行者、取得原根/目录独占权，让 SQLite 完成引擎恢复，再由新
健康连接核模型/计划/真实结构、固定规则、全部聚合/投影/根子历史、命令与保存收据。
已提交事务必须呈现完整接受结果及对应完整事实；任何部分状态、不完整收据或无法解释
的因果图属于完整性失败，保留并拒绝，不凭空生成接受结果。

没有接受收据时，不把普通空查询当作某个未持久意图的 NOT_COMMITTED 证明，也不恢复
旧请求的执行权限。完整库健康且旧执行者已隔离后，受保护恢复控制提交新 epoch，才可
重新接纳用户明确发出的命令；恢复过程本身不重播请求、不重掷、不补授予或自动继续叶子。
原 HTTP 上下文丢失时先查询实际状态/已接受结果，不能根据页面超时推断业务没发生。

这是当前单实例模型的选择，替换独立 C0/裁定方案；若将来引入异步命令队列或多实例接管，
必须重新设计其持久意图、隔离与归因合同，不能假定当前协议已覆盖这些新运行方式。
保存意图 P0 与业务 C0 是不同职责：P0 仍须持久固定文件发布的源、fileKey 与预期字节。

## 动作暂停、效果与时间

动作沿[唯一继续协议](action-continuation-protocol.md)保存父子帧、原骰、已付成本、窗口/
机会/决定和唯一待继续叶子。窗口关闭但父阶段未继续时仍有义务；继续在当前 epoch 和
版本下重新预检。保存、查询、END 或恢复不得隐含 PASS、继续、停止专注或结算剧情。

角色时钟由 `CampaignDomainEngine` 在同根后果中协调；持久化的各角色时间是受验证的
一致事实，不能独立漂移或由墙钟补进度。场景/战斗使用同一时间契约。持续效果保留来源、
目标、期限、全部压制原因与被引用的已结束实例；无贡献不等于可删除或跳过回调。

## 生命周期与恢复

状态来自库/目录事实与本进程资格：空闲、PREPARING、ACTIVE、阻断/RESIDUAL、SEALED。
当前阻断包含初始化/保存未完成、UNKNOWN、完整性错误与重启残留；没有周期 AUTO 状态。
所有实际阻断消除前不发布写资格。封存、放弃或清理标记优先，不得重新激活。

| 入口/转换 | 成功点与失败边界 |
|---|---|
| 启动 | 持根锁列出残留；没有残留才空闲，不自动恢复、保存、执行或清理 |
| 新建/打开 | 完整预检 → 新库单事务初始化 → commit 后读回 → INITIAL P0—P3，才 ACTIVE |
| 同进程读取 | 只重读已提交源，不初始化、到期回调或推进 revision |
| 业务命令 | 一个 BEGIN IMMEDIATE 统一状态/根子历史/接受，未知立即阻断 |
| 手动保存 | 排空命令并固定源，完成原 P0—P3；失败保留源和原意图，不换意图越过 pending |
| 同版显式恢复 | 核原库/全部事实与收据后新 epoch；不重写 prepared 业务身份，不补结构或重播 |
| END | 最新完整 FINAL 与 seal 在 P3 共同接受，再核验并按持久清理材料释放目录 |
| 精确放弃 | 只针对已识别非活动 run；先持久隔离/放弃依据，再白名单清理，保存文件不删除 |
| 关闭浏览器/正常停机 | 不等于 END；停机关闭句柄，未封存源留作下次显式恢复 |

有任一未处理残留时，禁止从相同或更旧文件另开运行；文件不是比工作库更高的权威。
技术 END 如实保存 pending，不替用户完成动作。P0—P3、删除与清理具体步骤见
[保存与恢复](save-and-recovery.md)。没有当前生产入口的 CANCELLED/REPAIR 控制分支不
作为既有能力陈述；未来新增须有准确收据和故障验证。

### 初始化残留的判定

| 独占恢复后已证明的事实 | 允许的后续 |
|---|---|
| 私有准备目录归属可核对，但原输入缺失或未写完 | `PREPARATION_INCOMPLETE`；保留或显式精确放弃，不编造输入或创建数据库 |
| 完整原输入匹配准备目录绑定，分配文件缺失或只有准确前缀 | 只补完该原分配、无覆盖发布目录并继续初始化；准备阶段不接受数据库材料 |
| 原分配材料完整、确定未提交且没有应用对象 | 仅按原输入/计划继续完整初始化；拿不到原材料则保留或精确放弃 |
| 已持久标记数据库开始，但数据库文件缺失 | 拒绝重建，保留查证或精确放弃；不把丢失源当作未初始化 |
| commit/rollback 未知 | 只查证真实库和原分配材料，不按空查询换目录重建 |
| 完整初始化已提交、INITIAL 检查点未完成 | 只继续完整读回与原首份保存，不 DDL/seed/重新装载业务 |
| 首份检查点与完整库/收据健康 | 显式控制提交新 epoch 后继续原运行 |
| 部分/额外结构、缺数据、错规则/计划或坏投影 | 保留拒绝，不 CREATE IF NOT EXISTS、ALTER 或重 seed |
| seal/放弃/墓碑 | 仅继续准确清理，不取得游戏资格 |

## 验收责任

真实 SQLite 测试须覆盖全部领域共享提交、两分支预检、晚写失败、已提交响应丢失、回滚/
关闭不明、跨进程恢复、旧 epoch 拒绝、同请求不重掷，以及已支付/未决动作的直接恢复。
初始化另覆盖 DDL/seed/规则/业务/历史/控制与首份保存窗口。恢复中 RNG、正常业务执行、
补表和 seed 调用应为零。全部收据/事实核验不能只由“找不到结果”用例代替。
真实平台的 journal、锁、权限/低磁盘、刷盘、硬链接发布与清理中断独立验证；MySQL/代理
测试不能代替。采用证据与剩余门统一记在[领域接合表](domain-integration.md)。
