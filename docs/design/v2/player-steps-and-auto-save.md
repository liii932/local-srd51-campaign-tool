# v2 玩家步骤与自动保存

当前应用每个游戏命令由 SQLite 共同事务耐久提交；INITIAL、MANUAL、FINAL 的完整
JSON 使用 P0—P3。**周期自动便携检查点与玩家步骤尚未作为当前应用运行必需采用**。
它们是下面明确保留的后续目标，启用前须完成容量/保留测量、真实实现和验证；不能把
“未启用 AUTO”当作跳过本轮领域保存/恢复/END 的理由。

## 当前耐久与显式检查点

- `CampaignStorageService` 的实例/目录独占与一个 `BEGIN IMMEDIATE` 共同提交状态、
  原骰、根子历史、revision 和接受收据；不是等到玩家一步结束才提交。
- 首份完整 INITIAL 检查点接受前不开游戏写。MANUAL 可保存任意已提交中途状态，FINAL
  接受后封存清理；反应窗口、已付成本和唯一继续叶子原样保存。
- 业务成功与文件保存成功是不同事实。P0—P3 未完成保留原保存意图和源，当前恢复按
  准确意图继续；没有独立 C0、周期 AUTO 阈值、水位增长累计或自动轮换的运行前提。
- 不自动删除旧保存文件或唯一好档腾空间。旧文件不能覆盖未保存的最新库提交，停机/
  浏览器关闭不暗中 END。具体合同见[保存与恢复](save-and-recovery.md)。

## 后续玩家步骤业务目标

这里的玩家是游戏参与者，不是网络账号，仍由单 DM 操作。当前有限战斗的回合完成不
自动证明下面完整玩家步骤已采用。

| 场景 | 目标的一步 | 不独立计步 |
|---|---|---|
| 非战斗 | 一名玩家在一轮中的全部操作，多 PC 合计一步 | 单次检定、字段/物品或消息变化 |
| 战斗 | 一个 PC 的完整回合，同玩家多 PC 分别计步 | NPC 回合、回合外反应、打开回合和模式交接 |

未来玩家名单使用稳定键、固定顺序及玩家到 PC 映射；不因角色离场/死亡自动删除玩家。
DM 显式确认完成，服务端检查步骤/回合身份、版本、根尾及全部领域完成条件；同一步
重复确认不重复计数，空步/放弃不撤销已发生消耗或历史。初期动态增删/重排名单仍须
专项设计，不由缺少玩家事实的旧文件推导。

探索/战斗模式必须有唯一来源。进入战斗挂起原非战斗步骤，退出恢复同一步，不补计、
清零或恢复旧请求资格。具体目标的模式/步骤需实际存储与严格文件字段，不凭“没有遭遇行”
推导。未终结动作流、待选择或关闭窗口后的必需继续阻止完成，合法跨回合 Ready/效果
仍按各自 owner 保存，不因存在未来触发就永久占当前步骤。

持续效果的到期/周期/贡献/结束义务按[效果协议](ongoing-effect-protocol.md)；压制中的
实例也参与完整边界检查。必需回调未结时保持关闭处理中，之后才计步；不自动解压或
重新施加。步骤确认本身不掷骰、扣资源或替用户选择。

## 后续自动便携检查点的启用条件

自动检查点只改善便携恢复点间距，不改变每命令工作库耐久。当前不固定 50 步/三档或
未经测量的字节阈值。启用前必须一起交付：

1. 明确有限 revision 距离、完整 canonical 文件正增长累计与总容量/保留预算，实测
   最坏规则链/历史/pending、库/journal、旧/新/临时文件、未清目录及解析/恢复内存峰值。
2. checkpointRevision 与 commitRevision、增长计量及清零在准确控制事务中持久化；
   相同请求/GET 不重复累计，文件大小回退不冲减已累计正增长，所有算术检查溢出。
3. 随机前以合法最大后缀预留完整保存和计量容量，实际提交后核准确增长，不能消费真
   RNG 后才发现保存不了。多角色、消息、NPC、反应/继续同样纳入计量。
4. 业务已明确提交后、下一游戏命令前建立自动保存屏障，按同一 P0—P3 保存准确前缀；
   失败不撤销已成功业务，也不替用户完成 pending 来凑步骤。明确保存失败/未知的继续/
   取消策略必须有真实入口和收据，不沿用仅写在设计中的 CANCELLED 分支。
5. 新自动文件 P3 接受并可独立读验后才允许删除策略内旧 AUTO，至少保留成功好档，
   MANUAL/FINAL 不自动淘汰。轮换失败只留额外占用，不能先删唯一档。
6. 同版残留的阈值/水位/计量与文件恢复的新本地状态明确区分；UNKNOWN/完整性/封存
   优先于阈值，不自动重播未持久命令或把查证当作取得执行资格。

## 验收与采用

未来验证必须覆盖两种阈值前后、一步多命令、大小回退、计量溢出、NPC/消息/反应/继续
触发、pending/效果存续保存、重复完成、模式往返、并发保存/END、首份失败、P2/P3 未知、
旧好档保护和重启水位。只有固定阈值正常路径不能证明这些边界。

当前领域生命周期仍须完整验证初始化、普通命令、手动/FINAL、文件打开、残留恢复与
准确清理，不等待周期 AUTO 才做首次端到端证据。未来启用须同步源码、测试、本页、
[运行事务](runtime-and-transactions.md)、[完整文件](save-and-recovery.md)、产品与
[接合表](domain-integration.md)。玩家名单/步骤和自动便携检查点可分别采用，不伪造
未实现部分，也不把既有正式能力的接合缺口藏到未来功能名下。
