# v2 玩家步骤与自动保存

状态：计步、模式交接和保存协议已确定；具体领域结算、完整文件和运行守卫尚待采用。
本文中的玩家是游戏参与者，不是网络账号，操作入口仍由单一 DM 控制。

## 步骤与模式

| 场景 | 一步的含义 | 不计步的操作 |
|---|---|---|
| 非战斗 | 一名玩家在一轮中的全部操作，多个 PC 合计一步 | 单次检定、消息或字段修改 |
| 战斗 | 一个 PC 的完整角色回合；同玩家多个 PC 分别计步 | NPC 回合、回合外反应、打开回合及模式交接 |

DM 显式确认完成，服务端检查准确步骤/回合身份、完整目标、版本、事件尾和领域完成条件。
空操作的正常确认、放弃剩余操作均计一步；放弃不撤销此前已提交状态、消耗或历史。
重复请求不重复计步，不同请求指向同一已完成步骤也不能创建第二次完成。

非战斗使用稳定玩家键、固定顺序及玩家到 PC 的映射；每个 PC 恰属一名玩家，每名玩家至少
有一个 PC。当前固定名单阶段不支持动态增删、重排或把映射 PC 改成 NPC；角色归档、死亡
或无法行动不自动移除玩家。全部 PC 不可行动时可以确认空步，但不授予角色行动资格。

模式有唯一权威来源，不能用“没有遭遇行”推导非战斗。进入战斗挂起当前未完成的非战斗
步骤；退出后恢复同一步，不补计步、不清零轮次。进入、打开回合、完成回合、离开战斗都
是独立受保护命令，回合规划和安全交接由战斗领域证明，不能复用 v1 最小遭遇状态冒充能力。

完成确认本身不自动结算骰子、选择、效果或资源；必须在完成前处理的义务由各自命令先
完成。合法跨步骤持续状态继续保留。缺少任一领域的完成判据就拒绝确认，不靠前端布尔放行。
迟到的上一模式/步骤请求在随机性前拒绝，模式往返不能恢复旧请求资格。

## 自动保存水位

本次运行维护完成步数 N 和已保存步数 W，独立初始化从 `0/0` 开始，无第 0 步自动档。
正常满足 `0 <= W <= N`、`N - W <= 50`；N/W 是本地技术水位，不是事件尾或业务轮次，
不进入战役文件，独立恢复不继承。业务轮次、当前玩家、模式与回合则须完整保存。

当新完成事务明确提交且 `N - W = 50`，服务端协调一次候选准备和一次晋升。它不依赖
浏览器补请求、定时器或后台循环。达到阈值后，所有新的游戏写入，包括 NPC、反应、消息、
模式交接和下一回合，都先暂停；读取、精确重放、获准重试保存和显式结束分别按守卫处理。

完成、候选准备、候选晋升是三个可独立失败的事务。保存失败不回滚已经成功的玩家步骤，
界面须分别反馈“步骤已完成”和“保存尚未完成”，不能引导换业务请求键重做。

## 候选、验证与轮换

1. 在共同守卫下重新读取最新完整源，保存一个未发布候选，绑定准确 run、目标步数、代次、
   源指纹和真实字节。全工具至多一个候选，它不提供下载或恢复资格。
2. 开启独立新事务，实际读回已提交候选字节，核对长度/raw 摘要、严格读取、直接恢复投影
   及完整源等价。不能复用编码数组或让 writer/reader 同漏字段后自证正确。
3. 复制合格候选的原字节成为不可变 AUTO，推进 W，并在同一事务完成候选释放、计费和
   轮换。每个稳定战役分组最多三份正式 AUTO，按服务端保存序列决定淘汰，不按文件名或时间。
4. FINAL 不参与 AUTO 轮换。被轮换字节有明确移除事实，原产物身份、接受结果与替代关系保留。

候选损坏只能按精确旧代次及确定坏证据替换，不能让旧页面自动跟随最新候选。晋升复制的
瞬时字节峰值也计入容量；不能借最终保存预留满足自动保存。

手动重试指定原 run、目标初始化代次、目标步数和候选代次；不提供任意“保存当前对象”或
“忽略保存继续游戏”入口。已接受 AUTO 返回原事实，文件当前是否仍存在另行判断。
重放、GET、下载、启动或提交查证均不触发新的保存。

结束可以在保存事务之间竞争，每次后继事务重新取得守卫并核验。最终保存读取最新源，
不把候选或旧 AUTO 改标 FINAL；结束清理纳入本次候选的准确范围。未知提交按
[运行事务协议](runtime-and-transactions.md)查证，不凭空候选槽推断未执行。

## 能力前提

完整规则、业务分区、领域结算/版本依赖、模式与步骤身份、存档覆盖、容量及共同接纳全部
具备后才开放这些入口。技术结束保存中途进度，不替玩家完成步骤或清理领域待办；
新建与名单材料的取得仍受[产品暂缓范围](../../product.md)约束。
