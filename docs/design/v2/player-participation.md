# v2 局域网玩家参与

本文规定一名本机 DM 主持、受邀玩家用浏览器参与的目标及当前原型采用范围。
SQLite runtime 已有成员/控制事实、玩家页面、独立授权和可选 HTTPS 请求边界；默认仍只启用
`http://127.0.0.1:8080`。应用不自行开放监听器、安装证书或改变防火墙，真实局域网设备验收
与部署仍须独立完成。下节区分实际消费者和剩余目标，后文不自动扩大当前支持范围。

该目标与[角色与历史](character-state-and-history.md)、[运行事务](runtime-and-transactions.md)、
[动作继续](action-continuation-protocol.md)、[完整文件](save-and-recovery.md)及
[玩家步骤](player-steps-and-auto-save.md)共同采用；各文档的当前实现说明仍按实际入口核实。
首期不做公网、端口转发、中继、全局账号、匿名观看或无会话访客；不因 LAN 目标扩大规则支持。

## 当前原型与剩余采用

| 范围 | 当前消费者与边界 |
|---|---|
| 成员、控制、共享、探索许可 | `CampaignParticipationData/Commands`；独立类型化聚合和 SQL 投影，全部变更进入共同根历史。一个成员最多控制 32 个活动 PC；同名不合并，NPC 不可分配。模式/场景变化、撤权和转交使探索许可失效 |
| 操作者与裁定 | 根事件保存实际 DM/PLAYER、行动角色及代操作所代表成员；`CampaignAdjudicationCommands` 保存类型化 `ABILITY_CHECK` 决定与原骰结果。界面提供属性、DC、理由，叙事回复不执行检定 |
| 接入和恢复 | `PlayerGatewayService` 与 `PlayerServlet`：十分钟邀请、逐人批准、凭据轮换、单写连接、暂停、只读精确收据及设备恢复。绑定关联当前成员版本；撤销后再启用不复活旧凭据 |
| 玩家视图与动作 | `PlayerCampaignProjection/PlayerCandidateFactory`：自己的规则/自由卡、明确共享的角色概况/场景/日志；候选由服务器纯预检生成，不下发 Host 图、全局版本、规则材料或秘密 DC |
| HTTP 边界 | `PlayerBoundaryFilter` 是全局首个 Filter，TLS 入口仅允许玩家固定路径；`HostBoundaryFilter` 不变。当前配置接受明确私有/链路本地/loopback IPv4，HTTPS 固定 8443；IPv6/DNS 地址尚未采用 |
| 完整文件 | `domains.participation` 与 `roots.actor`、裁定事实随当前完整模型保存并严格校验。旧文件缺少必需字段时拒绝，不补造身份或历史。`core_player_control` 只保存本次运行的安全状态，不进入文件 |

当前直接候选包含本人回合的攻击动作/近战、单格八方向移动、疾走/撤离/闪避/起身、结束
回合和专注；已登记的 Cure Wounds、Bless、Burning Hands，以及当前准确叶子的 PASS、
借机攻击、Shield、Counterspell、释放已有 Ready 和继续结算。探索装备/单次资源消耗须有
当前许可；有限探索场景中的施法、移动和结束专注同样须明确许可。实际可用性始终由原
规则预检决定；没有候选不等于取得任意命令权限。候选最多 1024 项，日志只返回最近 50 条
获准摘要；场景展示只包含自己或另行共享的角色，不因共享场景公开全部敌人。

自由卡目前可分配和查看，玩家不直接编辑或执行自由卡检定；新的 Ready 声明、更多施法
参数、预设秘密 DC 的直接检定、完整移动路径编辑和更多裁定类型仍需交互与消费者接合。
规则卡速度、战斗命令的逐项原骰说明和简易遭遇的共享投影也尚未接入玩家页面；当前共享
场景界面只提供规则战斗/探索场景及地点。裁定检定已展示原骰、总计和结果，不下发秘密 DC。
当前裁定界面限规则卡的独立属性检定；活动场景拥有者未关闭时拒绝该独立入口。
这些缺口不通过通用字段覆盖或“请求裁定即获准”绕过。

断线保留已发送请求的关联材料以便只读查证，不存在自动重放队列；空查证保持待确认。
当前未提供 DM 的“完整排空后确证未提交”操作台。进程重启须先由 DM 恢复并明确重新开放，
才能凭仍有效的同 run 设备绑定换新 Session；重新打开文件须重新邀请。设备信任引导、
跨实体手机/桌面的 LAN 实测、最坏容量和长期会话负载仍属于下文验收门。

隔离原型与重复验证入口见[测试指南](../../testing.md#玩家参与原型验证)；部署仍走
[现有部署流程](../../deployment.md#可选玩家-https-入口)，不把测试监听当作正式启用。

## 加入与玩家身份

1. DM 在已有活动战役中显式开放加入，展示准确玩家地址、有时效的房间邀请码及二维码。
   开放期可供多位玩家分别申请、逐人批准；服务端到期、关闭、轮换或更换运行后邀请码失效。
   关闭加入只停止新申请，不撤销已批准成员或使其断线；现有授权另由 DM 明确撤销。
2. 玩家进入受信任的 HTTPS 页面，提交邀请码和昵称，得到仅能查看本人加入进度的临时会话。
   昵称按 NFC、Unicode 码点和有限长度校验并拒绝控制字符；重名不能自动合并身份。
3. 页面显示等待核对。DM 根据现场本人和本次加入请求核对后，批准并分配稳定战役玩家键；
   也可明确拒绝。等待者不能读取角色、地图、日志、成员名单或提交游戏命令。
4. 重新申请绑定既有玩家身份时，DM 必须显式选择已有成员并核对；不按昵称、角色名、邀请码、
   存档玩家键或未经验证的旧设备自报自动认领。绑定成功后才建立本次运行的成员授权和玩家会话。
5. 邀请码只用于发起加入，二维码不包含已批准玩家的 bearer 凭据；批准后轮换临时会话凭据。
   房间邀请材料只放 URL fragment 或独立二维码载荷，不进入 URL query/path；页面读取后
   立即清理地址，仅通过受保护 POST 申请。房间码不作玩家 bearer，不写入访问日志或后续 Referer。

| 身份或材料 | 职责 | 完整战役文件 |
|---|---|---|
| 稳定战役玩家键、显示名、成员状态 | 业务参与者及历史归因；同名仍是不同成员 | 当前保存并严格校验 owner、codec 和历史 |
| 玩家到 PC 的控制映射 | 战役内控制关系及其变更事实 | 当前保存，断线不改写 |
| 本次运行的批准绑定、玩家 Session、活动写连接 | 证明当前连接可代表哪位成员 | 禁止携带；文件重开重新邀请、核对和绑定 |
| 同 run 已批准设备恢复绑定及凭据校验材料 | 私有本地安全控制，可换取新 Session，不能直接执行游戏命令 | 禁止携带；新 run 不接受原绑定 |
| 邀请、CSRF、bearer、设备配对材料、连接游标 | 有限时效的本地安全与传输材料 | 禁止携带，不作为业务身份 |

稳定玩家键不构成登录凭据。文件保留名单及控制历史，也不能让持有文件或知道键的人自行领走角色。
DM 可撤销本次成员授权；撤销立即失去读写资格，历史中的玩家身份仍保留，不删除或复用其键。

## 角色归属与控制

角色初始卡、当前状态、物品、资源和全部历史属于战役。玩家取得控制权，不取得独立角色库、
跨战役所有权或修改历史的权限；PC 死亡、离场、浏览器关闭和玩家断线不改变这一归属。

首期角色仍由 DM 按当前支持流程准备或创建，玩家可请求分配既有 PC；加入不自动建卡。
分配不绕过当前时间零点创建约束、支持 profile/等级或初始计划验证，也不补造过去的成长历史。
进行中新增角色、任意加入等级和玩家角色编辑器仍按各自独立设计采用。

- 每个 PC 同时至多分配给一名玩家；同一玩家可以经 DM 明确分配控制多个 PC。
- 未分配 PC 只能由 DM 操作；NPC 始终由 DM 控制，不通过加入或昵称匹配自动转给玩家。
- DM 可对已分配 PC 代操作；这不会把控制映射转给 DM，也不使玩家原先的过期请求重新有效。
- 分配、撤回或转交控制须是类型化、可审计的主持命令，串行检查当前成员、映射版本、
  角色状态及未决 flow/窗口/choice。映射和审计同事务提交，旧权限立即失效。
- 转交不自动 PASS、不终结动作、不退款，也不改写原行动者。新控制者只能从真实当前叶子
  取得新的合法选项；无法满足当前未决授权约束的转交先拒绝，由 DM 明确处理义务。

每位玩家在一次运行中只有一个活动写连接，多 PC 共用这一连接。其他标签或设备只能在
认证及授权通过后读取本人投影；启用写入须明确接管并原子吊销旧写连接。旧标签收到失效后
清除操作资格，服务端仍逐次拒绝其迟到请求，不能只依靠页面禁用按钮。

## 可见内容与服务端裁剪

玩家只能取得本人所控 PC 的完整可玩角色卡，以及 DM 明确共享的最小内容。
“完整卡”包括自己的当前能力、装备、资源、效果与合法选择，不包含隐藏来源、内部实现字段
或整个角色历史的 before/after 图；隐藏机制对自己产生的可见结果按领域投影说明。

默认只开放本人卡，场景、队友概况和行动日志均须 DM 主动共享。DM 在相应视图选择内容及
受众：全体已批准成员或指定成员；一次确定的共享政策持续用于其后更新，无需逐条重复批准。
“全体”包含后加入并获批准的成员，他们可读当前共享内容及仍获准的既往共享日志；指定成员
不因新成员加入而扩大受众。读取仍受容量限制，不变成全历史下载或其他私密内容的枚举入口。
共享战斗须包含可知的先攻顺序、当前回合/可行动者与可见位置，帮助玩家识别轮到谁；隐藏
对象及暗值继续裁剪。撤回后内容不再分发并清除应用缓存，不承诺抹掉玩家已经读到的信息。

| 内容或能力 | DM | 已批准玩家 | 等待加入、撤销或未认证连接 |
|---|---|---|---|
| 自己所控 PC 当前完整卡、可用动作和本人待决机会 | 完整主持视图 | 可读本人范围 | 不传递 |
| 其他 PC | 完整主持视图 | 仅 DM 明确共享的姓名、概况等字段 | 不传递 |
| NPC、隐藏敌人和私密内容 | 完整主持视图 | 仅明确揭示的最小描述；不传暗值或隐藏候选 | 不传递 |
| 地图、位置、场景和行动日志 | 完整主持视图 | 仅共享政策允许的区域、对象和记录 | 不传递 |
| 原骰和结果说明 | 可查完整业务审计 | 本人或获准共享的结果；不泄露秘密 DC、分支或目标暗值 | 不传递 |
| 完整根/子历史、文件、固定规则材料、路径及诊断 | 按主机权限 | 不提供下载、枚举或旁路查询 | 不传递 |
| 全局根序号、Host revision/epoch、隐藏对象版本 | 主机控制所需 | 不传递；使用玩家范围的不透明前置条件 | 不传递 |
| 规则选择、战役生命周期、成员/控制与共享设置 | 可操作 | 无管理权限 | 无权限 |

服务端在序列化前按当前成员和字段白名单生成逐玩家投影；不能发送完整对象再由客户端隐藏。
正常响应、错误、日志、动作候选、收据和轮询都复用此裁剪，不从数量、序号或对象存在性
旁漏隐藏内容。共享日志是授权投影，不是可遍历完整根历史的第二入口。

成员撤销、控制转移或共享范围缩小时，旧视图前置条件作废；客户端收到新授权视图或拒绝后
清除已撤回内容及候选缓存。应用使用 `no-store`，不维护离线私密数据包；服务端不再向旧权限
返回数据。玩家操作所需完整依赖版本由服务端保管，客户端只回传有界候选和不透明前置条件，
该条件仍须绑定当前会话、授权、运行和动作。采用[执行焦点](world-and-scene-spaces.md#执行焦点与冻结)时同时绑定空间与焦点代次，每次提交由服务端重验。切回原空间须取得新的候选与前置条件。

## 玩家允许提交的操作

| 意图 | 首期目标行为 | 服务端边界 |
|---|---|---|
| 自己回合内已支持的攻击、移动、施法、装备或资源使用 | 从合法候选直接提交，无逐步 DM 审批 | 当前控制、焦点和代次、动作经济、目标、规则、全部依赖版本及所属空间动作流 |
| 结束本人回合 | 直接提交；全部必需 pending 结清后推进，无逐回合额外 DM 批准 | 当前回合/控制、完整结束义务、flow 和版本均由服务端检查 |
| 本人当前反应或领域选择 | 直接选允许项或明确 PASS | 须匹配焦点流当前叶子的准确机会或 choice；目标跨空间链另核 scope、原根、受限决定类型及主体，不开放后台原流 |
| 探索中的已支持自身操作 | DM 明确开放的范围内直接提交 | 探索许可绑定角色、操作类别、场景及当前授权，不能扩成任意写入 |
| 叙事尝试、尚需 DM 确定的 DC/后果分支、规则外操作 | 提交裁定提案并显示等待 DM | 提案尚非已接受的游戏命令，不预扣资源、不掷骰或写游戏后果 |
| 他人角色、NPC、任意字段/状态、共享或文件管理 | 拒绝 | 不把请求转成默认获准的裁定，也不提供通用覆盖入口 |

服务端已配置但对玩家隐藏的 DC 仍可直接判定，不因玩家不知道数值就要求逐次审批或公开秘密。
客户端不得提交骰点、派生修正、结算后 HP/余额、任意算法、任意字段写入或候选集合。
服务器完整校验两分支后果、全部目标、当前资格和版本后才 RNG；状态、原骰、根子历史、
控制归因、版本及接受收据在同一业务事务提交。玩家与 DM 命令共用串行门，不能各自写一套状态。

探索许可由 DM 有限开放、撤销或随场景及模式变化失效。目标在焦点空间有未决流时，仅
接纳该叶子及阶段明确接受的操作。背景空间通常只提供权限范围内的观察，保留原动作和时间。
目标[跨空间因果范围](world-and-scene-spaces.md#causal-scope)可以授予后台参与者当前原因链
所需的有限决定入口；仍核成员/角色控制和准确版本，候选不泄露隐藏来源或其他空间私密状态。
它不授予移动、普通攻击、推进时间或后台原 flow 的权限；缺少接合时拒绝该轨迹，不能代 PASS。
结束本人回合按上述游戏命令推进；若结束阶段产生必需选择/反应，须先按真实流程结清。
尚未采用的[玩家步骤](player-steps-and-auto-save.md)另有独立计数及 DM 确认，不作为正常回合
结束的额外批准门；一次动作、断线或客户端显示完成不增加步骤或触发尚未采用的周期 AUTO。

## DM 裁定、代操作与暂停

普通代操作使用同一规则命令和完整校验，记录实际操作者为 DM、代表哪位玩家及行动角色；
不能冒写成玩家本人提交。未分配 PC/NPC 的 DM 操作也须保留真实操作者。

裁定提案只表示玩家希望 DM 决定的问题。已送达、等待裁定、被拒绝或过期都是沟通状态，
不是已接受业务收据，不预留 RNG、资源、版本或另一套游戏接纳队列。提案丢失或过期须明确
告知，由玩家重新提出；重连和服务重启不暗中执行提案。

DM 只能用已登记的类型化裁定处理相应领域：固定具体情境/目标、裁定类型、理由、允许的
DC 或有界后果、可见范围和事实依据。DM 填妥有界参数后，明确点击“裁定并执行”：这是新
的已授权游戏命令，记录实际 DM 操作者及其代表的玩家，完整预检当前事实后，将裁定事实、
原骰/成本、结果及接受收据同事务提交。当前事实有变化则重判或拒绝，不沿用旧候选直接执行。
提案已有内容可作为填写上下文，玩家无需再复填全部意图；后台不得自动把提案变成命令。
仅回应叙事说明不执行游戏动作；没有受支持裁定类型时明确告知无法自动处理，不伪造完成。
提案、裁定事实和最终业务结果在界面中分别标示。

裁定不能修复坏冻结数据、绕过不支持机制、泛用覆盖状态、任意重骰或伪造规则支持。
规则只允许 DM 选择 DC 时，选择 DC 不等于保证成功；已接受的随机结果只能按实际支持的
规则机制继续。若需新的家规裁定类型，须先补齐 consumer、历史、文件和恢复，不能用备注代替。

| 页面状态 | 含义与后续 |
|---|---|
| 操作无效或权限/版本已失效 | 明确拒绝；无本次 RNG、游戏写入或部分版本推进；重新同步合法选项 |
| 等待 DM 裁定 | 尚未接受该游戏动作；展示提案状态，不显示“正在结算”或自动重试 |
| 等待自己反应/选择 | 只展示本人当前合法选项，明确由谁作决定 |
| 等待他人反应、DM 裁定或暂停解除 | 保留原已接受进度，只展示获准的等待原因，不暴露他人秘密候选 |

DM 关闭浏览器、Session 到期或暂时离开不等于停服、暂停或 END，不建立心跳/在场租约写门。
服务仍运行时，已获准且规则可判定的本人动作、探索操作和当前反应继续可用；需要 DM 裁定、
新探索许可、加入批准或控制转交的事项显示等待 DM，不自动批准，也不把未知事项当成已获准。

DM 可显式“暂停玩家操作”，服务端持久记录本次运行的暂停控制并拦截新的玩家游戏命令；
恢复也须 DM 显式执行。暂停与玩家命令串行，已接纳的短事务先按原边界完成或回滚，pending
原样保留；DM 仍可读取、查证、保存及按合法入口代操作。暂停不自动 PASS、结束回合、转交
控制或推进时间，解除后从真实当前叶子继续。进程停止另按运行恢复处理，不借浏览器在线判定。

## 局域网连接与请求边界

本机 DM 保持 `http://127.0.0.1:8080`，现有 `/host`、`/api/host/*` 及其 Filter 不放宽。
可选玩家入口使用独立、受限的 HTTPS listener，端口为 `8443`，绑定显式选择的
LAN 地址；按精确 scheme、地址/Host、端口、接口白名单和 Origin 校验，不接受伪造转发头。
玩家入口不代理或转发主机页面、主机 API、诊断及文件；不能把主机 Connector 改绑到 LAN。

DM 展示与证书匹配的 HTTPS 地址和二维码，并提供手机/桌面浏览器首次信任引导。
证书须受设备信任且 SAN 匹配所用地址；不允许点击忽略证书错误、不回退到 HTTP。
地址或证书变化先重新配置和验证信任；连接失败显示可操作原因，不要求玩家猜主机端口。
证书私钥保管在 WAR 外受限配置，会话和邀请保存在本次运行的服务端安全状态中；
三者均不进入 Git、WAR、完整文件或普通日志。
listener、防火墙、证书和真实设备启用须按[部署](../../deployment.md)另行实施及授权，本文不执行这些动作。

玩家会话使用独立凭据与 Cookie 名称，具备 Secure、HttpOnly、SameSite 和有限超时；不与
DM Session/CSRF 共用权限。写请求须验证精确来源、Fetch Metadata、会话、CSRF、当前成员、
活动写连接、运行/暂停资格及操作前置条件。拒绝跨源放行和 `Origin: null`；错误不泄露内部数据。

首期采用 HTTPS POST 命令和有界短轮询读取逐玩家投影，不新增 WebSocket/SSE。
前台默认约 2 秒轮询，单连接同一时刻只发一个读取；失败按约 2/4/8 秒封顶退避并加抖动，
后台降频，恢复前台立即同步。这些数值是待真实设备实测的体验参数，不是游戏计时或授权来源。
每次读取都有容量上限；没有可恢复推送游标，也不把全局根序号、完整历史或另一玩家流发给客户端。

## 断线、重连与运行恢复

浏览器检测连接丢失或请求结果未明确时，立即锁定游戏操作并标记视图可能过期；旧显示只供
识别现场，不能据此发新动作。无离线命令队列、自动重发或换请求键重试；请求超时不等于失败。

重连必须按顺序完成：

1. 恢复 HTTPS 与会话认证，必要时使用已批准设备恢复绑定换取新 Session；重新核成员、
   控制映射、活动写连接、运行及暂停资格。没有可用认证/恢复凭据、被撤销或无法对应当前
   运行时回到 DM 核对流程；只读查询不能自行续得写权限。
2. 清除失效权限与候选缓存，取得当前获准范围的最小全量投影，包括真实 pending 和可用操作。
   不从断线前差量、时间戳或连接游标拼回状态；当前投影不是旧请求的接受结果。
3. 对恢复前本设备已批准绑定下发送且结果未明确的请求，按原 run、请求身份、准确意图与操作者只读查证。
   已接受只返回原事实的获准投影，不重骰、扣费或继续父动作；原 WAITING 收据仍是原 WAITING。
4. 查不到、无法精确关联或当前运行不允许查证时，保持“结果待查证”，交 DM 核真实状态及
   收据；普通空查询不能证明未提交。真正 UNKNOWN 由共同运行守卫阻断，走显式恢复。
5. 当前投影、未明确结果和写资格全部核定后才解锁；下一动作由玩家明确发出，使用新的当前
   前置条件。读操作、身份恢复、收据查询和解除只读本身都不执行未提交命令。

同 run 的结果待查证可由 DM 持串行门排空在途请求、隔离可疑旧执行者，再以健康连接完整
核验该 run 的收据、根子历史及状态。只有能确证该准确请求未提交时，才提示明确未执行，
允许用户取得新候选后主动提交；不自动重发，不另建 C0 或 NOT_COMMITTED 持久台账。
换 run、无法精确关联或仍无法确证时继续待查证，不以一次空查询解除 UNKNOWN。

同 run 的设备恢复绑定和凭据校验材料可保存在私有本地安全控制中，不进入文件或日志。
设备恢复凭据只换取新 Session，不携游戏写权；进程重启使旧 Session、epoch 和写连接失效。
DM 完整恢复运行并显式重新开放后，仍有效且未撤销的绑定可重新认证并全量同步，无需全员
再输邀请码；新写资格仍按单写连接及当前授权取得。凭据丢失/到期/撤销则由 DM 重新核对。

| 中断或转换 | 身份及可操作状态 | 业务与恢复语义 |
|---|---|---|
| 同一浏览器短断，凭据仍有效 | 先只读，按上述顺序重连 | 保留 PC 控制；原在途请求可能已提交，只读查证后明确继续 |
| 无有效会话及设备恢复凭据，或成员授权被撤销 | 无游戏读写；重新邀请并由 DM 核对既有成员 | 不按昵称或文件键认领；未决动作仍在，不能自动代选 |
| 另一设备或标签接入 | 核准后可读；写入须明确接管 | 同一玩家单写连接；旧连接吊销，迟到命令在 RNG 前拒绝 |
| 玩家离线，DM 决定代操作 | 玩家控制映射不自动改变 | DM 显式选择准确机会/角色代操作，记录 DM 和被代表玩家；玩家回来同步真实结果 |
| DM 浏览器关闭或 Session 到期，服务仍运行 | 既有合法动作/反应继续；需要 DM 的事项等待 | 不自动暂停、批准新权限或 END；无自动在场超时写门 |
| DM 显式暂停玩家操作 | 玩家可读和查证，游戏提交暂停 | 持久控制拦截新玩家写；pending 保留，DM 显式恢复才解锁 |
| 服务进程重启或提交 UNKNOWN | 旧连接失去执行资格；同 run 有效设备绑定可在 DM 恢复并重开后换新 Session | DM 独占核原库/历史/收据，恢复新 epoch；不自动重播 |
| 同 run 更新 epoch | 旧前置条件及连接写资格失效，重新核绑定和全量同步 | 旧接受事实只证明原执行；不能凭旧收据恢复写权或把空结果判为未执行 |
| END 完成或运行已封存 | 吊销该运行连接，只显示结束/不可用 | FINAL 原样保存 pending；不能从旧页面继续或借重连重新激活 |
| 完整文件重新打开为新 run | 新 epoch、会话及收据空间，重新邀请绑定 | 保留业务玩家/PC/历史；不携 bearer、邀请、连接游标或旧请求执行资格 |

玩家浏览器无权发起主机恢复、救援保存、END、放弃或清理。旧 run 已清理或文件已重开时，旧收据
不能证明新运行“尚未执行”，也不能作为重放任务；以新运行事实和 DM 明确判断为准。

## 验收与采用门

以下须用真实服务、HTTPS 及至少手机/桌面两类局域网浏览器验证，不能只凭文档或 DTO 存在通过：

| 场景 | 必须观察到的结果 |
|---|---|
| 同名玩家、邀请过期/关闭、二维码申请、未批准读卡 | 不串号/泄密；关闭保留已批准成员，query/path/日志不含邀请材料 |
| 多位玩家用同一开放房间码申请 | 独立临时会话及待批请求，逐人批准为不同成员；未批准者没有游戏视图 |
| 一个玩家两个 PC、两个玩家争同一 PC、NPC 请求控制 | 明确多 PC 分配成立，重复控制和 NPC 玩家控制拒绝 |
| 共享撤回、隐藏 NPC、他人卡及秘密 DC | 网络响应/错误/候选/收据均不带秘密；旧权限候选失效 |
| 默认本人卡、全体/指定共享、后加入成员及既往日志 | 受众和持续更新准确；共享战斗可识别回合及位置，撤回后不再分发 |
| 合法自身动作/结束本人回合与待他人反应时乱入 | 合法命令无逐步/逐回合审批；非当前叶子零 RNG/写入，计步确认独立 |
| 焦点切换后的候选和只读场景 | 背景保留可见结果，焦点离开或切回使原候选过期，迟到请求零 RNG 和游戏写入 |
| 目标跨空间因果选择 | 仅原 scope/叶子/受权主体可作准确决定；后台普通动作及旧 flow 继续拒绝，同次共同 APPLY 不留半边结果，保存不替参与者选择 |
| 裁定提案、DM 代操作、裁定并执行及仅叙事回应 | 归因可区分；明确执行才同事务写裁定和结果，未支持类型不放行 |
| 玩家提交后响应丢失、轮询失败、多次重连 | 单次原骰/成本/根/接受事实，先全量同步并查证，不自动重发 |
| 空收据查询、完整查证未提交、UNKNOWN、新 epoch/run | 空查询不判定；同 run 确证后才解锁主动新命令，未知仍阻断 |
| 多标签接管与控制转移和旧命令并发 | 串行只接受当时授权者，吊销/版本/pending 检查在 RNG 前完成 |
| 玩家反应中断线、DM 关闭浏览器、显式暂停、进程重启 | 各自遵循状态表；不自动 PASS/计步/转交/END，代操作和恢复可准确归因 |
| 同 run 重启、丢失恢复凭据、END/文件重开 | 有效本地绑定仅换新 Session；新 run 重新邀请，旧 bearer/收据不能登录或重放 |
| 错证书、错地址/Origin、玩家端直访主机接口 | 连接或请求拒绝；不提示绕过 TLS，不暴露主机管理面 |

采用须同步成员/控制与审计 owner、严格文件字段和直接恢复、逐玩家投影、真实请求安全边界、
单写/未知结果故障测试和设备操作流程，并在[接合表](domain-integration.md)记录实际入口与缺口。
玩家联网、玩家计步和周期 AUTO 可分别采用；任何一项完成都不替代其余验收或当前每命令耐久。
