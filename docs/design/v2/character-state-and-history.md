# v2 角色状态与历史

当前有限 SQLite 路线以完整 typed 角色/场景聚合、统一根历史和独立关系投影保存战役。
实际能力/验收见[领域接合表](domain-integration.md)，文件与事务分别见
[保存](save-and-recovery.md)和[运行](runtime-and-transactions.md)。完整 SRD、自由角色
编辑器及任意加入等级不是仅由这些存储类型取得的能力。

## 战役、初始卡与当前卡

`CampaignData.Snapshot` 是完整业务输入/输出，runtime 的 `CampaignDomainData.State`
保留 material、角色、全部战斗历史、节点/位置/简单物品及 roots。

| 责任 | 当前落点 |
|---|---|
| 战役稳定身份/名称 | Snapshot.campaignId/name；本地 core_control 关联该战役但不成为第二份业务历史 |
| 角色稳定身份/加入事实 | Character.initial 的 InitialPlan、准确来源/槽/选择/授予和初始化事件 |
| 当前卡 | Character 的名称/PC-NPC/active 与 History.current；其全部领域状态须可由保留历史验算 |
| 角色全历史 | History.events，包括原输入/选择/骰点、完整 before/after、资源/装备/健康/书籍等事实 |
| 场景/战斗 | combat History/current 与所有角色结果/因果依赖，共同回到一份战役根序号 |

初始卡不可随当前值更新，也不等于打开文件时的当前卡。当前角色模板按服务端标准数组
初始化；未来允许任意合法加入等级时须明确独立创建输入，不能伪造既往升级/冒险历史。
空队伍起点是当前受支持 profile 的明确状态，不是允许缺少必需消费者。

## 业务身份与本地执行身份

- campaign/character/scene/item/action/event 的稳定 UUID 和根序号保持原值，名称允许重复，
  不参与身份匹配。名称按 NFC/Unicode 码点和领域范围验证，读取不悄悄修改历史文本。
- schema-2 prepared Identity 的字段虽名 runId/snapshotId，当前作为初始/状态/历史及
  跨角色依赖的稳定业务标识保留，随文件保存。不能因字段名像运行标识就删除或重写。
- 角色/场景事件 version 和原 operation 若参与历史邻接/因果，同样保持；它们不授予旧
  HTTP 请求执行权。根中保留意图摘要是业务审计，不等于旧本地接受收据。
- 实际私有运行的 `core_control.run_id`、当前 Host epoch/revision、HTTP request 收据、
  保存收据及路径只属于本地控制，不进文件；独立文件打开重新建立，残留恢复保留库
  内事实但更新 epoch。旧页面不能借保存的 prepared 标识取得新连接或写权限。

PC/NPC 是游戏类型，active 是记录管理状态，均不代表账号权限、生命状态或回合资格。
离场对象仍供历史/物品/效果引用，不因不在当前队伍视图中就删除。

后续[玩家参与](player-participation.md)将战役玩家身份与玩家到 PC 的唯一控制关系作为
独立业务事实；角色本体、初始卡和历史仍归战役。离线不转移控制权，DM 代操作记录
实际操作者及代表玩家，不能伪装成玩家提交。玩家读权限另按共享范围裁剪，不从 PC/NPC、
阵营或对象标识推导。设备凭据及 Session 属本地执行控制，完整文件不授予连入权限；
这些是待采用模型，当前聚合/文件尚无玩家字段。

## 唯一 owner 与严格文档

角色 typed 状态拥有成长/授予、HP/死亡、生命骰/资源、装备、法术书、休息及每日使用事实。
场景 typed 状态拥有部署/位置/先攻/轮回合、动作流/反应/施法/效果、怪物健康/充能/休息。
`resources_character`、`equipment_instance`、`spellcasting_book` 等是角色聚合投影；
动作帧/效果/怪物表是场景聚合投影。它们不独立修改当前余额，写入同事务，读回逐行核对。
历史中的 before/after 是不可变已记录事实，不是第二份可写 current。

正文使用 `CampaignDomainCodec` 登记的封闭 record/enum typed TEXT；输入不指定 Java 类、
任意属性或 SQL。未知/缺失字段、类型不符、重复映射、非规范数值/文本与预算错误拒绝。
每次从数据库实际读回还执行领域/整场验证；损坏投影不能靠恢复时重建掩盖。

时钟由 `CampaignDomainEngine` 统一协调，所有受影响角色通过同根事件一起推进；各角色
持久时间必须完全一致。场景与休息/稳定恢复/效果沿同一时间契约，不从墙钟补收益，也不
把各自独立推进的局部历史相加。实际未接入的跨场景时机或消费者仍拒绝。

## 形态统计与健康交接

以下为 Polymorph 的目标合同。角色与怪物沿用同一战役主体键。主体 owner 持有本体、
实际生死和形态生命池，装备 owner 持有原物件及穿戴/持握关系，空间 owner 持有唯一
安置，效果 owner 持有法术 application、专注、期限和独立压制原因。法术、伤害和状态
继续点均引用这些事实，按形态变更创建新角色、发放装备或初始化资源均属无效。
[原文](../../references/srd-5.1/pages/page-169.md#right-column)

### 施加与有效形态

- DECLARE 锁定单一主体、目标真实自愿/非自愿事实、准确野兽属性块、施法位、当时
  60 尺距离和可见证明、主体/效果/位置/装备/holder 版本及所有可能的 placement 后果。
  CR 按准确有理数比较，目标有 CR 用声明时有效 CR，无 CR 用总等级。非野兽、过高 CR、
  缺冻结 reader 或初始形态落位不合法在声明成本和任何 RNG 前拒绝。合法 shapechanger、0 HP
  目标在法术结算时为 `NO_EFFECT`，保留已付成本且不作豁免。目标自愿须有实际控制者
  或授权 DM 的有界选择事实，缺少肯定选择视为非自愿。
- RESOLVE 先用公共施法阶段重验目标、初始落位和 holder。已失去资格时保留已付
  成本和 `NO_EFFECT`，不新增豁免。仍符合且不受抗魔等阻断时，自愿者跳过豁免，
  非自愿者用当前有效 WIS 做一次 `CheckStage`。成功为 `SAVED`，同样保留
  合法声明成本，不创建形态。失败/自愿且当前初始落位仍合法时进入
  `FormTransitionPlan(APPLY)`。已掷阶段中的合法后继使落位失效时，保留实际原骰和
  `NO_EFFECT`。普通施法有效期至多施法者个人经历 3600 秒，持久等待由实际施法
  叶子或该次豁免/安置子叶子保存。
- `FormLayer` 保存 target/application/statBlock 的完整身份、创建根与 ordinal、初始和
  当前形态 HP、形态 HP 上限及其来源、正常/形态展示的安置转换事实。有效形态选择引用
  存续 application 及当前 suppression，主体记录本体 HP 和条件/死亡事实。本体 HP 在
  形态有效时不接收普通伤害、治疗或长休 HP 恢复。本体显现时继续从自己保留的当前 HP
  结算。本项目保持一个随主体的临时 HP 缓冲，按其原来源期限与消费更新，切换不复制、
  补充或返还临时 HP。新层初始 HP 使用冻结块登记的 HP 值，成功施加只初始化一次。
- 有效统计以野兽块替代本体能力值（含 INT/WIS/CHA）、技能与豁免、AC、体型、速度、
  感官、可用行动与特性，并按公共协议叠加仍适用的独立条件和效果。只保留主体的身份、
  人格、阵营、关系、控制及原行动已消费前缀。形态不能说话或施法，不能使用需手或言语
  的动作，也不能取用本体职业特性或替代掉的资源。既有专注保持，仍用该阶段的当前
  有效 CON 检查。有效时原随身装备关系冻结为 `MERGED`，禁止使用、交易或掉落，
  无 AC、攻击或其他物件贡献。显现本体时恢复原关系并依当时条件和抗魔重新求值。
- 同一主体可有多个存续的同法术 application。本项目以形态 CR 较高者优先，同 CR 用
  公共同强顺序。只启用一个层，未获选层保留其已发生 HP 与期限，不形成嵌套本体或
  HP 堆栈。新命令以接纳时实际有效统计确定 CR 上限，继续重验。未来 winner 变化不
  重做已成功的施加，也不把其他形态的已损 HP 恢复到初值。新层、重叠及关联影响在
  完整预算内接纳。

### 单一伤害事实、回转与专注

`FormTransitionPlan` 接收准确 source/application、真实边界、当前主体/层/装备/空间
和伤害或终止证明。输出本体与层的前后值、可见统计/安置变化、已结算伤害引用、终结
原因、最终健康事实和待履行后继。步骤顺序固定。

1. [DamagePacket](multi-target-save-damage.md) 在其原防御时点使用有效形态统计及
   防御，保存逐分量原量和减免后量。健康 owner 用减免后总量先消费当前临时 HP，
   再扣有效层的 HP，记录实际受伤量与未吸收余数。普通治疗/HP 门槛作用于当前可见
   层，治疗溢出截在该层上限。不移动至另一层。
2. 当前层仍大于 0 时，提交该层结果并走正常受伤后继。层归零时只记录层耗尽和结束其
   application，回转至本体并把未吸收余数从本体当前 HP 扣除一次。该余数保留原包
   因果，不重新按本体抗性、易伤、临时 HP 或伤害反应减免，不递归耗尽落选形态。
   形态耗尽本身没有本体的 0 HP、掉落、PRONE、死亡豁免或专注失败。巨量伤害/死亡
   豁免按回转后本体与其应受余数结算。已在本体上生效的事实仍按原规则解释。
3. 持续时间、Dispel、专注结束等真实结束时回转，不产生溢出伤害。使主体直接死亡的
   登记机制按命中时的有效 HP 门槛/资格判断，之后保留真正死亡事实、结束该主体所有
   形态来源并展示本体遗体。回转不会复活。本项目让合法继续存在的落选层在当前包和
   必要健康观察结清后才可取得贡献，主体已死亡或本体处于 0 HP 时无新形态恢复。
4. 唯一健康 owner 先发布本次包的最终失能、死亡、掉落与实际安置，再由专注 owner
   处理。存活且未失能时按本包实际伤害检查一次，DC 为 10 或伤害一半的较高值，
   CON 用此刻已回转或仍有效的统计。溢出没有第二个伤害来源或集中骰。真正失能或死亡直接结束
   holder 及其完整存续子图。本项目用此明确先后处理 SRD 的形态归零与专注交接。

### 压制、体型、直接恢复

抗魔以该主体独立于体型的安置锚点判定目标型覆盖。区域裁切仍使用完整体积。原因从
无到有时 `FormTransitionPlan(SUSPEND)` 暂以本体显现，保留各层当前 HP、期限与
精确原因。最后原因消失且当前形态仍有资格时 `RESUME` 使用同一池。主体在抗魔内
所受本体伤害、治疗和真正死亡保留。压制期间本体降到 0 或死亡使现有形态结束，即使
随后治疗也不会恢复旧层。抗魔出现/移除均不重掷、不花额外行动，不因切换 HP 池本身
触发伤害、治疗或专注检查。参见[抗魔合同](ongoing-effect-protocol.md#antimagic-field)。

在改变体型或能力前，空间 owner 预检并执行
[`PlacementTransitionPlan`](spatial-and-area-contract.md#placement-transition)。
自动转换先试同锚点完整体型、再同锚点规则允许的挤行尺寸，再在有界合法候选中取最近
落点。这个顺序是项目安置政策。抗魔引起的转换要求新候选在该边界保持已决定的压制
模式，避免同一次安置再次翻转该形态。实际身体只占当前体型所需体积。强制转换如果没有
普通合法落点，提交真实层结束/压制、健康结果及 `UNPLACED_RETURN`，使用该合同的
必需位置补救叶子。没有合法身体时不继续用旧体型、占位、普通行动或反应。回转或恢复
导致的位置/体型事件进入同一闭包并重验其余移动/攻击。同锚点的体型改变本身不构成
主体的区域进入。该叶子仅处理安置，已经发生的伤害、结束或显现不得再次执行。
来源与主体获准分处不同空间时，强制回转仍走同一
[因果作用域](world-and-scene-spaces.md#causal-scope)，保留背景时钟及原 flow 前缀。
安置候选始终在此次转换的原场景和时间域内求解。等待期间若真实事件证实新的压制/
解除，按当前有效形态重规划该主体，取消旧模式的安置叶子并引用原转换前缀。跨空间
事件须沿它自己已获准的因果作用域提交。
若来源真正结束，以该来源仍存续为前提的旧返回叶子终结为 `CANCELLED_SOURCE_ENDED`，
只处理当前必须的本体或其他仍有效层的安置。真实结束事件可作为本体必需安置的来源证明。
重规划保留已提交的池值、伤害、结束和成本，无新 RNG，
也无再次施加。单次提交过期只拒绝该请求，重新读取当前叶子和候选后可继续。真实模式
改变由 producer 负责收束旧叶子，不能留下只能用过期证明提交的等待。
[安置继续](spatial-and-area-contract.md#placement-transition)

文件保存所有层、本体/当前层 HP、未合并物件的原关系与当前 MERGED 资格、来源期限
与压制、已结清的伤害和溢出事实、真实空间安置及未执行的精确 placement/health 叶子。
严格 reader 核对当时统计、旧池/新池和实际包总量、唯一最终健康事实及终止闭包，按原
事实装载。新根先覆盖最坏的形态和专注终结分支，至多 8 个同主体存续形态层。每个
形态变化只安排一个 placement 和各合法转移最多一份结束义务。二次伤害、错误池或
旧叶子以持续效果的版本/转换错误拒绝。任一提交点故障保留原池、安置、holder 和预留。

## 召唤主体、群组先攻与退场

以下为 Conjure Animals 的目标合同。效果 owner 保管 spell source、holder、期限和
结束闭包。战役主体 owner 保存 `SummonedMember` 的稳定身份、形态、健康和显隐。
空间 owner 保存实际安置。战斗 owner 保存 `SummonGroup` 的群组先攻及逐成员消费。
友善/敌对关系、谁能下口令、谁能操作战役 UI 分别核验。

### 声明、原子生成与群组回合

- 施法者从（数量、CR 上限）`(1,2)、(2,1)、(4,1/2)、(8,1/4)` 中声明一档。
  仅 5、7、9 环分别为 2、3、4 倍，3、4、6、8 环为原数量。例如六环选 2 只
  CR ≤1 时仍是 2 只。[升环解释](../../semantics/srd-5.1/spells-a-c.md#srd51-spell-conjuration-choices)
  DM 在 DECLARE
  前按冻结组合确定恰好该数量的属性块。每个成员必须为合格野兽，出生后同时保有
  BEAST、FEY 规则分类。声明锁定连续生成 ordinal、属性块及逐成员可见落位。完整
  核验施法资源、60 尺范围、完整 footprint、全组互斥占位、地形、敌友关系和战斗
  插入/结束上界。任何一个落位、CR、数量、版本或完整 reader 非法，整次声明零成本、
  零 RNG。合法声明花一动作与一法术位，取得 holder。结算仍需该 holder 有效，
  duration 为施法者个人经历 3600 秒。
- 真实 RESOLVE 重验同一计划。目标格已被反应占据、目标格此时不可见或无法结算
  时，记录 `NO_SPAWN` 和准确原因，保留声明成本，无选择新格或只生成好格的旁路。
  合法但由真实抗魔阻断的各格按[抗魔合同](ongoing-effect-protocol.md#antimagic-field)
  记录为 `BLOCKED_INITIAL`，无实际主体。正常格仍按计划结算。无人生成则结束空
  来源且无先攻。角色、怪物、场景、holder 子图和历史在同一
  `SummonLifecyclePlan(SPAWN)` 提交，不能借世界创建与第二个场景命令拆分。
- [Glyph 储存释放](spellcasting-extension-contract.md)复用 `SPAWN`，输入为已验证
  Glyph release、触发者及原冻结档/成员。以该触发者为参照，沿完整合法候选按距离
  及空间稳定顺序取最近的所需落位。目标和格位预检先于触发消费。该变体对触发者敌对，
  对其创建一份实际 `ATTACK` 任务作为生成后继，无虚构的说话者或命令成本。真实
  攻击仍按群组及其具体规则结算。按 `FIXED_DURATION_FROM_GLYPH` 从释放起使用
  完整持续时间，不重新支付施法者成本或取得 holder。Glyph 结束的引用只作历史因果。
- `SummonedMember` 保存源、group、生成 ordinal 和事实、准确块/分类、初始和
  当前 HP、友善关系、可见状态 `PRESENT/ABSENT_ANTIMAGIC/UNPLACED_RETURN/ENDED`、
  当前安置或最后安置引用、各原因、结束事实。主体 ID 由该 source 与生成 ordinal
  确定且不得复用。每个战斗的群组项键为 combat/group，所有在场成员只占一个先攻项。
  掷一次共享 d20，以实际生成且可行动的最小 ordinal 成员的有效 DEX 为组修正。
  无可行动成员则取实际生成的最小 ordinal。这个异质组修正是项目解释。初入战斗
  或在战斗中首次生成该组时结算一次，组员增减/暂隐/恢复不重掷。探索生成不预掷。
- 战斗 owner 以总值和该战斗确定的 tie rank 插入。初始战斗使用合法 tieOrder。
  中途并列在已有同分项之后，随后以创建根、ordinal、稳定键排序。用稳定 initiative
  项和本轮已关闭前缀判定插入位置。严格落在当前项之后可在本轮行动，位于当前或
  已关闭前缀之前/其中则下一轮。已经消费的轮/turn 身份保持。若因某次退出
  完成了当前项，先结清该项才选择下一项，避免按数组下标补发回合。
- 群组拥有真实 turn。START 时登记当时所有 PRESENT 成员的固定序列（生成 ordinal
  ASC），逐个结算成员 START 后继，再开放该成员行动，最后结成员 END。所有成员
  共用群组 turnId，逐成员各自维护一次真实行动、移动、反应及效果进度。此前已经
  用掉的反应和资源按各机制刷新时机处理。隐藏时无行动或反应。进入当前队列后的
  隐藏成员若到它的继续点仍不可用则记录跳过，已跳过者不在同 turn 补发。START 后
  新回到群组但未在队列内的成员等下个群组 turn。群组全部不可用时略过未开启项。
  该轮游标与原 rank 保留，恢复成员按正常位置和已关闭前缀判断首个可行动 turn。

### 口令、退场及进行中继续

`SUMMON_VERBAL_ORDER` 引用已存续 group、明确成员子集、施法者、当前空间/叶子与
版本、一个登记的指令以及所需听觉、目标、空间和持续证明。指令首期为 `ATTACK`
稳定主体、`MOVE_TO` 合法锚点、`FOLLOW` 稳定主体、`HOLD` 或 `CLEAR`。
实际成员动作只由正常候选和消费者接纳。指令不花 action、reaction 或 RNG，
允许施法者在自己行动阶段或无活动 flow 的探索边界开口。真实声音受失能、不能说话、
静音、听觉及传播阻挡约束，未听到的成员保留旧指令。暂隐成员无法接收新指令。
指令以最后一次已听口令生效，完成、撤销或引用已永久无效时清除。成员由 DM 操作，
玩家获准提议口令所依据的是其真实控制和施法者资格。没有有效口令时使用有限
`SELF_DEFENSE`。成员可对已通过真实攻击/敌对伤害事实威胁该成员的敌对者作攻击、自卫
移动、Dodge/Disengage 或合法防卫反应，按常规规则消耗。没有威胁事实时可原地
跳过，已核实威胁而缺安全行动时也可跳过。

- 单个成员归零/死亡即 `END_MEMBER`，源结束则 `END_GROUP` 枚举全部未终结成员，
  包括暂隐和安置待决。终结永久释放实际占位，清除该成员未执行的指令/候选和适用
  的持续关系，保留身份、健康、已消费成本和历史。无尸体、死亡豁免或复活入口。
  一员退场不重建 group、不重掷先攻。最后一员终结使空群组和来源终结并释放 holder。
  全员暂隐时仍存续，期限和专注可结束它。
- 受击、压制或法术结束发生在成员/群组作为当前项或其他父帧依赖者时，按真实边界
  在同根接合。已发生前缀、合法完成的旧骰和伤害仍保留，未执行动作/反应/目标在
  当前准确叶子按资格重验。已消失依赖得 `ACTOR_UNAVAILABLE` 或
  `TARGET_UNAVAILABLE`，按各登记分支跳过或结清。反应窗口保留已接受结果和其余
  仍合法机会。当前最后可用成员消失时走一次群组 CLOSING，完成必需叶子后才推进
  轮次和下一项。待结算的强制后继仍在原 flow。
- 抗魔 `SUSPEND_MEMBER/RESUME_MEMBER` 只改变在场/可行动与实际安置。原 HP、
  期限、身份、组先攻、消费、命令历史保留。取最后真实空间为复现参照，最后原因解除
  且来源有效时由[复现安置](spatial-and-area-contract.md#placement-transition)处理。
  复现候选限原场景和时间域，且在所有适用抗魔覆盖之外。等待复现时真正终结优先，
  旧叶子记 `CANCELLED_SOURCE_ENDED` 并结清，成员永久退场。新的真实抗魔覆盖
  原锚时旧叶子记 `CANCELLED_RESUPPRESSED` 并结清，原成员保持暂隐。所有原因
  再次真正解除时才形成新 return episode，继续使用同一主体、HP、命令和组先攻。
  这些转换保存旧前缀和最新叶子，无新 RNG。单次 stale CAS 保留当前可继续的义务，
  不替代上述真实取消原因。结束战斗释放 combat 项，存续主体留在原空间按探索资格行动。
  开新战斗按新 combatId 建项。当前召唤群组适用同空间连续作用，跨空间交接须沿
  [空间协议](world-and-scene-spaces.md)取得完整迁移/关联合同才可接纳。

文件逐字段保存生成计划及已阻断格、真实在场/不在场/结束成员、原伤害与结束原因、
完整命令及实际听到集合、组先攻原骰和 tie rank、插入/关闭前缀、当前成员游标、
消耗和待继续引用。直接恢复不重建已退场成员、不重投先攻、不重发任何额度/指令。
拒绝无存续 source 的在场成员、未消费的重复命令、二次先攻及不连续 turn。每源
最多 32 成员、每 combat/group 最多一组骰，口令至多列 32 个成员。接纳前计入每员
安置、原因/关系上界、一个单员终结或消失义务、一次组关闭和所有必需父继续。同一
来源 end/holder/归零命中共享该真实终结额度。过期 CAS、同键异意图或无合法叶子
零额外成本/写入，故障按共同事务保护整组的安置、历史和既有预留。

## 完整业务历史与因果

一份 `domains.roots` 连续分配战役根序号，外层 history 是其核验摘要。每个角色与场景
事件必须准确归属于一个根；没有根的子事件、重复操作、根摘要不符和孤儿对象拒绝。
全部既有 typed 输入/选择/原骰/前后状态与已完成/待继续义务保存，不并存可漂移的
recentEvents/stateEvents 根，不按 UI 近期列表截断或把未知类型降为 NOTE。

角色 profile、节点/位置、简单物品和消息根保留其 typed 前后事实。检定附带消息/后果
归同一检定根；`check-effects` 的完整两分支预检、实际检定子事件与健康/物品/位置/消息
一起提交。具体入口与验证类见接合表，代码存在不等于本次测试通过。

operation UUID 在取得物品、动作/掉落/效果来源或跨角色子事件中兼作业务因果键时必须
保留。排除本地请求收据不能连同这些业务引用一起删除；恢复也不能重新生成这些键。
恢复只用保存的结果验算邻接/算术，不通过历史命令驱动状态、不重新掷骰/扣费/发效果。

## 新建与文件恢复的公共初始化输入

当前完整输入包含准确 material/链、稳定战役身份、支持 profile 的初始/当前聚合、世界/
场景、全部历史/根尾、时钟和 pending。新建当前空队伍起点后，由实际角色命令建立真实
初始计划与初始化事件；首份检查点接受后才执行普通业务。

文件打开从严格 reader 直接装载已有事实，建立新物理 run/epoch/本地请求空间，不重写
prepared 业务身份或历史 version。一个初始化事务建立当前声明的 DDL/seed、规则与
整个业务/控制闭包，commit 后实际全量读回并完成 INITIAL P0—P3。缺事实或结果未知
不发布部分执行视图；残留恢复核原库，不重新装载/授予/seed。

原正式自由卡/基础字段/职业等级/熟练、MANUAL/SAVING_THROW、简易遭遇名单/阵营等通过独立
DM-managed typed 领域接合，不自动转换成 schema-2 角色，不用自由字段越过规则验证。
实际白名单、历史与文件字段、表单和本次证据由接合表逐项核实，尚未验收不能宣称全 v1
已闭合或改写成永久排除。

玩家稳定名单、玩家到 PC 映射、非战斗玩家步骤、任意加入等级和完整自定义角色编辑器
仍是独立后续产品输入；不存在真实实现时不向当前文件塞默认值。新增领域须同步严格
codec、唯一 owner、完整字段映射、根子历史和直接恢复测试，不能只增加一个空分区。
