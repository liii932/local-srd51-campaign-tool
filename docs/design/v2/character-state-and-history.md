# v2 角色状态与历史

状态：根归属与历史原则已确定；完整初始卡、当前状态及各领域历史仍须逐项细化和采用。
适用范围见 [v2 设计基线](README.md)，不改变现行 v1 角色表或存档解释。

## 战役工作集和四类根

| 目标责任 | 内容 | 生命周期 |
|---|---|---|
| `runtime_campaign_workset` | 本次 run/snapshot 下的战役根 | 完整初始化建立，可靠结束后清理 |
| `runtime_character_identity` | 战役内稳定角色身份 | 普通归档/离场保留，防止历史主体悬空 |
| `runtime_character_initial` | 加入战役时的不可变初始卡头及其领域内容 | 不随当前状态更新 |
| `runtime_character_current` | 当前名字、PC/NPC、记录状态、版本及各领域当前状态 | 由获准业务命令修改 |

上述为目标结构责任，不是已应用 SQL。一个角色身份恰有一个初始头和一个当前根；不建立
没有战役的角色根。初始卡可以是任意合法加入等级，不等于一级创建快照，也不等于本次
导入时的当前卡。恢复不得重新套模板、升级、掷骰或从初始值推算缺失当前值。

## 身份与引用

- `campaign_key` 和 `(campaign_key, character_key)` 是可移植业务身份，恢复原样保留。
- `run_id`、`snapshot_id` 和本地战役/角色行 ID 在独立导入时重新生成，不进入产品文件。
- 新根的 UUID 使用严格 UUIDv4 网络序 16 字节；本地数值 ID 使用 Java `long` 可精确表示
  的正有符号 BIGINT。旧 v1 的物理列不因这个目标改变。
- 同一角色、战役、run、snapshot 的复合归属贯通到所有领域子行；规则引用使用该行同一
  `snapshot_id` 加领域键。只查全库 `character_key` 不能选择活动对象。
- 名称允许重复，不参与身份匹配；名称为 NFC、1—80 Unicode 码点并拒绝控制字符和空白值。
  恢复/存储读回拒绝不规范值，不能悄悄改写历史名称。
- 本地 `row_version` 用于聚合并发，独立导入从 0 开始；不从文件恢复，不因只读或重放推进。

PC/NPC 表示角色类型；ACTIVE/ARCHIVED 表示记录管理状态。它们不表示账号权限、生命状态、
轮到谁或当前运行是否可执行。业务状态、初始状态和技术生命周期各自只有一个权威来源。

## 完整业务历史

所有历史类型共享战役内一份根事件序号空间，当前状态来源引用这份根。目标责任分别为
事件尾、公共事件根和各类型历史正文；不并存可独立漂移的 `stateEvents`/`recentEvents` 根。

稳定历史身份是 `(campaign_key, event_sequence)`。序号和事件尾是精确有符号 long，不能
经过浮点或 JavaScript Number 丢失精度。新业务按尾分配下一序号，并与状态、类型化历史、
版本、计费和幂等结果一起提交；失败不推进。恢复保留原序号和尾，不按插入次序重编号。

保存覆盖全部已记录业务历史，最近若干条只用于 UI。恢复不补造未记录历史，不把序号空洞
填成 NOTE；尾不小于现存序号，保存时必须独立比较全体已存根及正文，不能借允许空洞删历史。
不执行历史来重建当前状态，也不恢复旧命令的幂等执行权利。

独立 DM 消息 `NOTE` 是首个完整设计的历史类型：一根一正文，无角色主体、骰子或效果。
检定附带消息属于该检定根，不能改装成独立 NOTE；未知历史类型不能降为通用文本。
类型化来源还须检查事件类型、主体和领域资格，外键存在本身不足以证明来源正确。

归档或离场的角色、已消耗物品和已关闭过程仍须保留历史所需引用。完整删除只属于可靠
结束的工作集清理，不能在普通业务中删去身份再用名称或空引用替代。

## 采用前必须补齐的内容

完整初始卡、ASI 后属性、职业成长、熟练来源、装备/同调、资源、效果、位置、战斗过程、
法术状态和各类历史都需要准确的字段所有者、引用闭包、版本推进和存档映射。目录存在、
根表存在或数组为空，都不能证明领域已覆盖。

已有[角色目录](../../rules/character-catalog-v2.md)、[一级创建](../../rules/character-creation-v2.md)、
[成长](../../rules/level-advancement-v2.md)及[内部角色存档切片](../../rules/archive-format-2-character-state.md)
可以作为实现入口，但其旧 DRAFT 物理形状和最小事件闭包不是新完整状态/历史的兼容目标。
