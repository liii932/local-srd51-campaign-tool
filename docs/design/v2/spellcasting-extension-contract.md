# v2 施法授权、成本与效果扩展合同

本文定义从有限职业 profile 走向可扩展施法入口的**目标语义合同**。新增类型和行为尚未
接入实际作者、执行或文件读写。现行施法见[施法作者来源](../../rules/schema-2-spell-authoring.md)
及[有限施法合同](../../rules/schema-2-spells.md)。新增机制需连同规则支持门、实际消费者及
完整文件生命周期分别采用。[采用边界](adoption-boundaries.md) · [领域接合表](domain-integration.md)

公共身份、准确版本、覆盖链和机制支持沿用[模组接口基线](module-interface-baseline.md)；
暂停、反应、一次继续沿用[动作继续协议](action-continuation-protocol.md)；实例、压制、
重叠、专注和结束沿用[持续效果协议](ongoing-effect-protocol.md)，施法的空间与时钟归属
沿用[世界与场景](world-and-scene-spaces.md)。这里只补施法领域的
producer、输入和消费接点，不建立第二个施法栈、效果栈、时钟或可写法术位副本。

## 当前证据与职责边界

现行 `Schema2SpellRules.prepare/spend` 接受生命领域一级 Bless/Cure Wounds，以及单职业
Wizard 1—5 级已学且已准备的 Shield/Counterspell；`Schema2WizardSpellbookRules` 拥有
真实学习、准备及长休标记；`Schema2ActionFlowRules.beginCast/applySpell` 连接付款、窗口、
具体效果与 Ready。另有[有限 Burning Hands](../../rules/schema-2-spell-save-damage.md)
真实入口及其一至三环共享伤害，受自己较窄的区域、装备和特性守卫。法师元数据名单
可学习、可准备，不因此可执行。法术位、组件、目标和效果仍由这些有限 profile/算法约束。

| 责任 | 目标 owner 与边界 |
|---|---|
| 运行核心 | 提供准确规则绑定、权限、事务、CAS、幂等、保存预算与恢复保障。 |
| 应用共享动作机制 | 管理焦点空间的动作继续、触发窗口、选择与执行时机，按领域结果推进真实后继。 |
| 应用规则机制 | 资格、法术元数据/效果规格的类型与值域、组件替代、支付/中断时点、升环、目标及结果算法；每个新机制同时交付来源 reader、真实 consumer、历史、恢复和负例。 |
| 模组 | 用完整规则/条目身份声明内容、授予关系、可学习名单和已支持的有限机制参数，保留出处和覆盖链；不能提交类名、handler、SQL、自由表达式、阶段或 callback。 |
| 角色/怪物/物品领域 | 拥有真实获得、已知/准备/法术书、资源余额、物件/手位和使用次数。目录配置或用户勾选不产生这些事实。怪物/物品授权须有其真实领域 producer，不能伪造角色职业。 |
| 施法领域 | 选择一份真实授权，生成完整计划，接受一次成本，保存 cast/work/Ready 的进展及结果引用；具体健康、攻击、豁免、位置、条件和持续结果交给各唯一 owner。 |

内容扩展分开判断“规则声明合法”“角色取得资格”“这次可以施放”“全部效果可执行”。
通过前一项不能补后一项；未知但可能影响本次施法的特性、条件、反应或后继阻断接纳，
不能按名称忽略，也不能一概认为所有 `BLOCKED` 特性均无影响。

除已登记的有限 Burning Hands 位阶外，当前仍拒绝通用升环、等级 0、bonus action 法术、
长施法/仪式、通用组件袋/耗材、
多职业/Pact、怪物/物品施法、Dispel、Magic Missile 与其余未接入效果。现有正常可见
平面场景之外的感官、遮挡、区域和条件也须相应 reader；本文不是这些限制已解除的证据。

## 类型化授权与真实资格

以下是服务端语义必要集。引用使用完整结构化规则/条目身份并绑定同一固定快照；业务键
可移植，本地 run/snapshot/CAS 另核。每个 union 分支只接受自己的字段，未知、重复、
缺失、坏类型和超界均拒绝；不能用一个 `options` 或 `extra` JSON 袋填补未定类型。

| 类型 | 必要字段与不变量 |
|---|---|
| `CastingGrant` | 稳定 grant 键、施法者 `CreatureRef`、真实获得事实及其 owner、准确授予规则/条目、资格策略及版本、法术成员关系引用、施法能力/DC 策略、资源许可、组件/仪式许可引用、有效状态及失效原因。grant 是获得事实与冻结规则的类型化投影，不是新的可随意增删能力表。 |
| `SpellAccess` | 准确 grant/spell 及成员条目；封闭分支为真实已知、已知戏法、职业名单且真实普通准备、法术书且真实普通准备、始终准备、法术书仪式授权、实际物品授权或实际怪物授权。分别引用职业名单/学习/准备/获得事实；始终准备与普通准备名额分开。法术书仪式分支可不要求普通准备，但只许可 `RITUAL` 且必须有真实仪式特性；书中存在本身不许可普通施放。 |
| `CastIntent` | 施法者、准确 grant/spell、`NORMAL/RITUAL/READY_PREPARE/ITEM` 模式、服务端给出的资源选项键、该机制允许的目标/原点/有限选择、真实材料绑定及完整预期版本；反应另带准确窗口/机会/父 cast。铭刻时储存的施法另为铭刻计划的内部子计划。不能提交能力修正、DC、骰点、强度、成本结果或“已满足组件”。 |
| `CastPlan` | 服务端验证后的授权/法术规格、实际获得与成员依据、基础环级和本次有效环级、资源/组件支付计划、时间/work 计划、目标证明、能力/特性贡献依据、全部效果/反应/持续后继及容量闭包。计划无 RNG/写入，不把可变事实永久冻结为当前状态。 |
| `CastAttempt` | 稳定 cast 键、准确 grant/spell/机制版本、原意图及模式、work/turn/flow 来源、声明与成本收据、当前领域阶段、已完成前缀、具体效果及合法失效结果、Ready/holder/子计划引用。帧只引用它，不复制资源或效果状态。 |

资格检查必须分别使用真实职业等级、总角色等级、获得特性和法术学习上限。共享法术位的
有效施法者等级只决定共享池，不能把高环位变成某职业已能学习或准备高环法术。
同一 spell 来自两份 grant 时，用户明确选择一份；能力、名单/准备、仪式许可、focus 与
资源许可均按该份授权组合，禁止从另一份 grant 借条件。确有跨授权资源规则时，须由
明确的资源许可关系证明，不能靠“都是法术位”自动放行。

资格策略按所选模式检查：牧师/德鲁伊式普通职业名单准备与法师法术书准备分别有真实
准备事实；法师未准备法术的仪式例外只由 `RITUAL` 消费。`NORMAL/READY_PREPARE` 不得
借该例外绕过普通准备，仪式也不能借另一 grant 的名单或特性通过。策略为应用封闭
登记，不允许模组用任意布尔表达式拼出新的资格规则。

授予引用或名单被禁用时保留获得/学习历史，拒绝新的选择或声明。已声明 cast 与既有
持续来源沿原固定规则和已登记失效政策继续，不因重新查询目录而重施法、退款或消失。
运行材料不热切换；恢复仍核原准确组合，不能借新来源补缺失资格。

### 实物授予、储存与释放

物品模式消费[物件 producer](objects-and-magic-items.md#wand-charges)的
`ItemActivationGrant`。必要字段为真实物件、激活者、取得/同调/装备与压制见证、完整
魔法物品/法术条目及激活分支、实际资源与有效环级、组件例外、施法动作和能力/DC 来源。
它只授权当前尝试，不创建学习、准备或同调事实。火球魔杖按实际手持与同调验资格，
固定 DC 15，消费充能与一个 action，无角色位和 V/S/M；范围、豁免、点燃及升环照同一
Fireball 消费者执行。组件豁免不产生可见施法见证。销毁发生于付款后时，已接受的 cast
凭付款见证继续，不重验持有、改用另一根或再次扣费。

`SPELL_GLYPH` 的铭刻选择包含准确的储存法术及真实准备授权。实际有效环级不得高于
Glyph 所用位阶，三环 Glyph 至多储存三环，含满足资格的已准备戏法。法术的冻结目标规格
必须为恰好一生物或一个区域；可选多目标规格只有在其明确允许的实际档位为单目标时才合格，
例如选择一名生物的一环 Bless。
多目标、只指物件、需要额外未提供触发的反应、没有可用效果消费者或无法支持触发替代的
目标模式，在铭刻预检拒绝。必须预检单一触发者替代、区域居中或特定生成分支及所有
已冻结效果后继，不能等触发才发现未知效果。

铭刻是单一 `GLYPH_INSCRIPTION_WORK` 时间计划。Glyph 工作为最后连续 3600 秒；另一个
法术的实际正常/仪式施法若需要长工作，取其真实连续时长为尾段，同边完成，两者重叠
时是此专用组合的一次工作 action 和一个 holder。储存一 action 法术占最后一次工作
动作的一部分。组件和可见施法在各子工作的准确区间分别成立，最终一 action 法术也有
自己的可见施法窗口。预先证明两个真实施法的组件/手位可共存；同一消耗品或同一最后
法术位不可被两个成本计划重用。任一子施法被反制或合法失败时，未完成的组合以原因
终止，保留已接受的工作 action/时间；最终完成边的付款事务仅在两者均成功时接受。

铭刻完成同根保存 Glyph 的成本、另一个法术的真实施法及其独立位/其他资源和材料成本，
保存 `StoredCastReceipt`。收据含 Glyph、储存 cast、原授权与真实准备事实、完整法术/
效果版本、有效环级、铭刻时采样的 DC/法术攻击值与施法者贡献、完整效果模式/参数及原
持续时长，储存 cast 结果为 `STORED`，此时不执行它的立即效果，不额外扣工作 action。
仪式只有在自身 grant 有真实许可且仍真实准备该法术时可作储存施法；按其原仪式时间、
组件和无位分支保存，不能用物品、未准备的法术书仪式例外或无来源的免资源路径替代。

`GLYPH_RELEASE` 是原铭文[一次触发](objects-and-magic-items.md#glyph-lifecycle)和
`StoredCastReceipt` 共同授权的内部效果分派。无第二次角色 cast、组件、位、动作、
反应、施法前反制窗口或施法者当前资格/距离检查；历史中的储存者只给出冻结施法参数。
释放以真实触发者为输入，按下列确定替代重建目标，保留合法失效结果和已消费触发。

| 储存效果 | 触发替代与输出 |
|---|---|
| 单一生物 | 唯一指定目标是触发者，取当时实际形态和有效目标特征。原施法者的射程/触摸位置不参与二次检验。效果本身限定的生物种类、免疫或其他必要资格仍适用；合法触发但不适用记录 `TARGET_UNAVAILABLE`，不换目标、不退回铭文。 |
| 区域 | 原点替换为触发者当时位置，用准确效果的区域形状、半径、布局和传播读取完整集合。方向等非目标参数须在铭刻时按该规格合法固定，或者由准确规格从触发事实派生；不在释放时调用缺席施法者重新选择。 |
| 敌对召唤或有害物/陷阱 | [生成 owner](character-state-and-history.md#召唤主体群组先攻与退场)预检整个组的合法位置，以到触发者的空间距离从近到远，再按空间 owner 稳定坐标序分配。实际生成事实指定触发者为攻击目标，沿冻结攻击/陷阱机制执行其准确后续，保留生成、位置与后继收据。无足够合法位置时保存该分支的失败结果，无部分假生成或任意挪近。 |
| 原需专注的持续法术 | 从真正释放开始使用原有效环级和参数的完整最大时长，建立独立 source，存续条件为 `FIXED_DURATION_FROM_GLYPH`。以释放空间的 `DOMAIN_ELAPSED` 计结束期限。不占用或重获任一生物 holder，不依赖已触发而 ENDED 的 Glyph 继续活动。驱散、适用的压制及效果专有结束仍按其真实规则，伤害不产生替这个 source 维持专注的检定。 |

释放预检不足以闭合真实机制时，在铭刻时就拒绝该储存配置。缺少对应敌对召唤、物件/
陷阱、方向区域或完整持续参数的通用储存标签本身不授予执行资格。

## 法术规格与资源选择

目标 `SpellSpec` 至少含基础环级 0—9、学派、仪式标记、类型化施法时间、射程/目标政策、
V/S/M 需求、持续/专注政策及准确效果规格引用。学派只作为可被特性引用的分类，不自行
产生效果。字段的原子覆盖、组合约束和编码须与具体作者类型一起交付；现行“算法拥有
全部字段”的合同在前向采用前继续有效，不能先放开自由字段再补消费者。

`ResourceOption` 由服务端从所选 grant 与真实余额枚举，绑定准确池/使用规则、位阶或
次数、恢复 owner 及许可关系。请求选择一个准确选项；提交时重验，不自动改成更高位、
另一个池或免费施放。slot 消费、特性次数、物品 charge 和材料是不同成本项，不共享
一个无语义的 `amount`。等级 0、仪式等无 slot 模式使用明确 `NO_SLOT` 许可，
不绑定虚构池或零环位；其他次数/材料仍分别判断。资源恢复仍由原休息/物品/特性 owner 执行。

| 施法分支 | 必须分别保存并验证的语义 |
|---|---|
| 普通有环法术 | 选择实际可用且位阶不低于基础环级的许可法术位，消费一次；本次有效环级为所用位阶。没有该位阶的数值增强仍允许依规则升环，不能因此少付成本。 |
| 升环 | 各效果规格分别定义目标数、骰数、持续或其他真实变化；不能通用地每环加一个骰。Bless 的额外目标不增强单目标 d4。有效环级供 Counterspell/Dispel 判断，效果强弱比较仍按持续协议的具体比较器。 |
| 等级 0 | 真实已知戏法，环级恒为 0，无 slot 项，保留时间和组件；成长增强按该戏法登记的等级依据求值，不能以 slot 或职业等级默认代替总等级。 |
| 仪式 | 同时满足 spell 的 ritual 标记与该 grant 的仪式特性；按特性判断已准备/已知或法术书例外。施法时间额外十分钟、无 slot、有效环级为基础环级，不能升环；组件和长施法专注仍适用。 |
| 特性/物品/怪物免 slot | 必须有真实准确授权、规定有效环级、能力/DC 来源、次数与组件例外。免 slot 不意味着等级 0、仪式或免组件；未完成该 producer 的分支保持拒绝。 |

多职业共享位与 Pact Magic 以后可产生不同的合法选项；必须复用真实唯一余额。
[共享位基础](../../rules/multiclass-spell-slots-v2.md)目前只计算上限/适用性，不提供当前
共享池、Pact 位阶/恢复或完整施法授权，不能据此开放多职业施法。初始、学习、抄录、
准备、遗失/替换法术书与施放是不同命令；未来法术书实物关系不由一个学习列表冒充。

## 组件、成本与不可退款接受点

`ComponentPlan` 保存 V/S/M 各需求、真实状态依据和所选满足方式。组件豁免必须来自
真实特性/使用规则，不能由客户端布尔值或缺省字段声明。装备/物件 owner 证明所有权、
位置、可用手、数量、准确定义及状态；施法 owner 不建立另一份库存。

| 需求 | 决策合同 |
|---|---|
| V | 证明能正常发声并核对 gag、silence 等真实限制。没有感官/条件 reader 的相关场景拒绝，不能把未记录当作确定可发声。 |
| S | 至少一只可自由使用的手；没有 M 的 S 法术不能仅因持有 focus 视为满足。手被占用时须有准确已支持的例外。 |
| 普通、不消耗且无标价 M | 实际组件、可用组件袋，或该 grant 允许且实际可用的 focus，三者按明确分支选择。访问材料/持 focus 的同一只手可以满足该法术的 S；不凭“背包里有圣徽”推定可用。 |
| 标价 M | 必须绑定满足准确种类、数量与最低价值的真实物件；focus/组件袋不能替代，不自动把钱扣成材料。价值用精确货币最小单位，估值来源须有可审核领域事实。 |
| 消耗 M | 每次必须提供真实组件，即使未标价也不能以 focus 代替；按该法术的准确消耗规则产生库存变化。标价且不消耗的物件保留，不得通用扣除。 |
| 护甲/其他限制 | 复用真实护甲熟练及获得/条件限制；免组件不自动免护甲限制。focus 种类和佩戴/盾载圣徽等具体使用方式由授权与装备合同共同证明。 |

`CastCostReceipt` 是不可变业务事实，按 cast、成本种类与 ordinal 唯一，记录接受事件、
准确资源/物件及前后值、数量、真实 action/bonus action/reaction/work 消费引用；它不是
第二份余额。当前已接入法术没有材料消耗，实物能力的采用仍受各现行分支约束。

| 接受点 | 成本与专注的准确后果 |
|---|---|
| 预检未通过 | 不消费动作、slot、材料或 RNG，不替换旧 holder，不创建“失败 cast”来掩盖不支持。 |
| 一 action/bonus action/reaction 的 `DECLARE` | 完整预检成功后同事务接受对应动作、slot/次数及应耗材料，保存 cast，再开放真实施法完成前窗口；若需专注或 Ready 持有，同时结束旧 holder 并取得新 holder。 |
| 长施法 `START/WORK` | START 验证本工作与可达后果并取得 `CASTING` holder。实际投入 action 或承诺有界探索工作段后开放适用窗口；通过后从真实时间边取得工作信用。slot 和只在 DECLARE 应付的材料尚不消费；已发生时间/action 不因失败退回。 |
| 长施法完成的 `DECLARE` | 重验原选择的实际余额、组件、当前资格/目标及完整后继后，只接受尚未支付的 slot/次数/材料；最后一次工作 action 已支付时不得再扣一次。依机制可合法失败则保存真实终态，不能临时换资源。 |
| 已 DECLARED 的反制、后续打断/目标失效 | 保留接受成本；按准确效果政策记录 `COUNTERED/INTERRUPTED/TARGET_UNAVAILABLE` 或部分结果。不能统一空效果 `RESOLVED`、退款或恢复旧专注。回滚则全事务均未发生。 |
| Ready 准备/释放 | 准备时正常 DECLARE 并支付，接受 Ready 的唯一 holder；释放仅消费 reaction 及持有结果，无第二次 slot/材料/组件检查或 Counterspell 声明。范围、目标与失效按该 held 效果的 release 合同重验。 |

以上 DECLARE 是项目采用的成本边界。长施法开始后、完成声明前若被反制或失去专注，
保留已接受的工作前缀和动作成本，未接受的位和消耗材料不扣。显式重试必须新建工作。

## 时间、回合、Ready 与反应接点

施法时间类型分为 `ACTION/BONUS_ACTION/REACTION/LONG_WORK`；REACTION 必须绑定已登记
真实触发，不能把任意法术放进反应窗口。常态法术攻击、豁免和持续转换作为原 cast 的
普通 `CONTINUATION` 子计划，不再消耗 action，不增加反应深度。真实反应由施法所在
空间的 flow 安排，沿公共协议保存父 checkpoint、决定和已接受前缀。

同一 turn 的施法历史必须包含**所有人的**真实 cast 与各 actor 的 action 类型；另按
施法者筛选本 turn 的限制。本人用 bonus action 施法后，同 turn 其他施法只允许施法
时间一 action 的戏法；反向也须验证，先反应或施放有环 action 法术后不能再补 bonus
action 法术绕过。限制不按 round 泛化：在别人 turn 的 reaction 使用那个 turn 的历史。
合法接受后被反制仍留作已施放声明事实，不抹去成本/turn 限制；无资格请求不写此事实。

现有 INTERNAL 施法核验同场景各角色共同秒值。
目标的工作与时长由[时间 owner](time-and-calendar.md)按具体机制的空间、个人经历或
回合边界计量，沿持续协议的 occurrence/cursor 与准确待处理余集逐截止边界结清义务。
背景空间的施法工作、Ready、专注与时间保留原进度，切回以新焦点代次重验资格和后续依赖。
主动根施法不借跨空间许可在后台开始，未完成工作也不能跨空间搬迁。真实反应只在其已
登记的因果范围内，以准确见证和受限叶子接纳；它不是后台普通施法入口。已合法建立的跨空间持续效果按其具体机制和
[因果范围许可](world-and-scene-spaces.md#causal-scope)结算。明确允许随主体迁移的空间秒
期限按时间合同重绑，个人经历期限和已有周期游标保持原进度。

<a id="long-work"></a>
### 长施法的工作边、反制和完成

`CastingWork` 保存稳定 cast/work 键、原始授权、模式、目标或铭刻对象、所选位与材料
计划、要求秒数、真实已赚秒数、所属空间和时间域、唯一 `CASTING` holder、工作段有序
表、下一段与中断/完成事实。施法时长来自准确规格的正整数秒，目标值域为 1–86400 秒
（另按仪式规则加 600 秒）；超出采用范围的时长在 START 拒绝。每段保存
`(castKey, workOrdinal)`、准确 turn/时钟跨度、先决状态与组件见证、action 或专用
时间计划收据、窗口及真实已耗时间前缀。合法等待下一段本身不占活动 flow。

1. `START` 是首个 `WORK` 段，不产生重复声明或窗口。先预检真实授权、原选择、组件、
   当前目标、所有可达消费/反制/效果后继和容量。接受第一段时，结束旧专注并取得
   `CASTING` holder。在战斗接受该施法者当 turn 的唯一工作 action；探索明确接受一段
   连续排他工作计划。每个接受的工作 action 记入所在 turn 的真实施法 ledger，不是新的
   cast 或位消费。该 turn 有 bonus action 法术时不能接受此工作，已有工作时也不能再
   接受其 bonus action 法术。
2. 工作段接受之后、该段时间/工作信用开始兑现前，按[反制见证](#counterspell-witness)
   为可观察的实际施法发出 `CAST_BEFORE_COMPLETION`，同一工作序号最多一次。组合铭刻
   的同时活跃子施法按开始序及 cast 键各产生其自己的真实窗口。无合资格见证时记录空
   窗口或无窗口原因。成功反制则终结目标 cast/work，撤去同一 holder，本段尚未推进
   的秒数不消耗，已接受 action 和以前秒数保留。普通工作不中途收 slot/material。
3. 通过窗口后，时间 owner 按实际截止点推动本段。探索按时间计划确认连续工作秒数，
   首段及后续观察者/遮挡/条件变化边都须处理；连续、同一见证和无新反应资格的区间
   可合为一段，不能跨过真实义务。战斗要求从 START 所在回合起，施法者每个本方实际
   turn 至结束前支付工作 action。对应实际共享战斗时间边、且该轮已支付工作时才给
   信用；整轮标准六秒时只记该空间时间推进一次，不在每个工作 action 再加六秒。
   开始于部分时间段时只赚 START 后实际经历、属于该计划的秒数。漏投、失去 holder、
   失去持续组件能力/材料访问或离开要求持续接触的目标，均以准确边界中断。角色、
   装备和条件 producer 应在变化时生成中断，而非等待下次查看。
4. 同空间战斗/探索切换时交接已发生时间/工作前缀、待赚信用、源段和目标时间边，保留
   连续性及已接受 action；不得按模式重复计秒。有效目标的身份在 START 固定，后续
   验证原目标和组件；需要持续触摸的 Glyph 每段验证原表面/容器。明确在完成时采样的
   目标集合或区域在最后工作边重读。焦点冻结不赚信用，切回重验同一段的执行资格。
5. 到达要求信用且最后工作段窗口已消费后，重验所选余额、原授权、组件、目标和全部
   后继。一次 `DECLARE` 只接受本次实际位、次数和材料，完成动作已在工作段接受。
   此完成边没有同一最后工作段的第二个反制窗口；同一提交的效果/持有转交按具体机制
   执行或保存准确后继。原目标或余额合法失效时记录准确终态，不能改用其他位、物件或
   目标。异常回滚仅撤回未提交部分，先前真实前缀和同一 work 的继续身份保留。

战斗回合结束时须结清的工作段和最终声明进入[回合收束](action-continuation-protocol.md#closing玩家步骤和终结预留)
的准确队列，可能先保存当前 `CLOSING` 及其子窗口。收束继续不重新接受工作 action 或
推进已经记账的时间。

<a id="readied-spell"></a>
### Ready 的准备、等待与释放

Ready 只准备施法时间一 action 的法术。准备是实际 `READY_PREPARE` cast，接受原
action/资源/材料、转入唯一 holder，并在准备时按真实见证产生反制窗口。准备成功保存
`HeldCast`、原 cast/成本/效果引用、准确可感知触发、目标政策、原施法地点/有效环级、
持有状态和本人下一 turn START 截止。Prepare 被反制则无 HeldCast，已接受成本保留。

目标政策为 `LOCKED_AT_PREPARE` 或具体效果登记的 `CHOOSE_AT_RELEASE`。前者准备时
验证并保存固定选择，释放时从当前施法者位置重验原选择；后者准备时预检有限选择族及其
最坏闭包，真实触发完成后才服务端枚举所有合法选择，选择或放弃沿原 Ready 窗口。
两者在释放时都重建实际效果目标快照，不从准备时的区域名单执行。原目标合法失效时只给
不适用原因或允许忽略该机会，不能临时改选；待触发期间的 PASS 不消费持有状态。

真实释放消费一次 reaction 和 held 能量，不再声明施法或检查 V/S/M、位、材料，也没有
第二个 Counterspell 窗口。法术本身需专注时，将原 holder 转交真实效果 source；瞬时效果
结束持有。超期或失去 holder 的 held 能量永久失效，不重新取得专注。保存原准备/触发
事实、当前窗口及选择、是否已释放、目标快照和准确后缀，重复 RELEASE 不产生新成本或结果。

## 效果分派与公共领域 owner

`SpellEffectSpec` 是应用封闭登记的分支及有限参数，引用准确规则/稳定效果条目和版本。
一份 `SpellEffectPlan` 明确输入、有限执行序、成本来源、目标/检定/伤害/持续 child、
失败与部分结果、返回 checkpoint 和保存责任。它只能组合已支持的具体领域类型，
不能形成可递归任意嵌套的 JSON 程序；新增分支由应用实现，内容包不注册执行阶段。

| 分支与接点 | 必须交付的真实消费者 |
|---|---|
| 直接治疗/临时 HP | 健康 owner 取得精确目标、服务器骰/能力贡献、类型限制和应用量；保留原骰、requested/applied、上限与死亡/稳定等后果。生命门徒是所选真实获得特性的治疗贡献，不写死进所有 Cure Wounds。 |
| 法术攻击 | 攻击 owner 取得真实 cast 来源、近战/远程种类、目标、能力/PB 与当前贡献；复用攻击 CheckPlan、Shield 等真实命中窗口和 DamagePacket。无武器/Extra Attack action，不凭 spell 标签跳过近敌远程劣势。 |
| 豁免/共享伤害 | 目标/空间 owner 先证明完整目标集合，再通过共享检定核、伤害/健康/专注 consumer；沿[多目标豁免伤害](multi-target-save-damage.md)登记真实 cast 来源及自己的参数/阶段，不能把地狱猎犬 action 假装成 spell 或另写逐目标扣 HP。 |
| 无攻击的直接伤害 | 必须另登记真实 target、共享或独立骰、各 packet 的来源分组、免疫/防御与伤害后义务。Magic Missile 的 Shield 防护、飞弹分配和专注伤害来源划分未闭合前仍拒绝；不能从元数据或普通攻击窗口借用。 |
| 持续/条件/区域 | 产生持续协议的准确 source/application、贡献组、holder 依赖与期限；每个效果另定义同名强弱、压制范围、目标级结束和回调。沿空间/条件 owner 改真实状态，不保存并行布尔值。 |
| Counterspell/Dispel | 前者指向仍在准确声明窗口的 cast；后者选择 creature/object/真实魔法效果，再完整枚举该目标上的 spell application。两者均使用目标本次有效环级判断自动分支；需要能力检定时，以所选 grant 能力通过共享能力 CheckPlan，默认不加 PB，真实适用贡献仍须完整枚举。 |

公共目标引用区分 creature、object、point/area 和 spell source/application。射程 self
不是只可影响本人，touch 也不是通用的“五尺内任意对象”；目标种类、可见/可听、清晰
路径、尺寸/类型、友敌/自选和排除条件由具体规格校验。区域不能用用户给出的生物子集
代替完整场景 reader。范围/目标采样在 DECLARE、release、检定或后续持续时点分别登记；
已经施放后默认不以初始射程永久束缚效果，原文有要求时另定。

采用普通施法能力公式的授权，save DC 为
`8 + 所选 grant 的能力修正 + PB + 真实适用贡献`，spell attack 基础为能力修正加 PB。
物品等固定 DC/攻击值必须用该授权的封闭规则分支，不能一律套角色公式或由请求指定。
Counterspell/Dispel 需要的检定属于能力检定，不是攻击或豁免，也不自动熟练。
所有原骰、贡献采样和后置修改保留准确 audit。

Dispel 先选择一个 creature/object/真实 magical effect，再完整预检该目标上的全部
spell，不能选中 creature 后由用户只挑其中一项 buff。自动结束所有三环及以下法术；
使用四环以上位时，自动阈值为该位阶；对其余每个高环 spell 分别执行一次能力检定，
DC 为 `10 + 该次 spell 有效环级`，成功才结束对应效果。必须保留每次原骰、结果与
目标 application/source，包含仍存续但 suppressed/shadowed 的可驱散 spell；目标级
结束范围与是否结束整 source 由具体类型登记，不能扫掉其他目标。非 spell 魔法不因
“magical”就自动可驱散，瞬时施法已经造成的健康/物件事实不倒退。固定 DM 抗魔环境
是当前接入的独立家规 producer。目标的真实移动场域、例外和魔法使用见
[Antimagic Field 合同](ongoing-effect-protocol.md#antimagic-field)，实际驱散/压制消费者
按对应机制分别采用。

Magic Missile 采用前须有每镖 ordinal→target 绑定、同时命中事实、共享伤害 roll 引用、
Shield 的真实指定后/伤害前 producer、防护结果及准确健康/专注 packet 身份。它没有
攻击检定，不能制造攻击命中窗口。SRD 的多目标同时伤害一次 roll 与每镖伤害须在具体
规格中对齐；同一目标多镖的伤害来源如何归组、专注检查次数如何派生，p.102 没有明确
给出项目所需分组算法。实施前须记录明确的项目解释并以单目标多镖、多目标、部分目标
有 Shield、降至零 HP 和中途恢复的独立向量验证，不能把每镖一检或全法术一检冒充原文。

<a id="counterspell-witness"></a>
### 可观察施法与反制检定

施法 owner 只对仍未完成的真实 cast 发出见证。见证含准确施法者、规则/授权、有效环级、
已接受动作或工作段、施法动作的可观察来源、前置业务版本、施法时间/空间及准确窗口。
正常瞬时法术、实际反应子施法、Ready 准备和长施法当前工作段可以产生见证；已释放
Ready、已消费铭文及持续法术的一次后果没有新的施法见证。

反制者的真实机会须同时证明施法者是生物、距反制者不超过 60 尺、反制者确实看见正在
施法的生物和该次可辨认的施法活动，且具有法术所需清晰路径。见证来源是实际可见的
手势、组件操作、看见发声者且听到真实言语成分，或特定授权登记的其他可见启动表现。
仅看见生物、看到施法已产生的结果、持有物品、观察到不明发声，均不足以证明看到施法。
空间 owner 负责独立的[视线和路径](spatial-and-area-contract.md#visibility)证明。范围、
遮挡、当前感知、反应资格、V/S/M、位和所选授权在选择时按原窗口版本复核；候选展示
不会泄露目标的隐藏环级或组件细节。自己所用法术的 DC 与反制检定 DC 分别计算。

Counterspell 的基础自动阈值为三环，使用四环以上位时为该实际位阶。目标本次有效环级
不超过阈值时直接反制，零检定骰。否则以实际 Counterspell grant 的施法能力作共享
`ABILITY_CHECK`，DC 为 `10 + 目标本次有效环级`。不默认熟练，登记规则能证明适用的
能力检定贡献才计入，允许合法掷后决定并保留完整 audit。反制子 cast 若先被内层反制，
不再发起自身高环检定。已发布结果由施法 owner 在原 cast/work checkpoint 消费一次，
成功按该目标实际成本阶段终结，失败回父继续。现行至多三环的真实入口仅覆盖自动分支；
不可从私有 d20/INT 路径推断上述共享检定已采用。

<a id="spell-target-snapshots"></a>
### 完整法术目标与 Fireball

`SpellTargetSnapshot` 由施法 owner 通过空间 owner 的
[`SpatialSnapshot/AreaResolution`](spatial-and-area-contract.md#areas)生成。必要字段为
唯一来源（真实 cast 或 `GLYPH_RELEASE` 收据）、准确效果/空间规则版本、实际施法位置
与请求原点/固定目标、实际区域原点、采样事件和阶段、射程、请求点阻挡和到实际点的
清晰路径证明、区域形状和传播证明、完整
生物集合及物件集合、过滤结果及原因、几何/安置/物件/受影响聚合的全部依赖版本与
采用的稳定序。区域使用同一几何结果分别求生物占位和物件形状的相交；隐藏或不向施法者
展示的真实目标仍参与，两个集合均由服务端枚举。成功时保留各目标的真实入口或确定
排除原因，不能靠客户端提交更少对象来避开后果。

| 采样阶段 | 校验和消费 |
|---|---|
| `DECLARE` 或准备前预检 | 重算选定原点/目标、空间证明、整个效果与反应闭包，校验全部输入和预期版本后才付款。Ready 尚待选择的分支预检有限选择域；储存施法验证替代合同，不预设未来触发者。 |
| `RESOLVE` 或合法 `RELEASE` | 反制和所有已登记效果前反应结算后、首次效果骰前，用当前权威状态重验原选择和完整闭包，接受本次效果唯一目标快照。原请求目标保持不变；若真实位置/布局变化，空间 owner 重验路径并按准确政策重定向或记录合法失效。Ready 按释放位置重验，Glyph 采用触发替代。 |
| 目标处理与继续 | 快照接受后固定此次命中集合与后继；已经发生的目标/骰/点燃不会重新枚举、改序或被移除。机制允许的内部反应改变后续具体防御/燃烧状态时，按其准确阶段重验并留下失效原因。外部旧版本、错焦点或错叶子拒绝；只用原快照、已完成前缀和未消费义务继续。 |

Fireball 由普通法术位、火球魔杖或合资格储存释放使用同一效果 consumer。普通/物品
模式要求请求点距实际施法位置至多 150 尺。有清晰路径时接受原点，是否可见不另设门槛。
不可见且有实体障碍时按[空间合同](spatial-and-area-contract.md#visibility)采用第一
阻挡面的近侧实际原点。保存原请求点的不可见及阻挡见证，并独立证明施法位置到近侧实际
原点的清晰直线路径。其他没有合法清晰路径的情况按阶段拒绝或记录实际效果失效。
只用实际原点求 20 尺三维球体与绕角传播。Glyph 区域替换为触发者处，效果形状/传播不变。
生物调用共享伤害分支，
`(8+有效环级−3)d6` 共用一次，DEX 成功向下取整一半，之后按真实防御和伤害协议消费。
物件调用独立 `IGNITE(objectKey)` 分支，只对传播触达、可燃、未穿戴也未携带的在场
物件应用；容器内物件的可达性读真实壳体与开启状态，携带状态沿装备/容器链解析。施法
起点、效果体积及物品魔法属性分别向[抗魔协议](ongoing-effect-protocol.md#antimagic-field)
提交 `MagicUseContext`。区域中的被裁切部分不产生生物伤害或点燃，已经发生的燃烧
事实继续归物件 owner。

顺序为完整预检及唯一快照 → 共享骰与逐目标豁免/决定 → 共享
[Fireball APPLY](multi-target-save-damage.md#fireball-damage)处理健康和点燃并发布
伤害后义务。生物集合为空时不产生共享伤害骰或豁免，但完整点燃计划仍须执行。
不合法的原点/读集/配置在相关接受点前拒绝；两个集合合法为空则为有效施法和零效果。
保存原共享骰、各决定、实际点燃及已完成前缀与未决余集，存档恢复只核对已发生原证据，
无需实时 RNG，也不从当前区域重建过去受影响目标。

## 状态、历史与直接恢复

施法相关权威变化、根事件、成本/骰/效果正文、引用、版本和接受结果共用短事务。各
Repository 使用调用方连接；版本/锁/幂等与 UNKNOWN 查证不在本领域重造。下表补充
施法特有数据；公共 flow、持续实例及本地控制的保存规则仍以相应协议为准。

| 数据 | 状态/历史与恢复核验 |
|---|---|
| 获得与可用法术 | 完整 grant/授予与获得事实、名单条目、学习/替换/准备前后值、等级和长休/工作标记；法术书关系、戏法、普通准备与始终准备分别保存。恢复不从当前等级自动补学或按名单补准备。 |
| cast 与付款 | 原授权/意图、模式、基础/有效环级、实际资源/材料选择、各接受点和成本收据、action/turn/work 来源、阶段/结果及全部历史；结果须与余额/库存因果子事件一致，不能由当前余额猜过去付过哪一池。 |
| 工作与 turn 限制 | 原始时间计划、所属空间与时钟/turn 关系、每段身份、组件见证、窗口、已赚工作信用/消费前缀、holder、中断/完成；直接恢复真实逐 turn cast ledger，含反应与 bonus action 施法额度。 |
| 效果和 Ready | 完整目标快照、子计划/audit/packet/source/application/结果引用、已完成前缀和合法失效、held cast/触发/释放及 holder 转交；结束和反制历史保留，不因当前已无效果而删掉成本原因。 |
| 物品与储存授权 | 实物、授予及 charge/最后充能事实和准确 cast 引用；完整铭刻、真实储存子 cast 的独立成本与 `STORED` 终态、触发/释放唯一收据与原参数。当前同调者或储存者状态改变不重写历史。 |
| pending | 全部空间的施法进度、所属 flow/叶子/checkpoint、焦点或冻结状态、准确反应/choice 和尚未执行余集。直接恢复原骰、决定、工作/时间前缀和已付成本。 |

独立 reader 必须验证 grant 的真实获得与原资格、各模式与环级合法、receipt 唯一、物件
消耗/资源事件对应、长施法的信用连续性、turn 限制、holder 唯一性与效果依赖、结果/历史
和全部入出引用。writer/reader 往返不足：还须独立逐字段比较权威源到文件、文件到恢复
及真实存储读回。当前版本支持的运行、文件读写和恢复须对齐同一规则及数据模型，缺失
分区、未知机制和不支持的解释或格式均拒绝。后续版本可采用新的数据和文件合同；真实
数据迁移、重建或清理分别授权。

技术 END 保存正在施法、持有、声明后窗口或结果中途的真实前缀；不自动中断/结束专注、
PASS、推进 work/时间或重试。文件保留准确规则绑定及因果引用所需的业务身份和版本。
物理运行标识、行 ID、请求收据与本地 CAS 属于运行控制。恢复重建本地映射、执行前置与
收束预留后，按新焦点代次和当前版本显式提交意图才能继续。

## 可独立验收顺序与未完成门

P0/P1/P2 表示依赖优先级，各行均可作为单独前向切片验收，不能以“设计已写”计为实现。
每行须贯通作者/组合、准确来源与镜像、真实资格/执行、状态/历史/独立恢复；纯计算函数
或新增目录不够。[机制责任清单](mechanism-integration-checklist.md)规定共同验收责任。

| 顺序 | 有界交付与独立验收 | 仍须闭合才开放的内容 |
|---|---|---|
| P0 授权/成本骨架 | 把现有法术及 Ready 的真实获得、选择、能力、资源与成本事实映射到上述类型。验收跨 grant 借准备/能力/圣徽/资源被拒、元数据不可执行、非法声明保留旧 holder、一次付款与嵌套反制/恢复。 | 接入原子作者字段、类型化存储/结果/编码和容量界，同一版本运行与文件读写使用一致模型。 |
| P0 组件证明 | 先覆盖现有 V/S、手持圣徽和护甲限制，完整保存判定依据/无材料支出；负例覆盖错误物件/手位/所有权、伪造豁免、声明回滚和重复请求。 | 组件袋、focus 种类/佩戴方式、标价/耗材的真实库存和值域；无 reader 的 silence/手部限制场景。 |
| P1 资源与基础扩展 | 分别接入真实升环、已知戏法和一个 bonus action 法术；升环目标/骰数与有效环级独立测试，戏法成长与无 slot 独立测试，双向 turn 限制覆盖本人/他人 turn 的反应和被反制记录。 | 每个实例准确规格/消费者与真实可取得资源；不能只降低等级门。多职业/Pact 继续关闭。 |
| P1 共享效果消费者 | 分别以一个法术攻击、完整 Fireball、一个高环目标的 Counterspell 验证真实 child 与返回；共用原骰、伤害/专注 owner、目标完整性及一次成本。 | 接入准确施法见证、区域/遮挡 reader、点燃 consumer、合法目标失效及共享 CheckPlan 贡献；地狱猎犬设计本身不补这些实现。 |
| P1 持续/驱散 | 用一个已闭合的多目标持续效果验证强弱/压制/结束，再以 Dispel 验证逐 spell 检定、目标级/源级结束与回调一次消费；恢复含 suppressed、shadowed 和 ENDED 待结义务。 | 按具体效果采用 potency、采样时点、目标结束范围、回调和非 spell 排除；真实 [Antimagic Field](ongoing-effect-protocol.md#antimagic-field) 按其合同单独接入。 |
| P2 工作/仪式与完整组件 | 先交付一种长施法和一个具准确资格的仪式，覆盖 START/WORK/DECLARE 各边界的中断、材料/slot 余额变化、跨模式时间、保存及重试；再逐组件模式采用。 | 实际接入工作/时间 owner、真实物件/书本、工作计费、反制及独立时序/故障向量。 |
| P2 魔法物品与储存 | 先按物件合同贯通魔杖的准确授予和共同 Fireball，再按工作、触发、双付款及实际释放闭合 Glyph of Warding。 | 接入物件、日历、同调、一次释放及已登记效果的完整真实 consumer；储存法术的其他未登记分支按各自采用门。 |
| P2 其余授权与能力族 | 按机制族接入其他职业已知/准备、共享位/Pact、抄录/恢复、特性改法、怪物及其余效果，每个实例填写完整机制责任。 | [区域](spatial-and-area-contract.md#areas)、[召唤](character-state-and-history.md#summon-lifecycle)、[变形](character-state-and-history.md#form-health)及已登记的[传送抗魔边界](ongoing-effect-protocol.md#antimagic-field)按各自合同接入实际消费者。其他授予/替换、资源/组件例外、学校特性、复合选择及信息类效果按实例定义与采用。 |

最小怪物动作与地狱猎犬吐息可先独立采用真实 action/充能、完整区域目标、共享伤害、
逐目标豁免、反应/专注与恢复；它不依赖完整法术目录。施法接入其公共核时仍须自己的
真实 cast producer，怪物施法则另需真实 monster grant，不能把这两条依赖倒置。

其余 SRD 按机制族扩展时，角色、法术、怪物、装备、魔法物品和冒险分别提交从准确来源
到 consumer 的闭环，优先复用上表已采用 owner；一个职业学习名单或一个 spell metadata
集合不代表该族完成。完整文件与运行生命周期集成最终必须覆盖这里全部稳定状态和
pending：自动/FINAL 保存、直接恢复、清理/修复、同版重启显式恢复/救援、容量与制品保管分别验收，
不能只保存当前有限法术的活动效果头便开放完整运行。

所有新增实例都要有正常/边界、坏冻结规则、禁用/未知机制、旧版本/幂等、容量前拒绝、
事务故障/禁止部分写和中途直接恢复的独立向量；测试范围随所改机制选择，不以重复全套
掩盖缺失的真实消费者。实际采用以新增机制在准确本机规则组合、运行入口和完整文件中的
贯通证据为准。数据库与真实数据操作、安装接受、发布和部署分别核验授权。
