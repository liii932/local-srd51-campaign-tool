# v2 施法授权、成本与效果扩展合同

状态：本文补齐从有限职业 profile 走向可扩展施法入口的**目标语义合同**。下列类型不是
已经发布的 Java、作者 JSON、SQL、HTTP 或存档字节格式，不预留迁移编号。当前实现仍以
[施法作者来源](../../rules/schema-2-spell-authoring.md)和[有限施法合同](../../rules/schema-2-spells.md)
为准；本文不扩大 INTERNAL、完整 base、Host 或 archive format 2 的资格。

公共身份、准确版本、覆盖链和机制支持沿用[模组接口基线](module-interface-baseline.md)；
暂停、反应、一次继续沿用[动作继续协议](action-continuation-protocol.md)；实例、压制、
重叠、专注和结束沿用[持续效果协议](ongoing-effect-protocol.md)。这里只补施法领域的
producer、输入和消费接点，不建立第二个施法栈、效果栈、时钟或可写法术位副本。

## 当前证据与职责边界

现行 `Schema2SpellRules.prepare/spend` 接受生命领域一级 Bless/Cure Wounds，以及单职业
Wizard 1—5 级已学且已准备的 Shield/Counterspell；`Schema2WizardSpellbookRules` 拥有
真实学习、准备及长休标记；`Schema2ActionFlowRules.beginCast/applySpell` 连接付款、窗口、
具体效果与 Ready。法师元数据名单可学习、可准备，不因此可执行。法术位、组件、目标和
效果仍被这些有限 profile/算法封闭，不能从存在某个私有分支推断公共消费者已采用。

| 责任 | 目标 owner 与边界 |
|---|---|
| 框架 | 准确组合/固定快照、共同守卫、事务/CAS/幂等、唯一 flow、历史与保存预算；调度已登记机制，不解释法术正文或任意脚本。 |
| 应用规则机制 | 资格、法术元数据/效果规格的类型与值域、组件替代、支付/中断时点、升环、目标及结果算法；每个新机制同时交付来源 reader、真实 consumer、历史、恢复和负例。 |
| 模组 | 用完整规则/条目身份声明内容、授予关系、可学习名单和已支持的有限机制参数，保留出处和覆盖链；不能提交类名、handler、SQL、自由表达式、阶段或 callback。 |
| 角色/怪物/物品领域 | 拥有真实获得、已知/准备/法术书、资源余额、物件/手位和使用次数。目录配置或用户勾选不产生这些事实。怪物/物品授权须有其真实领域 producer，不能伪造角色职业。 |
| 施法领域 | 选择一份真实授权，生成完整计划，接受一次成本，保存 cast/work/Ready 的进展及结果引用；具体健康、攻击、豁免、位置、条件和持续结果交给各唯一 owner。 |

内容扩展分开判断“规则声明合法”“角色取得资格”“这次可以施放”“全部效果可执行”。
通过前一项不能补后一项；未知但可能影响本次施法的特性、条件、反应或后继阻断接纳，
不能按名称忽略，也不能一概认为所有 `BLOCKED` 特性均无影响。

当前仍拒绝升环、等级 0、bonus action 法术、长施法/仪式、通用组件袋/耗材、
多职业/Pact、怪物/物品施法、Dispel、Magic Missile 与其余未接入效果。现有正常可见
平面场景之外的感官、遮挡、区域和条件也须相应 reader；本文不是这些限制已解除的证据。

## 类型化授权与真实资格

以下是服务端语义必要集。引用使用完整结构化规则/条目身份并绑定同一固定快照；业务键
可移植，本地 run/snapshot/CAS 另核。每个 union 分支只接受自己的字段，未知、重复、
缺失、坏类型和超界均拒绝；不能用一个 `options` 或 `extra` JSON 袋填补未定类型。

| 类型 | 必要字段与不变量 |
|---|---|
| `CastingGrant` | 稳定 grant 键、施法者 `CreatureRef`、真实获得事实及其 owner、准确授予规则/条目、资格策略及版本、法术成员关系引用、施法能力/DC 策略、资源许可、组件/仪式许可引用、有效状态及失效原因。grant 是获得事实与冻结规则的类型化投影，不是新的可随意增删能力表。 |
| `SpellAccess` | 准确 grant/spell 及成员条目；封闭分支为真实已知、已知戏法、职业名单且真实普通准备、法术书且真实普通准备、始终准备、法术书仪式授权、实际物品授权或实际怪物授权。分别引用职业名单/学习/准备/获得事实；始终准备与普通准备名额分开。法术书仪式分支可不要求普通准备，但只许可 `RITUAL` 且必须有真实仪式特性；书中存在本身不许可普通施放。 |
| `CastIntent` | 施法者、准确 grant/spell、`NORMAL/RITUAL/READY_PREPARE` 模式、服务端给出的资源选项键、该机制允许的目标/原点/有限选择、真实材料绑定及完整预期版本；反应另带准确窗口/机会/父 cast。不能提交能力修正、DC、骰点、强度、成本结果或“已满足组件”。 |
| `CastPlan` | 服务端验证后的授权/法术规格、实际获得与成员依据、基础环级和本次有效环级、资源/组件支付计划、时间/work 计划、目标证明、能力/特性贡献依据、全部效果/反应/持续后继及容量闭包。计划无 RNG/写入，不把可变事实永久冻结为当前状态。 |
| `CastAttempt` | 稳定 cast 键、准确 grant/spell/机制版本、原意图及模式、work/turn/flow 来源、声明与成本收据、当前领域阶段、已完成前缀、具体效果及合法失效结果、Ready/holder/子计划引用。帧只引用它，不复制资源或效果状态。 |

资格检查必须分别使用真实职业等级、总角色等级、获得特性和法术学习上限。共享法术位的
有效施法者等级只决定共享池，不能把高环位变成某职业已能学习或准备高环法术。
同一 spell 来自两份 grant 时，用户明确选择一份；能力、名单/准备、仪式许可、focus 与
资源许可均按该份授权组合，禁止从另一份 grant 借条件。确有跨授权资源规则时，须由
明确的资源许可关系证明，不能靠“都是法术位”自动放行。

资格策略按所选模式检查：牧师/德鲁伊式普通职业名单准备与法师法术书准备分别有真实
准备事实；法师未准备法术的仪式例外只由 `RITUAL` 消费。`NORMAL/READY_PREPARE` 不得
借该例外绕过普通准备，仪式也不能借另一 grant 的名单或特性通过。策略为应用封闭
登记，不允许模组用任意布尔表达式拼出新的资格规则。

授予引用或名单被禁用时保留获得/学习历史，拒绝新的选择或声明。已声明 cast 与既有
持续来源沿原固定规则和已登记失效政策继续，不因重新查询目录而重施法、退款或消失。
运行材料不热切换；恢复仍核原准确组合，不能借新来源补缺失资格。

## 法术规格与资源选择

目标 `SpellSpec` 至少含基础环级 0—9、学派、仪式标记、类型化施法时间、射程/目标政策、
V/S/M 需求、持续/专注政策及准确效果规格引用。学派只作为可被特性引用的分类，不自行
产生效果。字段的原子覆盖、组合约束和编码须与具体作者类型一起交付；现行“算法拥有
全部字段”的合同在前向采用前继续有效，不能先放开自由字段再补消费者。

`ResourceOption` 由服务端从所选 grant 与真实余额枚举，绑定准确池/使用规则、位阶或
次数、恢复 owner 及许可关系。请求选择一个准确选项；提交时重验，不自动改成更高位、
另一个池或免费施放。slot 消费、特性次数、物品 charge 和材料是不同成本项，不共享
一个无语义的 `amount`。等级 0、仪式等无 slot 模式使用明确 `NO_SLOT` 许可，
不绑定虚构池或零环位；其他次数/材料仍分别判断。资源恢复仍由原休息/物品/特性 owner 执行。

| 施法分支 | 必须分别保存并验证的语义 |
|---|---|
| 普通有环法术 | 选择实际可用且位阶不低于基础环级的许可法术位，消费一次；本次有效环级为所用位阶。没有该位阶的数值增强仍允许依规则升环，不能因此少付成本。 |
| 升环 | 各效果规格分别定义目标数、骰数、持续或其他真实变化；不能通用地每环加一个骰。Bless 的额外目标不增强单目标 d4。有效环级供 Counterspell/Dispel 判断，效果强弱比较仍按持续协议的具体比较器。 |
| 等级 0 | 真实已知戏法，环级恒为 0，无 slot 项，保留时间和组件；成长增强按该戏法登记的等级依据求值，不能以 slot 或职业等级默认代替总等级。 |
| 仪式 | 同时满足 spell 的 ritual 标记与该 grant 的仪式特性；按特性判断已准备/已知或法术书例外。施法时间额外十分钟、无 slot、有效环级为基础环级，不能升环；组件和长施法专注仍适用。 |
| 特性/物品/怪物免 slot | 必须有真实准确授权、规定有效环级、能力/DC 来源、次数与组件例外。免 slot 不意味着等级 0、仪式或免组件；未完成该 producer 的分支保持拒绝。 |

多职业共享位与 Pact Magic 以后可产生不同的合法选项；必须复用真实唯一余额。
[共享位基础](../../rules/multiclass-spell-slots-v2.md)目前只计算上限/适用性，不提供当前
共享池、Pact 位阶/恢复或完整施法授权，不能据此开放多职业施法。初始、学习、抄录、
准备、遗失/替换法术书与施放是不同命令；未来法术书实物关系不由一个学习列表冒充。

## 组件、成本与不可退款接受点

`ComponentPlan` 保存 V/S/M 各需求、真实状态依据和所选满足方式。组件豁免必须来自
真实特性/使用规则，不能由客户端布尔值或缺省字段声明。装备/物件 owner 证明所有权、
位置、可用手、数量、准确定义及状态；施法 owner 不建立另一份库存。

| 需求 | 决策合同 |
|---|---|
| V | 证明能正常发声并核对 gag、silence 等真实限制。没有感官/条件 reader 的相关场景拒绝，不能把未记录当作确定可发声。 |
| S | 至少一只可自由使用的手；没有 M 的 S 法术不能仅因持有 focus 视为满足。手被占用时须有准确已支持的例外。 |
| 普通、不消耗且无标价 M | 实际组件、可用组件袋，或该 grant 允许且实际可用的 focus，三者按明确分支选择。访问材料/持 focus 的同一只手可以满足该法术的 S；不凭“背包里有圣徽”推定可用。 |
| 标价 M | 必须绑定满足准确种类、数量与最低价值的真实物件；focus/组件袋不能替代，不自动把钱扣成材料。价值用精确货币最小单位，估值来源须有可审核领域事实。 |
| 消耗 M | 每次必须提供真实组件，即使未标价也不能以 focus 代替；按该法术的准确消耗规则产生库存变化。标价且不消耗的物件保留，不得通用扣除。 |
| 护甲/其他限制 | 复用真实护甲熟练及获得/条件限制；免组件不自动免护甲限制。focus 种类和佩戴/盾载圣徽等具体使用方式由授权与装备合同共同证明。 |

`CastCostReceipt` 是不可变业务事实，按 cast、成本种类与 ordinal 唯一，记录接受事件、
准确资源/物件及前后值、数量、真实 action/bonus action/reaction/work 消费引用；它不是
第二份余额。当前四法术没有材料消耗，不因该目标类型出现就扩充现行装备能力。

| 接受点 | 成本与专注的准确后果 |
|---|---|
| 预检未通过 | 不消费动作、slot、材料或 RNG，不替换旧 holder，不创建“失败 cast”来掩盖不支持。 |
| 一 action/bonus action/reaction 的 `DECLARE` | 完整预检成功后同事务接受对应动作、slot/次数及应耗材料，保存 cast，再开放真实施法完成前窗口；若需专注或 Ready 持有，同时结束旧 holder 并取得新 holder。 |
| 长施法 `START/WORK` | START 完整验证本工作与可达后果并取得 `CASTING` holder；按真实 turn/时间段消费 action 与工作信用。slot 和只在 DECLARE 应付的材料尚不消费；已发生时间/action 不因失败退回。不能在 START 占用并提前扣掉未来 slot。 |
| 长施法完成的 `DECLARE` | 重验原选择的实际余额、组件、当前资格/目标及完整后继后，只接受尚未支付的 slot/次数/材料；最后一次工作 action 已支付时不得再扣一次。依机制可合法失败则保存真实终态，不能临时换资源。 |
| 已 DECLARED 的反制、后续打断/目标失效 | 保留接受成本；按准确效果政策记录 `COUNTERED/INTERRUPTED/TARGET_UNAVAILABLE` 或部分结果。不能统一空效果 `RESOLVED`、退款或恢复旧专注。回滚则全事务均未发生。 |
| Ready 准备/释放 | 准备时正常 DECLARE 并支付，接受 Ready 的唯一 holder；释放仅消费 reaction 及持有结果，无第二次 slot/材料/组件检查或 Counterspell 声明。范围、目标与失效按该 held 效果的 release 合同重验。 |

以上 DECLARE 是项目采用的成本边界。长施法开始后、声明前若被破坏专注，保留实际工作
前缀且不消费未接受 slot；显式重试必须新建工作，从零开始。长施法中的 Counterspell
可观察时段、提前声明及其成本不能从此条推导，须先闭合下节分支。

## 时间、回合、Ready 与反应接点

施法时间类型分为 `ACTION/BONUS_ACTION/REACTION/LONG_WORK`；REACTION 必须绑定已登记
真实触发，不能把任意法术放进反应窗口。常态法术攻击、豁免和持续转换作为原 cast 的
普通 `CONTINUATION` 子计划，不再消耗 action，不增加反应深度。真实反应仍由唯一 flow
安排，沿公共协议保存父 checkpoint、决定和已接受前缀。

同一 turn 的施法历史必须包含**所有人的**真实 cast 与各 actor 的 action 类型；另按
施法者筛选本 turn 的限制。本人用 bonus action 施法后，同 turn 其他施法只允许施法
时间一 action 的戏法；反向也须验证，先反应或施放有环 action 法术后不能再补 bonus
action 法术绕过。限制不按 round 泛化：在别人 turn 的 reaction 使用那个 turn 的历史。
合法接受后被反制仍留作已施放声明事实，不抹去成本/turn 限制；无资格请求不写此事实。

长施法的 `CastingWork` 保存 required/earned 工作信用、准确 action/时间来源及连续性、
原始选择、当前 holder、暂停/中断/完成事实。每 turn 须实际投入 action 并维持专注；
探索只能由显式时间 owner 承认经过的工作段，禁止墙钟、GET 或后台 tick 自动完成。
长期合法 CASTING 本身不占活动 flow；本次工作、中断或声明的待结义务使用原 flow，
等待时也不能另开普通写门。转战斗/探索必须传递原工作与唯一时钟，不能将 turn 期限
随意换成秒数或既加工作秒数又加一次通用 CAST 六秒。

从当前 scene 内的共享角色时钟推广到战役唯一时钟，须接合持续协议的 occurrence/cursor
与准确待处理余集。角色离队/入队、休息、长施法及战斗/探索交接都引用同一时间 owner；
逐真实截止边界结清到期、周期/后续豁免与回调，再推进后缀，不能先跳完六十秒或一次
长休再补 tick。压制、shadowed、离场与重新入队均不重置 cursor；具体离场状态是否
继续周期进展须有该效果政策，缺失时拒绝相关时间推进，不以丢弃效果解除阻断。

Ready 只准备施法时间一 action 的法术，复用真实 cast 与 holder。当前固定目标与有限
触发继续沿有限合同执行；未来欲在释放时才选目标的法术，必须先定义选择/范围采样点、
候选完整性、失效结果、容量与恢复字段，不默认开放。原法术若持续专注，释放时把同一
holder 合法转交其真实持续来源；普通瞬时法术释放后结束持有。失去 holder 的 cast 不能
在后续 RESOLVE 重新取得专注或创建依赖它的效果。

长施法采用前还须明确：工作信用的秒/turn 换算和起止边界、漏投 action 的中断算法、
组件在各工作段的持续要求与物件变化、目标何时确定、可见施法的反制窗口是否及何时
允许、被反制时处于哪个接受点、bonus action 限制如何登记 START/WORK。未闭合这些
字段、算法和时序测试时，不能仅实现一个剩余秒数就开放长施法或仪式。

## 效果分派与公共领域 owner

`SpellEffectSpec` 是应用封闭登记的分支及有限参数，引用准确规则/稳定效果条目和版本。
一份 `SpellEffectPlan` 明确输入、有限执行序、成本来源、目标/检定/伤害/持续 child、
失败与部分结果、返回 checkpoint 和保存责任。它只能组合已支持的具体领域类型，
不能形成可递归任意嵌套的 JSON 程序；新增分支由应用实现，内容包不注册执行阶段。

| 分支与接点 | 必须交付的真实消费者 |
|---|---|
| 直接治疗/临时 HP | 健康 owner 取得精确目标、服务器骰/能力贡献、类型限制和应用量；保留原骰、requested/applied、上限与死亡/稳定等后果。生命门徒是所选真实获得特性的治疗贡献，不写死进所有 Cure Wounds。 |
| 法术攻击 | 攻击 owner 取得真实 cast 来源、近战/远程种类、目标、能力/PB 与当前贡献；复用攻击 CheckPlan、Shield 等真实命中窗口和 DamagePacket。无武器/Extra Attack action，不凭 spell 标签跳过近敌远程劣势。 |
| 豁免/共享伤害 | 目标/空间 owner 先证明完整目标集合，再通过共享检定核、伤害/健康/专注 consumer；沿[多目标豁免伤害](multi-target-save-damage.md)登记真实 cast 来源及自己的参数/阶段，不能把地狱猎犬 action 假装成 spell 或另写逐目标扣 HP。 |
| 无攻击的直接伤害 | 必须另登记真实 target、共享或独立骰、各 packet 的来源分组、免疫/防御与伤害后义务。Magic Missile 的 Shield 防护、飞弹分配和专注伤害来源划分未闭合前仍拒绝；不能从元数据或普通攻击窗口借用。 |
| 持续/条件/区域 | 产生持续协议的准确 source/application、贡献组、holder 依赖与期限；每个效果另定义同名强弱、压制范围、目标级结束和回调。沿空间/条件 owner 改真实状态，不保存并行布尔值。 |
| Counterspell/Dispel | 前者指向仍在准确声明窗口的 cast；后者选择 creature/object/真实魔法效果，再完整枚举该目标上的 spell application。两者均使用目标本次有效环级判断自动分支；需要能力检定时，以所选 grant 能力通过共享能力 CheckPlan，默认不加 PB，真实适用贡献仍须完整枚举。 |

公共目标引用区分 creature、object、point/area 和 spell source/application。射程 self
不是只可影响本人，touch 也不是通用的“五尺内任意对象”；目标种类、可见/可听、清晰
路径、尺寸/类型、友敌/自选和排除条件由具体规格校验。区域不能用用户给出的生物子集
代替完整场景 reader。范围/目标采样在 DECLARE、release、检定或后续持续时点分别登记；
已经施放后默认不以初始射程永久束缚效果，原文有要求时另定。

采用普通施法能力公式的授权，save DC 为
`8 + 所选 grant 的能力修正 + PB + 真实适用贡献`，spell attack 基础为能力修正加 PB。
物品等固定 DC/攻击值必须用该授权的封闭规则分支，不能一律套角色公式或由请求指定。
Counterspell/Dispel 需要的检定属于能力检定，不是攻击或豁免，也不自动熟练。
所有原骰、贡献采样和后置修改保留准确 audit。

Counterspell 的基础自动阈值为三环；使用四环以上位施放时，阈值为该实际位阶。目标
法术的本次有效环级不超过阈值则直接反制，该自动判定不生成虚假检定或消费 RNG；
超过阈值时才以所选 grant 的施法能力进行共享能力检定，DC 为
`10 + 目标法术本次有效环级`，成功才反制。当前真实可施放集合和法术位至多三环，
仅能验证自动分支；ActionFlowRules 中不可由真实高环目标进入的私有 d20/INT 分支，
不是共享检定链已完成的证据。

Dispel 先选择一个 creature/object/真实 magical effect，再完整预检该目标上的全部
spell，不能选中 creature 后由用户只挑其中一项 buff。自动结束所有三环及以下法术；
使用四环以上位时，自动阈值为该位阶；对其余每个高环 spell 分别执行一次能力检定，
DC 为 `10 + 该次 spell 有效环级`，成功才结束对应效果。必须保留每次原骰、结果与
目标 application/source，包含仍存续但 suppressed/shadowed 的可驱散 spell；目标级
结束范围与是否结束整 source 由具体类型登记，不能扫掉其他目标。非 spell 魔法不因
“magical”就自动可驱散，瞬时施法已经造成的健康/物件事实不倒退。固定 DM 抗魔环境
继续是独立家规 producer；完整 Antimagic Field 的移动区域、例外和互相作用另行登记。

Magic Missile 采用前须有每镖 ordinal→target 绑定、同时命中事实、共享伤害 roll 引用、
Shield 的真实指定后/伤害前 producer、防护结果及准确健康/专注 packet 身份。它没有
攻击检定，不能制造攻击命中窗口。SRD 的多目标同时伤害一次 roll 与每镖伤害须在具体
规格中对齐；同一目标多镖的伤害来源如何归组、专注检查次数如何派生，p.102 没有明确
给出项目所需分组算法。实施前须记录明确的项目解释并以单目标多镖、多目标、部分目标
有 Shield、降至零 HP 和中途恢复的独立向量验证，不能把每镖一检或全法术一检冒充原文。

## 状态、历史与直接恢复

施法相关权威变化、根事件、成本/骰/效果正文、引用、版本和接受结果共用短事务。各
Repository 使用调用方连接；版本/锁/幂等与 UNKNOWN 查证不在本领域重造。下表补充
施法特有数据；公共 flow、持续实例及本地控制的保存规则仍以相应协议为准。

| 数据 | 状态/历史与恢复核验 |
|---|---|
| 获得与可用法术 | 完整 grant/授予与获得事实、名单条目、学习/替换/准备前后值、等级和长休/工作标记；法术书关系、戏法、普通准备与始终准备分别保存。恢复不从当前等级自动补学或按名单补准备。 |
| cast 与付款 | 原授权/意图、模式、基础/有效环级、实际资源/材料选择、各接受点和成本收据、action/turn/work 来源、阶段/结果及全部历史；结果须与余额/库存因果子事件一致，不能由当前余额猜过去付过哪一池。 |
| 工作与 turn 限制 | 原始时间计划、唯一时钟/turn 关系、已赚工作信用/消费前缀、holder、中断/完成；真实逐 turn cast ledger 包含反应与 bonus action，不能恢复后重新获得本 turn 施法额度。 |
| 效果和 Ready | 完整子计划/audit/packet/source/application/结果引用、已完成前缀和合法失效、held cast/触发/释放及 holder 转交；结束和反制历史保留，不因当前已无效果而删掉成本原因。 |
| pending | 唯一 flow/叶子/checkpoint、准确反应/choice 和尚未执行余集；直接恢复保原骰、决定、工作/时间前缀，不重施法、不重复支付、不退款、不重新选择资源或自动释放 Ready。 |

独立 reader 必须验证 grant 的真实获得与原资格、各模式与环级合法、receipt 唯一、物件
消耗/资源事件对应、长施法的信用连续性、turn 限制、holder 唯一性与效果依赖、结果/历史
和全部入出引用。writer/reader 往返不足：还须独立逐字段比较权威源到文件、文件到恢复
及真实存储读回。缺失分区、未知机制或旧 INTERNAL 历史无法映射时拒绝，另行审查实际
数据的前向采用方案；不能清空历史或改写已应用迁移来通过。

技术 END 保存正在施法、持有、声明后窗口或结果中途的真实前缀；不自动中断/结束专注、
PASS、推进 work/时间或重试。恢复重建本地映射/CAS/收束预留后，显式提交新版本意图
才能继续；业务文件不携带本地 row ID、run/snapshot、请求收据或可执行旧 CAS。

## 可独立验收顺序与未完成门

P0/P1/P2 表示依赖优先级，各行均可作为单独前向切片验收，不能以“设计已写”计为实现。
每行须贯通作者/组合、准确来源与镜像、真实资格/执行、状态/历史/独立恢复；纯计算函数
或新增目录不够。[机制责任清单](mechanism-integration-checklist.md)规定共同验收责任。

| 顺序 | 有界交付与独立验收 | 仍须闭合才开放的内容 |
|---|---|---|
| P0 授权/成本骨架 | 把现有四法术及 Ready 的真实获得、选择、能力、资源与成本事实映射到上述类型；保持当前允许值。验收跨 grant 借准备/能力/圣徽/资源被拒、元数据不可执行、非法声明保留旧 holder、一次付款与嵌套反制/恢复。 | 作者字段原子边界、类型化存储/结果/编码与容量界；旧真实 DRAFT 历史存在时的采用门。完成前继续使用现行 profile，不做双模型并行写入。 |
| P0 组件证明 | 先覆盖现有 V/S、手持圣徽和护甲限制，完整保存判定依据/无材料支出；负例覆盖错误物件/手位/所有权、伪造豁免、声明回滚和重复请求。 | 组件袋、focus 种类/佩戴方式、标价/耗材的真实库存和值域；无 reader 的 silence/手部限制场景。 |
| P1 资源与基础扩展 | 分别接入真实升环、已知戏法和一个 bonus action 法术；升环目标/骰数与有效环级独立测试，戏法成长与无 slot 独立测试，双向 turn 限制覆盖本人/他人 turn 的反应和被反制记录。 | 每个实例准确规格/消费者与真实可取得资源；不能只降低等级门。多职业/Pact 继续关闭。 |
| P1 共享效果消费者 | 分别以一个法术攻击、一个已登记范围豁免伤害、一个高环目标的 Counterspell 验证真实 child 与返回；共用原骰、伤害/专注 owner、目标完整性及一次成本。 | 准确法术来源、区域/遮挡政策、合法目标失效、CheckPlan 贡献与完整读取；地狱猎犬设计本身不补这些实现。 |
| P1 持续/驱散 | 用一个已闭合的多目标持续效果验证强弱/压制/结束，再以 Dispel 验证逐 spell 检定、目标级/源级结束与回调一次消费；恢复含 suppressed、shadowed 和 ENDED 待结义务。 | 每个效果的 potency、采样时点、目标结束范围、回调和非 spell 排除算法；不顺带开放所有条件或 Antimagic Field。 |
| P2 工作/仪式与完整组件 | 先交付一种长施法和一个具准确资格的仪式，覆盖 START/WORK/DECLARE 各边界的中断、材料/slot 余额变化、跨模式时间、保存及重试；再逐组件模式采用。 | 上文长施法时序决策、真实物件/书本/值域、工作计费与反制接受点；每项需要字段、有限算法、独立时序及故障测试。 |
| P2 其余授权与能力族 | 按机制族接入其他职业已知/准备、共享位/Pact、抄录/恢复、特性改法、怪物/魔法物品施法和其余效果，每个实例填写完整机制责任。 | 获得/替换/资源/组件例外、学校特性、复合选择/部分失败、区域/召唤/传送/变形/信息裁定的独立合同；不得用通用 DM 成功或任意 JSON 兜底。 |

最小怪物动作与地狱猎犬吐息可先独立采用真实 action/充能、完整区域目标、共享伤害、
逐目标豁免、反应/专注与恢复；它不依赖完整法术目录。施法接入其公共核时仍须自己的
真实 cast producer，怪物施法则另需真实 monster grant，不能把这两条依赖倒置。

其余 SRD 按机制族扩展时，角色、法术、怪物、装备、魔法物品和冒险分别提交从准确来源
到 consumer 的闭环，优先复用上表已采用 owner；一个职业学习名单或一个 spell metadata
集合不代表该族完成。完整文件与运行生命周期集成最终必须覆盖这里全部稳定状态和
pending：自动/FINAL 保存、直接恢复、清理/修复、重启救援、容量与制品保管分别验收，
不能只保存当前四法术的活动效果头便开放完整运行。

所有新增实例都要有正常/边界、坏冻结规则、禁用/未知机制、旧版本/幂等、容量前拒绝、
事务故障/禁止部分写和中途直接恢复的独立向量；测试范围随所改机制选择，不以重复全套
掩盖缺失的真实消费者。真实数据库迁移/权限、内容接受、发布和部署仍为各自检查点。
RELEASED v1、新战役默认、既有迁移和已发布摘要保持原合同，完整 DRAFT 发布门保持关闭。
