# v2 世界节点、局部场景与战役时间

本文规定[模组分层设计](module-layering.md)下的位置、执行焦点和跨空间接纳目标。战役
可以保留多个有参与者和未完进度的场景，普通游戏执行集中在一处焦点。第四阶段目标增加
有界三维空间证明及受限跨空间被动结算。距离、区域和安置见[空间证明](spatial-and-area-contract.md)，
日历与期限见[时间合同](time-and-calendar.md)，实际采用见[领域接合表](domain-integration.md)。

## 世界位置与局部坐标

| 事实 | 权威领域 |
|---|---|
| 主体身份与分类 | 角色或怪物领域拥有战役内稳定主体身份。同一主体通过入场、离场和重开文件保留身份。PC/NPC 分类、玩家控制、场景阵营、记录状态、生命状态及行动资格分别维护，见[角色状态与历史](character-state-and-history.md)和[玩家参与](player-participation.md)。 |
| 世界节点与路线 | 世界领域拥有战役内节点、允许的连接及影响通行的世界事实。节点使用稳定身份，连接与通行条件由应用核验。 |
| 场景与网格 | 场景领域拥有稳定场景身份、世界锚点、局部范围和 PhysicalFrame 嵌入。空间 owner 拥有布局/占位及真实证明，物件 owner 拥有动态门等互动事实；详见空间证明合同。节点锚点不提供两个场景间的距离。 |
| 主体当前位置 | 位置领域拥有唯一安置。世界节点、直接空间位置、依附位置、暂隐及强制受限位置互斥，实例身份始终保留。名册/地图与物件持有位置从该事实和严格父链派生，不能双写 current。 |
| 模式与战斗过程 | 场景维护局部探索或战斗模式。战斗机制拥有先攻、轮次、回合和相应资格。开始或结束战斗是模式转换，主体仍处于该场景。离场是空间转换，关闭场景另须处理剩余占位和领域义务。 |
| 执行焦点 | 战役保存当前唯一可执行空间和焦点代次。尚未安置的空战役允许未选焦点。世界节点与局部场景均可独立成为焦点。 |
| 空间时间 | 同一时间服务拥有各空间逻辑秒与日历映射；个人经历、自然日活动、物件黎明按时间合同区分。被动跨空间结果不推进背景秒、日历或个人时间。 |

规则模组提供应用已支持的移动、距离、地形与时间规则定义。实际节点、布局、主体格位、阵营、模式、焦点与时钟是战役事实。界面可以切换世界图和局部图、缩放、筛选、作私人标记，并提交有界目标或路径。应用依据当前事实和该战役冻结规则重算所有影响结算的结果。查询返回按权限裁剪的位置、候选及可见原因。

## 执行焦点与冻结

DM 显式切换焦点。服务端核权限、战役和目标空间身份、当前焦点代次及有关版本，将新焦点、代次、根历史和接受结果共同提交。切换推进零游戏秒。界面浏览任何已获准可见的空间只改变显示。普通游戏命令及继续命令必须匹配当前焦点、焦点代次和当前事实；离开后再回到原空间也须重新读取候选并校验执行权限。持久成员和角色控制事实继续按自身合同维护，候选与许可的执行资格以本次焦点核验为准。

背景空间不推进时钟、日历、个人经历、休息或自主动作，切回不补算。唯一游戏事实写入
例外是本合同[因果作用域](#causal-scope)允许的被动结算及其受限反应/选择。该例外不是
普通后台操作许可，也不能由界面浏览触发。每空间至多一条本地未终结 flow，其后台前缀
冻结；当前可执行叶子属于焦点 flow，或由它持有的跨空间 scope。候选和继续沿
[动作协议](action-continuation-protocol.md)，不能因为被动结果改变了状态而倒改原骰或退款。

两个互不依赖的空间仍可以各自保留未决动作并显式切换。正在处理跨空间 scope 时，相关
空间已加入同一因果义务，焦点切换及新的普通根暂不接受，直到 scope 的当前义务终结。
可保存或技术 END；重开仍停在原 scope 叶子，不替任何人选择。

## 空间和模式命令

| 意图 | 接纳与结果 |
|---|---|
| 沿世界路线转移 | 从主体实际所在的焦点世界节点校验目标、连接、资格与全部影响。适用机制决定时间、后果与可中断阶段。 |
| 进入场景 | 从场景锚点对应的世界节点进入。核验场景、完整主体集合及准确落位，包括当前版本、权限、网格边界、占位与地形；提交当前安置和接合后果。进入战斗如属于同一业务意图，先完整预检相关先攻、目标和其他义务。 |
| 局部移动 | 从实际格位校验完整路径及各阶段的移动预算、占位、地形、触发和影响目标。按支持的机制应用有序步段，已完成前缀及未完成后缀沿[动作继续协议](action-continuation-protocol.md)记录。 |
| 开始或结束战斗 | 校验同一场景的参加者、当前模式和未决义务，按支持的规则接合先攻或结束流程。世界锚点、主体身份和实际位置继续由各自领域负责。 |
| 离开或关闭场景 | 从当前格位按锚点/嵌入交接，关闭另需处理所有主体和依赖。已定义关系按实际距离、源期限和因果合同保留或结束，未知关系拒绝；不能因场景名不同自动结束。 |

应用以完整主体及受影响目标预检每次转换，包含状态/权限、源和目标版本、全部分支及容量，
先于 RNG。跨空间交接须有 DM 明确授权的目的空间；旅行时间在源焦点结算，实际交接一次
提交安置、关系/期限/活动账本、焦点与代次、版本、根子历史及接受结果。目的空间保留原钟，
日界/黎明只订阅严格未来发生。分阶段时保留源安置及目的计划，继续复验后缀。
迁移未决普通动作、长施法工作或真实 turn 责任仍须其专门转换；不能借被动 scope 搬走它们。
已具备本页因果和具体效果合同的持续关系允许跨空间保留，其他未知依赖仍失败关闭。

## 空间时钟与直接恢复

### 旅行与 DM 裁定

首期旅行由 DM 对本次转移明确裁定整数分钟数及说明（0–1440 分钟）。耗时属于本次
命令意图和根历史，不固定在路线，也不由客户端速度或路径距离推算。先验证完整主体集合、
相邻连接、源/目标空间与全部后果，再在源焦点结算耗时并原子交接。速度、地形和随机遭遇
算法后续独立接入。零分钟仍须明确裁定，并经过相同空间守卫。

自由卡与规则角色使用同一安置和网格。场景选择明确的 DM 裁定或规则结算模式；自由卡
可以出现于场景并参与 DM 裁定战斗，出现资格不授予自动规则结算资格。自动动作仍核验
所涉及主体的完整规则事实；缺少事实的目标不能被静默忽略。DM 对移动、耗时和手工结果
的裁定也写入共同根历史，并遵守焦点、占位、未决动作和完整目标预检。

### 角色累计经历时间

角色个人经历时间只随所在空间实际推进累加；切焦点、转移和后台被动结算均不增加。
长休间隔和奥术回想继续保留个人经历规则；旅行/食水使用独立自然日账本，物件使用自身
安置域黎明。转移携带所有余额、已用资格、累计和进度，不当场恢复。精确字段、发生身份、
归属和同刻顺序唯一见[时间与日历](time-and-calendar.md)，不在本页维护另一套日界公式。

健康 owner 保管稳定恢复的个人截止值和原骰。当前位置绑定时间域，空间截止值由
`空间当前秒 + (个人截止秒 - 个人累计秒)` 唯一派生；交接根保留前后空间钟与位置，故可
直接核验剩余时长不变，无需第二份可独立改写的健康期限。场景效果的截止值由场景 owner
保管。目标的各种 DOMAIN/PERSONAL/TURN/CALENDAR 期限按[期限基底](time-and-calendar.md#portable-time)
分别交接；活跃休息、回合期限和未决动作缺少对应迁移合同仍拒绝。

战斗、探索、旅行、休息和效果机制根据冻结规则提出有界时间后果。时间服务按已接受的推进单调更新焦点秒值，先核验受影响的完整集合，在每个截止点处理适用义务，再推进剩余时间。每个秒期限携带时间域，回合期限携带准确场景与回合边界。空间间秒值独立，战役根序号记录跨空间因果顺序。回合内移动、跨空间接合、暂停继续及效果到期按实际已耗时间记录前缀和未决后缀。焦点切换、查询、保存与恢复都消耗零游戏秒，后台时间在切回时保留原值。

允许迁移的 DOMAIN 秒期限按源剩余量重绑，PERSONAL 期限保留个人截止值，CALENDAR
订阅迁移后只看严格未来发生。到期义务先在源处理；效果贡献按
[持续效果协议](ongoing-effect-protocol.md)在真实位置和阶段重新核验。

根事件保留准确操作者、命令意图、规则引用及来源、前后空间、模式、焦点与时钟、受影响版本、原骰、选择和子历史。完整文件保存世界图、全部场景与网格事实、真实安置、焦点、各逻辑时钟、全部历史和各空间的待处理动作、交接及到期义务，并绑定准确规则组合。打开文件直接装载经核验的事实；已有历史可用原结果核对。残留恢复先核原私有库及收据，显式建立新 epoch 后才允许用户发出下一命令。技术 END 可保存中途状态，按[运行与事务](runtime-and-transactions.md)及[保存与恢复](save-and-recovery.md)处理。

<a id="causal-scope"></a>
## 跨空间被动因果作用域

`CausalScope` 是当前焦点已接纳动作的受限跨空间执行范围，不是新的后台战役或自动队列。
规则包只能使用已登记机制；只有应用机制可从真实来源产生此 scope。普通客户端请求不能
提交 `includeBackground=true`、写目标列表或自报依赖闭包。

| 必需事实 | 含义与 owner |
|---|---|
| `scopeId/originOperation/originSpace/focusEpoch` | 稳定业务因果身份和本地接纳前置；动作协调者拥有 scope，运行核心核焦点/权限 |
| `causeGraph` | 真实伤害/效果/关系/施法/物件原因、阶段和有向依赖边；每边有具体 consumer、输出种类和终止证明 |
| `readClosure/writeClosure` | 所有可预判分支涉及的主体、物件、源、安置、布局、关系、动作/资源及其版本；不因目前在后台而省略 |
| `attachments` | 被借入空间、参与主体、允许阶段操作、依赖版本、原本地 flow/叶子/已发生前缀；不复制一份角色或 HP |
| `stage/frontier/leaf` | 当前 APPLY 或选择/反应/结束阶段、已消费发生、未决余集、准确唯一可执行叶子与返回点 |
| `budget/termination` | 有界节点、边、反应深度、可能结果和保存字节；无证明的递归或未知 consumer 在首 RNG 前拒绝 |

scope 从原 flow 取得当前执行责任；后台已有 flow 被标为 `SUSPENDED_BY_SCOPE`，仅引用其
原前缀，不重放也不结束它。当前 scope 只有一个可推进叶子；背景旧叶子不能同时接受继续。
scope 结束后后台旧 flow 恢复为冻结状态，保留原成本/骰，之后进入焦点时重新证明其后缀。
被动 HP、状态、资源、位置资格变化可以使其原候选失效，不能把它当事务故障退回旧值。

### 接纳、关系证明和受限继续

1. 在任何新骰/成本前，从完整来源/关系图求出可能的前后台写集合，核同战役、真实
   [SpatialProof](spatial-and-area-contract.md#spatial-proof)、存续/范围/目标资格、每项具体
   consumer、容量与当前所有版本。相同世界锚点不证明 60 尺内；未知距离不能当超距结束。
2. 将背景参与者借入 scope，只允许下表登记的真实直接消费者及其完整后继。时钟、日历、
   个人经历、turn/普通动作额度保持原值；规则明确消费的反应/
   资源可以消费一次，不能因被借入而刷新。
3. 需要其玩家/DM 选择时，提供绑定 `scopeId/originOperation/leaf/actor/decisionType`
   和全部当前版本的候选。参与授权仍逐主体核验，空间借入不授予控制权或额外可见信息。
   后台玩家可选当前灵感/防御等登记选项，不能借此 MOVE、开新攻击、推进时间或原后台 flow。
4. 缺少受限选择/反应接口、无法证明任何潜在后果或未知闭包时，该轨迹不受支持，预检拒绝。
   不得代 PASS、丢失反应窗口或把结果等到切回再应用。

| 受限入口 | 真实 producer 与允许后果 |
|---|---|
| `DAMAGE_PROPAGATION` | 当前伤害和已建立的关系，进入防御、健康、归零/死亡、形态、专注及结束消费者 |
| `RELATION_REEVALUATION` | 前台真实安置/装备变化，重验已存在的 Warding Bond/同调等登记关系；更新同调离身锚点或结束关系，不推进后台个人时间 |
| `AREA_COVERAGE` | 已登记持续区域的真实移动/建立/终结，重算完整覆盖与压制及其形态/召唤/门户后果；是否产生进入伤害由该效果的真实触发政策判定 |
| `OBJECT_TRIGGER` | 已许可的实物/容器/表面变化及其完整互动事实，消费现存 Glyph 谓词与一次释放，或同一已成立效果的点燃后果；不替后台生物创造主动开箱动作 |
| `PLACEMENT_CONSEQUENCE` | 上述真实转换所需的形态回转、召唤暂隐/返回及旧安置等待失效，使用原空间的安置计划；不开放普通移动或任意跨空间传送 |

每个入口只覆盖应用已登记的具体机制和可证明闭包；表中名称不是规则作者可提交的通用
命令。直接消费者同样有唯一 occurrence/阶段、版本、状态/历史与恢复接合，后继不得借
“被动”跳过应有选择或反应。没有真实触发的后台施法、移动和其他普通动作仍拒绝。

反应的发起仍以真实触发和当前资格为准。所谓“被动”限定因果范围，不取消规则本来允许
的反应；接受/放弃须由合法操作者明确提交。后台原动作持有的未消费候选不锁定资源，
scope 内合法消费后原动作继续必须重验，且原先已付部分不能被再次消费。

<a id="cross-space-apply"></a>
### 同一伤害阶段的共同提交

伤害使用共享伤害合同的唯一 `DamagePacket/HealthPlan`；健康 owner 在需要形态交接时
消费角色合同的 `FormTransitionPlan`，不是另一个健康写入器。对 Warding Bond，目标防御后的实际
伤害作为给施法者的后继输入，施法者适用自己的防御；不是事后按 HP delta 推测，也不是
另起一条没有来源的手动扣血。具体伤害/结束规则见[Warding Bond](ongoing-effect-protocol.md#warding-bond)。

一个 APPLY 阶段必须先得到该阶段全部前后台目标的合法健康候选及所需的前置选择，然后
一次提交所有对应 HP/temp HP/形态/归零事实、版本、原骰、伤害身份和根子历史。
若阶段前仍有任一选择未定，保存原骰、成本、计划、依赖版本和准确叶子，所有属于该 APPLY
的健康变化都不应用。不能先扣前台 7，再让后台之后扣 3。

APPLY 后才有语义依据的专注豁免/伤害后反应可以成为后续阶段；它们与已成立的前后台
伤害共同保存在同一 flow/scope 中，当前根明确返回 WAITING。已经提交的伤害不会因为
后续选择等待而撤销。每次后续阶段自身的全部领域后果也一次提交，当前义务未结束前
不开放新的普通业务或宣布整个 scope 已完成。

健康归零、死亡、形态回转、专注中断及来源结束必须走唯一真实 owner。产生进一步
伤害或结束回调时加入当前 causeGraph，不另建脱离原链的后台根。背景原 flow 的当前
世界状态改变是真实事实；它尚未执行的后缀可以合法失效，已记录攻击/骰/付款保持原值。

### 重复、递归与终止

每个应用身份包含 `(scope, producerOccurrence, sourceInstance, consumer, subject,
phase, ordinal)`，一次边只消费一次；保存、重新求值、请求重发不建立新 occurrence。
同一攻击的多个有意义伤害分量与另一次真实伤害事件分开，不能过度去重吞掉合法第二次伤害。

创建/变更关系和根预检都检查有向因果图。目标跨空间损伤传播要求在同一阶段形成
可拓扑排序的有向无环依赖；层内按稳定源/主体身份排序，规则规定的先后优先。
其他机制只有给出严格下降的有限度量及对应消费者时才可加入本次闭包；不能仅以“最多
循环十次”丢弃仍应发生的后果。无终止证明的循环返回 `CAUSAL_CYCLE_UNSUPPORTED`，保持
原状态；该拒绝不是声称支持无限循环规则。

单 scope 最多 4096 个实例、8192 条消费边和 64 个空间；反应深度/帧预算按动作协议。
容量/可能后继在 RNG 前预留，实际终结回调不能因日志接近上限而被省略。只读关系可以
跨越更多已证明事实，但不能绕过固定读集合/字节限制。新 scope 不借入另一未终结 scope
的作用域；等待必须先完成已存在原因链，禁止彼此等待的 scope 环。

### 状态、历史、失败与直接恢复

保存完整 scope、原因图、attachments、原后台 flow 前缀、当前阶段/叶子、原骰/成本、
全部已消费/未决边及对应前后台事件。各主体仍只有一份当前事实，不以 scope 保存副本
覆盖 later current。历史记录每一边真实 producer 和结果，包括合法无效果及失效证明。

恢复先验证全图、阶段前后、每边唯一消费、关系/位置依据、被挂起 flow 引用和唯一可执行
叶子，再直接装载；不重新传伤、不重做死亡/结束回调、不推进后台时间。新本地 epoch/CAS
须重新建立，旧请求不能借保留的业务 scope 身份取得权限。技术 END 不自动 PASS 或终结 scope。

任何同阶段写失败整体回滚，包括前台、后台、历史、版本和接受收据；此前已接受阶段保留。
响应丢失返回原收据，commit 未知按运行合同隔离和只读查证。过期来源、焦点、参与权限、
空间或对象版本使继续前置拒绝；不会再抽原骰或先修复后台状态。

### 纸面验证向量

| 向量 | 必须成立的结果 |
|---|---|
| 原 V16 | 两空间的真实 frame 关系证明仍在 60 尺内；14 火伤经目标抗性为 7，再经施法者火抗为 3；同一 APPLY 同时提交，后台秒/个人秒/日界不变 |
| 作用关系 | 距离 65 尺先结束来源；没有共同 frame 证明拒绝，不能把未知当超距或同节点当近距 |
| 选择前保存 | 若任一当前防御需选择，前后台该阶段 HP 均保持原值；保存原骰/成本和叶子，恢复后只执行未定后缀 |
| 专注及后继 | 两侧 APPLY 后的专注/归零后果都在 scope 中结清；任一结束再影响另一侧时保留真实 cause 边，不脱离根 |
| 后台旧动作 | 后台原攻击在等待中被打至失能，原攻击骰/成本保留；scope 结束后切回，后缀依当前资格合法失效，不重掷攻击 |
| 越权/重复/故障 | 后台 MOVE 或推进自己旧 flow 拒绝；重复传伤身份只读原结果；末尾后台落库失败不留下前台半次伤害 |
