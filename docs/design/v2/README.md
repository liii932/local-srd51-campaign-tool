# v2 设计导航

本目录记录完整规则族的产品与跨领域设计，供实现、评审和后续细化共同使用。设计正文由
项目维护，不依赖任何 Agent 工作区；目标、领域合同与采用边界均从本文的主题导航定位。

“v2”是设计简称。项目完整 SRD 基础模组的身份仍为 `dnd5e2014_srd51_se` release `"1"`，
canonical/archive 目标为 `2/2`，发布状态保持 DRAFT。它不是所有模组的统一身份，也不表示
所有版本字段都应变成数字 2。

模组公共接口从[模组接口基线](module-interface-baseline.md)进入。当前组合方案是一个完整基础模组
加零到多个扩展/兼容模组，形成固定的有序准确组合。本文与各专题记录这一选择；当前单模组
实现及内部切片的采用差异见[采用边界](adoption-boundaries.md)。

## 设计状态与实现状态

项目处于原型阶段。本目录记录当前选择，不因曾被标记为“已确定”“已批准”或
“已完成”而成为后续任务必须继承的方案。需求、实现成本或验证证据变化时，可以重新比较
并替换设计，同时同步相关合同、实现、验证和采用边界。版本支持范围见
[产品说明](../../product.md#原型阶段的版本范围)。

- **当前设计选择**：记录产品原则、职责和跨领域方案，以及采用前须满足的条件；重评时明确改变的范围和理由。
- **待细化或暂缓**：尚缺领域字段、文件合同、完整算法或明确产品决定；缺项不能用空数据补齐。
- **实现边界**：以当前源码、迁移和对应合同为据；测试、数据库安装和部署另需各自证据。

这里记录的是当前设计选择，不是全领域列级 SQL、最终 HTTP 协议或发布版字节合同。表名和流程
例子中的未落地结构不预留迁移编号。语言与工具分区、成长与恢复纯规则模型已有内部切片
合同；它们不等于完整角色领域链路。其余领域应在实施时补齐准确字段、引用、锁序、存档
投影及验收条件，不能把本目录的概要当作缺项的默认实现。

## 文档职责与冲突处理

- [架构](../../architecture.md)、[数据库](../../database.md)及 `docs/rules/` 描述现行合同和
  已有内部切片；未发布切片不自动成为最终模型。
- 本目录记录当前 v2 设计。与当前实现的差异及方案变更登记在[采用边界](adoption-boundaries.md)，
  文档修订不能代替实现、数据处理和验证，也不能重新解释已保存的事实。
- 模组接口基线集中记录当前公共接口；方案变化时同步其调用、存储和恢复边界。其他字段
  草案、机制方案和实施步骤按当前需求与证据判断，不因历史批准或完成记录自动采用。
- 当前支持的准确规则身份与其已接纳内容、摘要须一致，明确保留的真实数据维持原有解释。
  这不要求未来版本永久保留旧发布的源文件、读取器或物理结构；现有数据库的演进与重建
  按[迁移合同](../../database.md#迁移合同)选择。DRAFT 的模型、API、目录、canonical/archive
  和测试可以协调演进；同一受支持版本内的规则绑定、事务原子性和完整恢复仍须验证。
- Agent 指令只负责工作方法和授权边界，通过导航引用本目录，不另行定义产品规则。
- 历史提案、批准措辞、测试计数和任务完成记录不作为新实现或外部操作证明。新增设计细节
  直接维护在对应专题，当前实现以源码、迁移及对应测试重新核验，不回读本地 Agent 工作区。

任务进度与未完成实施工作使用 GitHub Issues/Milestones 管理。本目录保留稳定的能力前提和
暂缓范围，不保存易失效的完成计数；本地待办不得因记录设计而被视为已关闭或已转交。
