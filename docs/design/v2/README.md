# v2 设计基线

本目录记录完整规则族的产品与跨领域设计，供实现、评审和后续细化共同使用。设计正文由
项目维护，不依赖任何 Agent 工作区；无需本地 `.pi` 或 `.codex` 即可理解目标及采用边界。

“v2”是设计简称。项目完整 SRD 基础模组的身份仍为 `dnd5e2014_srd51_se` release `"1"`，
canonical/archive 目标为 `2/2`，发布状态保持 DRAFT。它不是所有模组的统一身份，也不表示
所有版本字段都应变成数字 2。

模组公共合同统一从[模组接口基线](module-interface-baseline.md)进入：一个完整基础模组
加零到多个扩展/兼容模组，形成固定的有序准确组合。本文与各专题采用这一目标；当前单模组
实现及内部切片的采用差异见[采用边界](adoption-boundaries.md)。

## 设计状态与实现状态

两种状态分别判断，不能互相推导：

- **目标已确定**：产品原则、职责和跨领域不变量按本目录执行；有意改变时需明确修改相应设计。
- **待细化或暂缓**：尚缺领域字段、文件合同、完整算法或明确产品决定；缺项不能用空数据补齐。
- **实现边界**：以当前源码、迁移和对应合同为据；测试、数据库安装和部署另需各自证据。

这里记录的是设计基线，不是全领域列级 SQL、最终 HTTP 协议或发布版字节合同。表名和流程
例子中的未落地结构不预留迁移编号。语言与工具分区、成长与恢复纯规则模型已有内部切片
合同；它们不等于完整角色领域链路。其余领域应在实施时补齐准确字段、引用、锁序、存档
投影及验收条件，不能把本目录的概要当作缺项的默认实现。

## 文档职责与冲突处理

- [架构](../../architecture.md)、[数据库](../../database.md)及 `docs/rules/` 描述现行合同和
  已有内部切片；未发布切片不自动成为最终模型。
- 本目录描述新 v2 目标。与当前实现有差异的部分登记在[采用边界](adoption-boundaries.md)，
  由前向实施切片连接，不能用文档变化重新解释已保存的数据。
- 模组接口基线中已列明的公共合同作为正式目标；本地材料中的其他字段草案、机制方案和
  实施步骤不随之自动采用。新增细节仍须进入对应正式领域合同并明确验证边界。
- 冻结 v1、已应用迁移、真实持久化身份和已发布摘要继续受保护。DRAFT 的模型、API、目录、
  canonical/archive 和测试可以协调演进，不默认承担旧草稿兼容。
- Agent 指令只负责工作方法和授权边界，通过导航引用本目录，不另行定义产品规则。
- 本地设计材料保留作来源线索，历史批准措辞、测试计数和任务完成记录不作为新实现或外部
  操作证明。同一主题继续维护这里的正文；发现未收录细节时先核对适用性再补入。
