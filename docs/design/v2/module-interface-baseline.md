# v2 模组接口基线

状态：公共身份/作者/组合合同与当前有限应用 profile 共同维护。生产制品/组合及当前
SQLite frozen 材料/完整文件已有实际入口；完整 SRD 和通用自定义包安装/接受/发布仍须
独立采用，不能从有限内置运行推导。当前实际覆盖/证据见[接合表](domain-integration.md)。
本文是 [v2 设计导航](README.md)的模组公共入口，与[采用边界](adoption-boundaries.md)
共同区分目标、当前实现和后续规格。记录合同不代表已实现、安装、发布或部署。

## 组合结构与加载顺序

每个组合恰有一个 `base`，允许零到多个 `extension` 和 `compatibility`。当前内置四包
共同提供明确的有限应用 profile，base/扩展的职责不表示完整 SRD 已实现。完整 SRD 或
未来自定义体系的基础资格另需对应完整领域/机制和发布门，语言/工具分区不能冒充该资格。

基础位于加载清单首位且无外部依赖；扩展和兼容模组至少有一个直接依赖，并通过依赖链
连接这个唯一基础。兼容模组使用相同修改协议，在其依赖之后加载，角色不带隐藏优先级。
本版不组合两个基础。有限 profile 的准确依赖链、结构/文件/消费者须闭合，不能通过
“片段组合”跳过任何已声明机制的运行、历史或恢复责任。

用户显式提供有序准确模组清单；同一模组只能出现一次并选择一个准确版本，重复相同版本
也拒绝。依赖先于依赖者，全部额外顺序约束必须满足；系统检查用户顺序，不自动重排。
后加载模组仅覆盖其明确修改的字段，未声明字段保留已有结果；作者文件顺序不产生优先级。

## 稳定身份、直接依赖与联合兼容

规则身份由原始所属模组、规则类型、稳定规则键组成；条目身份由所属规则完整身份、集合键、
条目原始所属模组及稳定条目键组成。引用和修改目标统一使用带 `kind` 的完整结构化身份，
本模组也不省略归属。身份不可由普通修改改变；准确发布版本另由组合清单绑定。

直接引用或修改外部内容必须声明直接依赖，不能仅靠传递依赖。条目身份中的规则所属模组
和条目所属模组均需检查，当前模组自身除外。显示名、目录名和数据库行 ID 不代替身份。
版本按准确 ASCII 字符串比较，`"1"`、`"01"`、`"1.0"` 不同；不取最大值或使用版本区间。

所有模组均显式提供依赖、联合兼容及顺序约束三个顶层字段，依赖项声明支持版本。
以下结构拒绝未知、缺失、重复字段、null 和坏类型：

| 字段 | 公共合同 |
|---|---|
| `dependencies` | 数组；每项恰含 `module_key`、`supported_versions`；拒绝自依赖、重复依赖 |
| `supported_versions` | 非空准确版本字符串集合；拒绝重复，不转换或自动选择版本 |
| `compatible_combinations` | 非空数组；每项完整映射全部直接依赖到各一个准确版本；拒绝缺项、多项、重复配对 |
| `load_order_constraints` | 数组；每项恰含 `before`、`after`；端点限声明者及其直接依赖 |

每个依赖的支持版本集合须恰等于其在全部联合配对中出现的版本集合；支持 A1/A2 与 B1/B2
不自动产生四种交叉兼容。无依赖基础固定声明 `dependencies=[]`、
`compatible_combinations=[{}]`、`load_order_constraints=[]`。
顺序约束拒绝自指向、重复、冲突和循环；合法冗余约束不撤销依赖顺序。
独立兼容模组显式依赖被协调模组，不提供依赖缺席时跳过修改的路径。

## 作者入口与字段修改

目标作者入口固定为 `author-package.json`，`author_schema_version` 为整数 `2`。
清单声明模组键、准确版本、显示名、角色、依赖/联合兼容/顺序约束及全部作者文件。
`files` 以 `kind`、包内 `path` 登记文件，用途为 `definitions`、`entries`、`changes`；
同用途可有多个文件，同路径只登记一次，各文件根为数组。作者清单不自报发布资格。
作者 schema、组合算法、canonical、archive 与数据库 schema 各有职责，不共同升级编号。

[schema 2 最小组合链路](schema-2-composition-validation.md)给出清单、结构化身份、类型化
声明与修改的具体输入，以及最终字段、完整覆盖链和拒绝条件；其中局部验证材料不取得
完整基础模组资格，也不改变现行 schema 1 作者源。

新增规则本体和集合条目分别提供完整声明，原始归属为当前模组，默认启用。
本体完整声明一次，条目可分文件收齐后组装；新增外部规则下的条目仍须检查直接依赖。
重复新增同一完整身份一律拒绝；领域内容使用固定类型结构，不采用任意属性袋。
修改只面向前序已加载模组的既有目标，缺失即拒绝；本模组新增对象直接声明最终内容。

| 操作 | 语义 |
|---|---|
| `set_field` | 设置一个领域原子字段的完整明确值 |
| `clear_field` | 将领域明确允许为空的字段置为无值，不恢复低优先级值 |
| `set_enabled` | 显式设置规则或条目的启用状态 |

未提供操作、设置值、显式清空分别处理，null 不作清空简写。复合字段的必要配套值整体覆盖，
列表/成长表/关系集合按稳定条目键新增、修改或禁用；第一版不整表替换，不提供加减、倍率
或表达式补丁。游戏中已支持的规则计算仍由应用机制负责。
同一模组准确版本的全部文件内，同一目标的同一字段只许修改一次；相同值重复也拒绝，
并报告两处作者位置。字段原子边界、允许清空范围及内容类型由逐领域合同规定。

定义不显式删除；禁用后仍保留完整内容、引用与来源。关系条目禁用只抑制该关系，
不改变目标定义状态。启用状态按最后一次显式设置决定，更高优先级可重新启用。
禁用项仍校验结构、类型和引用，可只读查看与身份引用，禁止新选择和直接执行。
职业自动授予的特性被禁用时，保留职业和授予引用，特性不生效；种族、背景或职业固定
授予的语言/工具熟练被禁用时，保留授予事实和来源并标记抑制，不产生有效能力或熟练加值。
必需能力或必选候选不足则阻断组合，只跳过领域明确允许忽略的效果。
检查结果列出禁用项及上述受影响的授予关系；其他领域授予语义由其领域合同明确。

## 四阶段校验与发布资格

| 阶段 | 必须完成的检查 |
|---|---|
| 离线安装 | 原包与文件清单、作者格式、身份、类型/值域、重复声明、机制支持及依赖声明自洽 |
| 组合检查 | 所选准确版本及接受资格、依赖/顺序、逐模组引用与修改目标、最终跨领域完整性 |
| 新建/文件恢复 | 当前内置四包经生产 reader/compose，文件携带完整 frozen material/链并核对本版三种组合指纹；核全业务/历史后按应用 JSON 计划同事务建立 DDL/seed/规则/事实/控制，commit 后完整读回与 INITIAL P0—P3 接受后才执行。未来外部内容须另满足准确本地接受 |
| 运行命令 | 使用固定快照，在随机性和写入前验证选择、禁用状态、业务条件、版本及幂等 |

以下离线安装/接受要求用于现有来源维护与未来开放外部内容；当前内置四包不要求运行时
连接来源 MySQL 或为其伪造接受账本。可在依赖未安装时先安装结构合法的扩展；外部引用、准确版本与接受资格必须在实际组合
中核验，不能换成其他版本或跳过指令。基础无外部依赖，离线阶段须核验其声明范围；
当前基础与扩展共同闭合有限 profile，不把一个基础包或语言/工具分区当作完整 SRD。
逐模组输入与操作错误直接阻断，后续覆盖不能掩盖。合法操作全部应用后再检查最终一致性，
兼容模组可修正中间不一致，中间结果始终没有运行资格。旧界面报告不代替开始时复核。
诊断包含稳定错误码、发现阶段、说明和可取得的位置；重复声明指出双方，不能虚构来源。
作者位置绑定准确版本、制品摘要、包内路径与 JSON Pointer；JSON 未解析时使用字节偏移。

应用机制支持与内容发布分开判断：项目内建发布使用独立批准；自定义模组使用应用已有
机制时，目标允许经离线验证及本地 DM 对准确内容的显式接受独立发布，无需随应用更新。
未知字段或机制仍须应用支持，接受事实、安装成功及摘要自洽均不能越过机制与完整性检查。

“应用已支持”按[机制接入责任清单](mechanism-integration-checklist.md)逐机制说明合同、
真实消费者和验证证据。只有目录、参数模型或计算函数完成，不构成完整接入；模组作者
只能在已支持的准确机制范围内声明内容，不能通过接受记录补足未实现的执行或恢复责任。

目标接受事实独立且不可改写，绑定准确身份、角色、原始 ZIP/逻辑双摘要、相关协议和操作。
安装入口不授予接受资格；独立最小权限接受入口复核展示过的准确材料后原子登记，
应用只读，不由运行请求自动接受。接受提交未知按原操作查证，不换标识自动重试。
已接受准确版本绑定唯一原包；同逻辑不同 ZIP 或同版本不同逻辑均拒绝替换，修改使用新版本。
完整匹配的本机重导入可复用原事实；新来源环境仍须本地接受，包内声明不自动授信。
schema 2 的[离线安装与接受](../../rules/schema-2-installation-and-acceptance.md)按这些责任提供
独立维护入口与不可变事实；具体可接受范围、真实数据库采用门和运行阻断见该合同。
既有内建注册表与 schema 1 PARTITION 安装事实不因此转化为 schema 2 接受记录。

### 行为声明的目标接合

下面是目标支持族及其语义 owner，不是当前作者包已接受的新 discriminator。每一族的
字段、范围、事实来源、阶段及消费者由对应合同固定，规则包只能选择有限分支和参数。
实际作者编码须随消费者一次采用；不能先接受一个自由 `effects` 列表再猜测解释。

| 有限声明族 | 必须接入的权威合同 |
|---|---|
| 检定贡献、命中附加项、攻击替代 | [动作继续](action-continuation-protocol.md#check-stages)：真实 grant、适用 check、贡献时点/次数、准确成本与公开结果；擒抱及联动移动有独立领域分支 |
| 时间/恢复与跨空间关系 | [时间日历](time-and-calendar.md)、[因果范围](world-and-scene-spaces.md#causal-scope)：明确期限基准、日界归属、发生身份、范围证明及真实后果；不能以通用秒数或后台标志代替 |
| 区域、压制及持续后果 | [空间几何](spatial-and-area-contract.md#areas)、[持续效果](ongoing-effect-protocol.md)：有限形状/传播、完整目标及物件、作用 provenance、发生去重和结束消费者 |
| 形态与召唤 | [角色状态](character-state-and-history.md#form-health)：准确属性块、替换字段/健康策略、装备、生成/群组/退场及空间交接；不给作者任意复制或恢复 HP 的指令 |
| 物件、充能与储存施法 | [物件](objects-and-magic-items.md)、[施法](spellcasting-extension-contract.md#item-and-stored-grants)：真实物件授予、固定谓词词汇、资源接受、一次触发与真实储存收据 |

新增类型不继承任意未声明能力。例如火伤不自动点燃物件，效果名字不证明神祇来源，
储存标签不授权没有 consumer 的法术，叙事裁定不允许写任意状态。表外语义先作有界设计，
未闭合前拒绝对应声明；[复验报告](rule-behavior-interface-validation.md)保留这些边界，不能
用缩小后的替代轨迹改变原样例结论。

## 规则能力与应用存储模块

规则制品、规则模组、游戏机制和应用存储模块分别承担原包/接受、准确组合/覆盖、行为支持
及物理结构责任，不能因共用“module”称呼而相互授予资格。模组 JSON 只提供应用已知的
类型化规则、参数及引用；不提供 DDL、表名/列、SQL、表达式、驱动或本地运行/档案路径。
作者包内文件清单路径仍按严格制品合同校验。

应用随当前版本交付 JSON 完整结构定义，声明表、列、类型、主外键、索引、有限约束、
静态 seed 和存储模块依赖，由受限 SQLite 编译器生成 DDL 与初始化写入计划。该定义是
结构的完整声明源，领域仓储、校验和严格文件投影仍由应用实现。
它不向规则作者开放，不提供通用 ORM、多方言或跨版本迁移能力，也不泛化来源 MySQL。
当前复杂规则/角色/场景/历史采用严格 typed TEXT 聚合和逐行独立核验的关系投影；
无需把每个叶字段拆回旧 MySQL 表，但不得使用任意属性袋或恢复时修补投影。
具体模型、允许结构及编译拒绝条件见[存储结构与规划](storage-schema-and-planning.md)。

应用从强制核心、准确组合的全部规则/来源链、受支持机制的完整写入足迹，以及初始计划
或文件中的全部状态/历史/pending 引用取种子，沿封闭依赖计算最小闭包。后续合法命令
可能产生的结构须在初始化时具备；不能只取当前非空行或当前启用内容。禁用定义、历史
引用的终结实例、已支付成本和未结回调均不能遗漏。规则与链的结构支持不授予执行资格，
`BLOCKED` / `METADATA` 及禁用项仍按原合同拒绝执行。施法可能依赖资源/健康、装备、
动作流、反应、效果、专注和时钟，不能单凭一个法术分区关闭其他责任。

存储闭包按依赖与稳定模块 ID 确定装配顺序，不改变用户规则组合的加载顺序。未知模块/
能力、缺依赖、协议或结构冲突和未处理循环阻断初始化；文件不能自报省略分区来缩小闭包。
本地存储模型、精确模块清单和 `schemaPlanDigest` 不进入可移植规则摘要或战役文件。结构只在
新空私有库初始化，同版残留核验既有结构，不补表或重复 seed，初始化未知先查证原结果。

运行存储及真实引擎/文件系统验收见[规则存储](rule-storage-and-versioning.md)，逐域 owner
与字段覆盖及采用顺序见[数据覆盖与实施路线](storage-data-map-and-rollout.md)。应用声明
支持一个机制，须同时具备该闭包的执行、业务历史、文件与直接恢复工件；JSON 定义、
生成 DDL、目录元数据或接受事实均不能补足缺失的真实消费者。

## 固定运行材料与健康空闲切换

工具健康且真正空闲时可重新选择准确组合，无需为正常选择重启；未决提交、可恢复活动残留
或未隔离的清理故障均不算空闲，已封闭墓碑的处理沿[运行生命周期](runtime-and-transactions.md)。
活动运行固定完整准确组合，来源安装及预设编辑不改变它；文件恢复沿用存档原组合。
改变该组合须可靠保存并封闭原运行，再以新组合新建战役，不能继承旧状态和历史后更换
解释；查询筛选只改变可见范围，不改变组合或执行资格。规则切换不绕过故障查证、独占
所有权或新运行初始化边界。

当前准确材料由应用交付的四个原包决定，详细有限范围见
[包指南](../../../rule-packages/srd51-runtime/package-guide.md)。未来外部自定义内容的来源
MySQL 可保管准确原包/独立接受及可重建索引；现有来源代码仍按其合同逐列核验，
改变职责须连同 reader、installer、schema/权限和测试一起采用，不能由当前内置路线省略。

新建或 JSON 打开分配新的物理 core run、epoch 与随机私有目录，取得工具级/目录独占权。
目录/连接参数不来自文件或战役键。SQLite 保存完整准确 material/链、业务/历史/本地收据。
schema-2 prepared Identity 中 runId/snapshotId 是保留初始/历史的稳定业务引用，文件
打开不重新生成；它们不代表旧运行连接或 HTTP 权限。完整规则身份/业务归属由 typed
验证核验，关系索引独立对照；无跨库外键/事务或普通命令来源连接。

覆盖链包含初始值/无值、每次显式设置/清空/禁用/重新启用的前后值、准确提供者、加载位置
及作者位置；相同值覆盖仍保留，无操作不造步骤。每条链终值必须与最终快照一致。
开始前可查看检查结果，活动运行内的规则及来源查询使用本次持久化固定材料。

初始化先验证当前内置生产材料；未来使用外部来源时须先正常结束/关闭独立来源事务。再按完整存储闭包
编译应用 JSON 结构。在一个运行初始化事务中建立 DDL、静态 seed、本地模型/计划绑定、
组合、完整快照、完整覆盖链、业务/全历史及初始化收据。必须实际读回并独立核验结构、
seed、字段、链、引用和全部历史，
初始化 commit 明确成功，并完成[保存协议](save-and-recovery.md)的
首份完整检查点 P0—P3 接受后才发布执行视图；检查点缺失、失败或结果未知时保持阻断。
只核对头摘要、行数或内存对象不足，未知提交不发布部分候选。事务和故障采用
[运行与事务](runtime-and-transactions.md)的共同边界。

当前新建、JSON 打开、运行与同版残留都不要求外部来源在线。应用独占核完整 typed
material/链、本版 composition/final/chain、状态/全部历史/pending 和全部本地收据；
通过后显式新 epoch 才取得继续/保存/结束权限。已封存只清理，缺损/未知保留阻断，
不重放未持久意图、不补掷或用旧文件覆盖。未来外部包的准确接受资格须另行实现和验证，
不能由当前 frozen 内容或输入自报“已接受”绕过。
尚未接受首份完整检查点的残留须先完成原初始化/保存协议，不能绕过该门继续游戏。

## 五类摘要、规则制品与战役文件

| SHA-256 摘要 | 核验职责 |
|---|---|
| 原始 ZIP | 接受并保管的准确原包完整字节 |
| 模组逻辑 | 模组身份、准确版本、角色、逻辑声明、定义、条目及修改指令 |
| 组合配置 | 有序准确成员、各成员双摘要、相关协议及组合算法版本 |
| 最终规则 | 全部最终稳定身份、完整字段及启用状态，包含禁用内容 |
| 完整覆盖链 | 准确组合绑定、完整覆盖过程、前后值、提供者及作者位置 |

后四类各用独立规范编码与摘要域，不复用 RELEASED v1 持久化域。JSON 排版、文件拆分、
压缩信息不进入模组逻辑摘要；它们仍受原包及作者位置核验约束。最终规则摘要不包含
加载顺序、发布版本或覆盖过程；相同最终规则不能证明准确组合相同。
组合配置摘要不包含结果摘要；覆盖链绑定组合配置摘要，避免摘要循环。
数据库行 ID、run/snapshot、接受时间、操作标识和预设名不进入可移植规则摘要。

单模组以唯一 ZIP 交付并保管原包。准确组合规则包是可选外层 ZIP，包含有序清单、摘要及各
成员原始 ZIP，导出保留内层原始字节；它只承担分发/保管，不是第三份规则权威，不授予接受
或执行资格，也不要求来源和运行各维护一份组合包。规则制品与战役 JSON 文件分开保管。
当前完整战役文件除准确有序应用 rules 绑定外，还在 domains.material 保存完整
StoredMember、最终规则/entries 和 FieldChain。Material.restore 将四个完整字段集合
逐项精确比对本版已验证固定投影；复用其 composition/final/chain 指纹，并核全部业务/
历史，不逐次重新组合，也不能只按摘要从未知规则源重建。
当前使用独立 VITALITY_CAMPAIGN/format 1 应用协议，非旧 MySQL format 1，也非通用
完整 CAMPAIGN/format 2。未来完整格式与外部内容接合另行采用，旧内部角色片段不自动匹配。
记录算法版本不承诺未来保留旧组合算法恢复能力。完整业务文件仍按[保存与恢复](save-and-recovery.md)细化。

## 采用范围与受保护合同

当前 [CharacterCatalogAuthorPackageReader](../../../src/main/java/com/dndtool/module/CharacterCatalogAuthorPackageReader.java)
只读 schema 1，固定完整 SRD 键、release `"1"`、canonical/archive `2/2` 和语言/工具两分区；
它不读取本基线 schema 2、依赖或修改指令。
[Schema2CompositionKernel](../../../src/main/java/com/dndtool/module/composition/Schema2CompositionKernel.java)
独立实现[最小链路](schema-2-composition-validation.md#9-内部组合内核)规定的有限严格读取、
依赖与修改、完整局部投影及覆盖链；其原验证入口仍使用验证专用制品/摘要且拒绝生产资格。
[生产制品合同](../../rules/schema-2-rule-artifacts.md)复用类型化语义，另校验准确原始 ZIP 并编码
五类生产摘要；[安装与接受](../../rules/schema-2-installation-and-acceptance.md)和
[来源账本](../../rules/schema-2-source-ledger.md)保存独立维护事实，不授予完整组合运行资格。
[SourceInstallation](../../../src/main/java/com/dndtool/offline/rules/SourceInstallation.java)
只登记 PARTITION 安装操作事实，不产生完整内容摘要、DM 发布接受或运行资格。
[BuiltinModuleReleaseRegistry](../../../src/main/java/com/dndtool/module/BuiltinModuleReleaseRegistry.java)
仍是原 MySQL 模型的内建批准路径；当前 SQLite 四包由 BundledCampaignRules 提供独立
有限支持材料。语言/工具链路可复用，不等于通用组合平台。

本基线确定公共身份、作者/修改、组合/校验、接受、快照/链、摘要和文件绑定方向。
除最小组合链路和生产制品合同明确覆盖的有限类型外，其余逐领域字段、原子边界、规范编码
及独立字节向量仍须按范围规格化。来源 V003 不替代真实 SQL/权限、故障与容量验收，
完整运行快照、组合规则包和业务存档/恢复也须独立采用。
本基线仅涵盖上述公共合同；其他局部字段、机制
和实施草案需按对应范围核对并进入正式合同，不自动随本基线采用。

未配置 DND_STORAGE_ROOT 仍使用原 MySQL 运行链/来源迁移和 JNDI；配置后走独立有限
SQLite 的声明、严格聚合、共享事务和完整文件，实际覆盖/证据见接合表。原
Schema2InitializationPreparationService/CampaignArchiveFormatDispatcher 的旧完整资格门
不被改写，也不是该有限新路线的调用入口。真实 JDBC/文件系统/故障和独立恢复仍各自
取得证据，代码接合不表示迁移、部署或完整发布。

`dnd5e2014_srd51_se_v1` 保持 RELEASED 和新战役默认，身份、算法、摘要及格式 1 不变。
完整 `dnd5e2014_srd51_se` release `"1"` 保持 DRAFT，canonical/archive 目标仍为 `2/2`；
archive format 2 尚未正式激活，当前内部 DRAFT 投影不等于发布批准。
该完整规则族在完整领域与跨领域发布门通过前不得取得正式运行或默认资格。已应用迁移和持久化事实
继续不可改写；本文不授权安装、迁移、接受、发布、部署或默认切换。
