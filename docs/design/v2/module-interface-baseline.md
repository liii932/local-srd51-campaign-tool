# v2 模组接口基线

状态：下述公共合同已确定；有限 schema 2 组合内核、生产制品编码及独立安装/接受维护链路
已有实现边界；完整基础、逐机制支持、运行快照与恢复仍须分别采用。
本文是 [v2 设计基线](README.md)的模组公共入口，与[采用边界](adoption-boundaries.md)
共同区分目标、当前实现和后续规格。记录合同不代表已实现、安装、发布或部署。

## 组合结构与加载顺序

第一版每个组合恰有一个完整 `base`，允许零到多个 `extension` 和 `compatibility`。
基础模组可以由项目或自定义内容提供，须独立具备该体系运行所需的完整领域与机制。
基础可拆成多个领域作者文件；语言/工具分区或其他不完整片段不能冒充完整基础。

基础位于加载清单首位且无外部依赖；扩展和兼容模组至少有一个直接依赖，并通过依赖链
连接这个唯一基础。兼容模组使用相同修改协议，在其依赖之后加载，角色不带隐藏优先级。
本版不组合两个基础，也不以多个不完整基础片段拼装运行体系。

用户显式提供有序准确模组清单；同一模组只能出现一次并选择一个准确版本，重复相同版本
也拒绝。依赖先于依赖者，全部额外顺序约束必须满足；系统检查用户顺序，不自动重排。
后加载模组仅覆盖其明确修改的字段，未声明字段保留已有结果；作者文件顺序不产生优先级。

## 稳定身份、直接依赖与联合兼容

规则身份由原始所属模组、规则类型、稳定规则键组成；条目身份由所属规则完整身份、集合键、
条目原始所属模组及稳定条目键组成。引用和修改目标统一使用带 `kind` 的完整结构化身份，
本模组也不省略归属。身份不可由普通修改改变；准确发布版本另由组合清单绑定。

直接引用或修改外部内容必须声明直接依赖，不能仅靠传递依赖。条目身份中的规则所属模组
和条目所属模组均需检查，当前模组自身除外。显示名、目录名和数据库行 ID 不代替身份。
版本按准确 ASCII 字符串比较，`"1"`、`"01"`、`"1.0"` 不同；不取最大值或使用版本区间。

所有模组均显式提供依赖、联合兼容及顺序约束三个顶层字段，依赖项声明支持版本。
以下结构拒绝未知、缺失、重复字段、null 和坏类型：

| 字段 | 公共合同 |
|---|---|
| `dependencies` | 数组；每项恰含 `module_key`、`supported_versions`；拒绝自依赖、重复依赖 |
| `supported_versions` | 非空准确版本字符串集合；拒绝重复，不转换或自动选择版本 |
| `compatible_combinations` | 非空数组；每项完整映射全部直接依赖到各一个准确版本；拒绝缺项、多项、重复配对 |
| `load_order_constraints` | 数组；每项恰含 `before`、`after`；端点限声明者及其直接依赖 |

每个依赖的支持版本集合须恰等于其在全部联合配对中出现的版本集合；支持 A1/A2 与 B1/B2
不自动产生四种交叉兼容。无依赖基础固定声明 `dependencies=[]`、
`compatible_combinations=[{}]`、`load_order_constraints=[]`。
顺序约束拒绝自指向、重复、冲突和循环；合法冗余约束不撤销依赖顺序。
独立兼容模组显式依赖被协调模组，不提供依赖缺席时跳过修改的路径。

## 作者入口与字段修改

目标作者入口固定为 `author-package.json`，`author_schema_version` 为整数 `2`。
清单声明模组键、准确版本、显示名、角色、依赖/联合兼容/顺序约束及全部作者文件。
`files` 以 `kind`、包内 `path` 登记文件，用途为 `definitions`、`entries`、`changes`；
同用途可有多个文件，同路径只登记一次，各文件根为数组。作者清单不自报发布资格。
作者 schema、组合算法、canonical、archive 与数据库 schema 各有职责，不共同升级编号。

[schema 2 最小组合链路](schema-2-composition-validation.md)给出清单、结构化身份、类型化
声明与修改的具体输入，以及最终字段、完整覆盖链和拒绝条件；其中局部验证材料不取得
完整基础模组资格，也不改变现行 schema 1 作者源。

新增规则本体和集合条目分别提供完整声明，原始归属为当前模组，默认启用。
本体完整声明一次，条目可分文件收齐后组装；新增外部规则下的条目仍须检查直接依赖。
重复新增同一完整身份一律拒绝；领域内容使用固定类型结构，不采用任意属性袋。
修改只面向前序已加载模组的既有目标，缺失即拒绝；本模组新增对象直接声明最终内容。

| 操作 | 语义 |
|---|---|
| `set_field` | 设置一个领域原子字段的完整明确值 |
| `clear_field` | 将领域明确允许为空的字段置为无值，不恢复低优先级值 |
| `set_enabled` | 显式设置规则或条目的启用状态 |

未提供操作、设置值、显式清空分别处理，null 不作清空简写。复合字段的必要配套值整体覆盖，
列表/成长表/关系集合按稳定条目键新增、修改或禁用；第一版不整表替换，不提供加减、倍率
或表达式补丁。游戏中已支持的规则计算仍由应用机制负责。
同一模组准确版本的全部文件内，同一目标的同一字段只许修改一次；相同值重复也拒绝，
并报告两处作者位置。字段原子边界、允许清空范围及内容类型由逐领域合同规定。

定义不显式删除；禁用后仍保留完整内容、引用与来源。关系条目禁用只抑制该关系，
不改变目标定义状态。启用状态按最后一次显式设置决定，更高优先级可重新启用。
禁用项仍校验结构、类型和引用，可只读查看与身份引用，禁止新选择和直接执行。
职业自动授予的特性被禁用时，保留职业和授予引用，特性不生效；种族、背景或职业固定
授予的语言/工具熟练被禁用时，保留授予事实和来源并标记抑制，不产生有效能力或熟练加值。
必需能力或必选候选不足则阻断组合，只跳过领域明确允许忽略的效果。
检查结果列出禁用项及上述受影响的授予关系；其他领域授予语义由其领域合同明确。

## 四阶段校验与发布资格

| 阶段 | 必须完成的检查 |
|---|---|
| 离线安装 | 原包与文件清单、作者格式、身份、类型/值域、重复声明、机制支持及依赖声明自洽 |
| 组合检查 | 所选准确版本及接受资格、依赖/顺序、逐模组引用与修改目标、最终跨领域完整性 |
| 开始/恢复 | 重新完整读取实际来源并重新组合，核验初始/存档业务状态，按共同守卫建立快照 |
| 运行命令 | 使用固定快照，在随机性和写入前验证选择、禁用状态、业务条件、版本及幂等 |

可在依赖未安装时先安装结构合法的扩展；外部引用、准确版本与接受资格必须在实际组合
中核验，不能换成其他版本或跳过指令。基础无外部依赖，离线阶段就须自成完整基础。
逐模组输入与操作错误直接阻断，后续覆盖不能掩盖。合法操作全部应用后再检查最终一致性，
兼容模组可修正中间不一致，中间结果始终没有运行资格。旧界面报告不代替开始时复核。
诊断包含稳定错误码、发现阶段、说明和可取得的位置；重复声明指出双方，不能虚构来源。
作者位置绑定准确版本、制品摘要、包内路径与 JSON Pointer；JSON 未解析时使用字节偏移。

应用机制支持与内容发布分开判断：项目内建发布使用独立批准；自定义模组使用应用已有
机制时，目标允许经离线验证及本地 DM 对准确内容的显式接受独立发布，无需随应用更新。
未知字段或机制仍须应用支持，接受事实、安装成功及摘要自洽均不能越过机制与完整性检查。

“应用已支持”按[机制接入责任清单](mechanism-integration-checklist.md)逐机制说明合同、
真实消费者和验证证据。只有目录、参数模型或计算函数完成，不构成完整接入；模组作者
只能在已支持的准确机制范围内声明内容，不能通过接受记录补足未实现的执行或恢复责任。

目标接受事实独立且不可改写，绑定准确身份、角色、原始 ZIP/逻辑双摘要、相关协议和操作。
安装入口不授予接受资格；独立最小权限接受入口复核展示过的准确材料后原子登记，
应用只读，不由运行请求自动接受。接受提交未知按原操作查证，不换标识自动重试。
已接受准确版本绑定唯一原包；同逻辑不同 ZIP 或同版本不同逻辑均拒绝替换，修改使用新版本。
完整匹配的本机重导入可复用原事实；新来源环境仍须本地接受，包内声明不自动授信。
schema 2 的[离线安装与接受](../../rules/schema-2-installation-and-acceptance.md)按这些责任提供
独立维护入口与不可变事实；具体可接受范围、真实数据库采用门和运行阻断见该合同。
既有内建注册表与 schema 1 PARTITION 安装事实不因此转化为 schema 2 接受记录。

## 固定运行材料与健康空闲切换

工具健康且真正空闲时可重新选择准确组合，无需为正常选择重启；未决提交、运行残留、
结束清理未完成均不算空闲。活动运行固定组合，来源安装及预设编辑不改变它；恢复沿用
存档原准确组合。规则切换不绕过故障后重新准备、共同守卫或新运行初始化边界。

来源库保存各准确模组、原包、声明及安装/接受事实；组合不回写基础模组。
运行库保存有序组合、协议/摘要、完整最终规则快照及完整字段覆盖链，业务和历史以同一
`snapshot_id` 和完整规则身份引用它们，防止跨运行串用。两侧沿用类型化领域表，
不建立跨 schema 外键、跨库事务或普通业务对来源库的读取能力。

覆盖链包含初始值/无值、每次显式设置/清空/禁用/重新启用的前后值、准确提供者、加载位置
及作者位置；相同值覆盖仍保留，无操作不造步骤。每条链终值必须与最终快照一致。
开始前可查看检查结果，活动运行内的规则及来源查询使用本次持久化固定材料。

初始化先完整复核来源并形成固定材料，正常结束来源事务、关闭连接，再在一个运行事务
保存组合、完整快照、完整覆盖链、业务/历史及必要控制/结果事实。必须实际读回并独立核验，
明确提交成功后才发布执行视图；只核对头摘要、行数或内存对象不足。未知提交保持阻断，
不发布部分候选。事务和故障采用[运行与事务](runtime-and-transactions.md)的共同边界。

## 五类摘要、规则制品与战役文件

| SHA-256 摘要 | 核验职责 |
|---|---|
| 原始 ZIP | 接受并保管的准确原包完整字节 |
| 模组逻辑 | 模组身份、准确版本、角色、逻辑声明、定义、条目及修改指令 |
| 组合配置 | 有序准确成员、各成员双摘要、相关协议及组合算法版本 |
| 最终规则 | 全部最终稳定身份、完整字段及启用状态，包含禁用内容 |
| 完整覆盖链 | 准确组合绑定、完整覆盖过程、前后值、提供者及作者位置 |

后四类各用独立规范编码与摘要域，不复用 RELEASED v1 持久化域。JSON 排版、文件拆分、
压缩信息不进入模组逻辑摘要；它们仍受原包及作者位置核验约束。最终规则摘要不包含
加载顺序、发布版本或覆盖过程；相同最终规则不能证明准确组合相同。
组合配置摘要不包含结果摘要；覆盖链绑定组合配置摘要，避免摘要循环。
数据库行 ID、run/snapshot、接受时间、操作标识和预设名不进入可移植规则摘要。

单模组以唯一 ZIP 交付并保管原包；准确组合规则包为外层 ZIP，包含有序清单、摘要及各
成员原始 ZIP，导出保留内层原始字节。规则制品与战役文件分开保管。
战役文件使用 `rules` 绑定有序准确成员、各成员双摘要、必要协议/组合算法版本及组合、
最终规则、覆盖链三种摘要；不携带规则正文或含规则值的覆盖链。恢复从准确规则材料
逐项重算、核验并重新构建快照/链，仍须本地接受、机制支持及完整业务状态验证。
记录算法版本不承诺未来保留旧组合算法恢复能力。完整业务文件仍按[保存与恢复](save-and-recovery.md)细化。

## 采用范围与受保护合同

当前 [CharacterCatalogAuthorPackageReader](../../../src/main/java/com/dndtool/module/CharacterCatalogAuthorPackageReader.java)
只读 schema 1，固定完整 SRD 键、release `"1"`、canonical/archive `2/2` 和语言/工具两分区；
它不读取本基线 schema 2、依赖或修改指令。
[Schema2CompositionKernel](../../../src/main/java/com/dndtool/module/composition/Schema2CompositionKernel.java)
独立实现[最小链路](schema-2-composition-validation.md#9-内部组合内核)规定的有限严格读取、
依赖与修改、完整局部投影及覆盖链；其原验证入口仍使用验证专用制品/摘要且拒绝生产资格。
[生产制品合同](../../rules/schema-2-rule-artifacts.md)复用类型化语义，另校验准确原始 ZIP 并编码
五类生产摘要；[安装与接受](../../rules/schema-2-installation-and-acceptance.md)和
[来源账本](../../rules/schema-2-source-ledger.md)保存独立维护事实，不授予完整组合运行资格。
[SourceInstallation](../../../src/main/java/com/dndtool/offline/rules/SourceInstallation.java)
只登记 PARTITION 安装操作事实，不产生完整内容摘要、DM 发布接受或运行资格。
[BuiltinModuleReleaseRegistry](../../../src/main/java/com/dndtool/module/BuiltinModuleReleaseRegistry.java)
仍是当前内建批准路径；语言/工具链路可复用，不等于通用组合平台。

本基线确定公共身份、作者/修改、组合/校验、接受、快照/链、摘要和文件绑定方向。
除最小组合链路和生产制品合同明确覆盖的有限类型外，其余逐领域字段、原子边界、规范编码
及独立字节向量仍须按范围规格化。来源 V003 不替代真实 SQL/权限、故障与容量验收，
完整运行快照、组合规则包和业务存档/恢复也须独立采用。
本基线仅涵盖上述公共合同；其他局部字段、机制
和实施草案需按对应范围核对并进入正式合同，不自动随本基线采用。

`dnd5e2014_srd51_se_v1` 保持 RELEASED 和新战役默认，身份、算法、摘要及格式 1 不变。
完整 `dnd5e2014_srd51_se` release `"1"` 保持 DRAFT，canonical/archive 目标仍为 `2/2`；
archive format 2 尚未正式激活，当前内部 DRAFT 投影不等于发布批准。
完整领域与跨领域发布门通过前不得取得正式运行或默认资格。已应用迁移和持久化事实
继续不可改写；本文不授权安装、迁移、接受、发布、部署或默认切换。
