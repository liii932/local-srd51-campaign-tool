# 空间证明、联动安置与真实区域

本文是第四阶段的目标合同，负责距离、视线、体积、安置和区域的权威输入/输出。
当前程序仍是有限二维格点模型，见[采用边界](adoption-boundaries.md)；本文没有改变运行能力。
空间/焦点接纳归[世界与场景](world-and-scene-spaces.md)，物件事实与互动归
[物件与魔法物品](objects-and-magic-items.md)，时间归[时间与日历](time-and-calendar.md)。

本合同采用有界离散三维表示，不要求保留现有 Java Position 或旧文件。下述网格采样、
绕角传播、同距落位及无空间时的裁定是明确的项目解释，不宣称 SRD 规定了这些计算方法。
它们随机制解释版本冻结；运行时不能为了某次结果临时换算法。

<a id="spatial-proof"></a>
## 必要事实与查询证明

| 类型 | 必需字段与真实来源 |
|---|---|
| `PhysicalFrame` | 战役内稳定 ID、位面身份、封闭已知边界、布局版本。由 DM 的类型化地图命令创建；同世界节点或相同场景名不产生空间等价 |
| `SceneEmbedding` | scene/frame、整数平移和正交轴变换、版本；限制为轴交换/符号改变的刚体变换，不缩放。多个场景可嵌入同一物理 frame，独立时间仍由时间合同管理 |
| `Placement` | 主体/物件 ID、唯一位置分支、frame/scene、anchor、占位规格来源和版本。分支为直接安置、依附物件/持有者、暂隐、强制受限安置；物件父链另由物件 owner 管理，最终世界坐标只派生一次 |
| `SpatialLayout` | 有界静态实体、门/可动物件引用、阻挡体积、可通行面、光照/可见性及声音阻挡的封闭属性；动态门状态从物件 owner 读取，不另存一份 open 值 |
| `SpatialSnapshot` | 准确规则绑定、操作/阶段、涉及 frame/嵌入/全部安置/布局/感官/光照版本；查询范围内完整实体索引和有界空间证明。查询不修改位置或消耗 RNG |
| `SpatialProof` | snapshot 引用、请求的关系、确定的距离/接触/视线/传播/覆盖结果、全部依据和排除理由、采样阶段；UNKNOWN 是诊断，不能解释成无限远、无遮挡或无目标 |

长度单位固定为 1/4 尺，坐标为有符号整数，单轴绝对值不超过 2²⁰ 单位。场景显示格默认
5 尺；Tiny 的 2.5 尺占位能精确表示。形体用有限轴对齐包围体及稳定 anchor 表示；真实
体积和战斗控制面积分别保存。体积来自模板/形态规格或有界 DM 体积裁定，不能以 Size 名称
臆造唯一身高。每实例最多 32 个包围体，每次区域查询最多检查 2²⁴ 个格点/传播节点、4096 个
实体及 64 个区域裁切来源；超限在发起命令 RNG/付费前拒绝，不能静默裁掉目标。

同 frame 的距离由变换后的几何计算，平方比较使用受检整数，不使用浮点 epsilon。
位置到位置取规定的安置 anchor；实体之间的范围/触及取其战斗控制占位的最近格位基准点。
具体 reader 必须声明 `ANCHOR_DISTANCE` 或 `CONTROL_SPACE_DISTANCE`；不能在同次命令内混用。
Warding Bond/同调离身使用后者，Glyph 原点位移使用前者。不同位面或不同 frame 只有
明确登记的空间关系才能比较；无关系返回 `SPATIAL_RELATION_UNKNOWN`，不因切场景而自动结束法术。

跨 frame 的传送是两端已证明的安置操作，不把两个 frame 硬接为可测量的直线空间。
场景嵌入及布局修改必须预检全部依赖，包括 Glyph 位移、60 尺羁绊、同调离身和区域覆盖；
修改本身也有准确版本与根历史，不能借“编辑地图”跳过真实后果。

<a id="visibility"></a>
## 视线、清晰路径与覆盖分别证明

`WitnessQuery(observer, subjectOrPoint, sense, phase)` 返回可感知方式、距离、光照/遮蔽、
隐形等状态依据和 `SEEN/HEARD/NOT_PERCEIVED`。普通视觉由观察点到目标采样点的线段与
不透明体积相交判定，再消费观察者的真实感官；看见位置不等于看见隐形施法者。
特殊感官只有其声明的有限消费者可提供 `SEEN` 资格，听见施法不能替代 Counterspell 的看见。

`ClearPathQuery` 单独证明施法者到直接目标/区域原点的通路。透明实体可能阻挡法术却不
阻挡视觉；烟雾可能阻挡视觉却不阻挡通路。全掩护使直接目标不合法。看不见的区域原点若
被障碍截断，取原射线与阻挡体的最先交面，选择其近侧合法格点作为实际原点，保留请求点
与实际点。精确交点用整数比表示，不用浮点四舍五入。每轴枚举该交点格坐标的
`floor−1 … ceil+1`（至多 64 个候选），仅保留面对施法者的严格近侧半空间、已知边界内、
不在阻挡体内、在法术射程内且施法者到候选有清晰直线路径的点。按到交点的精确平方距离，
再按 x/y/z 排序取首项；并列首交面按稳定布局键定序，仍须同时通过全部实体阻挡检查。
无候选返回 `NO_LEGAL_NEAR_SIDE_ORIGIN`，不能把实际点推进墙内或默认为施法者脚下。
这是离散表示的明确取样选择，真实原射线上不必另有整数格点。重定向由服务端计算，仍须
完整预检实际点的区域和目标，不先付费再发现未知区域。

目标体积的格点集合/观察点均由安置规格唯一派生，不由客户端挑一个“有利角落”。
直线传播只保留从原点到目标点未穿过全掩护阻挡体积的点。部分掩护由布局上的
`NONE/HALF/THREE_QUARTERS/TOTAL` 覆盖面及射线关系派生，供检定/攻击 consumer 使用；
DM 对不易建模的遮挡可以先建立有界覆盖面事实，不能直接提交本次最终命中或豁免修正。

视线、路径和目标资格按动作/施法指定的阶段采样。窗口打开时的真实“看见正在施法”证据
保留；反应接受时复验仍适用的距离、视线、反应资源与该 cast 未终结。后来改变遮挡不倒改
已经接受的原骰/成本，未执行后缀使用新版本重新证明。

<a id="areas"></a>
## 区域的完整目标与部分体积

`AreaQuery` 必须给出 source/cast、frame、已证明实际原点、形状、尺寸、方向、
`DIRECT/RADIUS_WRAP` 传播、纳入的实体种类、采样阶段和依赖版本。形状为封闭的
`SPHERE/CUBE/CYLINDER/CONE/LINE`：半径/边长/高度/宽度是非负受检整数，方向是已登记
轴向或有限规范方向。球体含原点和半径边界；锥/立方/线的原点包含策略由法术规格决定。

球体点 p 满足 `|p-origin|²≤radius²`。立方按三个坐标区间，柱体按平面半径与高度，
锥按轴向距离及该处全宽等于距离，线按长度与宽度检验。实际效果采用这些形状在有界
1/4 尺格点上的集合；对象/生物的体积有任一有效采样点被覆盖即可进入对应目标候选。
对目标整体的魔法压制另按效果合同的稳定 anchor 判定，不能与面积裁切混为一谈。

`DIRECT` 在形状内再作原点到点的通路检查。Fireball/Glyph 爆炸使用 `RADIUS_WRAP`：
在原球体内从原点对六邻接可传播格点作确定性可达闭包，任何一段不能穿过完全阻挡表面；
只绕行到球体内可达点，不穿密封墙、不越出半径再绕回来。传播路径长度不替代原球体半径。
薄墙/关闭门的面相交也阻断邻接边，不能因面不经过格点而漏墙。开门改变完整可达集合。

`AreaResolution` 的必需结果如下：

| 结果 | 消费规则 |
|---|---|
| `geometry` | 实际原点、形状、原始覆盖、传播后覆盖、被独立区域裁掉的覆盖及各来源；无需存储另一份可独立编辑的地形 |
| `creatures` | 全部候选 ID、受影响部分、距离/掩护/可见性等证明、纳入/排除理由和版本；健康/检定 owner 再核规则资格 |
| `objects` | 全部物件/表面 ID、覆盖部分、穿戴/携带/容器关系、物理与魔法性质证据和版本；包括不受生物伤害分支影响的物件 |
| `dependencies` | 完整空间、实例、布局、对象父链、效果源和规则读取集合；请求不可提供缩减后的集合替代服务器查询 |
| `boundaryChanges` | 移动/生成/消失/开合导致的前后覆盖差，标明真实原因与发生身份；交给效果 owner 判断触发，不直接产生伤害 |

区域与 Antimagic Field 的交集/差集在同一格点模型内计算，独立原因取并集，删除一个原因
只删除其覆盖。一个区域部分被抗魔裁掉不结束整个源；抗魔场彼此不裁掉对方，神器/神祇
例外按效果源证明判断。派生覆盖可以缓存，缓存键含全部版本，不进入第二份权威 current。

Fireball 的对象消费者对全部覆盖的可燃、未穿戴且未携带物件提交 `IGNITE`，不对这些对象
冒造 DEX 豁免。零生物仍执行对象后果；零生物且零可燃物是合法已付费无效果。
若没有需要伤害骰的真实 consumer，则不为“动画”抽 8d6。已穿戴/携带物件的排除依据必须
保留，物件不能以客户端名单遗漏。燃烧的后续损伤按物件的明确燃烧规格处理。

实际区域超出已知布局时，完整查询必须先取得该 frame 的相邻布局事实；缺少事实或达到
预算上限整个请求拒绝。无法证明“区域外没有目标”不能当作空集合。持续区域移动和开门
同样要证明新覆盖内完整集合，不允许先提交位置再发现不支持的消费者。

<a id="coupled-move"></a>
## 联动移动与真实边界

动作 owner 的 `CoupledMoveRequest` 给出主移动者、受影响主体/物件的稳定 ID、真实关系
（例如 Grapple）、完整路径、各段牵引模式、原安置、行动/关系/空间版本和预算。空间 owner
返回 `CoupledMoveResult`：逐段各主体候选安置、合法性/路径成本依据、真实跨界证明和
全部触发候选；它不扣动作、不抽骰、不改变关系或 HP。

擒抱拖带由主移动者指定服务端核验的被拖目标随行路径；每个段末都须在合法触及内，不能
只验证主移动者终点。先核整个可预判路径/占位/全部目标，随后逐段执行：

1. 在原位置处理主移动者离开触及的 BEFORE 窗口；被动拖动者不因这种非自身行动移动触发 OA。
2. 若窗口后擒抱、速度或资格已失效，保留原已走前缀，停止或重建合法后缀，不回滚真实攻击。
3. 当前段所有安置与主移动者消耗一次提交；被拖者不扣自己的移动额度。大小差/拖带减速
   由动作规则解释，空间只提供 Size、路径和地形证据。
4. 提交该段真实 entry/exit/物件位移事实，再结各自 AFTER 后果；若需等待，所有成员保留
   同一个已走段号。Glyph 容器移动、羁绊超距和区域触发不会落在彼此不同的“半段位置”。

每次位移原因区分 `SELF_MOVE/DRAG/PUSH/TELEPORT/AREA_MOVE/SPAWN/RETURN`，由真实 producer
签入内部计划；作者/客户端不能自报来绕过 OA。区域扫过静止主体不是该主体的移动 entry，
效果是否触发由其合同决定。瞬移只消费离开/到达关系，不伪造经过中间每格。

<a id="placement-transition"></a>
## 生成、变形、暂隐与强制回归

`PlacementTransitionPlan` 的输入包含 producer/phase、主体集合、前状态、当前和目标
占位规格、固定 anchor、原因、依赖关系、候选 frame/界限、版本与返回 checkpoint。
输出为每主体安置结果、完整碰撞依据、区域关系变化、真实不再占位事实以及待解决位置叶子。
生命周期由角色/效果 owner 决定；空间不能因“不好放置”复活已结束的来源或复制主体。

自愿生成/变形的可知初始落位不合法在初次成本/RNG 前拒绝。随机失败/成功都有合法的
后果和保存空间。自动回转/返回采用以下顺序，作为项目明确采用的无原文细则时的裁定：

1. 原 anchor 正常落位；如规则允许挤入小一级空间，则保留原 anchor 并标记正常 squeezing。
2. 无法在原位落下时，在原 scene/time domain 与同一已知 frame 内按距离、x/y/z
   确定性排序找最近合法 anchor；不跨越未知布局、位面或其他场景。跨空间安置只能由
   另有完整交接许可的显式转换提出，不能借共享 frame 偷换主体的时间域。
   计划同时携带本次已确定的 `requiredSuppressionMode`：候选须
   保持引发本次转换的压制/非压制模式。召唤返回须处于全部适用抗魔区之外，不能选到另一
   抗魔区再立即消失；形态转换也不能靠寻找新格反复翻转本次模式。实际位移和原因进入
   历史，其他区域和距离后果仍须完整处理。
3. 完全无合法点时建立 `WAITING_PLACEMENT`。来源终结及目标形态/返回义务已成立，尚未
   解决的是安置，暂停时间/父后缀。DM 只能在此叶子选择已证明的新合法位置，或下列有界裁定。

保证存在的裁定出口是 `CONFIRM_CONFINED_AT_ORIGINAL_ANCHOR`：服务端固定原 anchor、真实
形体和相交对象集合，DM 记录原因后形成 `FORCED_CONFINED` 安置例外。它如实记录被迫
重叠，不删除障碍、不传送、不修改 HP，也不新增失能 condition。角色仍存在，动作按自身
规则和实际通路判断；下一段自愿移动必须取得正常合法安置，不能把例外变成穿墙许可。
另可选择 `EXPAND_AND_PLACE`，仅限原 scene 在同 frame 的边界扩展及完整已知空闲区域的证明，不能顺手
改其他主体或障碍。两种裁定均遵守本次压制模式；受限原位使用引发转换的原 anchor，
不借裁定改变抗魔资格。两种裁定都使用共同预检、权限、版本、根历史和幂等，不是自由状态编辑。

AMF 内暂隐的召唤主体保留身份、HP、命令和时间依赖，空间记录 `ABSENT_BY_SUPPRESSION`
与返回锚点，不保留阻挡别人合法移动的虚构占位。解除最后一个原因后用上述计划返回。
期间来源结束则永久退场，之后解除压制也不再返回。

位置等待保存稳定 `placementEpisode`、原 anchor/scene、触发事实、要求模式与已完成前缀。
等待期间发生获准的被动变化时，由同一 scope 的真实边界消费者处理旧义务，不能只让
旧候选永久 stale：来源终止优先将召唤返回置为 `CANCELLED_SOURCE_ENDED` 并按退场规则
收束；又被抗魔覆盖则置为 `CANCELLED_RESUPPRESSED`，同一主体保持暂隐和原 HP，不执行
旧 RETURN。之后最后一个真实原因解除才能产生新 episode。形态因新的真实压制/结束边
改变目标身体时，关闭旧位置计划并为当前合法身体建立新计划，已结伤害/溢出、成本与来源
结束都不重做。只改变占位的事实则重算同 episode 合法候选，保留当前要求模式。
取消、重规划、原 flow 失效与准确新叶子同事务保存；重复边界不再创建 episode。

Polymorph 的压制资格使用不随形态 footprint 改变的稳定主体 anchor；大小改变重新计算
实际占位和其他区域覆盖，不反复用新大小推翻同一轮自身压制判定。结束/回归不是自愿移动，
不消费移动额度或触发 OA；确有 entry 的其他效果按其明确政策处理。

## 原子后果、恢复与拒绝

查询结果只在其完整版本集合和阶段有效；接纳、每次继续、强制返回均重验。空间变化与
对象互动、关系结束、形态/召唤事实、效果贡献、flow 前缀、根子历史和接受收据一次提交。
在多个空间发生的被动结果还必须满足[跨空间政策](world-and-scene-spaces.md)，空间证明
本身不赋予后台执行权。

完整文件保存 frame/嵌入/布局、每个稳定对象的唯一安置、形体来源、暂隐/受限例外、原位置、
操作原因、placement pending 与全部前后证据。历史中的 AreaResolution 保留其采样版本和
真实目标/排除结果，不能按打开时布局重选过去目标。恢复只核验并装载，查询不触发 Glyph、
点燃物件、解除抗魔或自动完成位置裁定。

错误区分 `SPATIAL_RELATION_UNKNOWN`、`INCOMPLETE_AREA`、`ILLEGAL_PLACEMENT`、
`STALE_SPATIAL_PROOF`、`SPATIAL_CAPACITY` 和损坏的引用/几何。纯预检拒绝零骰/零写入；
合法强制回归进入等待不是数据损坏。重复请求返回原结果，同键异意图拒绝；末尾物件失效
不能留下前面生物已受伤或半个联动位移。落库失败按共同事务回滚，已提交响应丢失只查收据。

## 纸面复验入口

- V06：球内绕角可达、密封墙不可达、部分被抗魔裁切、可燃物单独存在与最后物件 stale。
- V04：拖带原位 OA、两主体一段提交、关系中断后停止、后续保存不重复消耗移动。
- V08/V09：形态归零回转、抗魔大小变化稳定、召唤暂隐后原格被占、无合法格的确定等待与裁定。
- V13/V14/V16：真实物件父链、Glyph 位移 10/15 尺、跨场景有/无 physicalFrame 的距离证明。

这些是合同的手工推演入口，行为复验与原结论对照集中在
[接口验证报告](rule-behavior-interface-validation.md)，不是自动化测试通过记录。
