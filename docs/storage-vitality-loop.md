# SQLite 当前有限战役：规则、运行与完整文件

本页规定显式 SQLite 模式的当前使用方法、数据责任及同版文件生命周期。
`DND_STORAGE_ROOT` 启用此模式，`/host` 进入 `/host/storage`；未配置时仍使用原 MySQL
简化模式。两者在启动时选择，不双写、不因连接或文件错误自动切换。现有 MySQL 真实
数据、迁移、账号和格式 1 存档须独立保管，不能把启用 SQLite 当作数据迁移。

当前应用模型为 `applicationModel=campaign-spaces-3`、`storageModel=sqlite-campaign-3`。
所有新战役采用完整领域状态和准确规则组合；简单角色由自由卡承担，不再提供独立 HP
记录或定额治疗创建模式。旧应用/文件模型明确拒绝，不转换真实数据。当前有限支持范围
不代表完整 SRD `RELEASED` 或 MySQL 的完整 archive format 2；见[领域接合表](design/v2/domain-integration.md)。

## 选择规则与开始使用

1. 在 `http://127.0.0.1:8080/host/storage` 的本机规则库导入作者 ZIP，或逐个导入应用候选。
   审阅准确身份、角色、双摘要、依赖和可读声明后，明确接受每个包。导入不等于接受。
2. 按顺序加入一个 base 与零到多个扩展，最多八包。预览须通过准确接受、依赖/顺序、
   最终引用及当前机制/创建模板校验，之后创建战役。已有机制允许新内容与覆盖；未知机制、
   缺少执行 owner、无效模板或超预算均在分配运行前拒绝。选择/预览本身不产生接受记录。
3. runtime 的规则卡可创建 fighter、Life-domain cleric、Wizard PC/NPC，查看初始/当前卡，
   使用角色、装备、检定、健康、成长、资源、休息及场景动作；HP 和伤害/死亡状态由真实
   规则拥有。规则卡从未安置、累计经历为零开始；执行游戏命令前先安置到焦点。
   法师完成短休时，可在成长与休息表单选择已消耗的法术位进行奥术回想；全部为零可放弃。
   后端核验法术书、等级预算、位数缺口和角色累计经历时间的日界，保存与重开保留使用日。
4. runtime 同时提供独立 DM 自由卡，可从空白或 NPC 模板创建，编辑基础字段、职业等级、
   技能/豁免熟练及简单物品，执行 MANUAL、属性、技能或 SAVING_THROW 检定和有序分支
   后果。自由卡保留自己的初始/当前卡和全部根历史，不转换成规则卡；HP 为零仍是记录值。
   两种卡使用同一网格和安置合同。DM 裁定场景可包含自由卡、规则卡和怪物，DM 显式切换
   探索或战斗模式。规则场景的自动行动由具备准确规则事实的主体参与。
5. 世界节点、场景、安置、简单物品、角色资料和消息共用战役根历史。只有执行焦点可写入
   游戏事实并推进时间。后台的角色、效果和 pending 保持原态，切回后核对新的焦点代次。
6. 保存生成不可变完整 JSON；继续游戏不会修改已有保存点。结束先接受最新 FINAL，
   再封存并清理原运行。打开保存文件建立新运行，保留原初始事实、消耗、骰子及全部历史。
7. 浏览器刷新只读当前状态。重启发现残留时先显式恢复或精确放弃，不自动新建或用旧档
   覆盖尚未保存的最新提交。上传导入、下载、打开、删除与放弃残留分别针对准确身份。

## 跑一段短冒险

使用[测试指南](testing.md#sqlite-结构完整文件与运行验收)的隔离启动入口，准备空白私有
存储根，等待应用就绪后打开工作台。可用“旧哨塔”作为短冒险：

1. 导入并逐个审阅接受下表标准四包，按顺序选择、预览并创建战役。建立营地和哨塔两个世界
   节点，浏览营地并设为执行焦点，添加营地到哨塔的路线。
2. 建立战士 PC 和守卫 NPC，在营地首次安置。分别取得武器并装备到主手，执行一次探路检定，
   查看服务器骰点及分支后果。选中需要旅行的角色，填写本次裁定分钟数和说明，沿路线转移。
3. 在哨塔建立规则场景，从锚点入场时为双方选择相邻格及不同阵营。开始战斗后按当前先攻
   行动，先开始攻击动作，再选目标和已装备武器。出现待处理行动时，选择反应或放弃，
   再按当前继续点结算。可切换焦点并保存，切回后读取该空间保留的继续点。
4. 结束战斗后角色仍在场景内探索。显式离场回到锚点，处理全部场景义务后可关闭空场景。
   “保存”保留完整文件并继续游戏；“保存并结束”接受最终文件后封存当前运行。
5. 正常结束后关闭浏览器，再次打开工作台并打开所需文件。刚结束时页面会选中本次最终
   文件；各文件保留自己的进度，不能根据列表顺序推断哪个文件最新。继续后确认角色、
   装备、位置、骰点和记录保留，再执行下一步冒险。

请求处理时工作台显示进行中的操作并暂时禁用提交。普通成功操作直接采用服务器返回的
完整状态；创建、打开、恢复、结束等改变运行权限的操作仍刷新 Session。失败或响应不明时
先重新读取状态，不自动重发游戏命令。直接关闭浏览器不等于结束战役；应用重启后若发现
未结束运行，应选择“恢复战役”保留最新提交，而不是打开更早的文件覆盖进度。

## 可选玩家入口

玩家入口仅用于上述 SQLite runtime，另需显式玩家配置和独立 HTTPS Connector；
默认仍关闭，配置与网络边界见[配置说明](configuration.md)和[安全模型](security.md)。
DM 在工作台开放邀请、核对申请并批准设备，再分配 PC、共享内容及探索许可。玩家只能
看到服务端白名单视图，执行当前候选；成员身份或 PC 键本身不提供访问权限。

当前候选覆盖有限规则卡的装备/资源、战斗回合、移动、攻击、有限施法及反应/继续；
探索操作须有对应许可，仍逐条经过规则预检。自由卡可分配控制并查看，但玩家没有其
动作候选。DM 可拒绝文字提议、给出叙事回复，或对有限规则 PC 执行有理由的属性检定；
当前不提供通用裁定执行器。文字沟通尚未执行为业务事实时只存在于当前网关内存。
DM 仍独占完整文件管理与保存/结束；玩家不通过重新连接自动补发游戏命令。

## 有限 schema-2 规则材料

runtime 的作者源在 `rule-packages/srd51-runtime/`，资源在
`src/main/resources/storage/rules/`。`BundledCampaignRules` 经
`ProductionRuleArtifact.read` 验证每个原始 ZIP，再调用
`ProductionSchema2Projection.compose` 建立生产投影；不从测试 fixture 取得规则，
不使用来源 MySQL 的安装/接受账本。五个应用候选可组成以下标准或家规四包组合，
与外部包一样由本机规则库登记导入及独立接受：

| 包 | 角色与直接依赖 |
|---|---|
| `srd51_runtime@4` | base；语言/工具/熟练/角色来源与休息等基础 |
| `srd51_characters@4` | extension；直接依赖 `srd51_runtime@4`，声明战士 Extra Attack 与勇士 Improved Critical |
| `srd51_magic@4` | extension；直接依赖前两包 |
| `dm_runtime_house_rules@7` | 标准组合的第四成员，extension；直接依赖 `srd51_runtime@4` |
| `dm_runtime_house_rules@8` | 家规组合的第四成员，extension；直接依赖 `srd51_runtime@4` 与 `srd51_characters@4` |

标准组合选择家规 @7，变体选择 @8。变体的运动技能改用感知、
固定直接伤害从 6 改为 3、工匠背景固定语言从矮人语改为侏儒语。这是内容覆盖，不增加新
算法，也不代表 SRD 原文。说明见[变体指南](../rule-packages/srd51-runtime/dm-runtime-check-variant/package-guide.md)。

解释合同、原始/逻辑摘要、完整身份、最终规则和每个字段的完整链固定在本次工作库内。
`CampaignRuleContext` 从完整冻结材料重建，核对全部摘要和当前应用机制/模板支持范围；角色
创建计划、候选、执行和目录来源均使用该上下文。准确身份包含模组、类型与键，不按显示名
或局部键合并外部内容。新建与文件打开从已接受原包重组；打开逐项比对所有冻结材料。
最多两份上下文缓存以完整不可变材料为键，损坏规则行或链不能借相同摘要绕过校验。
改变成员、版本或规则解释必须新建战役，不在历史上热改规则。
缺少新解释/绑定字段的旧 runtime 文件明确拒绝，不补默认值或转换。
数据来源、许可、确定性构建和完整限制见[包指南](../rule-packages/srd51-runtime/package-guide.md)。

Fighter 支持到职业 6 级、Life-domain cleric 到 1 级、Wizard 到 5 级。当前角色是有限应用
profile。种族属性提升、完整背景技能和起始装备整包均超出该范围。
勇士 3–6 级的[精通重击](rules/schema-2-improved-critical.md)由真实子职业授予驱动，普通近战、OA 与 Ready
选中 19 或 20 时重击；未决反应与原骰沿完整文件保留。战士正常升到职业 5 级
获得[额外攻击](rules/schema-2-extra-attack.md)，单职业战士可在自己回合的一个 Attack 动作内
执行至多两次有界近战攻击。其余未接入的 Fighter 特性和 Evocation Savant/Sculpt Spells
保留为 `OPTION` 目录，选择的 Champion/Evocation 身份仍保留。Wizard Spellcasting、
Arcane Recovery 和一级 Life profile 由各自施法和休息消费者解释。
Grappler 仅保留阻断元数据，不允许在当前 SQLite 运行中获得；缺少执行 owner 的自动影响失败关闭。

施法只支持 Bless、Cure Wounds、Shield、Counterspell 和 Burning Hands 的有界算法；
其余 Wizard 法术只可作为学习/准备元数据。多施法职业共享槽不得由独立资源拼凑。
Hell Hound Fire Breath 是唯一可执行怪物动作，其他动作明确为 metadata。
DM 抗魔区域及固定直接生命效果是显式家规，不称作 SRD 法术或物品。

## 结构、所有者与事务

结构唯一源是 `src/main/resources/storage/campaign-schema.json`。
`StorageSchemaCatalog` 严格读取应用声明，`StoragePlan` 计算依赖闭包、纳入原因与计划摘要，
编译 DDL/索引/静态种子，并由 `SqliteSchemaVerifier` 核对真实 SQLite。选择规则缺项不
自动补选；结构依赖则完整纳入，包括空角色集合以后可能写入的表。结构不能来自请求、
规则作者包或战役文件。新建/文件打开建立新库，同版残留恢复不补表、迁移或重 seed。

| 所有者 | 当前职责 |
|---|---|
| `HostStorageServlet` 与安全过滤器 | 解析有限命令，验证 loopback、Session/CSRF、来源、epoch、revision、请求 UUID/摘要；不接物理路径或 SQL |
| `CampaignStorageService` | 持接纳门及实例锁，协调初始化、同一 SQLite 业务事务、幂等、保存/结束、打开和恢复 |
| `CampaignDomainEngine` | 无连接的领域执行/预检和历史验证，复用已有纯角色/战斗规则，控制随机性及跨角色时间/后果 |
| `CampaignSpaceData` / `CampaignSpaceCommands` | 唯一安置、规则或 DM 场景、焦点与代次、空间钟、怪物身份和世界交接；协调角色累计经历与实际场景后果 |
| `CampaignDomainData` / `CampaignDomainCodec` | 封闭 record 类型、准确规则/字段链、初始计划、当前状态、完整角色/场景/因果历史与未决动作 |
| `CampaignDomainRepository` | 在调用方事务写聚合文档及关系投影，读回逐行独立核对，不自行提交、回滚或修复 |
| `CampaignCodec` / `CampaignDomainValidation` | 核验整场战役、根/子事件归属、历史邻接、当前状态和准确规则，产生完整便携文件 |
| `CampaignParticipationCommands` / `CampaignAdjudicationCommands` | 成员、控制、共享、探索许可与有界裁定；真实操作者、决定、结果和根历史共同提交 |
| `PlayerGatewayService` / `PlayerCampaignProjection` / `PlayerCandidateFactory` | 运行私有授权、单写/暂停、逐人白名单视图和纯规则候选；经同一 `CampaignStorageService` 门提交，不取得原始连接 |

领域文档是带封闭 discriminator 的严格类型化聚合，不是任意 JSON 属性袋。未知/缺失字段、
未登记类型、错误标量、坏 Unicode、非法映射顺序或越界集合拒绝。数据库同时保存可核对的
资源、装备、法术书、场景/动作帧、效果、怪物等关系投影；聚合与任一投影不符时拒绝，
不重建一份“看似正确”的索引后继续。

`CampaignCheckEffects` 承接成功/失败两条有序效果分支：健康必须引用支持的健康规则，
简单物品用有界 delta，消息独立记录。两分支完整预检后才掷骰，实际后果及原骰同根提交。
位置变化通过单独的空间意图提交。`CampaignManualData` / `CampaignManualCommands` 接合独立
DM-managed 自由卡、职业等级/熟练与 MANUAL/SAVING_THROW。共享安置及场景按[空间合同](design/v2/world-and-scene-spaces.md)管理。

初始化的 DDL、seed、准确规则、战役事实和控制同一事务提交；独立连接完整读回且首份
检查点接受后才开放游戏命令。每个领域命令先验证完整冻结规则、对象/目标集合、版本、
领域集合/事件计数容量和继续义务，再消费真实随机性；当前状态、原骰、全部根/子历史、跨对象后果、版本及
幂等结果共同提交或回滚。实例根锁、串行接纳门和一个 `BEGIN IMMEDIATE` 覆盖该次
接纳及业务提交，不另设独立 C0 或 NOT_COMMITTED 裁定。commit/rollback 未知时禁止
新写，显式 recover 核验真实库、完整历史和全部接受收据后建立新 epoch；未持久意图
不自动重试或重播。不会调用另一条 MySQL 服务事务保存其中一部分。
分配首先以原子目录创建发布 `.prepare-<runId>_<inputDigest>_<planDigest>_<inputLength>`
归属绑定；此阶段只允许空锁及原输入/分配的 `.part`、`.json` 固定槽，不得存在数据库。
原输入以 runId 为文件身份，完整字节、长度和计划均须匹配目录绑定，分配内容严格核对。
完整文件经 force/读回后以硬链接发布，再将验证完成的目录改名为 runId；已有目标拒绝。
数据库开始标记先于首次打开数据库，之后数据库缺失时拒绝重建，避免把丢失的已提交库
当成未初始化。运行目录改名由实例锁串行化；应用不把持同账号的外部文件篡改视为受支持
并发操作。
完整候选的 16 MiB 文件字节上限在纯结果产生后、任何领域 SQL 写入前核验；超过上限则
拒绝本次结果，不记录其随机事实、不改变原状态或截断历史。领域事件预留不是所有后续
文件体积的预留，不能据此宣称无限历史或最坏体积已通过容量验收。

连接固定 SQLite JDBC `3.50.3.0`、UTF-8、`journal_mode=DELETE`、`synchronous=EXTRA`、
`foreign_keys=ON` 与有界 busy timeout，并读回核验。数据库文本按原始 UTF-8 字节严格
解码。实例锁覆盖整个受管根，业务/保存串行接纳，原始写连接不交给 Servlet 或规则消费者。

## 本机规则库与中断恢复

`rule-library/originals/` 按真实 SHA-256 保管不可变原始 ZIP，`ledger.db` 保管导入绑定、接受和
原操作收据。一个模组键/版本只允许一个角色、协议及双摘要；修订内容必须采用新版本。
导出返回原始字节，不重新压缩。规则库锁与运行事务分开，普通游戏、保存和残留恢复不读规则库。

浏览器保留未决导入/接受的原操作 UUID 与意图，先查询并查证该操作。提交已确认时返回原结果；
证明未提交才允许同键同意图续作，原包发布后未登记也只能由原意图复用。缺损材料或未知结果
保持阻断，禁止换键跳过。库写入和新绑定会等待查证，健康活动运行继续使用冻结材料。
持久记录、文件发布和故障边界详见[本机规则库](design/v2/local-rule-library.md)。

## 完整文件与直接恢复

文件为 `fileKind=RULE_BOUND_CAMPAIGN`、`formatVersion=3`，不属于 MySQL 存档协议。
根字段为 `applicationModel/campaign/domains/fileKey/fileKind/formatVersion/integrity`。
领域根历史是唯一历史权威，不再重复存储外层 HP 角色、事件摘要或规则 profile。
业务整数用规范十进制字符串；完整根 canonical 对象键排序、数组保留业务顺序，使用
`DND-CAMPAIGN-FILE` 域和 canonical 1 的 SHA-256 完整性绑定。

runtime 的 `domains` 保留准确成员/最终规则/完整字段链、每个角色加入时的初始计划与标准
数组初始事件、当前状态及所有角色事件、全部场景历史、节点、唯一安置、焦点代次、各空间
逻辑钟、简单物品和连续根因果事件。角色状态保留累计经历及个人恢复期限。所有场景的动作
流/叶子、反应窗口、原骰、效果、怪物和充能随类型化历史保存。校验按根的原请求和保留骰
纯重建各历史前缀，核对状态、空间和全部子事件；未决后缀在本次打开后等新的合法命令。
`CampaignDomainValidation` 最多缓存两份已核验的不可变快照。只有完整根前缀精确相等时
才复用已核验前缀，新根仍逐条核验，最终完整状态必须相等。

`domains.participation` 保存稳定成员、PC 控制、共享与探索许可；根事件的类型化
`actor` 保存实际 DM/PLAYER、行动角色及被代表成员，已执行裁定同时保存明确决定与结果。
这些必需字段由完整历史重建核对，旧文件缺项不静默补造，也不因保存了成员键或控制关系
取得连接权限。运行私有 `core_player_control` 的暂停、设备凭据摘要和已发送请求关联
不进入完整文件；文件重开建立新 run，须重新批准设备。

文件不含 SQLite DDL、物理结构计划、路径、HTTP Session、CSRF、当前安全 epoch 或本地
请求收据。保留的角色准备身份属于业务事实；打开文件只分配新的本地运行/安全权限，
保留身份用于因果引用。纯核验完成后直接装载已记录事实，读取不调用实时 RNG、不写入
历史结果，也不补算冻结空间的时间。

## 保存、导入、删除与残留

P0 用短控制事务固定保存意图和源 revision；P1 在受管档案目录写临时文件、force、关闭并
读回；P2 通过同目录硬链接原子发布唯一 fileKey，POSIX 平台同时 force 目录，Windows
按[平台落盘合同](configuration.md#sqlite-当前应用存储配置)保留明确的目录元数据限制。
P3 从正式文件独立核验后接受收据，FINAL 与封存在同一事务。硬链接不受支持就失败，
POSIX 目录同步失败也拒绝，不降级为覆盖复制。
文件 I/O 不持数据库事务。未完成 P3 的文件不列为可打开保存点，原工作库保留为恢复源。

上传导入先严格读取完整文件，再保留文件原 fileKey 登记受管文件；已有同 fileKey 仍返回
`FILE_CONFLICT`，不重新分配身份、覆盖或冒称另一次导入成功。若发布后响应中断，同字节
重试可在独立核验正式文件后，清除同 fileKey 且完整字节与身份均相同的暂存硬链接或副本；
未知、部分、异字节或符号链接暂存均保留。上传本身不激活运行，也不授予规则接受。
打开文件需在本机导入并明确接受所绑定的准确原包；相同逻辑但重新压缩的 ZIP 不能替代原包。
下载只读取已经核验的准确受管文件，不接受任意路径。删除保存文件先排除活动/残留运行及
收据依赖，核验正式文件后先清除上述可证明同属该完整文件的暂存名，再删除正式文件；
中断不能先失去正式文件而遗留已确认的暂存。删除不结束运行，也不删除规则来源包。
精确放弃只处理明确的非活动 run：取得锁、核对分配/隔离材料与受控白名单后清理，保存点
保留。未知文件、身份不符或锁冲突均阻止清理，不能递归移除未知内容。

END 先重新核对 FINAL 与完整源状态并持久化清理材料；清理中断后只继续准确封存流程，
不能重新开放游戏。正常停机释放进程资源，并保留未结束运行供显式恢复。浏览器关闭只
中断页面交互，Session 到期只使相应会话失效，服务与当前运行继续。以上操作均不隐式 END。
恢复原残留核对模型、计划、真实结构、规则、全部事实/历史及保存收据，不重放 DDL、seed
或游戏命令；缺库、部分结构或坏材料保持阻断。不能手删热 journal 或用旧文件覆盖新提交。
同一 run 的 `core_player_control` 随私有工作库保留；恢复推进 epoch，旧 Session、写连接、
邀请码和临时提议失效。DM 重新开放后，未过期且授权版本仍匹配的原设备可重新认证，
并用原请求的准确关联材料只读查证收据；仍须显式取得新写连接。打开完整文件则建立
新 run，设备须重新批准。

| 失败位置 | 恢复责任 |
|---|---|
| 规则/结构/输入预检 | 不分配运行、不写 DDL 或消费骰子 |
| 准备目录、锁或 input 写入中断 | 原输入不完整返回 `PREPARATION_INCOMPLETE`，仅可显式精确放弃；未知文件、超限、完整字节身份不符继续保留 |
| 完整 input、allocation 写入中断 | 核对原目录绑定与原输入，只补完准确分配前缀并继续原初始化；不生成另一次业务输入 |
| 初始化事务失败 | 保留可识别准备材料，完整回滚；部分/未知结构不修补 |
| 提交后首份检查点失败 | 保留原库，只继续独立读验与原检查点 |
| 业务提交/响应不明 | 阻断后续写，持久请求结果及完整事实显式查证，不重掷或重复后果 |
| P2 后/P3 前失败 | 保留已发布文件和原源，只完成同一保存意图 |
| 重启发现残留 | 阻止新建/打开，用户显式选择准确 run 恢复或放弃 |
| 封存清理失败 | 保持封存，仅按持久清理材料继续，未知文件不删除 |

创建、打开、恢复等技术操作的 HTTP 请求号与普通业务幂等结果不是同一协议；丢失响应先
查询当前状态。当前每命令 SQLite 耐久、INITIAL/MANUAL/FINAL 与完整残留恢复承担
保存责任；周期 AUTO、保留/轮换须先测量容量再实现，不作为运行先决条件。平台断电耐久、
各故障窗口和逐域验收只按[领域接合表](design/v2/domain-integration.md)记载的实际证据判断，
不由正常往返推定。

## 本地验证与运行环境

运行采用 Java 21+、外部 Tomcat 10.1、空闲的 `127.0.0.1:8080` 和仓库/WAR 外的本地
私有根。原生 Windows 使用 NTFS/ACL，Linux/WSL 使用 POSIX 私有权限；具体权限、锁、
无覆盖发布与落盘边界见[配置](configuration.md#sqlite-当前应用存储配置)。
Windows 进程中断和锁释放须由原生 Java/SQLite JDBC 验证，不能用 WSL 通过代替。
不能为隔离验收终止无关服务或改动已有 Tomcat。正式 WAR 与测试 classpath 启动的证据
分别记录，可重复命令见[测试指南](testing.md#sqlite-结构完整文件与运行验收)。

测试仅使用一次性临时根，不连接 MySQL。人工验收先在页面 END，再停止该隔离进程，
保管需要的 JSON，最后仅清理明确生成的测试根。真实部署仍只按[部署指南](deployment.md)
执行停机、完整备份、WAR 审计、可回滚替换和独立授权；代码和测试存在不表示已经部署。
