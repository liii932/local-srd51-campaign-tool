# Schema 2 来源到运行快照

本合同连接[生产制品](schema-2-rule-artifacts.md)、[来源账本](schema-2-source-ledger.md)
和运行库中的有限类型化材料。`Schema2SnapshotTransferService` 提供内部材料转存及准确规则绑定
核验，`JdbcSchema2RuntimeSnapshotRepository` 提供不访问来源库的完整读回。

材料范围明确为 `INTERNAL`：当前类型为语言、工具、两类候选集合及其成员，以及种族、亚种、背景、
职业的初始熟练来源元数据和稳定授予槽。来源读取、组合、运行存储和
规则绑定可以独立验证；它们不创建战役、角色、业务历史或游戏执行视图。来源安装器仍拒绝所有
不完整基础包及未接入真实消费者的内容。测试中的完整账本夹具直接构造这些有限材料，不经过
安装资格门，也不证明存在可安装、可运行的完整基础模组。

## 来源读取与能力隔离

`JdbcSourceSchema2Repository.load` 使用独立连接，在只读 `REPEATABLE_READ` 事务中核对
准确默认库、完整 RULES 迁移账本和 `Schema2SourceLedger`。共享 reader 只执行 SELECT，
离线安装器复用它后仍单独执行封闭资格检查；离线写入、接受、票据和秘密能力不进入 WAR。

先有界读取所有制品和接受元数据，核对序号、操作身份、计数和总字节预算，再逐一有界读取
原始 ZIP 并检查 EOF。每个包重新严格解析，重算原包和生产逻辑摘要，比较准确身份、角色、
协议、展开长度和完整接受绑定。选中项必须都有本地接受事实；返回顺序保持调用方准确选择。
未选中但属于同一账本的损坏行也使这次账本读取失败。

来源 V004 的三类作者材料按作者原顺序保存来源声明、授予槽和完整字段操作。
reader 逐列比较原 ZIP 的类型化声明与物理行，包括复合授予原子及 parent race 引用；
缺行、多行、错误包/版本/作者序号或任一类型字段不一致都拒绝。语言/工具旧包和空 add-on 的
新增投影为空，可继续读取；含新来源内容的原包不能省略新表行。跨包引用由组合器验证，
来源表仅 FK 绑定同一原包，不要求被依赖包预先占据作者材料表。

来源事务明确结束、连接状态恢复并关闭后才返回材料，随后才允许借运行连接。来源关闭失败
不继续写运行库。调用方事务入口 `read` 要求既有只读 RR 事务，不改变连接状态、不提交或关闭。
读取成功只证明来源事实与材料完整性，不授予规则机制支持。

## 类型化运行材料

运行链通过 V021 建立内部材料表，通过 `V023__schema2-runtime-tools.sql` 追加工具类型表与
类型化字段链约束；`V024__schema2-character-grants.sql` 追加初始熟练来源、稳定槽与复合字段链值。
既有迁移原字节不变，新表与旧
PARTITION 头分离，不把旧固定单模组字段改成通用组合，也不保存源库连接、原始 ZIP 或通用 JSON 规则袋。

| 表 | 责任 |
|---|---|
| `s2_runtime_identity` | 永久、互异 UUIDv4 run/snapshot 身份对 |
| `s2_runtime_snapshot` | INTERNAL 范围、生产协议及组合/最终规则/完整链摘要、准确行数 |
| `s2_runtime_member` | 加载序号、准确模组/版本/角色及原包和逻辑双摘要 |
| `s2_runtime_language` / `s2_runtime_language_set` / `s2_runtime_language_entry` | 完整最终类型字段、可空备注、关系身份及启用状态 |
| `s2_runtime_tool` / `s2_runtime_tool_set` / `s2_runtime_tool_entry` | 工具类别、来源页、集合及工具成员；与语言共用连续规则/条目序号，但引用类型分离 |
| `s2_runtime_character_source` | 种族、亚种、背景、职业的完整最终元数据、可空备注、启用状态及亚种 parent race 类型引用 |
| `s2_runtime_proficiency_grant` | 来源类型/身份、原声明模组和稳定 slot key；原子 LANGUAGE/TOOL × FIXED/CHOICE、准确目标或集合及有界 count |
| `s2_runtime_field_chain` / `s2_runtime_chain_step` | 完整目标/字段、初始与显式覆盖步骤、前后类型化值、提供者、加载位置和作者位置 |
| `s2_runtime_operation` | 不可改写的操作 UUID、CAPTURE/RESTORE、意图指纹、身份对、连续序号及数据库时间 |
| `s2_runtime_control` | 永久单例守卫、协议、材料计数与版本 |
| `business_write_guard` | V025 的永久共同业务守卫，先于材料守卫锁定 |

Repository 接受调用方连接；完整模型验证在首次 INSERT 前完成。父子行写入后，必须从
真实查询结果独立重建成员、领域字段和每条覆盖步骤，再核对规范字节及三种结果摘要。
读取检查完整字段链、初始/清空/同值覆盖/启停语义、前后连续性、来源成员、最终值、序号及数量；
只看头摘要、行数或同一内存对象都不算成功。读取后的不可变投影不包含来源能力。

来源规则与原有语言/工具共用连续规则序号，授予槽与集合成员共用连续条目序号。
完整父种族先于亚种插入；授予目标必须属于同一 snapshot 中准确的语言、工具或对应候选集合。
`grant` 的前后值是单个类型化原子，FIXED 不允许 count，CHOICE 必须含 1—16 的整数 count；
不保存嵌套 JSON，不拆开覆盖 kind/category/target/count。PARENT_RACE 的链值保留准确种族身份。

运行本地材料不是作者包，不能仅凭它重新验证未保留的作者依赖声明；来源组合负责这部分
完整校验，写入时逐字节比较来源组合和实际运行读回。恢复重新读取准确原包，不从旧快照伪造作者输入。

## 原子转存、重放与查证

协调层先取得全部业务写入口共用的非阻塞进程门，再完成来源读取与组合，最后借运行连接开启
`READ_COMMITTED` 事务。第一条运行 SQL 锁永久业务守卫，随后锁材料守卫；之后核对完整运行迁移账本、控制行、
全部收据、身份对与实际快照。残缺、孤立或错误绑定的行拒绝新写入。

新身份、组合、最终规则、覆盖链、收据和守卫计数同事务提交或回滚。计数与版本均等于不可变
操作数量，操作序号从 1 连续增长。相同操作的准确重放返回原事实，既有键但不同意图或身份碰撞
在 INSERT 前拒绝；重放不新增计数。不把接收请求或来源读取当作接受结果。

指纹采用独立域 `local-dnd/schema2-snapshot-transfer/1` 后接一个零字节。随后依次写操作 UUID、
CAPTURE/RESTORE、run UUID、snapshot UUID、规范 profile、组合算法、有序成员及三种结果摘要；
成员为模组键、准确版本、大写角色名、原包摘要、逻辑摘要。字符串按 UTF-8，前置四字节大端长度，
成员数为四字节大端整数。UUID 使用标准小写带连字符文本；摘要使用小写十六进制。
此指纹不替代五类规则摘要，也不进入其既有域。

只有 commit 明确成功，才返回新材料快照。commit 响应不明或 rollback 失败时不发布候选，
共同事务边界阻断后续写入并隔离原连接；不能恢复 autoCommit 或把未决连接正常归还池。
明确提交后连接恢复/关闭失败仍报告已提交事实，协调器同时保持阻断，不能重做写入。
运行事务中的严重异常仍原样抛出，同时尝试回滚；回滚失败则隔离连接，协调器保持阻断。

`resolve` 只查证本实例保留的准确原意图，并要求原连接已成功隔离；查证使用新连接锁同一守卫，
重验完整收据和快照，不补写、重试或清理。完整永久历史中原事实缺席且原执行者隔离已确认时，
才能判定未提交。新实例的 `inspect` 可读取已提交事实；单纯查不到行不能证明原操作回滚。
查证不恢复已失效的协调器或任何游戏执行资格。跨进程重启后的未决恢复仍属于完整生命周期采用。

## 准确恢复绑定

`Schema2RulesBinding` 包含准确 profile/算法、有序成员及每个成员双摘要，并绑定组合、最终规则
和完整链三种摘要。RESTORE 转存从来源重新解析、组合后逐项比较它，失败时不借运行连接。
相同最终规则不能替代相同版本、顺序、原包和来源链；不接受替换版本或重新打包的近似材料。

这一绑定只是完整战役恢复的规则部分，不是 archive 2 编解码器。当前没有用空角色、空历史
或空领域分区代替业务恢复；完整工作集、业务事务、保存/END/清理及 Host 入口继续按
[运行设计](../design/v2/runtime-and-transactions.md)和[采用边界](../design/v2/adoption-boundaries.md)接入。

## 容量与验证

每份材料最多 4 个成员、256 条规则、512 个条目、3072 条字段链和 4096 个步骤；各类型的
字符串和数字范围仍由作者合同约束。运行规范配置/最终规则/覆盖链的字节总和每份最多 8 MiB。
协调层最多保留 16 份内部材料，规范字节累计最多 16 MiB，超限在新写入前拒绝。
工具固定向量覆盖真实 37 项工具的类型字段、候选去重、临时不足后修复、语言与工具混合
序号及完整链读回。初始熟练固定向量独立提供原始 ZIP 和最终规范字节，覆盖四种来源、
稳定槽、父种族覆盖后恢复、完整授予分支替换、禁用来源/槽/目标、重复目标及候选不足后修复。
运行读回逐项校验来源、槽、复合链值及作者位置；缺失、混合快照或损坏不能成为有效投影。
这些材料供[初始熟练规则](schema-2-proficiency-grants.md)消费，不开放战役创建或安装资格。
这些是局部拒绝预算，不能作为完整战役、数据库物理体积或 JVM 峰值的容量承诺。

无数据库测试使用真实 JDBC 适配器和事务代理，核对独立固定 JSON/摘要期望、来源关闭顺序、
实际完整读回、损坏和跨快照拒绝、各写点回滚、重放与提交故障。SQL/授权静态测试保护追加迁移，
但不证明真实 MySQL 的触发器、锁、权限、连接池隔离或耐久性。重复命令见[测试指南](../testing.md)。
迁移结构与守卫的只读现场检查使用 [V021 核验 SQL](../../database/verify/v021-schema2-runtime-snapshot.sql)，
V022—V024 新结构另见[授予与工具核验 SQL](../../database/verify/character-proficiency-grants.sql)；
账号增量见[运行快照权限](../../database/grants/schema2-runtime-snapshot.sql)。

候选 WAR 包含生产读取、组合、快照和协调类；不包含离线安装类、原包、来源 SQL、测试向量、
秘密或真实存档。运行迁移、账号授权、隔离 MySQL 验收和部署仍分别执行；本合同不改变默认
RELEASED v1，不激活 archive 2，也不自动装配第二 JNDI 或游戏运行入口。
