# Schema 2 倒地姿态、爬行与起身

## 规则来源与应用范围

[Being Prone](../semantics/srd-5.1/combat.md#srd51-core-being-prone)，SRD 91–92 页，
规定主动卧倒不花移动、起身花速度的一半且速度须大于零，以及爬行每尺多花一尺移动。
[Prone](../semantics/srd-5.1/conditions.md#srd51-condition-prone)，SRD 359 页，
规定倒地者攻击劣势、五尺内攻击倒地者有优势、较远攻击倒地者有劣势。
[机会攻击](../semantics/srd-5.1/combat.md#srd51-core-opportunity-attack)和
[Ready](../semantics/srd-5.1/combat.md#srd51-core-ready)，SRD 93–95 页，补足移动反应的时机和成本。
[探索时间](../semantics/srd-5.1/exploration.md#srd51-core-time)、
[速度](../semantics/srd-5.1/exploration.md#srd51-core-speed)与
[特殊移动](../semantics/srd-5.1/exploration.md#srd51-core-special-movement)区分短时移动、长途速度和爬行成本。
语义标识只定位规则，不用作模组键、算法或持久身份。

当前支持 SQLite 场景中的真实规则角色，无职业或等级门槛。正常创建、入场后，
角色可在 EXPLORATION 主动卧倒、爬行和起身；进入 ACTIVE 战斗后仅在本人回合主动改变姿态或移动，
Ready 移动另可在触发时以反应爬行。
主动卧倒是自愿改变自己的姿态，不需要攻击、特性授予、物品或目标；不能伪造他人的姿态。
推撞、擒抱、困难地形、穿越占格、飞行、传送、强制移动及怪物主动姿态命令不在范围内。

探索 `DROP_PRONE` 不推进时间，`EXPLORATION_MOVE` 与 `STAND_UP` 沿用应用现有六秒活动粒度，
推进同场景时间和到期效果。它们不制造回合，不扣除或刷新旧战斗移动、动作和反应余额，
也不借用旧 Dash 增益。探索卧倒按即时姿态变更处理而不推进时钟、移动与起身采用六秒活动、
每段按当前速度限额，均为应用策略。SRD 规定卧倒不花移动，未单独规定探索卧倒的世界时钟增量，
也未规定起身耗时六秒；本应用的短时活动不代替长途旅行速度。主动卧倒、移动和起身均要求角色存活且 HP 大于零；
移动和起身还要求全场景可安全推进时间，起身要求速度大于零。
`END_COMBAT` 和重新进入战斗均保留倒地，探索移动不会隐式起身。
尚未死亡的倒地规则角色离场或关闭场景会被拒绝（包括零 HP），须显式起身后再转移；零 HP 者需先治疗。
零速度不能起身；本组不提供搬运或战斗场景内装备调整来解除这类限制，不能通过离场隐式解除。
完整文件的 `END` 是运行结束，
不等于结束战斗、站起或清理状态，重开可直接继续原战斗或探索场景。

## 应用与模组责任

这组行为属于应用能力修改（B）。既有 `adventure.combat` 的 `SRD_2014_COMBAT_V1`
声明战斗解释，`character.movement` 的 `SRD_2014_WALKING_SPEED_V1` 提供准确种族速度，
护甲 owner 提供已有速度惩罚。没有新增作者参数、同义算法或包名特判。
`CampaignRuleSupport`、严格组合和实际角色支持检查继续约束所选材料及全部已取得影响。

| 接合边界 | 复用入口与状态 | 修改类别 |
|---|---|---|
| `DROP_PRONE` | 既有命令与 `Schema2CombatRules`，仅写唯一 `Combatant.prone`；探索分支沿场景共同事务接纳 | B：扩展应用消费者，不新增作者声明或资源 |
| `EXPLORATION_MOVE` | `Schema2ExplorationRules` 预检当前速度与完整路径，原场景移动执行逐格区域核对和末尾时间推进 | B：按既有权威姿态派生成本，保留原探索移动编码 |
| `STAND_UP` | 原 ACTIVE 半尺移动预算及 EXPLORATION 六秒活动入口 | B：复用起身消费者、时间和离场门，保持两种场景的原成本 |

现有原包、版本、准确依赖及 [包指南](../../rule-packages/srd51-runtime/package-guide.md)
保持不变；新增消费者需要更新应用。内容作者可继续用既有格式导入应用已支持的速度或战斗声明，
不需要为内容更新重建 WAR。活动战役始终使用原准确冻结组合，规则库更新不能热改它。

## 命令、预算与唯一状态

| 行为 | 服务端约束与后果 |
|---|---|
| `DROP_PRONE` | SQLite 真实规则角色在本人 ACTIVE 回合或 EXPLORATION、存活且 HP 大于零、没有未决流时可用；已倒地明确拒绝。设置 `Combatant.prone`，不花 action、reaction、移动、攻击序列额度或时间。 |
| `MOVE` | 无客户端姿态或成本选项；由权威倒地状态派生爬行。每走一格五尺，直立花五尺、倒地花十尺移动；全部路径先按实际剩余额度和占格检查。 |
| `READY_MOVE` | 声明和释放分别检查当时姿态及路径。释放只花一次 reaction，以速度为独立移动上限；爬行仍为双倍成本，不消费本人回合已花移动，也不借 Dash 增益扩张反应上限。 |
| `EXPLORATION_MOVE` | 无客户端姿态、速度或成本选项；每段完整路径按当前权威速度预检，直立每格成本五尺、倒地每格十尺，不能超过当前速度。整段完成后推进六秒；不消费旧回合余额，不开启 OA/Ready 窗口。 |
| `STAND_UP` | ACTIVE 时需本人回合、已倒地且速度大于零，剩余移动至少为速度的一半；清除倒地并支付准确半速成本。EXPLORATION 时需安全推进六秒，清除姿态并推进场景时间；两者均不重置动作、反应或攻击序列。 |

`Combatant.movementSpentHalfFeet` 继续保存半尺单位的本回合移动成本。
25 尺速度起身花 25 个半尺单位，即 12.5 尺；爬行五尺花 20 个半尺单位。
Dash 增加的是原速度等额预算，不把爬行改为普通步行。
`Movement.spent` 继续表示已实际走过的距离，与 `cursor × 5` 一致；它不是移动成本。
Ready 移动的已用成本由该距离及有效姿态派生。
探索每段独立按当前速度检验：30 尺速度最多爬行三格（15 尺），25 尺速度最多两格（10 尺）；
未用额度不结转，也不累加到 `movementSpentHalfFeet`。`movementBonus`、action、reaction
和原攻击序列保留原值，只有合法重新进入战斗才按原合同开始真实回合。

唯一姿态仍归战斗 owner；不另建可写条件副本、资源余额或模组特性。
普通、OA 和 Ready 攻击复用原倒地优劣势消费者，不改变暴击、伤害、法术或豁免规则。
卧倒和起身不触发移动离开触及；爬行依实际离开触及时机触发 OA，撤离仍按原合同抑制它。
未决流阻止卧倒、起身及新的根动作；已有攻击序列允许在完成的两击之间改变姿态或移动。

## 中断、事务和恢复

爬行在离开触及前暂停，尚未跨过的格子不扣成本。反应放弃或结算后仅继续原路径后缀。
移动者降到零 HP 时原移动停止；后续同一反应链中的治疗也不自动重启原移动，
苏醒后保留倒地，需在合法时机发出新移动或起身命令。这是当前有限继续协议的中断边界。
Ready 释放的 reaction、已走前缀和原骰均保留，不因停止退还或重付。

探索移动在写入前验证完整路径、连续性、全部占格和成本，每个实际经过的格子依次核对区域
压制原因，最后才推进六秒并处理效果到期；失败不能留下路径前缀、姿态变更或部分时间。
姿态、位置、移动预算、流、根子历史、版本与请求回执沿原共同事务提交。
重复请求返回原结果；同键异意图、旧版本、非法命令字段、未知或损坏冻结规则均拒绝。
晚写故障完整回滚。完整保存、END、直接重开恢复姿态、路径游标、成本和反应窗口；
恢复核验原命令与保留骰，不重新执行、不随机、不再消费成本。

没有新增持久字段、SQLite 结构或迁移。MySQL INTERNAL 对新增 `DROP_PRONE` 命令及其
历史明确拒绝，沿用已应用 SQL；原有 `MOVE`/Ready 移动编码的爬行成本由共享纯规则解释，
但这不构成真实 MySQL 数据库验收。

## 行为证据

`Schema2ProneRulesTest` 覆盖姿态、探索零耗时卧倒、精确预算、Ready/OA 与失能中断；
`Schema2ExplorationRulesTest` 保护六秒活动、路径预检、冻结移动声明和到期效果；
`CampaignProneIntegrationTest` 从原 ZIP 导入、审阅接受、有序预览和新建开始，
通过正常角色取得、生产命令、临时 SQLite 和完整文件核对组内每个行为，包括探索姿态链、
旧战斗预算保留、战斗交接、幂等不重付时间和晚写回滚。
`PlayerProneCandidateTest` 验证邀请、审批、控制后的服务端候选和共同动作入口。
`tools/storage/browser-prone.cjs` 验证真实 Host 表单、姿态和成本展示及重开继续。
定向范围和隔离启动见[测试指南](../testing.md#prone-verification)。这些证据不提升擒抱、
推撞、怪物主动姿态或整个 Prone producer 族的完成状态。
