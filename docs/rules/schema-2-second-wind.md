# Schema 2 有限战士回气

## 语义与支持范围

[Second Wind](../semantics/srd-5.1/classes-fighter-monk.md#srd51-class-fighter-second-wind)
从战士 1 级取得：在本人回合用附赠动作恢复 `1d10 + 战士等级` HP，完成短休或长休后
才能再次使用。来源为 SRD 第 24 页；[附赠动作](../semantics/srd-5.1/combat.md#srd51-core-bonus-action)
和[治疗](../semantics/srd-5.1/combat.md#srd51-core-healing)分别补足行动资格和 HP 上限。
治疗超出当前最大 HP 的部分舍弃；满 HP 使用仍支付成本，不产生临时 HP。
语义标识不充当模组键、算法或持久化身份。本切片不另作规则语义解释。

当前应用支持 SQLite 战役中单职业战士 1–6 级的回气。必须正常取得特性、存活且 HP 大于 0，
位于焦点规则场景的 ACTIVE 战斗，并轮到本人；未决动作流先完成再执行。
它可在普通动作之前或之后、两次已结算攻击之间使用，不改变普通动作、反应、移动或攻击序列。
本切片不开放战斗外回气、多职业、其他附赠动作或 MySQL INTERNAL 回气执行。
这些是应用边界，不能解释成 SRD 的职业限制。

## 声明、组合和正常取得

沿用严格 `character.feature` 格式：

| 字段 | 约束 |
|---|---|
| `feature_kind` / `execution_mode` | `FEATURE` / `AUTOMATIC` |
| `execution_algorithm` | `SRD_2014_FIGHTER_SECOND_WIND_V1` |
| `owner` | 完整的启用 `character.class` 身份，键为 `class.fighter` |
| `level` / `source_page` | `1` / `24` |
| 对应资源 | 该职业提供者中的准确 `resource.fighter.second_wind` |

资源必须属于同一完整职业身份，启用且为 `AUTOMATIC`；容量固定为 `1-20:1`，恢复为
`1-20:SHORT_REST`，来源第 24 页。短休资源也由标准长休恢复。组合只允许一个启用的
回气能力；原声明、最终覆盖与冻结材料分别校验，后续覆盖不能修复非法原声明。
未知算法、错误模式/等级/出处/所有者、缺失或错误资源、重复能力均拒绝。
算法不绑定包名或显示名，特性键可由作者选择；内置使用 `feature.fighter_second_wind`。

正常一级创建与成长从冻结规则产生实际 `FeatureState` 和资源状态。
服务端验证完整授予、所属职业和当前支持等级，不能以等级、名字或客户端声明替代取得事实。
普通 `RESOURCE_SPENT` 不能替代已接入回气的执行与支付；资源目录的 `directResourceSpend`
查询标记只控制普通资源入口的展示，执行权限仍由服务端重验。

## 执行、成本与唯一状态

`SECOND_WIND` 命令只提交行动者及共同版本/幂等信息，不接受目标、治疗量、骰点、等级或资源选择。
战斗 owner 先验证完整材料、实际授予、回合、健康、资源、未决流和历史容量，再请求一颗 d10。
以真实战士等级计算治疗量，依次产生准确资源扣减和健康治疗子事实，同根提交。
健康 owner 保存请求治疗量、实际恢复量及前后 HP；资源 owner 保存准确余额和前后状态。
满 HP 的实际恢复量为零，仍保留原骰并扣一次使用。

本版唯一可执行附赠动作是回气。固定的每次休息一次资源、战斗中禁止休息和显式新回合入口，
已经保证每回合最多使用一次；`SECOND_WIND` 根事实标明本次附赠动作及所属战斗回合。
不新增与这些事实重复的可编辑附赠动作余额。未来接入第二种附赠动作消费者时，必须同步
建立并消费共同回合预算，不能把本切片的证明推广成通用附赠动作支持。

使用回气不花普通 action/reaction，也不重置攻击额度或退还已付动作。
无动作能力、非本人回合、资源耗尽、错误焦点/版本、待处理反应或无真实授予均在骰前拒绝。
该能力没有分阶段选择或自己的反应窗口；调用前的未决流不会被它取消或跳过。
动作进行中的回气需等当前叶子结算完毕，可继续保留同一个未关闭的 Attack 序列。

## 历史、完整文件与恢复

资源和 HP 仍归 `characters_runtime_character` 的当前状态与完整角色历史；战斗命令、
`SECOND_WIND_HEALING` 原骰、两项子后果及根事实归 `combat_scene` 的完整历史。
不新增持久字段、表、SQLite 初始化结构或数据库迁移。没有可独立修改的第二份回气余额。
历史核验分别归因于回气或施法，不能借放宽治疗/资源的施法约束接受伪造结果。
健康子事实使用父战斗操作派生的准确回气帧，并核对本人、实际授予及原骰加职业等级，
才接受 d10；其他现有治疗仍保留 d8 边界。父战斗历史同时核对原命令、帧、扣次、治疗和版本。

相同请求只读原结果，不再掷骰、扣费或治疗；同键异意图、旧版本/epoch 明确拒绝。
晚写失败回滚 HP、资源、角色/战斗版本、根子历史和接受结果；随机源不要求倒退。
完整保存、END 和打开保留准确组合、真实授予、原骰、成本和攻击序列。
打开只校验并直接恢复，不重复执行回气、不补资源，也不重新应用治疗。

完成标准短休或长休才恢复使用；开始休息、未满时长、放弃尝试、升级或新回合均不恢复。
休息生命周期沿[现有合同](schema-2-character-rest.md)，不借普通资源命令绕过。
MySQL INTERNAL 入口及其局部历史恢复对本命令明确拒绝，现有已应用迁移保持不变。
本切片的导入与冻结入口是 SQLite `LocalRuleLibrary`；MySQL 规则来源安装和运行镜像
未接入此能力，不能将本地 ZIP 通过校验解释为 SQL 来源目录也已支持。

## 制品与验证

首次执行本能力需要更新应用。使用既有能力的后续外部规则内容更新仍可通过导入新包使用，
不以重建 WAR 为前提。同版本不可替换字节，准确依赖和内置 ZIP 同步更新。
规则库变更不修改活动战役；结束后另选组合新建，打开已有文件仍核其准确成员和本机接受。
不加入旧格式默认值、兼容 reader 或真实数据重置步骤。

真实取得、生产命令、事务及保存恢复见 `CampaignSecondWindIntegrationTest`；
Host 表单由 `tools/storage/browser-second-wind.cjs` 验证。
`PlayerSecondWindCandidateTest` 从邀请、审批、控制与接管进入玩家候选，验证本人回合执行、
拒绝客户端骰点/成本、使用后候选消失及原回执查证。
定向规则、组合、休息、历史和共享消费者按[测试入口](../testing.md#second-wind-verification)选择。
本切片不改变行为接口报告 16 条原轨迹的结论，也不证明其他治疗特性或通用附赠动作完成。
