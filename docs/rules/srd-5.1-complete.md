# 完整 SRD 5.1 覆盖目标

> 规则基线：D&D 5e 2014 / SRD 5.1
> 产品形态：loopback-only、单 DM、本机 Web 工具
> 当前状态：目标合同；当前已发布的简化 v1 仍由 [srd-5.1.md](srd-5.1.md) 单独冻结

## 1. 范围定义

项目目标是完整支持 SRD 5.1 中能够用于创建角色、运行冒险和结算游戏状态的规则。这里的
“完整”指规则实体、前置条件、资源、计算、状态变化和 DM 裁定入口均可由产品表达、验证、
持久化、审计、导出和恢复；不是只收录一份可搜索文本，也不是宣称程序能够替代 DM 处理
所有开放式叙事判断。

规则与内容边界以官方 [SRD 5.1](https://media.dndbeyond.com/compendium-images/srd/5.1/SRD_CC_v5.1.pdf)
及仓库 [NOTICE](../../NOTICE) 中的许可和署名为准。SRD 5.2.x、未包含在 SRD 5.1 中的商业
出版内容、自创扩展和第三方内容不自动进入本目标；若要加入，必须分别确认规则身份、许可、
稳定合同和兼容策略。

本文定义完整规则版的产品能力与验收边界，不定义尚未批准的 module key、算法键、字段键、
事件/效果类型、摘要域或规范编码字节。具体持久化身份必须在相应领域设计中先建立 DRAFT 基线，
再通过新的前向迁移演进；只有跨领域发布候选通过后才成为不可变发布合同。

## 2. 功能覆盖

### 2.1 角色构筑与成长

- 种族、亚种、种族特性、体型、速度、语言及能力调整；
- 背景、熟练项、工具、语言、装备选择和背景特性；
- 十二职业、SRD 子职、职业等级、生命骰、职业能力和资源；
- 属性值生成、一级创建、阵营与角色描述、升级、生命值增长、熟练加值、属性值提升和专长；
- 多职业前置条件、熟练项增量、等级合计和施法资源合并；
- 属性、技能、豁免、被动值、AC、速度、最大生命值、先攻和施法属性等派生值；
- 角色选择的合法候选、互斥关系、数量、等级要求和来源追踪。

### 2.2 检定与通用骰子

- 属性检定、技能检定、豁免、对抗检定、被动检定和攻击检定；
- 普通、优势、劣势及其抵消规则；
- d4、d6、d8、d10、d12、d20、百分骰和由冻结规则批准的组合骰式；
- 修正、加骰、减骰、重掷、取高/取低、最低值和其他已定义的骰子变换；
- 自然 1、自然 20、暴击和自动命中/失败只在适用的具体检定类型中生效；
- 所有候选骰、选择过程、修正来源、最终结果和资源消耗由服务端生成并保存。

### 2.3 冒险与资源

- 时间、旅行速度、行军、困难地形、跳跃、攀爬、游泳和不同移动速度；
- 视野、光照、遮蔽、隐藏、察觉和搜索的规则关系；
- 灵感、探索、社会互动、休整活动及需要 DM 判断的能力检定流程；
- 坠落、窒息、食物、水、物体、陷阱、毒药、疾病、环境危害和 SRD 中可确定的冒险规则；
- 坐骑、载具、旅行装备及其速度、载重和费用；
- 短休、长休、生命骰、生命值和按休息恢复的职业、法术及物品资源；
- 负重、携带能力、货币、费用和消耗品；
- 规则需要 DM 判断时，保存裁定依据、选择和结果，不伪造自动结算。

### 2.4 战斗

- 遭遇建立、参战者、敌我关系、突袭、先攻和同值处理；
- 轮次、回合、动作、附赠动作、反应及每回合资源重置；
- 移动、速度消耗、距离、触及、范围、区域、掩护和位置合法性；
- 攻击、命中、失手、暴击、伤害骰、伤害类型、治疗和临时生命值；
- 抗性、易伤、免疫、伤害调整顺序和多个伤害分量；
- 0 HP、昏迷、稳定、死亡豁免、承受伤害、即死和恢复；
- 擒抱、推撞、借机攻击、准备、疾走、撤离、闪避、协助、躲藏、搜索和使用物品；
- SRD 中的特殊战斗环境及坐骑等可由系统表达的规则。

### 2.5 状态、效果和持续时间

- SRD 全部状态及其对移动、攻击、检定、豁免、感知和行动的影响；
- 效果来源、目标、开始/结束时机、持续单位和剩余时间；
- 回合开始/结束触发、重复豁免、受击结束、施法结束和显式解除；
- 状态免疫、效果叠加、同名效果、覆盖和优先级；
- 专注、持续伤害、持续治疗、光环和区域效果；
- 效果应用、拒绝、替换、到期和解除都进入事件与事务边界。

### 2.6 法术

- 法术目录、职业法术列表、等级、学派、施法时间、距离、成分、持续时间和描述；
- 戏法、已知法术、准备法术、法术书、法术位和多职业施法；
- 法术攻击、法术豁免 DC、目标选择、合法目标、区域和遮挡；
- 专注、仪式、升环、消耗材料、反应施法和每回合施法限制；
- 伤害、治疗、召唤、变形、移动、状态、区域和资源效果；
- 可确定的法术效果由封闭算法执行；开放式效果必须提供类型化 DM 裁定入口。

### 2.7 装备、经济与魔法物品

- 武器、护甲、盾牌、弹药、工具、冒险装备、容器和装备包；
- 价格、货币换算、重量、数量、携带、装备、卸下和使用状态；
- 武器属性、攻击距离、伤害、双持及相关熟练判断；
- 护甲熟练、穿戴要求、AC 公式、力量要求和隐匿影响；
- 消耗次数、充能、恢复、消耗品和资源来源；
- SRD 魔法物品、稀有度、同调、使用限制、效果和诅咒等可表达属性。

### 2.8 怪物、NPC 与遭遇支持

- SRD 怪物完整属性块、类型、阵营、AC、HP、速度、属性、技能、豁免和 CR/XP；
- 感官、语言、抗性、易伤、免疫、状态免疫、特性和施法；
- 动作、附赠动作、反应、传奇动作、巢穴动作及 SRD 中存在的其他行动结构；
- 多段攻击、特殊攻击、充能、重掷恢复、召唤和变形；
- 遭遇 XP 汇总与 SRD 所定义的难度支持；
- NPC 和怪物使用与 PC 相同的事务、事件、位置、状态和资源边界。

### 2.9 战役状态、事件和存档

- 所有权威命令产生明确的根事件、规则快照、输入摘要和结果；
- 角色、战斗、法术、装备、资源、状态和位置变化原子提交或整体回滚；
- 在使用随机数前完成请求、冻结目录、目标集合和乐观版本校验；
- 幂等重放返回首次保存结果，不重掷、不重复消耗资源、不重复触发效果；
- 存档覆盖完整当前状态并使用稳定业务键，导入严格校验且不依赖数据库 ID；
- 旧格式和旧规则发布版保持可识别；升级必须显式、可验证且不能改写原战役绑定。

### 2.10 规则目录与 DM 工作流

- 完整收录 SRD 5.1 中属于目标范围的种族、背景、职业、专长、装备、法术、魔法物品、怪物、状态和规则表；
- Host 页面提供按名称、类型、等级、来源和适用条件查询的规则目录，不建立公开规则 API；
- 战役、角色构筑、遭遇、战斗、法术、装备和休息操作都从冻结目录进入，不能复制成互相漂移的硬编码清单；
- 不能唯一自动结算的规则仍须可查询、关联到当前事件并进入类型化 DM 裁定流程；
- 以官方 SRD 5.1 目录和正文小节建立覆盖映射，每一项标明数据覆盖、自动结算、受限选择或 DM 裁定方式及对应测试；
- 法律声明、许可文本和署名按 NOTICE 管理，不作为运行时规则算法，但不得因规则数据扩充而遗漏。

## 3. 自动化边界

每条规则能力必须在设计和测试中归入以下一种执行方式：

| 方式 | 适用范围 | 必要保证 |
|---|---|---|
| 服务端自动结算 | 公式、候选集合、骰子、伤害、资源、持续时间等可确定规则 | 只使用冻结目录和权威状态，结果可重复审计 |
| 服务端验证后由 DM 选择 | 规则给出有限候选，但需要操作者选择目标、选项或顺序 | 候选由服务端生成，客户端不能扩张候选集合 |
| 类型化 DM 裁定 | 幻象、开放式描述、创造性使用等无法由固定算法唯一决定的结果 | 裁定类型、目标、资源和结果有界并写入事件，不接受任意脚本 |

任何 SRD 规则都不能仅因难以自动化而静默忽略。允许 DM 裁定并不允许客户端指定骰点、
派生修正、算法、版本推进、任意数据库身份或未经目录批准的效果。

## 4. 产品与安全边界

完整规则版继续遵守以下边界：

- 唯一受支持入口是 `http://127.0.0.1:8080`；
- 只有单一 DM 操作者，不建立玩家账号、角色所有权或外部写入；
- 不增加 LAN/公网、HTTPS、反向代理、`/display` 或 `/api/public/*`；
- 不增加公开配置、公开投影、公开事件、推送、WebSocket 或 SSE；
- 不提供模组上传、编辑、在线下载或运行时脚本插件；
- 不使用运行时动态 DDL 或任意 JSON 规则参数；
- 所有新页面和接口仍位于 `/host/*` 与 `/api/host/*`，并复用现有安全过滤器。

## 5. 版本与兼容要求

现有 `dnd5e2014_srd51_se_v1`、发布版本 1、`canonical_format_version=1`、23 个规范分区、
内容摘要及 V001—V018 均不可修改。迁移历史不可变与 DRAFT 兼容是两件事：已写入迁移的身份
不得原地重命名或重写，但未发布目录、运行模型、API、canonical/archive 投影和测试可以通过
新的前向迁移及协调实现继续演进。除非验收标准指出必须保留的真实数据，不为被替代的 DRAFT
行为增加兼容层。

完整规则版必须满足：

1. 先批准新的 DRAFT 身份、稳定键、算法编号、字段和事件/效果类型；
2. 使用新的规范格式定义完整逻辑投影，不能向 v1 字节流隐式追加字段；
3. V011 建立角色 DRAFT 目录；后续定义和运行状态使用下一个实际可用的前向迁移；
4. 角色、装备/冒险、战斗/状态、法术和怪物/魔法物品在同一完整规则身份下持续整合，不在单个领域完成后转为 `RELEASED`；
5. archive format 2 在 DRAFT 中随领域渐进实现严格读取、导出、预览、确认和原子导入测试，但在跨领域发布候选前不激活或承诺最终兼容；
6. 发布候选阶段独立验证完整目录、规范字节、SHA-256、archive 严格往返、不可变保护和默认发布切换；
7. 旧战役继续绑定原 v1；新战役只有在完整发布版正式可用后才可绑定它；
8. 战役升级如被支持，必须是显式操作，并拥有独立预览、兼容校验、事务和存档恢复边界；
9. 存档增加新格式版本，不改变 `formatVersion=1` 的字段语义。

完整规则族当前映射为：module key `dnd5e2014_srd51_se`、release version 1、canonical format
version 2、archive format version 2。V011 和
[角色目录与 canonical format 2](character-catalog-v2.md) 建立当前角色 DRAFT 投影基线；该身份
保持 `DRAFT`，直到所有主要规则领域完成整合并通过统一发布门。应用当前显式默认仍是旧 v1。
迁移文件存在不构成数据库已经执行或发布成功的证据。

V012 的[一级角色创建合同](character-creation-v2.md)、V013 的
[升级与生命骰合同](level-advancement-v2.md)与 V014 的
[职业、子职业与职业特性合同](class-features-v2.md)以及 V015 的
[多职业、ASI 与专长合同](multiclass-asi-feats-v2.md)只扩充该 DRAFT 身份。多职业施法和专长的
战斗效果仍明确阻断。这些迁移不会开放 archive format 2。V017 及内部 DRAFT codec 已为当前角色状态建立稳定事件
闭包、严格写入/读取、预览与原子恢复基础；V018 固定多职业施法贡献并提供共享法术位上限计算，
但尚未建立法术权威状态或接入升级事务。它们均未接入完整战役文件、released dispatcher 或 Host
路由；后续领域仍须渐进补齐新增权威状态，最终由跨领域发布门统一激活。

## 6. 完成判定

一个规则领域只有同时满足以下条件，才算进入已实现范围：

- SRD 实体、关系、范围、前置条件和执行时机具有审核后的设计；
- 稳定身份、规范编码、目录校验和发布摘要完整；
- Host UI/API 只接受有界输入，Service 重新计算权威候选和结果；
- Repository 保存完整状态、事件、快照、资源变化、版本和幂等结果；
- 正常、边界、畸形冻结数据、过期版本、重复请求和事务失败均有聚焦测试；
- 默认 `mvn clean verify` 通过；需要真实 JDBC 语义时另行运行显式 MySQL 集成测试；
- 存档导出、严格读取、预览、确认、失败回滚和旧版本识别已覆盖；
- 生产资源变化后的 WAR 审计没有秘密、本机路径、日志、备份或真实存档；
- README 与架构文档准确区分已实现行为和剩余目标，不把设计目标写成发布事实。

只有所有领域均达到上述标准，项目才可声明“完整覆盖 SRD 5.1”。
