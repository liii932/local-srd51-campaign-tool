# 运行语言快照分区

`JdbcRuntimeLanguageSnapshotRepository` 在运行库内保存经过验证的 18 项语言分区。它使用调用方
提供的同一个 JDBC 事务，将永久身份登记、快照头和语言镜像一起写入，并从数据库实际回读。
这一能力只供隔离的分区验收使用；它不接入战役新建、导入、恢复、启动目录或规则执行。
同次保存语言与工具时使用 `JdbcRuntimeCharacterCatalogRepository`，复用相同登记、头和语言
校验，再原子写入 V020 工具镜像；合同见[工具熟练目录分区](tool-catalog-partition.md)。

## 数据与身份

运行链的 `V019__runtime-language-snapshot.sql` 仅创建三张空 InnoDB 表及其约束、触发器：

| 表 | 职责 | 身份与生命周期 |
|---|---|---|
| `runtime_run_identity` | 已使用运行身份的永久技术登记 | `run_id` 主键、`snapshot_id` 唯一、二者组合唯一；禁止更新和删除 |
| `runtime_rule_snapshot` | 不可变本地规则快照头 | `snapshot_id` 主键、`run_id` 唯一，组合外键必须匹配永久登记；禁止更新 |
| `runtime_rule_language` | 类型化语言镜像 | 主键为 `(snapshot_id, language_key)`，排序号在快照内唯一，外键只引用本地快照；禁止更新 |

`run_id` 和 `snapshot_id` 是两个不同的服务端 UUIDv4，使用 16 字节网络顺序保存和绑定。拒绝
空值、非 16 字节、错误版本/variant、零 UUID 和相同身份对；不使用 `UUID_TO_BIN` 的交换模式。
API 不从客户端、来源 ID、内容摘要、作者包或存档决定这两个技术身份。

相同语言内容可以生成多个不同的运行/快照身份对。已提交登记中的任一身份再次使用都构成
冲突，不重放旧结果，也不充当幂等成功。失败事务中的登记与其余写入一起回滚；成功登记则
长期保留，即使将来合法清理了快照和业务行，也不允许回收身份。

当前 Repository 固定保存 `dnd5e2014_srd51_se` release `1`、canonical/archive `2/2`、`SHA-256`、
`DRAFT`、`PARTITION`，`content_sha256` 为 SQL `NULL`。语言数据只含稳定键、显示名、说明、
分类、来源页和排序号；不复制源发布行 ID、安装 ID、revision 或历史 COMPLETE 事实。
时间列由数据库生成 UTC `DATETIME(6)`。

表结构可表达经未来完整校验后建立的 COMPLETE 头，但当前 Repository 不能写入或读取它。
PARTITION 不得冒充完整规则摘要、已发布状态或运行就绪状态，也不能通过原地更新升级为
COMPLETE。未来完整装配必须经独立发布门，以新的身份对一次性建立完整快照。

## 校验与事务

写入前先校验全部输入和连接边界；连接必须属于 `dnd_tool_se`，关闭 auto-commit、可写，且使用
`READ_COMMITTED`、`REPEATABLE_READ` 或 `SERIALIZABLE` 隔离级别。Repository 不借出连接，
不改变连接状态，不创建 savepoint，也不提交、回滚或关闭调用方连接。

调用方依次完成：

1. 开启满足上述条件的运行事务，提供新的身份对和完整 `LanguagePartition`。
2. 写入登记、快照头和全部语言行；每次写入都必须影响准确行数。
3. 在同一连接上用实际 SELECT 读取登记、头和语言，校验身份、固定头字段、精确集合及完整值，
   将回读结果与待写入分区比较。
4. 继续本次操作所需的其他写入，所有步骤成功后才由调用方提交。

任一步骤抛错，调用方必须回滚整个事务，包括后续业务写入失败。捕获异常后继续提交可能留下
未完成分区，因此不属于这个合同。Repository 不通过内部 rollback 或另开连接掩盖调用方责任。

读取必须提供完整身份对，先验证登记和头一致，再限定 `snapshot_id` 读取语言。相同语言键
不能让一个快照借用另一个快照的行。固定有界查询最多读取 19 行，以识别缺失、重复和额外行；
坏数据失败关闭，不从作者文件、源库、其他快照或旧目录补齐。

语言合同复用[语言作者分区](language-author-package.md)：准确 18 个键及键/分类矩阵、排序号
`1..18` 各一次、来源页 `3..74`、显示名最多 120 Unicode 码点、说明最多 1000 码点。
JDBC 数值与字节类型必须准确；文本须为合法 Unicode 标量、NFC，且不得为空、全空白或含
C0/C1/DEL。存储读取拒绝不规范文本，不做归一化修复。

## 迁移与账号

V001—V019 的文件、顺序和批准摘要保持不变。V020 追加工具结构和账本记录，应用
正式清单要求 V001—V020。未安装 V020 的数据库不能通过该候选版本的 schema 核验；
这不意味着应自动运行迁移或部署新 WAR。

迁移前须按[数据库](../database.md)及[部署](../deployment.md)完成授权、备份、隔离重放和
维护检查点。SQL 文件存在不表示已经安装。结构核验与增量授权分别使用：

- [V019 只读核验](../../database/verify/v019-runtime-language-snapshot.sql)。
- [运行语言快照最小授权](../../database/grants/runtime-language-snapshot.sql)。

应用账号对永久登记仅有 `SELECT`/`INSERT`，对快照头和语言表仅有 `SELECT`/`INSERT`/`DELETE`，
无 `UPDATE`、DDL、授权管理或跨 schema 权限。永久登记的更新/删除和镜像更新还受触发器限制。
模板中的 DELETE 是后续清理职责的数据库权限上限，不构成当前清理 API；它不能单靠 MySQL
权限区分正常清理和恶意删后重插。清理所有权、生命周期保护和完整快照执行视图仍需分别实现。

## 可重复验证

无数据库定向命令见[测试指南](../testing.md)。Repository 的 JDBC 代理测试核对 SQL、参数绑定和查询回读、
独立 UUID 网络字节向量、身份复用/错配、坏字段、缺失/额外语言、每个写入点与回读故障，以及
调用方后续失败时的整笔模拟回滚。结构测试核对迁移、约束、授权和正式清单；这些不替代 MySQL
引擎验收。

另行授权的 disposable MySQL 实例须原样重放 V001—V020，再验证语言合同及工具增量：

- 三表初始为空、账本准确，旧 RELEASED 与 DRAFT 目录不变。
- UUID/ASCII/Unicode/范围 CHECK、唯一键、组合外键和更新/删除触发器实际拒绝非法写入。
- 应用账号的有效授权准确；有身份冲突时不能得到旧接受结果，错配快照不能跨域引用。
- 第九条语言写入、回读或调用方后续写入失败后，整个事务无已提交半分区；完整成功时一次提交。
- 合法补充字符按码点计数、二进制键按字节比较，驱动返回类型符合严格读取合同。

普通 Maven 构建不启动数据库。WAR 审计必须包含 Repository 与 V019/V020，排除作者包、
离线安装类、授权/核验脚本、测试向量、秘密和真实数据。语言分区验收通过也不改变旧 RELEASED
默认选择、完整规则族的 DRAFT 状态或 archive format 2 的发布门。
