# Schema 2 内部休息、时间与治疗

本合同连接[角色成长与资源](schema-2-character-statistics.md)中的真实角色状态和
[共同业务事务](business-write-transactions.md)。支持范围是准确运行快照下的单角色
INTERNAL 运行：标准短休、逐次生命骰选择、标准长休、职业资源恢复和对应时间历史。
完整战役、多角色共同时间推进、Host 入口和 archive format 2 发布仍遵循原采用边界。

## 模组声明与执行责任

模组通过类型化 `adventure.rest` 规则声明 `SRD_2014_REST_V1`。身份使用完整
`module_key / rule_type / rule_key`；规则键以 `rest.` 开头。字段为 `display_name`、
`description`、`source_page`、`algorithm` 和可选 `author_note`。当前算法只接受
`SRD_2014_REST_V1`，原文页码固定为 87；文本、字段修改及完整来源链复用 schema 2 合同。
执行要求准确快照中恰有一个启用的休息规则，且角色各职业均使用 `CHARACTER_ADVANCEMENT`。
规则缺失、禁用、冲突、未知算法或仅有统计能力时拒绝执行。
休息预检扫描准确快照中所有属于当前职业的启用资源，按各自职业等级判断是否已经取得。
已取得而执行模式为 `BLOCKED` 的资源会阻断整次休息；不能仅遍历可消费状态后遗漏这些义务。
尚未取得的未来资源声明仍完整验证，但不会提前成为当前休息的恢复目标。

模组继续通过每个职业资源的完整 `maximum_profile` / `recovery_profile` 声明容量和恢复
时机。执行器负责检查活动、时间、健康、生命骰选择、版本和历史容量，再实施确定的后果。
模组不能提供代码、数据库连接、客户端骰点或“已经完成休息”的自由声明。

## 唯一时间与封闭运行范围

本内部消费者一个 `run_id` 最多拥有一个真实角色根，初始化和恢复都在写入前检查，数据库
同时具有唯一约束。角色不可变事件链中的 `RestState.minute` 是该运行唯一权威时钟；
不会为同一内部运行建立两个各自推进的角色时钟。时间为 0—1,000,000,000 的整数分钟，
初始化为 0，每次推进输入为 1—1440 分钟，累计溢出在写入前拒绝。

这是有明确范围的内部采用层级，不是完整多角色战役的时钟实现。后续完整运行应将所有
角色、时间、健康和效果 owner 接入共同协调，而不能简单取消唯一约束后保留独立时钟。

当前运行的初始状态和全部可执行命令是封闭的：授予、成长、职业资源和本合同的休息命令
均不产生持续效果实例、专注、伤害包、环境周期义务或动作继续帧。共同守卫同时排除 legacy
活动战役和 PARTITION 残留。因此当前时间推进的适用持续效果集合可以从准确初始化及完整
命令历史证明为空；这个结论不能由客户端布尔值、模组声明或“未查询到效果”替代。
获得 `BLOCKED` 特性只记录获得事实，不激活该特性的效果。

启用任何持续效果、环境周期或动作 producer 前，必须先接入[持续效果协议](../design/v2/ongoing-effect-protocol.md)
要求的完整时间窗口、到期和后继闭包。未知命令、未支持活化和无法证明上述运行范围的状态
继续拒绝。这里没有实现通用持续效果引擎，也不自动应用饥渴、疾病、毒素、耗竭或施法效果。

## 命令与休息状态

每个命令都保存完整输入、前后状态及必要的服务端骰点；请求摘要包含全部有界选择。
下列字段互不通用，夹带无关字段会在服务事务前被拒绝。

| 命令 | 有界输入 | 作用 |
| --- | --- | --- |
| `REST_STARTED` | `SHORT_REST` 或 `LONG_REST` | 保存准确休息规则、开始分钟和开始 HP；已有窗口时拒绝 |
| `TIME_ADVANCED` | 活动和分钟数 | 活动仅 `SLEEP`、`LIGHT`、`STRENUOUS`；无窗口时只接受 `NONE` |
| `REST_COMPLETED` | 长休可选择各面数恢复数量 | 验证整个休息过程后一次提交收益；短休进入生命骰选择窗口 |
| `HIT_DIE_SPENT` | 一个已拥有的 d6/d8/d10/d12 池 | 消费一个可用生命骰并使用一个服务端骰点治疗；保留后续选择窗口 |
| `REST_ENDED` | 无 | 结束未完成尝试或关闭短休生命骰窗口，不额外发放收益 |

活动记录是 DM 对经过时间的有限叙事输入，不使用墙钟推断游戏内经过时间。每段都成为
不可变事件。状态保存睡眠、轻活动、剧烈活动累计分钟、最后活动、连续剧烈活动分钟和
中断标记；同类连续推进不能靠拆成多个请求规避中断门限。不同活动分隔的段不会合并成
同一个连续剧烈活动期间。历史恢复逐条验证这些状态变化。

休息进行中或短休生命骰窗口尚未关闭时，成长和职业资源消费拒绝；生命骰窗口中不能
继续推进时间。完整成长范围也不能直接调用 `RESOURCES_RECOVERED` 绕过休息条件，该旧
有限命令只留在明确标记的统计能力中。

## 标准短休

按本地 [SRD 第 87 页](../references/srd-5.1/pages/page-087.md)，短休至少持续 60 分钟，
期间不能发生剧烈活动。一次剧烈活动使本次尝试中断，后续增加安静时间不能修复它；
需要结束本次尝试后重新开始。

成功完成时恢复适用的短休职业资源，并打开逐次生命骰窗口。每次请求只选择一个已有面数，
完整前提、版本、资源集合与历史容量在随机性之前检查。服务端掷 `1..sides`，加当前体质
修正，治疗量最低为 0，实际治疗不超过缺失 HP；无论实际治疗多少都消费该生命骰。
调用方看到已提交结果后可以选择另一个生命骰或结束窗口。重复请求回放原结果，不再掷骰。

`Schema2CharacterHealthRules` 是本切片的治疗 owner：明确区分请求治疗量、实际治疗量和
前后 HP。它不推导伤害来源，也不把治疗转换成临时 HP。通用伤害、死亡、临时 HP、健康
转换和相应反应仍需各自真实消费者，不能借本治疗入口伪造。

## 标准长休

标准长休要求至少 480 分钟，其中睡眠至少 360 分钟，轻活动不超过 120 分钟；连续剧烈
活动达到 60 分钟使尝试中断。开始时必须至少具有 1 HP。种族、法术或特性对标准休息的
特殊替代不由显示文本推断，需要相应显式机制才能开放。

完成时，距上一次获得长休收益的完成分钟必须至少 1440 分钟。时长可以分段累计，但
收益间隔、开始健康和活动条件必须同时满足。失败不写完成事件或收益；之前真实提交的
活动和时间仍保留。成功后同事务完成：

- 恢复全部缺失 HP；
- 按选择恢复已消费生命骰，总数最多 `max(1, floor(totalLevel / 2))`，不能选择不存在的
  面数或超过该池缺额；
- 按各资源所属职业等级恢复适用的短休与长休职业资源；
- 保存本次长休收益完成分钟并关闭窗口。

资源的无限标记和规范零值保持不变；资源、生命骰、HP 与时间不能部分提交。需要独立选择
或额外条件的法术位／职业特殊恢复，必须先有相应正式声明和消费者，不退化为普通资源填满。

## 历史、恢复与验证边界

状态、活动段、生命骰选择、保存骰点、资源、长休收益时间和幂等结果共同提交或回滚。
提交未知沿用共同隔离、永久写阻断和原操作只读查证。历史保存全部前后事实，直接恢复
只验证并写入既有事实，不再次推进时间、掷骰、治疗、恢复资源或重发升级收益。

执行前检查每类集合容量、128 个事件上限和 32768 个历史子行上限。恢复要求原准确运行
快照、初始计划和规则绑定已经存在。当前局部恢复不等于完整战役文件或多角色时间恢复；
其最终生命周期接合仍遵循[保存与恢复](../design/v2/save-and-recovery.md)。

定向验证入口为 `Schema2CharacterAdvancementAndRestServiceTest`、
`Schema2CharacterRuntimeServiceTest`、`JdbcSchema2CharacterRuntimeRepositoryTest` 及
schema 2 成长、来源和快照测试。JDBC 夹具与静态 SQL 检查不代替真实 MySQL 的触发器、
权限、锁及连接池验收。
