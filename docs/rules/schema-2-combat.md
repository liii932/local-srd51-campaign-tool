# Schema 2 战斗、移动与动作继续

## 范围与责任


`CampaignDomainEngine` 通过冻结规则和有规则事实的场景成员接纳先攻、回合、近战攻击、步行、疾走、
撤离、闪避、起身与机会攻击。同一根处理[有限施法与持续效果](schema-2-spells.md)和
[有限怪物部署、充能与吐息](schema-2-monster-breath.md)，复用角色健康与唯一动作流。

角色可在本人攻击序列中执行[擒抱与推撞](schema-2-melee-control.md)，并通过同一战斗领域执行挣脱、释放与拖带。

规则数据来自[战斗作者合同](schema-2-combat-authoring.md)，动作流遵守
[动作继续协议](../design/v2/action-continuation-protocol.md)。

框架提供稳定身份、共同事务、幂等、类型化存储、容量预留与恢复；D&D 机制提供先攻、回合、
攻击、反应、移动和健康后果；模组提供明确的战斗算法、武器攻击参数和角色速度。
不存在动态脚本、任意效果参数袋或模组自定义执行阶段。


场景按照实际安置选择同一战役的角色和怪物。名册及规则依赖按事件当时的快照核验；
后台空间保留自己的时钟与未决事实。

战斗唯一拥有位置、先攻顺序、回合、动作／反应可用性、移动预算、倒地、攻击序列和动作流。
HP、临时 HP、死亡记录、装备实例、法术位资源及时间仍在原角色状态中。一次战斗命令产生的全部角色子事件
与战斗事件共同提交或回滚，不建立第二份可写 HP、装备、法术位或时钟。

## 接纳条件

调用方提供准确 operation、combat、campaign、完整成员绑定、冻结规则绑定、战斗版本、
全部成员版本和封闭命令。客户端不能指定先攻结果、命中、AC、伤害、反应余额、移动额度、
骰子、死亡结果或推进后的版本。同分顺序由有限的完整角色排列裁定，只作用于相同先攻总值。

`Schema2CombatRequest` 绑定准确成员和版本。
执行与历史复验均按 `local-dnd/schema2-combat-command/4` 的字节布局计算请求摘要。

支持的场景是所有人已警觉、彼此可见、无遮挡的平坦五尺方格，角色占一个格子，阵营固定。
步行路径每段相邻、不得进入已占格子；距离使用方格距离。地形、遮蔽、特殊感官、突袭、
穿过其他生物、飞行、游泳、攀爬、传送及推撞、拖带之外的强制移动需要各自消费者。
ACTIVE 规则角色和规则怪物的[爬行](schema-2-prone.md)复用相同路径与反应图，每尺支付两尺移动。
EXPLORATION 以每段当前速度为成本上限按同一姿态派生爬行，不借用旧战斗移动余额。
本入口没有把这些情况默认为普通步行的参数。

所有适用武器必须有启用的普通近战 profile，所有已取得特性／专长及其他效果必须在当前
闭合能力范围内。未知或缺失消费者在 RNG 与写入前拒绝，不能从候选中静默删除。
START 遇到已经零 HP 但仍持物的非战斗状态明确拒绝；本入口不凭空伪造历史掉物动作。

## 命令与实际后果

每名参战者在能行动的本人回合开始时获得一次普通动作、一次附赠动作和自己的步行额度。
`Combatant.actionsRemaining`、`bonusActionsRemaining`、`reactionAvailable` 和以半尺为单位的移动消耗分别记账。
战士可在同一回合用攻击动作开始攻击序列，再花附赠动作回气。额外攻击只改变该序列的可攻击次数。
角色步速来自其种族和实际装备，规则怪物步速来自战役内冻结的属性块。疾走增加等于当前速度的移动额度。

| 命令 | 接受事实与结果 |
|---|---|
| `START` | 服务器掷先攻 DEX 检定，应用不熟练护甲造成的劣势，保留全部原骰；按总值及同分裁定排序，开始第一个真实回合。 |
| `BEGIN_ATTACK` | 消费本回合 action 一次，创建有限攻击序列；普通额度为一次，冻结规则与实际已取得的[战士 Extra Attack](schema-2-extra-attack.md)可派生为两次。客户端不能指定额度。 |
| `ATTACK` | 从实际手持实例、冻结 profile、角色属性、熟练和目标 AC 派生攻击；自然 1 失手、自然 20 重击，真实取得的[精通重击](schema-2-improved-critical.md)可使选中 19 也重击。命中才掷伤害，按目标防御结算伤害，更新目标角色或规则怪物实例。玩家只能在共享场景中选择向本人揭示的怪物，战果随本人收据返回。 |
| `SECOND_WIND` | SQLite 有限回气：已实际取得的单职业战士在本人回合用附赠动作恢复 `1d10＋战士等级` HP，扣一次准确职业资源。普通动作、反应、移动和攻击序列保持。 |
| `FORFEIT_ATTACKS` | 明确放弃当前序列剩余额度并关闭序列，不退还 action。 |
| `DASH` / `DISENGAGE` / `DODGE` | 消费 action，分别增加速度等额移动、免除本人本回合机会攻击、建立真实闪避贡献。 |
| `MOVE` | 角色和怪物逐格走完整路径。整段先验证步速、可用移动、相邻格与实际占位。每步只在跨格后扣费，离开敌人触及时可在跨格前暂停。倒地每尺花两尺移动。 |
| `DROP_PRONE` | SQLite 规则角色在本人 ACTIVE 回合或 EXPLORATION 主动卧倒，不消费 action、reaction、移动、攻击额度或时间；仅存活且 HP 大于零的角色可用，已有倒地或未决流拒绝。 |
| `STAND_UP` | ACTIVE 本人回合清除倒地、消费速度的一半；半尺预算使 25 尺速度精确消费 12.5 尺。EXPLORATION 以独立六秒活动起身并推进场景时间，尚未死亡的倒地规则角色起身前不能离场。怪物姿态随它的实例转场。 |
| `END_TURN` | 关闭未完成的攻击序列，轮到下个角色；其反应恢复，必要的死亡豁免由服务器执行一次。 |
| `CAST` | 仅一级单职业生命领域的始终准备 Bless/Cure Wounds；真实组件、完整目标、action 与共享一级位通过首 RNG/写入前预检，成本与后果同事务接受。 |
| `END_CONCENTRATION` | 没有活动动作流时主动结束本人专注，不消费 action，可在他人回合执行。 |
| `END_COMBAT` | 无活动动作流及待到期 Shield／Ready 时，收束当前轮六秒并转为 `EXPLORATION`，保留角色、位置、倒地姿态、存续效果、独立原因及历史。 |
| `READY_ATTACK` / `READY_MOVE` / `READY_SPELL` | 用 action 准备真实响应；保持法术先支付成本并占用专注。触发后 `RELEASE_READY` 消费 reaction；详见施法合同。 |
| `CREATE_ENVIRONMENT_ZONE` / `END_ENVIRONMENT_ZONE` | 依准确冻结环境定义放置／结束固定抗魔区域，独立记录其对各目标应用的压制原因。 |
| `EXPLORATION_MOVE` | 按权威姿态和当前速度预检完整路径：每格直立成本五尺、倒地十尺；逐格核对区域，末尾推进六秒并结算到期。保留原移动、Dash、动作和反应余额，不开启战斗移动反应。 |
| `EXPLORATION_ADVANCE_TIME` / `EXPLORATION_HEALTH` | 在同一场景中显式推进时间及真实冻结健康效果；持续时间、压制与专注仍由原 owner 处理。 |
| `REENTER_COMBAT` / `CLOSE_SCENE` | 原场景保留效果和姿态重新掷先攻，或在全部来源关闭且没有尚未死亡的倒地规则角色时终结场景。 |

反应按本人下一回合开始恢复，不能在全局轮次边界统一恢复。每个完整 round 对所有成员的
原角色时钟推进六秒，秒余数、稳定恢复期限和长休收益间隔均精确保留；轮次内各角色回合
不分别加六秒。结束战斗显式收束当前轮并结算六秒，不开始下一回合或额外执行死亡豁免。
探索时间仍受未稳定零 HP 状态的约束，不能用结束战斗绕过需要处理的死亡风险。

攻击的优势／劣势包括实际护甲限制、闪避、倒地和失去意识。对五尺内失去意识目标的命中
为暴击；更远的倒地劣势与失去意识优势抵消。伤害在零 HP 时依普通／暴击记录一次／两次
死亡失败，并保留临时 HP 与即死处理。降到零 HP 同事务倒地，将手持物变为 `GROUND`，
保存物品原身份、战斗及准确格坐标。自然 20 死亡豁免恢复 1 HP 不会自动站立或重新持物。
[主动卧倒、爬行、Ready 爬行与起身](schema-2-prone.md)共用此唯一姿态；爬行仍触发 OA，
降至零 HP 中断原移动，不因同链治疗自动继续。拾取、重新装备及其他条件／效果仍需独立消费者；
掉落物不会伪装为 `CARRIED`。

施法资格、组件、共享法术位、Wizard 法术书、Bless／Shield 贡献、专注、同名覆盖、独立压制、
Ready 及探索持续见[施法合同](schema-2-spells.md)。怪物吐息与其适用防御见
[有限怪物合同](schema-2-monster-breath.md)。怪物近战与 OA 共享攻击、Shield 和伤害结算，狼命中后续接一次力量豁免。来源、伤害和倒地裁定见[怪物近战](schema-2-monster-attacks.md)。战士 5–6 级 Extra Attack 按[独立能力合同](schema-2-extra-attack.md)接合。
勇士 3–6 级 Improved Critical 由同一武器消费者用于普通、OA 和 Ready 单击，
反应后用原选骰重验；19 的自动命中解释与准确授予门见[精通重击合同](schema-2-improved-critical.md)。
SQLite 的[一级回气](schema-2-second-wind.md)在无未决流时同根完成附赠动作、职业资源扣减与治疗。
其他怪物动作、双持附赠攻击、高等级或其他职业 Extra Attack、
角色抗性和其他法术／反应机制仍须各自消费者，不能借通用命令绕过其成本与后果。

同一 Attack action 的 `limit/performed/forfeited/closed` 由战斗序列拥有；每击的
`sequenceKey/attackOrdinal` 关联原序列。每击完成后才增加已用次数，未决攻击期间不能开始
下一击或放弃绕过动作流。两击之间可合法移动、处理真实反应、改变目标或放弃余数。
机会攻击与当前 Ready 攻击响应各执行独立单击，不引用或扩大发起者普通 Attack 序列。
恢复校验额度范围、已付动作、连续 ordinal、完成击数与未决击数，再以原冻结规则和取得事实
核对未结束序列的额度；全部历史仍按原依赖和保留骰验算，恢复不调用随机源。

## 暂停、反应和继续

唯一活动 flow 保存多个真实移动记录、各自路径游标／已走前缀、frames、checkpoints、windows、
类型化反应选项、selection、施法和攻击事实。机会攻击可暂停于 Shield，Shield／Counterspell
声明可继续开放 Counterspell，Ready move 可嵌套机会攻击；所有子帧准确返回同一个父图。

战斗机会按先攻顺序排列，探索机会按稳定角色 UUID 排列，每个 actor 一个机会；
真实武器、施法 profile／法术位或 Ready 来源的有限选项在触发时冻结。
继续命令绑定准确 flow、leaf、window、opportunity 和完整乐观版本：

1. `PASS_REACTION` 仅忽略当前机会，不消耗反应或骰子。
2. `DECLARE_OPPORTUNITY_ATTACK` 重验当前来源、目标、触及及资格，消费一次反应并执行真实
   攻击子帧；已发生攻击原骰与伤害不会在父移动恢复时重做。
3. `ADVANCE_WINDOW` 仅在当前机会已经失资格时记录 `INELIGIBLE`，不抽骰、不消耗反应。
4. 全部机会终结后保存 `CLOSED`；普通写门仍关闭。
5. `CONTINUE_FLOW`／移动的 `CONTINUE_MOVEMENT` 仅消费准确 CLOSED 窗口一次，继续其实际 owner。
   移动者仍有资格则离开原格；已失能则保留完成前缀并停止。Shield 和反制不重掷父攻击或重付原法术成本。

GET、超时、重启和恢复都不隐式 PASS。旧请求只返回其不可变接受事实；继续新阶段必须
取得当前身份和版本。OPEN/CLOSED 窗口阻断无关新根及主动结束专注；反应子施法只从当前准确机会进入。
战斗或探索场景存续期间，角色的普通装备、健康、成长、休息等写命令
在幂等查证之后、首 RNG 之前被阻断，不能绕过回合和动作流。


## 事务、存储、预算与恢复

`Schema2CombatState` 定义命令、结算和前后状态，`Schema2CombatHistory` 定义成员、依赖版本
及连续事件。`CampaignDomainEngine` 按焦点安置选择依赖，显式传入 `sceneSecond` 结算法术期限和怪物休息。
同场景角色增加实际耗时，各自累计经历值可以不同。[空间合同](../design/v2/world-and-scene-spaces.md)

场景聚合保存完整成员、状态、版本闭包、成本、原骰、动作流、帧和窗口。
角色因果子事件保留其健康、时间、治疗及资源唯一归属，按根操作、角色和子序号获得稳定身份。
自我治疗先付资源再写健康；角色版本连续。持有、压制、Ready 和环境效果保留准确来源和结果。

新根与继续在首 RNG 前验证完整来源、全部目标与候选、当前及可达后果、版本、幂等和
容量。START 还为最多 128 个事件可经过的轮次与最长稳定恢复期限预留 253 分钟的时钟上界余量；
只在开始时检查，不在已接受后继重复扣除这份余量。每场景最多 128 个命令事件、16 个成员、128 个 flow、65,536 个历史子行；路径最多
64 格。协议图上限仍适用，具体预算可能更早拒绝新根。预留包含所有必需的窗口决定、父继续、
状态快照、角色子事件、回合事实到期及来源结束／场景关闭的额度，不截断候选，也不把超界自动解释为 PASS。

`Schema2CombatHistory` 对类型化历史和完整前后快照计数并预留必需后继。
完整文件和同版残留保留所有 OPEN／CLOSED 窗口、路径位置、已付成本、原骰和角色结果。
恢复核对规则、依赖版本及全部因果引用，保留唯一继续点。提交不明时按
[运行与事务](../design/v2/runtime-and-transactions.md)查证原操作。
