# Schema 2 战斗、移动与动作继续

## 范围与责任

`Schema2CombatRuntimeService` 是有限 INTERNAL 战斗消费者。它通过真实准备、来源快照和角色历史，
接纳先攻、回合、普通近战攻击、步行、疾走、撤离、闪避、起身及机会攻击；
[施法与持续效果](schema-2-spells.md)沿同一 owner 接纳 Bless、Cure Wounds、Shield、Counterspell、Ready、独立抗魔环境和探索场景。
规则数据来自[战斗作者合同](schema-2-combat-authoring.md)，动作流遵守
[动作继续协议](../design/v2/action-continuation-protocol.md)。

框架提供稳定身份、共同事务、幂等、类型化存储、容量预留与恢复；D&D 机制提供先攻、回合、
攻击、反应、移动和健康后果；模组提供明确的战斗算法、武器攻击参数和角色速度。
不存在动态脚本、任意效果参数袋或模组自定义执行阶段。

一个战斗引用同一 campaign 的 2—16 个真实准备角色。各角色保留自己的 run、snapshot、
preparation 绑定，冻结规则绑定必须完全一致，开始时角色时钟的分钟和秒必须相同。
这扩展的是 INTERNAL 多角色战斗接合，不能把独立准备记录称为已完成的整战役初始化。

战斗唯一拥有位置、先攻顺序、回合、动作／反应可用性、移动预算、倒地、攻击序列和动作流。
HP、临时 HP、死亡记录、装备实例、法术位资源及时间仍在原角色状态中。一次战斗命令产生的全部角色子事件
与战斗事件共同提交或回滚，不建立第二份可写 HP、装备、法术位或时钟。

## 接纳条件

调用方提供准确 operation、combat、campaign、完整成员绑定、冻结规则绑定、战斗版本、
全部成员版本和封闭命令。客户端不能指定先攻结果、命中、AC、伤害、反应余额、移动额度、
骰子、死亡结果或推进后的版本。同分顺序由有限的完整角色排列裁定，只作用于相同先攻总值。

支持的场景是所有人已警觉、彼此可见、无遮挡的平坦五尺方格，角色占一个格子，阵营固定。
步行路径每段相邻、不得进入已占格子；距离使用方格距离。地形、遮蔽、特殊感官、突袭、
穿过其他生物、飞行、游泳、攀爬、爬行、传送及强制移动需要各自消费者。
本入口没有把这些情况默认为普通步行的参数。

所有适用武器必须有启用的普通近战 profile，所有已取得特性／专长及其他效果必须在当前
闭合能力范围内。未知或缺失消费者在 RNG 与写入前拒绝，不能从候选中静默删除。
START 遇到已经零 HP 但仍持物的非战斗状态明确拒绝；本入口不凭空伪造历史掉物动作。

## 命令与实际后果

| 命令 | 接受事实与结果 |
|---|---|
| `START` | 服务器掷先攻 DEX 检定，应用不熟练护甲造成的劣势，保留全部原骰；按总值及同分裁定排序，开始第一个真实回合。 |
| `BEGIN_ATTACK` | 消费本回合 action，创建有限攻击序列；当前普通 Attack 的额度为一次。 |
| `ATTACK` | 从实际手持实例、冻结 profile、角色属性、熟练和目标 AC 派生攻击；自然 1 失手、自然 20 暴击，命中才掷伤害，真正更新目标角色。 |
| `FORFEIT_ATTACKS` | 明确放弃当前序列剩余额度并关闭序列，不退还 action。 |
| `DASH` / `DISENGAGE` / `DODGE` | 消费 action，分别增加速度等额移动、免除本人本回合机会攻击、建立真实闪避贡献。 |
| `MOVE` | 接受完整有限路径，按实际走过的段消费移动；有机会攻击时在离开触及之前提交暂停。 |
| `STAND_UP` | 清除倒地，消费速度的一半；移动预算用半尺单位，25 尺速度精确消费 12.5 尺。 |
| `END_TURN` | 关闭未完成的攻击序列，轮到下个角色；其反应恢复，必要的死亡豁免由服务器执行一次。 |
| `CAST` | 仅一级单职业生命领域的始终准备 Bless/Cure Wounds；真实组件、完整目标、action 与共享一级位通过首 RNG/写入前预检，成本与后果同事务接受。 |
| `END_CONCENTRATION` | 没有活动动作流时主动结束本人专注，不消费 action，可在他人回合执行。 |
| `END_COMBAT` | 无活动动作流及待到期 Shield／Ready 时，收束当前轮六秒并转为 `EXPLORATION`，保留角色、位置、存续效果、独立原因及历史。 |
| `READY_ATTACK` / `READY_MOVE` / `READY_SPELL` | 用 action 准备真实响应；保持法术先支付成本并占用专注。触发后 `RELEASE_READY` 消费 reaction；详见施法合同。 |
| `CREATE_ENVIRONMENT_ZONE` / `END_ENVIRONMENT_ZONE` | 依准确冻结环境定义放置／结束固定抗魔区域，独立记录其对各目标应用的压制原因。 |
| `EXPLORATION_ADVANCE_TIME` / `EXPLORATION_MOVE` / `EXPLORATION_HEALTH` | 在同一场景中显式推进时间、合法移动及真实冻结健康效果；持续时间、压制与专注仍由原 owner 处理。 |
| `REENTER_COMBAT` / `CLOSE_SCENE` | 原场景保留效果重新掷先攻，或在全部来源关闭后终结场景。 |

反应按本人下一回合开始恢复，不能在全局轮次边界统一恢复。每个完整 round 对所有成员的
原角色时钟推进六秒，秒余数、稳定恢复期限和长休收益间隔均精确保留；轮次内各角色回合
不分别加六秒。结束战斗显式收束当前轮并结算六秒，不开始下一回合或额外执行死亡豁免。
探索时间仍受未稳定零 HP 状态的约束，不能用结束战斗绕过需要处理的死亡风险。

攻击的优势／劣势包括实际护甲限制、闪避、倒地和失去意识。对五尺内失去意识目标的命中
为暴击；更远的倒地劣势与失去意识优势抵消。伤害在零 HP 时依普通／暴击记录一次／两次
死亡失败，并保留临时 HP 与即死处理。降到零 HP 同事务倒地，将手持物变为 `GROUND`，
保存物品原身份、战斗及准确格坐标。自然 20 死亡豁免恢复 1 HP 不会自动站立或重新持物。
拾取、重新装备、爬行及任意条件／效果仍需独立动作消费者；掉落物不会伪装为 `CARRIED`。

施法资格、组件、共享法术位、Wizard 法术书、Bless／Shield 贡献、专注、同名覆盖、独立压制、
Ready 及探索持续见[施法合同](schema-2-spells.md)。怪物动作、双持附赠攻击、Extra Attack、抗性、
其他法术／反应机制仍须各自消费者，不能借通用命令绕过其成本与后果。

## 暂停、反应和继续

唯一活动 flow 保存多个真实移动记录、各自路径游标／已走前缀、frames、checkpoints、windows、
类型化反应选项、selection、施法和攻击事实。机会攻击可暂停于 Shield，Shield／Counterspell
声明可继续开放 Counterspell，Ready move 可嵌套机会攻击；所有子帧准确返回同一个父图。

战斗机会按先攻顺序排列，探索机会按稳定角色 UUID 排列，每个 actor 一个机会；
真实武器、施法 profile／法术位或 Ready 来源的有限选项在触发时冻结。
继续命令绑定准确 flow、leaf、window、opportunity 和完整乐观版本：

1. `PASS_REACTION` 仅忽略当前机会，不消耗反应或骰子。
2. `DECLARE_OPPORTUNITY_ATTACK` 重验当前来源、目标、触及及资格，消费一次反应并执行真实
   攻击子帧；已发生攻击原骰与伤害不会在父移动恢复时重做。
3. `ADVANCE_WINDOW` 仅在当前机会已经失资格时记录 `INELIGIBLE`，不抽骰、不消耗反应。
4. 全部机会终结后保存 `CLOSED`；普通写门仍关闭。
5. `CONTINUE_FLOW`／移动的 `CONTINUE_MOVEMENT` 仅消费准确 CLOSED 窗口一次，继续其实际 owner。
   移动者仍有资格则离开原格；已失能则保留完成前缀并停止。Shield 和反制不重掷父攻击或重付原法术成本。

GET、超时、重启和恢复都不隐式 PASS。旧请求只返回其不可变接受事实；继续新阶段必须
取得当前身份和版本。OPEN/CLOSED 窗口阻断无关新根及主动结束专注；反应子施法只从当前准确机会进入。
战斗或探索场景存续期间，原角色服务的普通装备、健康、成长、休息等写命令
在幂等查证之后、首 RNG 之前被阻断，不能绕过回合和动作流。

## 事务、存储、预算与恢复

所有写入使用[共同业务事务](business-write-transactions.md)。`JdbcSchema2CombatRuntimeRepository`
是调用方拥有连接的叶仓储；运行 V033/V034 保存类型化成员、输入、版本闭包、原骰、结果、
状态前后值、帧、窗口、机会、移动、攻击及角色子事件引用。V032 保存冻结战斗规则镜像。
数据没有任意 JSON 状态袋。角色子事件包括伤害、回合死亡豁免与六秒时间推进，引用准确的
战斗操作和领域事实；其幂等键按根操作、角色和子序号稳定产生。
运行 V035/V037 保存[施法作者](schema-2-spell-authoring.md)的准确镜像，V036/V038 保存类型化施法命令/目标、
CAST 帧与结果、持续实例/目标、贡献骰、豁免及精确子行数，并前向修正战斗帧状态 CHECK。
`COMBAT_RESOURCE_SPENT` 与 `COMBAT_HEALING_APPLIED` 是引用真实施法帧的角色因果子事件；
自我治疗先消费资源再应用健康，角色版本连续，叶仓储不拥有提交权。Ready、Shield、专注 holder、
区域与每个独立原因均为类型化事实；`COMBAT_ENVIRONMENT_HEALTH` 保留冻结健康输入与真实结果。

新根与继续在首 RNG 前验证完整来源、全部目标与候选、当前及可达后果、版本、幂等和
容量。START 还为最多 128 个事件可经过的轮次与最长稳定恢复期限预留 253 分钟的时钟上界余量；
只在开始时检查，不在已接受后继重复扣除这份余量。每场景最多 128 个命令事件、16 个成员、128 个 flow、65,536 个历史子行；路径最多
64 格。协议图上限仍适用，具体预算可能更早拒绝新根。预留包含所有必需的窗口决定、父继续、
状态快照、角色子事件、回合事实到期及来源结束／场景关闭的额度，不截断候选，也不把超界自动解释为 PASS。

`read` 返回战斗及完整成员角色历史；读取重新核对原准备、规则、全部依赖版本、保存的骰子
与角色因果引用，不调用 RNG。`restore(Save)` 在相同准确准备快照下直接恢复全部类型化事实，
保存 OPEN／CLOSED 窗口、路径位置、已消费成本、原骰和角色结果。任何冲突、缺行、多行、
错误引用或不一致结果均拒绝。包含战斗子事件的角色不能单独恢复成没有其 owner 的孤儿。

提交响应丢失时返回 `UNKNOWN`，共同写门保持冻结；`inspect` / `inspectRestore` 只查证原操作，
不得盲目重试。这个内部恢复接口不是 archive format 2，也不开放 Host 路由、完整 base 安装、
完整战役生命周期或发布。采用边界见[状态矩阵](../design/v2/adoption-boundaries.md)。

规则依据优先查本地 SRD：先攻与回合 [p.90](../references/srd-5.1/pages/page-090.md)、
反应与移动／起身 [p.91–92](../references/srd-5.1/pages/page-091.md)、
攻击 [p.94–95](../references/srd-5.1/pages/page-094.md)、
零 HP [p.98](../references/srd-5.1/pages/page-098.md)、
倒地与失去意识 [p.359](../references/srd-5.1/pages/page-359.md)。
字段、范围、稳定错误与事务合同仍由项目定义。

`Schema2CombatRulesTest` 验证规则与继续，`Schema2CombatTimeRulesTest` 验证精确时钟，
`Schema2CombatRuntimeServiceTest` 经过真实准备／快照／角色／战斗仓储，验证完整闭环、幂等、
随机性前拒绝、原子故障和直接恢复；来源、镜像、事实仓储及 schema 测试分别验证各自边界。
JDBC 代理与静态 SQL 检查不代替真实 MySQL 约束、触发器、权限或部署验收。
